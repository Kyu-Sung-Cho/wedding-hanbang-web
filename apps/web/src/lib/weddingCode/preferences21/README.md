# 새 21문항의 문항 → 응답 설명 계약

이 디렉터리는 사용자가 2026-10-10에 제공한 새 21문항 전용이다. 기존 30문항의 문항·점수·네 글자·캐릭터 연결을 가져오지 않는다. 사람 대상 이해도·신뢰도·타당도는 **UNVALIDATED**다. 자동 테스트는 원문 보존과 계산의 재현성을 확인하며 사람 검증을 대신하지 않는다.

정본 입력은 이 작업에 첨부된 `붙여넣은 텍스트.txt`의 §4·§5·§6이다. 실행 코드의 exact 문구는 `bank.ts`, 허용 결과 문구는 `report.ts`의 `AGREEMENT_COPY`·`READING_COPY`다. 문항·안내·상황·선택지 변경은 이번 첫 배포에서 0건이며, 후속 의미 변경은 새 문항판과 호환성 계약을 요구한다.

## 버전과 API

| 경계 | 식별자 | 정본 |
|---|---|---|
| 문항 | `preferences21-20261010-r1` | `VERSIONS.questionnaireVersion` |
| 응답 설명 | `preferences21-reading-alpha.1` | `VERSIONS.interpretationVersion` |
| 결과 표시 | `preferences21-report-alpha.1` | `VERSIONS.displayVersion` |

`Answers`는 Q01~Q21을 모두 소유한 일반 객체다. 값은 정확히 `1`·`2`·`3`·`4`·`5`·`unknown`·`not-applicable`·`skipped`·`null` 중 하나다. `null`은 아직 미응답이며, 별도 응답을 자동으로 채운 값이 아니다. `parseAnswers`는 배열·빠진 ID·추가 ID·이름을 바꾼 ID·문자열 숫자·범위 밖 숫자·상속 객체를 거부한다. 버전은 저장·공유 봉투에서 별도로 검증해야 한다. 같은 ID 철자만으로 서로 다른 문항판을 비교하지 않는다.

`buildReport(Answers)`는 핵심 요약, 주제별 `insights`, 전체 원문·원답 `evidence`, 상황 한계, 파트너 질문, 행동 제안, 알 수 없는 부분을 반환한다. `insight.itemId`가 근거의 동일 ID로 이어진다. 수치 응답이 0개일 때도 응답 상태를 존중하는 전역 상황 안내·파트너 질문·행동 제안을 제공하며 이 세 항목의 `itemId`는 근거 문항이 없는 전역 안내를 뜻하는 `null`이다. 제안 문구는 실행 사실·상대의 답·공동 합의가 아니다. 모든 결과는 고정 문구이고 AI 호출·총점·축 점수·가중치·심리 유형을 만들지 않는다.

`buildSafeSummary(Answers)`는 친구 공유 **전에 확인할** 비가족 명시 선호 문구만 만든다. 공유 동의는 호출자가 받아야 한다. 원답 숫자·중간·낮은 답·가족 문항·상대 답은 반환하지 않는다. 반환값은 `{headline, summary, lines: [{itemId, text}]}`이며 `text`는 아래 동의 문구다. 공유의 복원·허용 ID 검증·최종 공개 범위는 `share.ts` 계약을 따른다.

## 해석 규칙의 선택

세 가지 방식을 비교했다. 문장별 직접 응답 설명은 원문과 답을 그대로 추적할 수 있다. 네 주제를 임의의 양극 점수로 합치는 방법은 반대 의미가 확인되지 않았고 양쪽 동의를 손실한다. 생성형 AI로 자유 설명을 만드는 방법은 불필요한 성격 추론과 같은 답의 문구 변동을 추가한다. 첫 배포는 문장별 고정 설명을 선택했다.

4·5는 각각 ‘대체로 맞아요’·‘아주 잘 맞아요’이므로 두 답 모두 아래 명시 선호 문장으로 설명한다. 원답 4와 5의 차이는 `evidence.response`·`responseLabel`에 보존한다. 3은 문장에 끌리는 정도가 반반이라는 설명을 반환한다. 1·2는 해당 문장이 원하는 방식과 맞지 않는다고 설명하며 정반대 선호를 만들지 않는다. 이 구분은 척도 이름을 읽는 규칙이며 잠재 특성의 절단점이나 정확도 기준이 아니다.

각 주제 핵심 줄은 동의한 문항 중 원래 순서의 첫 문장을 사용한다. 동의가 없으면 반반의 첫 문장, 반반도 없으면 낮은 동의의 첫 문장을 사용한다. 중요도·확신도 순위가 아니며 자세한 결과에서 수치 응답 전체를 읽을 수 있다. 응답 하나를 바꾸면 해당 문항의 설명과 그 주제 요약·전체 응답 수·관련된 동시 동의 안내만 달라질 수 있다.

## 동시 동의와 비수치 응답

Q02+Q03은 예산 집중과 재배분을 각각 보존한다. Q05+Q06은 함께 탐색할 범위와 먼저 찾을 범위를 추가로 물으며 모순 처리하지 않는다. Q13+Q14는 의견을 듣는 두 시점을 보존한다. Q18+Q19는 업체 연락과 밀린 준비를 각각 설명한다. Q20+Q21 모두 동의는 조건·순서를 답만으로 알 수 없다고 명시하고 방문 당일 첫 휴식을 직접 확인하도록 제안한다. 이 안내는 두 문항 모두 실제 4·5일 때만 나온다.

`responded`는 수치와 세 종류 별도 응답을 합친 수이고 `numeric`은 1~5만 센다. 모두 모름·모두 비해당·모두 건너뜀·모두 미응답에서는 수치 해석을 반환하지 않으며 남긴 상태를 구분해 설명한다. 가족 문항의 비해당은 가족 관계나 가치관으로 바꾸지 않는다. 소수 수치 응답은 그 문항의 장면만 설명하고 미확인 부분을 보여준다.

네 글자·16캐릭터 목표는 유지하지만 이 판의 연결은 **pending**이다. 미확정 연결을 임의의 가중치·절단점으로 확정하지 않는다. 이전 판의 캐릭터는 이전 판 응답과 당시 의미로 읽히도록 상위 진입·호환 코드에서 보존해야 한다.

## 자동 검증 기록

2026-10-10 좁은 모델 검증: `model.test.ts` 18개 통과, Vitest 4.1.11, Node 환경. 원문 21개·주제 순서·상황·안내·척도·버전, 엄격한 입력, 모두 1/3/5, 모두 모름/비해당/건너뜀/미응답, 혼합 응답, 동시 동의, 가족 비해당, 인접 값 원답, 전체 21개에 대한 단일 수정 격리, 비가족 공유 요약을 확인했다. 전체 앱 검사·브라우저·배포·인간 검증은 이 기록에 포함하지 않는다.

실행은 `PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=error`, `PNPM_CONFIG_OFFLINE=true`를 사용했다. 최초 실행은 기존 설치 상태와 기본 실행 설정의 차이로 테스트 로딩 전 실패했고, 당시 상태와 맞춘 `enableGlobalVirtualStore=false`·`nodeLinker=isolated` 플래그로 실행했다. 이후 공유 작업의 의존성 상태가 바뀌어 마지막 2026-10-10 22:14 KST 실행은 추가 플래그 없이 `corepack pnpm --filter @hanbang/web exec vitest run src/lib/weddingCode/preferences21/model.test.ts --environment node`로 18개 통과했다. 이 모델 작성자는 설치나 패키지 파일 변경을 수행하지 않았다. 전체 의존성 변경의 감사는 통합 릴리스 기록에서 별도로 확인한다.

남은 사람이 확인할 항목은 문항을 자기 말로 설명할 수 있는지, 실제로 떠올린 상황, 한 문장에서 서로 다른 판단이 섞였는지, 중간·모름을 구분할 수 있는지, 결과 문구가 본인의 답을 과장하는지다. 현재 실제 참여자 수나 인간 검증 결과를 이 구현에서 주장하지 않는다.
