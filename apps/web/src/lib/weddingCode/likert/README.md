# Likert preparation preference alpha

이 모듈은 30문항 개편본이다. 기본 `/wedding-code` 진입에서 사용하며, 구판을 지정한 쿼리·fragment는 기존 진입기로 읽는다. 구판 v3.1/v4/v5 문항, 코드, 저장 키와 링크를 재해석하지 않는다. 운영 반영 여부는 릴리스 증거로 별도 확인한다.

- 측정판: `likert-preferences-alpha.1`
- 문항판: `preferences-20261008-r2`
- 표현판: `likert-letters-alpha.4`
- 저장 키: `hanbang:wedding-code:likert-alpha.1:draft`
- 공유: `/wedding-code#wc-likert=…`의 별도 fragment schema. 이전 `/wedding-code-next#wc-likert=…` 주소도 같은 답으로 읽는다.
- 자동 저장 설정: `hanbang:wedding-code:likert-alpha.1:draft:autosave`. 구판의 명시적 저장 끄기도 읽어 존중하되 구판 설정을 쓰지는 않는다.
- 보관: 마지막 실제 저장부터 30일. 재방문·이어보기만으로 저장하거나 기간을 연장하지 않는다. 만료·잘못된 저장값은 복원하지 않고 원본 바이트를 보존하며, 사용자가 이 판의 저장 지우기를 누르면 제거한다.

## 해석 계약

비용 C/E는 기본 구성 보강/원하는 경험 추가, 과정 J/T는 직접 비교/합의 기준 아래 후보 분담 수용,
가족 O/U는 가족 생각 확인/둘의 기준 정리, 도움 L/A는 경청/구체적인 정리 도움이다.
두 관점은 독립된 긍정 문장으로 묻고, 평생 성격이나 능력의 양극으로 설명하지 않는다.
T는 한 사람이 초기 후보를 추려 공유해도 괜찮다는 수용 응답이다. 누가 후보를 추리는지,
본인이 위임하고 싶은지, 상대를 신뢰하는지와 참여 의지가 낮은지는 측정하지 않는다.
J4/T5도 직접 비교와 분담 수용에 모두 동의한 원답이며, T가 대표여도 수행자를 정하지 않는다.
L은 준비 직후 상대가 내 이야기를 들어주는 도움을 받고 싶은 마음이다. 사실 전달도 포함하며,
경청 응답만으로 감정 상담·위로·해결을 원한다고 좁히지 않는다.
함께 쉬기와 혼자 쉬기는 글자에 합산하지 않고 상황별 원답과 직접 요청에 남긴다.

1~5는 문장에 대한 동의 응답이다. 3, 모름, 비해당, 건너뜀, 미응답은 서로 다른 상태다.
차감, 평균, 역채점, 결측 대체를 하지 않는다. 동일 장면의 두 완전 응답 중 더 높은 값이 4/5일 때만
그 관점에 장면 한 표를 준다. 표가 더 많은 쪽을 임시 대표로 표시한다. 모든 장면의 일치를 요구하지 않는다.
양쪽 높은 응답, 낮은 응답, 동점, 장면 차이와 자료 부족은 별도로 보존한다.
이 표수·4/5 구분은 제품 편집 가정이며 실증 절단점이나 심리적 확신도가 아니다.

비율은 각 facet에 4/5로 답한 수를 그 facet의 1~5 응답 수로 나눈 동의 빈도다.
분자·분모와 반올림한 정수 비율을 함께 표시한다. 분모 0은 `null`이고 0%가 아니다.
각 방향의 분모가 독립적이므로 양쪽 100%도 가능하며 합을 100으로 맞추지 않는다.
모름·비해당·건너뜀·미응답은 분모에서 제외한다. 대표 표와 비율, 장면별 원답은 별도로 읽는다.

캐릭터는 새 네 글자의 16조합과 정적 일대일 대응한다. 임의 해시, 무작위 동점 해소,
9동물 순환, 구판 VWUH 등의 단순 ID 재사용을 하지 않는다.
모호한 글자는 부분 코드와 근거에 맞는 후보로 보이며, 정보가 없는 욕구를 채우지 않는다.
개인 결과와 두 사람의 대화는 캐릭터 이름 대신 실제 문항별 원답을 우선 사용한다.

## 데이터와 검증 범위

본인 답은 이 판의 새 브라우저 키만 사용한다. 초대받은 답이나 두 사람 링크를 자동으로 본인 저장에 넣지 않는다.
공유 링크는 두 동의를 확인한 뒤 생성하며, 답은 fragment에 있고 서버로 전송하지 않는다.
상대에게 자동 전송하거나 연결하지 않는다. 상대가 자신의 답을 마치고 두 사람 링크를 직접 돌려줘야 먼저 답한 사람도 비교할 수 있다. 답 수정 뒤에는 공유 동의를 다시 확인해 새 고정 링크를 만든다. 이미 전달한 링크를 바꾸거나 회수하지 않는다.
잘못된 버전·revision·응답 값은 그대로 거절하고 저장된 구판 자료를 삭제하거나 수정하지 않는다.
alpha.2는 T 설명의 과도한 위임 추론을 바로잡았고, alpha.3은 L 정의와 장면별 도움·쉬기 설명을
문항의 뜻에 맞춘 표현 수정이다. 참여자 문항·계산 규칙은 유지하며 측정판·문항판·저장 키도 유지한다.
alpha.4는 같은 문항·계산으로 결과의 장면별 준비 포인트와 짧은 부탁을 보완하고 반복된 원문 근거를 펼쳐 보기로 제공한다.
동일 측정판·r2의 표현 alpha.1·alpha.2·alpha.3 원답을 명시적으로 호환한다. alpha.1에는 T·L 교정 안내,
alpha.2에는 L·장면별 설명 교정과 원답 유지 안내, alpha.3에는 문항·원답·계산 유지와 이번 표현 보완만 안내한다. 현재 alpha.4에는 교정 안내를 붙이지 않는다.
읽기는 기존 저장·링크를 쓰지 않고 메모리에서 alpha.4 결과를 표시한다. 본인 이어쓰기·새 링크 생성은
alpha.4로 기록하며 원답·커서·사람 순서·날짜를 보존한다. 다른 문항판·측정판·미래 표현판
(alpha.5 포함)·v3.1/v4/v5는 호환하지 않으며, 거절할 때도 기존 저장 바이트와 구판 키를 보존한다.
선택 세부 취향과 우선순위는 결과 진입 조건이 아니다.

사람 대상 검증 0명. 진단, 정확도, 궁합, 결혼 결과 예측, 과학적 타당성, 실제 전문가 검증을 주장하지 않는다.
코드·단위 검사·실제 로컬 앱 화면 검증은 구현 검증이며 소비자 유용성 검증과 구별한다.
출시 일정과 인터뷰 인원은 이 개편본의 합의된 완료 기준이 아니다.
