## ⚠ 이 파일의 한계 — 닭과 달걀

이 문서는 **클론한 뒤에야** 읽을 수 있다. 그래서 진짜 처음 옮길 때는 아래 프롬프트를
클라우드·메모·휴대폰 등 **리포 밖**에 복사해둬야 한다.
백업 zip 을 두는 클라우드 폴더에 같이 넣어두는 게 가장 실용적이다.

두 번째 컴퓨터부터는 클론만 하면 이 파일이 있으니 그대로 쓰면 된다.

## ⚠ 주의 — 로컬이 운영 DB를 본다. 화면 작업은 전용 런처로

이 `.env.local` 은 운영 Supabase 를 가리키고, `SUPABASE_PRODUCTION_WRITE_CONFIRM` 까지
채워져 있어 **운영 쓰기가 열린 상태**다. `next dev` 로 띄우면 로컬에서 누른 것이
실사용자 데이터에 닿는다.

**화면을 눈으로 볼 목적이면 이걸 써라:**

```bash
node ./scripts/dev-web-local.mjs
```

합성 Supabase 환경을 주입해 띄우므로 **어떤 실제 프로젝트에도 접근할 수 없다.**
(`package.json` 에 등록돼 있지 않아 `node` 로 직접 실행한다.)

운영 데이터가 필요한 화면을 볼 때만 정상 `.env.local` 로 띄운다.

**권장 — 0단계 (XS)**: 운영 핀 6개(URL / ANON / SERVICE_ROLE / EXPECTED_URL /
EXPECTED_REF / WRITE_CONFIRM)를 Next 가 자동 로드하지 않는 별도 파일로 빼고,
운영 점검 스크립트를 돌릴 때만 명시적으로 주입한다. 이것만으로 실수 위험이 0 이 된다.

상세와 스테이징 전환 절차는 **`로컬개발-운영DB분리.md`** 참조.
