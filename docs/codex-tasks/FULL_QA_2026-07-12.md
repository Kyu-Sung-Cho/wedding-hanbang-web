## 운영 전 필수 조치

1. **역사적 baseline:** 전체 제품 QA 기준 `9200a545`와 EAS runtime 수정 `76a64403`을 commit/push했고, 두 exact SHA의 당시 Quality Gate와 Vercel Preview가 통과했다. 현재 PR 후보에는 적용되지 않는다. 새 PR HEAD의 merge 전 검증을 통과한 뒤에도, 실제 merge commit/origin main을 release SHA로 다시 고정해 CI·Vercel health·EAS `gitCommitHash`가 모두 일치하기 전에는 출시 승인으로 사용하지 않는다.
2. 운영 Amora·예약 blocker와 rewrite/delete inventory를 제품·개인정보 책임자가 분류·승인하고 forward-only 정리 절차로 0을 만든다.
3. 기존 모바일과 오래 열린 브라우저의 Data API/Auth/Storage 쓰기를 실제로 막는 자동 fence를 구현·연습한 뒤에만 `verified-v1`로 전환한다.
4. maintenance 이후 복구 지점, Storage inventory/export, 별도 프로젝트 restore drill과 측정 RPO/RTO를 확보한다.
5. **부분 완료:** Vercel에 직접 로그인해 production branch/domain, project root/build/install/Node 설정과 Production 변수 이름·target을 확인했다. 연구 접수와 삭제 cron은 `false`, 연구 이메일 검증 secret은 추가했다. 아직 launch-gate를 포함한 production anchor deployment와 rollback ID는 만들지 않았다.
6. EAS production에는 `EXPO_PUBLIC_SUPABASE_URL`, publishable key, site URL을 설정했다. exact `9200a545`의 Android internal preview 두 건은 Preview profile에 Node 고정이 없어 pnpm 11.7.0이 `node:sqlite`에서 실패했다. development·preview·production 모두 Node 22.13.0과 pnpm 11.7.0을 고정한 뒤 exact `76a64403`의 Android internal preview build `4db05478-e8b7-49d1-aa17-5f98fa45967c`가 FINISHED였고, 이후 exact `3af4e666bb67bfff1dcee5647553d0473f2c309f`의 Android internal preview build `e5701924-15fa-4d2d-8fc7-9dcf478399ef`도 FINISHED로 확인됐다. 둘 다 최신 PR 후보를 증명하지 않는 내부 검증 자산이며 store candidate가 아니다. iOS·production/store build와 실기기 증거는 없고, 최신 PR `headRefOid` 및 post-merge release SHA의 exact `gitCommitHash`로 다시 검증해야 한다.
7. Android `assetlinks.json`에는 Play App Signing 인증서, iOS AASA에는 Apple Team ID가 필요하다. 현재 두 production URL은 404이므로 store release 전 배포·검증한다.
8. 노출된 OpenAI 키를 폐기·회전한 뒤 PDF/Word/이미지 전체 조합, 취소, 429/5xx, 거부 응답을 운영 canary에서 확인한다.
9. Kakao 공급자 콘솔에서 과거 키 회전·폐기 이력과 도메인/IP/package 제한을 확인한다.
10. Vercel Deployment Protection automation-bypass 비밀의 consumer를 값 없이 inventory하고 새 비밀 선배포→성공 확인→구 비밀 폐기·거부→사용 로그 검토 순서로 회전한다.
11. GitHub `main`은 현재 branch protection과 required check가 없다. Private 저장소 plan 제한으로 API 설정이 403이므로, 지원되는 plan/ruleset을 확보하거나 병합 전 수동 독립 승인 절차를 별도 강제한다.
