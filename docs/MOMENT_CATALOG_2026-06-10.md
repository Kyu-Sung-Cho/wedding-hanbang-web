## (2) v1 우선 12개 풀 설계

선정: 빈도(전 커플 공통) × 불안 강도 × 트리거 가능성. 청첩장 모임은 파운더 지명 포함. 표기: **갭**=신규 작성 필요.

**① 양가 첫인사** — 소스: P1(대본·금기·비용)
- D-3: "첫인사 3일 전이야. 제일 무서운 건 '뭘 들고 가야 하나'일 텐데, 빈손만 아니면 절반은 성공이야. 과일이나 떡 케이크 10~20만 선, 오늘 주문해야 안 늦어."
- D-1 체크: 선물 / 단정한 복장(P1) / 호칭 '아버님·어머님' / 10분 일찍 도착 / 돈·집 얘기 금지. 💬 자기소개 대본 P1 기존.
- D+1: "어머님이 뭘 좋아하시는 것 같았어?" → 저장: 양가 부모 취향·호칭·분위기(명절·집들이에 재사용).

**② 상견례** — 소스: P2 + checklist `meeting`
- D-3: "상견례 사흘 전. '무슨 얘기 하지' 걱정되지? 대화 주제는 3개면 충분해. 오늘은 딱 두 개만 — 예약 재확인, 부모님 음식 취향 체크."
- D-1 체크: 예약·인원 확정 / 자리배치(부모님 안쪽 상석) / 금지주제(예단·돈) 양가 공유 / 계산 주체 합의 / 건배사(P2). 💬(부모님께): "엄마, 내일 12시 ○○ 예약했어. 돈 얘기는 그 자리에서 안 꺼내기로 했으니까 그것만 기억해줘!" — **갭: D+1 교차 감사 대본 신규**
- D+1: "어제 분위기 어땠어?" → 저장: 합의사항(예단 여부·예식 시기), 양가 성향.

**③ 예식장 투어/계약** — 소스: checklist `venue` + quoteCheck/contractShield + hiddenCosts
- D-3: "투어에서 제일 많이 당하는 게 보증인원이랑 성수기 할증이야. 질문 리스트 만들어놨으니 이것만 들고 가."
- D-1 체크: 보증인원 최소치 질문 / 식대 인상 조건 / 취소·변경 규정 / 예약금 상한 합의. 💬 계약 보류 대사: "오늘은 둘러보러 온 거라 견적서만 받아갈게요." — **갭: 투어 대본 신규**
- D+1: "어디가 제일 마음에 남았어?" → 저장: 후보 홀·견적(quoteCheck 연동).

**④ 드레스 투어** — 소스: checklist `dress` + hiddenCosts checkQuestion — **갭: D-1 패키지 조립 신규**
- D-3: "피팅비는 샵당 3~5만 현금이야, 미리 뽑아둬. 사진 금지 샵 많으니까 마음에 든 드레스는 이름이라도 적어 와."
- D-1 체크: 누드톤 심리스 속옷(검정 비침 사고 잦음) / 머리끈 / 본식 굽 높이 신발 / 스타일 참고 사진 / 현금.
- D+1: "몇 번째 드레스가 제일 예뻤어?" → 저장: 선호 라인·샵별 인상·헬퍼비 고지 여부.

**⑤ 스튜디오 촬영일** — 소스: P12(대본·체크·금기) + hiddenCosts studio
- D-3: "촬영 3일 전. 오늘 챙길 건 부케 생화 예약 확인이랑 헬퍼이모비 현금 — 이거 깜빡하는 사람이 제일 많아."
- D-1 체크: 신부—누드브라+여분·보정속옷·셀프촬영복 / 신랑—구두·벨트·무라벨 양말 / 오늘 밤 린스 금지(샴푸만)·과식 금지 / 간식(3시간+ 소요).
- D+1: "고생했어, 허리 안 아파? 제일 마음에 든 컷 있었어?" → 저장: 촬영 완료, 컨셉 선호(본식 스냅에 재사용).

**⑥ 가봉·최종피팅** — 소스: checklist `dress` 후반 + 리서치
- D-3: "가봉 최대 실패가 '가봉 후 다이어트'야. 지금 체중 그대로 가는 게 정답이야, 진짜야."
- D-1 체크: 본식 굽 슈즈 지참(키 차이 조정) / 신랑 동행해 나란히 서보기 / 앉기·걷기 테스트 / 베일·장갑 확정. — **갭: 신규 패키징**
- D+1: "수선 들어간 데 있어?" → 저장: 최종 드레스 스펙, 본식 헬퍼비 금액.

**⑦ 청첩장 모임** (파운더 지명) — **갭: 3셀 전체 신규** (P4 발송예절만 보유)
- D-3: "이번 주 ○○ 모임이지? 청첩장은 인원수+2장 여유로, 식사는 너희가 내는 게 국룰이야 — 1인 5만 잡으면 마음 편해. 답례품은 10명 중 8명이 생략하니까 부담 갖지 마."
- 당일 출발 전 체크: 종이 청첩장 매수 / 모바일청첩장 링크 / 계산용 카드 / 예약 재확인 / (선택) 답례품. 💬: "와줘서 고마워~ 밥은 우리가 살게, 부담 없이 와!"
- D+1: "애들 반응 어땠어? 못 온 친구한텐 모바일로 보냈어?" → 저장: 그룹별 전달 완료, 예상 하객 수 갱신(guestGuarantee 연동).

## (3) 트리거 인프라 요구사항 (기존 대비 증분만)

1. **이벤트 모델 확장**: `scheduleEvents.ts`의 카테고리당 1개 upsert 한계 해소 — `progress.__events`에 `momentType`(위 36개 enum) + 복수 이벤트 배열 허용. 청첩장 모임·투어 복수건 필수.
2. **날짜 캡처 툴**: 별도 온보딩 폼 불필요. 아모라 채팅 중 "토요일에 상견례야" 류 발화에서 날짜+momentType을 `__events`에 upsert하는 tool 1개 추가. 주 1회 "다음 주 일정 있어?" 질문을 proactive에 포함.
3. **momentLoop 모듈**: `lifecycle.ts`에 추가 — 입력: 이벤트(타입·날짜)+오늘 날짜, 출력: 해당 D-3/D-1/D+1 셀. 콘텐츠는 신규 `constants/moments.ts`(모멘트 × {d3문안, d1체크·대본, d1질문, memoryKeys, 소스 참조})에서 로드.
4. **proactive 라우트 배선**: 현재 미배선 상태 해소 — Vercel cron 1일 1회(오전 9시) per-user 스캔 → 라우트 호출. 6시간 쿨다운 유지하되 D-1·D-0 셀은 우선순위 예외. 발화 우선순위: 모멘트 셀 > lifecycle 가드레일.
5. **D+1 보조 신호**: cohort 이벤트(`tour_done` 등)는 날짜 미입력 모멘트의 D+1 안부 폴백으로만 사용.
6. **기억 저장**: D+1 응답을 customer_insights에 memoryKey 단위로 저장(부모 취향, 정산 합의, 하객 수 등) — 후속 모멘트 문안에 주입.
7. 알림 채널(웹푸시/알림톡)은 v2. v1은 앱·웹 진입 시 proactive 메시지로 충분.

12개 × 3셀 = 36셀. **기존 자산 재조립 약 22셀**(P1·P2·P5·P6·P9·P10·P12·P21, checklists, hiddenCosts checkQuestion). **신규 작성 14브리핑**: 청첩장 모임 3셀, 드레스투어 D-1 패키지, 예식장 투어 대본, 가봉 패키지, 신혼여행 출발 패키지, 사회자 전달·상견례 D+1 대본, D+1 안부질문 12개(각 1~2문장, 묶어서 1브리핑). 셀당 150~300자 분량.
