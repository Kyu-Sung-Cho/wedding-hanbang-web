## 완료 기준을 바꿔야 하는 부분

### 1. 작성한 내용을 다시 쓰게 만들지 않기

- 같은 계정·같은 공개 범위의 화면 왕복, 뒤로 가기, 칸 전환, 실패 후 재시도에서 초안 보존.
- 새 질문 제안은 기존 초안을 몰래 대체하지 않기.
- 계정 변경·연결 해제·삭제 후에는 옛 초안이 다른 사용자에게 나타나지 않기.
- 앱 종료 후 원문을 보존하려면 보관 위치·기간·동의와 삭제 계약부터 정하기. 무조건 영구 저장하는 해결책은 금지.

### 2. 성공·실패·결과 불명을 다르게 표시하기

- “저장됨/복구됨/완료”는 각각 확인한 저장 영수증·실제 입력·유효 완료 이벤트와 일치해야 한다.
- 서버가 저장했을지 모르는 경우에는 무작정 새 요청을 만들지 않고 같은 요청을 확인·복구한다.
- 늦은 응답이 최신 편집이나 다른 계정 상태를 덮지 않게 한다.

### 3. 기다림에 끝과 다음 행동이 있기

- 세션 확인부터 HTTP·본문·재조회까지 전체 작업에 종료 조건을 둔다.
- 시간이 지나면 초안을 남긴 채 재시도/상태 확인 등 실제 가능한 복구 행동을 제공한다.
- 앱을 강제 종료해야만 빠져나오는 로딩을 완료 상태로 보지 않는다.

### 4. 읽기와 입력의 자리를 지키기

- 320/375px, 짧은 높이, 큰 글씨, 키보드 표시 중에도 입력·전송·취소에 접근할 수 있어야 한다.
- 긴 고지와 검색 패널이 입력을 밀어내지 않기. 해결을 위해 중요한 고지나 공개 범위를 없애지 않는다.
- 오래된 기록의 접근 경로와 새 메시지 도착 시 읽던 위치 보존을 검증한다.

### 5. 오해를 바로잡되 실제 위험 보호는 유지하기

- 농담·부정·인용·평범한 합의·명시적인 정정을 실제 위험 문장과 함께 비교한다.

- 기억 안내는 사용자 설정뿐 아니라 실제 실행 가능 상태와 삭제 결과까지 반영해야 한다.
