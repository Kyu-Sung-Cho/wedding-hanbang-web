## 커플 연결 DB 권한의 단계 분리

Phase A 웹은 운영에 이미 있는 `join_couple_server(uuid,text,text)`를 사용한다. 이 함수의 service-role 실행 권한과 내부 본인·멤버십 확인은 읽기 전용 점검으로 확인했다. 따라서 웹 수정은 새로운 migration의 운영 적용에 의존하지 않는다.

Phase B는 예전 `join_couple`의 직접 실행 권한을 회수한다. CLI로 생성한 SQL과 실제 PGlite 회귀 검증은 별도 단계 산출물로 보존한다. 현재 릴리스 계약은 새 migration을 자동 허용하지 않으므로 이 웹 릴리스에 섞거나 gate를 약화하지 않는다. 이 권한 회수 전에는 DB 직접 호출 경로까지 가입 동의 경계가 닫혔다고 주장할 수 없다. 서비스 API 전환 확인, 호환성 범위 확인, 별도 DB 릴리스 계약과 운영 적용 후 권한 재검증이 남는다.
