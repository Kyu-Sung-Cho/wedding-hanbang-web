# 팀원 HTML 기반 랜딩 구현

상태: 별도 작업 트리의 로컬 구현. 운영 배포를 의미하지 않는다.

## 요청과 적용 범위

사용자가 전달한 `Main.dc.html`과 `LandingMobile.dc.html`을 실제 브라우저에서
렌더링하고 기존 랜딩과 비교했다. 파일 내부의 제작 안내는 참고 자료로 읽었으며,
실행 지시나 새로운 기능 요구사항으로 취급하지 않았다.

- 작업 트리: `wedding-amora-audit-fixes`
- 브랜치: `codex/amora-audit-fixes-20260906`
- 웹: `/landing`. `/`의 기존 로그인 상태별 이동은 유지한다.
- 모바일: 휴대폰 브라우저의 반응형 랜딩. 네이티브 앱 화면은 이번 디자인 범위가 아니다.
- 앞선 아모라 수정은 같은 작업 트리에 보존했다. 원래 `wedding` 폴더는 수정하지 않았다.

## 시안에 맞춘 내용

두 원본은 각각 1440px·390px 고정 폭이며 반응형 규칙이 없다. 원본의 데스크톱
1200px 내용 폭과 모바일 18px 여백을 기준으로 중간 폭을 연결했다.

- 제목은 고운돋움 400, 본문·버튼은 IBM Plex Sans KR, 테이프는 개구체다.
  랜딩에만 적용하며 제품 화면의 Paperlogy는 유지한다. 외부 폰트 호출 없이
  OFL 고지와 함께 필요한 글자만 WOFF2로 제공한다.
- 따뜻한 바탕·옅은 로즈와 세이지·둥근 흰 카드·가는 꽃가지 SVG를 적용했다.
  꽃 좌표는 첨부에서 가져왔으며 색은 기존 토큰을 사용했다.
- 히어로는 데스크톱 두 열, 모바일 제목 세 줄과 전체 폭 CTA로 바뀐다.
  라운지 예시는 모바일에서 첫 행동 뒤에 놓인다.
- 아모라 섹션은 모바일에서 설명 → 대화 → 공개 범위 순서다.
  커플 의견 섹션은 제목 → 대화 → 설명 → CTA 순서다.
- 예산·할 일·일정 카드는 모바일에서 아이콘과 설명을 가로로 배치한다.
  확인 예시는 최대 700px이며 모바일 선택지 배치는 두 개 + 한 개다.
- 무료 도구는 데스크톱 네 열, 모바일 아이콘 옆 설명이 있는 한 열이다.
  커뮤니티는 같은 따뜻한 구역에 이어지고, 마지막 신뢰·CTA는 어두운 띠로 묶인다.
- 확인·무료 도구 제목의 마지막 어절은 모바일에서 다음 줄, 데스크톱에서 같은 줄이다.

## 시안과 다르게 유지한 부분

첨부에는 실제 링크가 없고 일부 문구가 자리표시자다. 제품의 현재 동작과 연결했다.

- 주 CTA는 가입, 보조 CTA는 웨딩코드, 도구·커뮤니티·정책은 실제 경로로 연결했다.
  기존 클릭 계측과 로그인 상태별 이동을 유지한다.
- `[이용 커플 수]`와 인물 아바타를 실제 성과로 표시하지 않았다.
  사진이 제공되지 않아 “사진 자리·1440×300” 같은 제작 안내는 공개하지 않았다.
- 라운지 숫자·대화·승인 모형의 예시 표시를 카드 안에 유지한다.
- 개인 상담 처리·저장 범위, AI 답변의 한계, 웨딩코드 공유 링크,
  가격 원문 출처·기준일, 약관·개인정보·문의 경로를 유지한다.
  따라서 고지문이 있는 카드와 푸터는 시안보다 길다.
- 현재 커플 중 한 분의 확인으로 반영되는 동작을 따르도록
  “둘이 확인한 것만”을 “직접 확인한 것만”으로 명확히 했다.
- 분기 목록은 현재 날짜에서 계산한다. 원본에 고정된 2026~2027 목록을 복사하지 않았다.

## 검증 기록

- 실제 Chrome에서 320·390·768·1024·1440px 가로 넘침, 주 CTA 경로,
  본문 앵커, 예시 표시, 모바일 메뉴의 열기·Escape·초점 복귀·항목 선택 닫기,
  sticky 헤더를 확인했다.
- 로컬 폰트가 실제 렌더에 사용되는지 Chrome의 플랫폼 폰트 정보를 확인했다.
  기존 개구체 부분집합에 없던 글자가 다른 글꼴로 섞여 나오는 문제도 보완했다.
- 기존 노트 디자인의 고정 CSS 문자열 검사를 새 시안의 실제 렌더 계약으로 갱신했다.
  저장·개인정보·광고·샘플·가입·계측 계약은 유지한다.
- 랜딩 전체 **17파일·151개 통과**. 수정 파일과 랜딩 테스트 lint는 오류 0개이며,
  수정하지 않은 `twoSidedTrust.test.ts`의 기존 미사용 변수 경고 2개가 있다.
- 마지막 변경 후 웹 typecheck와 `build-web-safely.mjs` 빌드가 모두 통과했다.
  운영 키 없는 합성 환경이며, 연구용 경로의 운영 산출물 혼입 검사도 통과했다.
- 완성된 빌드를 `next start`로 띄워 다섯 폭의 브라우저 검사를 다시 통과했다.
  마지막 모바일 제목 줄바꿈을 포함하며, 브라우저 런타임 오류는 발생하지 않았다.
- 별도 담당자의 320·390·1440px 검수에서도 글자 잘림이나 기능 오류가 발견되지 않았다.
  Chrome 플랫폼 폰트 정보로 실제 글리프가 지정한 로컬 서체를 사용하는지 확인했다.
- 관련 아모라 초기화 검사 9파일·527개와 새 migration 릴리스 검사 32개도 통과했다.
  실제 운영 DB 적용, 다중 연결 잠금 경합, 유료 AI 장기 대화 재시험은 이번에 하지 않았다.
