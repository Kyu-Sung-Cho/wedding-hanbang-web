## 반영 내용

- 공통: 기존 자체 호스팅 Gowun Dodum·IBM Plex Sans KR 폰트를 재사용한다.
  따뜻한 배경, 얇은 선, 둥근 카드, 220px PC 사이드바, 18px 모바일 여백을 적용했다.
  `.planning-workspace`로 범위를 제한하고 `DESIGN.md`를 함께 갱신했다.
  작고 흐린 글자와 조작 경계는 읽을 수 있는 기존 대비 토큰을 유지한다.
- 체크리스트: PC 860px 상세창, 모바일 전체 폭 하단 시트, 진행률 고리와 단계별
  완료 수를 적용했다. 제목·하단 안내는 유지하며 긴 본문은 따로 스크롤된다.
  결혼식장·첫인사의 PC 최대 높이는 760px, 긴 상세는 900px이며 화면 높이에 맞춰 제한한다.
  모바일 최대 높이는 90dvh다. 체크리스트 외 기존 일정·검색의 기본 상세창 경로도 유지한다.
- 실제 21개 분야와 기존 ID·그룹·항목·저장·검색·상태 필터·제외 기능을 보존했다.
  분야 상태만 선언되고 개별 항목 확인이 없으면 가짜 완료율 대신 ‘항목은 확인 전’을 표시한다.
- 예절 가이드: 공개 목록과 25편 상세에 같은 디자인을 적용했다. 절별 요약,
  역할 선택, 타임라인, 대화 예시, 출처 더 보기, 앞뒤 가이드 링크를 유지한다.
  모바일에서는 시간 순서를 세로로, 다열 대화를 한 열로, 표를 모든 값이 포함된
  설명 목록으로 배치한다. 읽기 화면에 가상의 사용자·상대 동의·읽기 진행률을 만들지 않았다.
- 모바일 하단 메뉴와 상담 버튼이 겹치지 않도록 위치를 조정했다.
  닫힌 모바일 사이드바의 숨은 링크가 키보드 탐색에 남지 않게 했다.
  상담 패널은 체크리스트 시트가 열린 동안 그 시트의 Tab·Escape 처리를 가로채지 않는다.

## 시안과 현재 데이터의 차이

모바일 시안은 신혼집·혼인신고의 일부 항목을 생략하고, 축의금·하객 가이드는
본문 일부만 발췌했다. 실제 신혼집 12개·혼인신고 11개·첫인사 5개·결혼식장 9개 항목과
25편 전체 절·본문·법적 근거·표의 시점 및 한계·모든 출처를 보존했다.
`weddingPlanning.ts`, `scripts/manners/parts.json`, 생성된 `lib/manners/data.ts`는 변경하지 않았다.

자료 검토에서 시안의 판례 번호와 축의금 통계 출처 연결이 현재 원문과 다른 부분을 찾았다.
시안의 숫자·출처 축약을 새 사실로 복제하지 않고 현재 데이터와 주의 문구를 유지했다.
이번 작업은 가격·법률·여행 관행의 최신 외부 검증을 수행한 작업은 아니다.

교차 검토에서 조건부 항목이 ‘다음 할 일’이 될 때 조건 태그와 접근성 이름이
사라질 수 있는 문제를 고쳤다. 실제 조건을 화면과 스크린리더 이름에 모두 남긴다.
전역 dialog 스타일이 상세창 최대 폭을 덮던 문제도 명시적 너비로 보완했다.

## 검증

- 관련 웹 통합 43파일·442개 테스트 통과. 체크리스트·상세창·예절·레이아웃·상담 패널·
  아모라 미션/보드/저장창·랜딩 회귀를 포함한다. 전체 저장소 모든 테스트 실행을 뜻하지 않는다.
- 체크리스트 그룹·가이드 매핑·원문 생성·화면 필드 보존에 관한 저장소 계약 20개 통과.
- 웹 타입 검사 통과. 웹 전체 `eslint src`는 오류 0개·기존 경고 17개.
- 개별 브라우저 검사: 첫인사 상세의 Escape·원래 버튼 초점 복귀·쿼리 보존,
  가이드 이동 후 뒤로 가기·근거 링크의 실제 절 앵커를 확인했다.
- 예절 역할 필터의 마우스·방향키, 선택 라벨 초점, 더 보기의 Enter 조작,
  모바일 타임라인 방향과 표 내용 보존을 확인했다.

- 운영 키 없는 합성 환경에서 `build-web-safely.mjs` 통과.
  연구 경로의 운영 빌드 산출물 혼입 검사도 통과했다.
- 그 빌드를 `next start`로 실행한 Chrome 최종 검사에서 체크리스트 25화면과
  예절 46화면을 확인했다. 320·390·768·1024·1440px에서 목록·대표 상세를 확인하고,
  390px에서는 예절 25편 전부를 열었다. 가로 넘침·누락된 절/출처·페이지 오류는 없었다.
- 같은 빌드에서 예절 역할 필터·더 보기·표·타임라인 8화면 상호작용을 재검사했다.
  기존 랜딩·아모라 미션·보드도 390·1440px의 6화면에서 서체·폭·제목·런타임 오류를 확인했다.
- 체크리스트 상세의 끝 항목 접근, 체크 전환, Escape, URL 정리, 스크롤 잠금 복원을 확인했다.
  닫힌 모바일 메뉴는 숨겨지고 열기·닫기가 되며 PC에서는 메뉴가 보인다.
  모바일 상담 버튼이 하단 내비게이션과 겹치지 않는 것도 확인했다.
- 체크리스트 브라우저 검증은 기존 서버 검증 방식의 서명된 로컬 체험 세션을 썼다.
  예절은 로그인 없는 공개 경로를 사용했다. 이 검사에서 서버 변경 요청은 없었다.
  실제 사용자 계정 저장의 운영 E2E, 네이티브 기기, 운영 DB는 검증 범위에 포함하지 않았다.
- 원본 19개 해시를 마지막에 다시 계산해 불일치 0개를 확인했다.
  `git diff --check` 통과, 원래 작업 트리의 `git diff HEAD --quiet`도 통과했다.
