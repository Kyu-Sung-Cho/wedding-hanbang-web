# 아모라 팀 테스트 한도 예외

상태: 로컬 구현·회귀 검증 완료. 기존 59개 계정의 Vercel 설정 저장 완료, 코드 배포 대기.

사용자는 2026-09-09 현재 생성된 모든 계정이 팀원 계정이라고 확인하고 전체 해제를
요청했다. 같은 날 15:43 KST에 Supabase Auth 사용자 목록을 끝까지 조회해 확인한
기존 계정 59개의 UUID만 허용 목록으로 고정했다. 이후 신규 가입자는 포함하지 않는다.
개별 이메일과 UUID는 Git 문서에 남기지 않는다.

## 요청과 변경 범위

팀원이 아모라 테스트를 반복할 수 있도록, 서버가 지정한 Supabase Auth 사용자 ID만
채팅 시간당 요청 제한과 커플 누적·일일·서비스 전역 턴/비용 한도에서 제외한다.
웹과 모바일이 사용하는 `/api/chat`에 적용한다. 개발 환경의 기존 중재 경로도
같은 판정을 사용하지만 운영의 자동 중재 차단은 유지한다.

`AMORA_TEST_USER_IDS`가 없거나 비어 있으면 예외는 없다. 쉼표 또는 줄바꿈으로
구분한 완전한 UUID만 허용하고, 요청 본문·이메일·부분 일치·와일드카드는 사용하지
않는다. `auth.getUser()`가 확인한 사용자 ID만 비교하며 데모·평가 경로는 제외한다.

전체 비용 가드 비활성화와 관리자 승격도 검토했으나, 각각 일반 사용자 제한과
관리자 접근 권한까지 바꾸므로 계정별 테스트 예외를 선택했다.

## 유지하는 경계와 한계

- 인증, 커플 소유권, 공유/개인 범위, 동의, 입력 검증, 도구 승인 계약은 유지한다.
- 유료 호출은 동일한 receipt 예약·유효성 검증·정산·AI 로그를 거친다.
- 팀 계정도 예약 RPC나 receipt 검증에 실패하면 호출을 차단한다.
- 기존 전역 장부는 공유하므로 팀 사용량도 일반 사용자 전역 사용량에 포함된다.
  이 변경은 비용 장부를 분리하지 않는다. 팀 테스트 비용은 계속 발생한다.
- 별도 기억 컴파일 작업과 외부 AI 제공자의 계정/결제/요청 제한은 해제하지 않는다.

## 적용과 복구

1. 운영자가 승인한 팀 계정의 Supabase Auth UUID를 확인한다. 이번에는 현재 생성된
   모든 계정을 승인받아 목록을 조회했다. `profiles.is_admin`은 변경하지 않는다.
2. 적용할 Vercel 환경에 해당 UUID만 `AMORA_TEST_USER_IDS`로 저장한다.
3. 배포 전 현재 운영 버전과 릴리스 게이트를 다시 확인한다. 설정만 저장하면
   이미 실행 중인 배포에는 반영되지 않으므로 해당 변경을 포함한 배포가 필요하다.
4. 지정 계정의 한도 초과 상태에서도 상담이 생성·저장되고 receipt/AI 로그가
   남는지 확인한다. 일반 계정과 데모의 제한도 확인한다.
5. 복구할 때는 환경변수에서 대상 ID를 제거하고 다시 배포한다. 대화와 사용량
   장부를 삭제하거나 카운터를 초기화하지 않는다.
