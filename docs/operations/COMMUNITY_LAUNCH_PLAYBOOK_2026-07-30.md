# 웨딩한방 커뮤니티 출시·운영 플레이북

> 기준일: 2026-07-30  
> 제품 계약: 아모라가 결혼 준비를 예산·체크리스트·일정으로 정리하고, 커뮤니티는
> AI가 직접 겪을 수 없는 실제 경험의 빈칸을 채운다.

## 1. 커뮤니티가 해결할 한 가지

초기 커뮤니티를 넓은 웨딩 게시판으로 운영하지 않는다.

**첫 집중 문제**

> “이 추가금·계약 조건·업체 대응이 보통인지, 먼저 겪은 사람에게 묻고 공개 근거와
> 함께 다음 행동을 정하는 곳”

사용자에게 보여줄 핵심 흐름은 하나다.

```text
아모라로 준비 정리
→ 경험이 필요한 고민을 구체적으로 질문
→ 관련 경험자가 직접 겪은 범위만 답변
→ 질문자가 도움됨·해결 표시
→ 필요한 내용을 예산·체크리스트·일정에 반영
```

가입자 수나 글 수보다 이 한 바퀴가 실제로 끝나는지를 우선한다.

## 2. 운영 헌법

아래 항목은 성장보다 먼저 지킨다.

1. 일반 회원인 척하는 운영팀·AI 계정을 쓰지 않는다.
2. 글과 답변의 출처를 일반회원·운영팀·AI·업계종사자·광고·협찬으로 구분한다.
3. 협찬은 받은 혜택을 글 첫 화면에서 항상 보이게 한다.
4. 광고·협찬 글을 인기·추천·검색 결과에 넣지 않는다.
5. “인증후기”는 검증 기준·시점·주체를 증명할 수 있을 때만 표시한다.
6. 사람 답변만 답변 SLA와 도움 지표에 포함한다.
7. 검색어·견적 내용·글 초안을 분석 서비스로 보내지 않는다.
8. 비판 글도 광고주 여부와 무관하게 같은 운영 기준으로 처리한다.
9. 공개 합성 활동이 0건임을 확인하기 전까지 유료 유입을 확대하지 않는다.

## 3. 질문과 답변의 품질 기준

### 좋은 질문

다음 네 가지 중 최소 세 가지를 포함한다.

- 지역과 준비 시점
- 계약 전·계약 후·취소 협의 중 같은 현재 단계
- 실제로 안내받은 금액 또는 문구
- 지금 가장 결정하기 어려운 한 가지

개인정보, 계약서 서명, 전화번호, 계좌, 청첩장 주소는 올리지 않도록 작성 화면과
운영 답변에서 반복 안내한다.

### 좋은 답변

다음 중 최소 두 가지를 포함한다.

- 본인이 직접 겪은 시점·지역·단계
- 실제 비용 또는 추가금 구조
- 계약서에서 다시 확인할 문구
- 다시 한다면 먼저 물어볼 한 가지
- 질문자가 지금 실행할 다음 행동
- 확인된 사실과 개인 의견의 구분

“저도 그래요”, 업체 순위, 근거 없는 단정만 있는 답은 해결 답변으로 세지 않는다.

## 4. 창업자가 직접 해야 하는 첫 72시간

### 1일 차 — 신뢰 기준선

- 공개 글·댓글을 사람·운영팀·AI·업체·광고·협찬으로 전수 분류한다.
- 합성 계정 콘텐츠 은퇴 마이그레이션을 운영 릴리스 절차로 적용하고 read-only
  사후 검증 증거를 남긴다.
- `웨딩한방 운영자`임이 명확한 프로필과 운영 원칙을 공개한다.
- 운영 시트에 `질문`, `답변자`, `모집`, `신고`, `지급`, `채널` 탭을 만든다.

### 2일 차 — 답변 공급

- 최근 2년 안에 결혼한 지인·실사용자 후보 30명을 적는다.
- 그중 10명에게 1:1로 연락하고 5회의 15분 인터뷰를 잡는다.
- 현재 준비 중인 사람에게 실제 고민 3건을 동의받아 수집한다.
- 질문마다 답변할 경험자 2명을 미리 지정한다.

### 3일 차 — 첫 해결

- 실제 질문 3건을 공개하거나 통제된 베타에서 공유한다.
- 질문마다 경험자 2명에게 직접 답변을 요청한다.
- 질문자에게 답변을 전달하고 도움이 됐는지 확인한다.
- 해결된 질문만 개인정보를 제거해 검색 가능한 글로 남긴다.

## 5. 첫 4주 운영

| 기간 | 창업자 행동 | 목표 | 다음 단계 통과 조건 |
|---|---|---:|---|
| 1주 | 하루 10명 개별 연락, 인터뷰 10회, 질문 5건 직접 매칭 | 답변자 8명, 해결 3건 | 합성 활동 0, 출처 표시 100% |
| 2주 | 답변자 안내, 첫 온라인 질문 클리닉 | 답변자 15명, 누적 질문 10건 | 24시간 사람 답변률 70% 이상 |
| 3주 | 해결 글 3건 발행, 유기 채널만 시험 | 누적 해결 12건 | 질문자 재방문 40% 이상 |
| 4주 | 첫 투명성 보고, 취약 분야 답변자 보강 | 누적 해결 20건 | 24시간 답변률 80%, 중앙 6시간 이내 |

목표를 못 맞추면 날짜만 보고 다음 단계로 넘어가지 않는다. 질문 유입을 늘리기 전에
답변 공급을 먼저 보충한다.

## 6. 매일 운영 루틴

- 09:00, 20분: 개인정보·신고·밤사이 미답변 확인
- 12:30, 30분: 새 질문마다 경험자 2명 매칭, 답변자 모집 연락 5건
- 20:30, 45분: 질문자·답변자 응대
- 21:30, 20분: 도움됨·해결 확인, 추가 질문 보완
- 마지막 15분: 해결된 질문 하나를 검색·SNS용으로 정리

24시간 운영을 약속하지 않는다. 실제 확인 가능한 운영시간을 공개한다.

## 7. 답변 SLA

| 상황 | 운영 기준 |
|---|---|
| 전화번호·계좌·주소·서명 등 개인정보 | 운영시간 내 1시간 이내 임시 숨김 |
| 계약 마감이 72시간 이내 | 1시간 내 접수 확인, 6시간 내 첫 사람 답변 목표 |
| 일반 질문 | 12시간 내 첫 사람 답변 목표, 최대 24시간 |
| 12시간 동안 답변 없음 | 관련 경험자 3명에게 추가 요청 |
| 24시간 동안 해결 단서 없음 | 질문자에게 필요한 정보 보충 요청 |
| 48시간 동안 경험 답변 없음 | 공식 확인 경로와 다음 행동 안내, 미답변 상태 유지 |

## 8. 북극성 지표와 출시 게이트

북극성 지표는 **주간에 실질적인 도움을 받거나 준 사람 수**다.

필수 지표:

- 1시간·24시간 안에 사람 답변을 받은 질문 비율
- 첫 사람 답변까지 걸린 시간의 중앙값
- 24시간 이상 미답변 질문 수
- 질문자 도움됨·해결 반응률
- 답변 후 질문자 재방문률
- 주간 사람 질문자·답변자 수
- 비운영진 답변 비중
- 공개 합성 활동 수
- 광고·협찬 대가 상세 공개율
- 신고 처리 시간

### 유입 확대 금지 조건

다음 중 하나라도 발생하면 신규 유입을 줄이고 답변·운영 공급을 보충한다.

- 24시간 답변률이 이틀 연속 80% 미만
- 미답변 질문이 5건 초과
- 신고가 24시간 넘게 대기
- 미표시 AI·협찬·업체 영업 발견
- 운영자가 설명할 수 없는 활동량 증가
- 개인정보 사고

## 9. 현재 구현 상태

### 이번 로컬 구현에 포함

- 아모라 → 준비 도구 → 커뮤니티 질문·피드 → 공시 근거의 화면 계층
- 최근 질문 중 답변 대기 글 노출과 피드 중복 완화
- 피드의 `답변 기다려요`·`답변 N개`·`해결됨` 상태
- 광고·협찬 대가의 상시 표시
- 광고·협찬 글의 인기·추천·검색 제외
- 랜딩 진입만으로 동기방에 자동 가입시키던 동작 제거
- 커뮤니티 검색어·글 초안의 페이지뷰 분석 전송 차단
- 댓글 답글 복구와 질문 해결 토글의 로컬 구현·검증

### 운영 릴리스 전에 반드시 별도 확인

- 합성 커뮤니티 활동 은퇴 마이그레이션의 운영 적용과 사후 증거
- 댓글·글 RLS 및 운영 전용 컬럼 위조 방지
- 사람 답변만 집계하는 `content_origin`과 공개 뷰
- 답변 알림·읽음·동의·재시도·해지 정책
- 인증후기 검증 워크플로
- 댓글 신고·제재 집행·이의제기·불변 감사 로그
- 게시글별 서버 메타데이터·공유 이미지·canonical·soft-404
- 모바일 320px·375px와 데스크톱 실제 브라우저 검증

이 문서는 운영 계획이다. 운영 DB 반영이나 프로덕션 배포가 완료됐다는 증거로 사용하지
않는다.
