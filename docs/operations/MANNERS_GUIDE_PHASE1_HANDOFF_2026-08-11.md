## 데이터 계약 — 왜 이렇게까지 하는가

```ts
type MannersSource = { label; url; checkedAt; scope; supports }
// supports = "이 출처의 어느 대목이 무엇을 뒷받침하는가"
//   → 출처 세탁 방지. 진짜 URL을 붙였는데 그 페이지가 그 수치를 말하지 않는 것이
//     가장 흔한 실패다. 여기에 적을 수 없으면 그 출처는 쓰면 안 된다.

table.asOf   // "2025년 4월 조사" — 표 **안**에 배지로 노출
table.limits // "이 숫자가 말하지 않는 것" — 표 **안**에 노출
```

`asOf`·`limits`를 넣은 계기가 이 기능의 핵심 교훈이다.
**출처·확인일·적용범위를 다 붙여도 오해가 남는다.** 한국소비자원 참가격의 1인당 식대
중간가격 58,000원은 전국 예식장 370곳을 합친 값이고 **조사에 상차림·유형 구분이 없다**.
같은 기관의 2026년 2월 동향에서는 코스식 11만 9,000원 / 뷔페식 6만 2,000원 /
한상차림 5만 5,000원으로 **두 배 넘게 갈린다**. 호텔 예식을 앞둔 사용자에게 58,000원은
실제의 절반짜리 기준이었다.

각주가 아니라 **표 안**에 두는 이유: 사용자는 표만 캡처해서 옮기고, 캡처에는 각주가 안 따라간다.

### 6차가 드러낸 것 — 이 기능에서 가장 중요한 교훈

**편집 지시문 9건이 5차례 감사와 사람 눈을 통과했고, 그걸 막으라고 만든 계약 테스트가 초록불이었다.**

원인은 가드가 특정 문구(`(이 항목 수정)`)만 막았기 때문이다. 실제 유출은 형태가 제각각이었다.

```
"해당 셀을 다음으로 교체: …"      "note를 교체: …"
"warning 항목을 교체: …"          "tip \"…\"에 항목 추가: …"
"기존 항목 뒤에 다음 항목을 추가하세요 — …"
"say: \"…\" / note: \"…\""        ← 직렬화 원본이 통째로 say 필드에
"{\"kind\": \"warning\", \"items\": [ …"   ← raw JSON이 본문에
checklist title 자리에 249자 문단  ← 필드 종류 불일치
```

**모든 유출의 출처가 같다 — 감사 결과의 `fix` 필드를 일괄 적용하는 단계.**
감사 에이전트는 사람에게 말하듯 "이 항목을 교체하세요"라고 쓰는데, 패처가 그걸 그대로 넣는다.

수렴 판정의 결론이 정확하다:
> *"지금까지의 의미론적 렌즈(톤·누락·모순)는 수확 체감에 들어섰다. 남은 위험은 **기계로 잡는 종류**다.
>  이번에 네 렌즈 중 셋이 검증 안 된 법률 문구를 그대로 넣자고 했다 = **과교정 신호**."*

그래서 가드를 **특정 문구가 아니라 지시문의 문법**을 막도록 다시 썼다 —
편집 대상을 가리키는 말(필드명·블록종류·인덱스) + 명령형 어미 + 직렬화 흔적.
**변이 6종으로 검증했다**(지시문 4형태 + 마크다운 + 필드종류 불일치, 전부 탐지).

### 4차에서 잡힌 출시차단 3건

1. **`cost-saving` 2절** — 주어가 잘린 문장 + 근거 없는 날짜("2026년 1월 27일") + 자율 공개를 의무로 뒤집은 서술.
   *"틀린 것을 자신 있게 말했고, 독자가 그걸 근거로 업체 앞에서 말을 꺼내면 반박당하는 쪽이 그 사람이 된다."*
2. **`guest-manners` 초상권** — 같은 문장이 두 번, 두 번째는 **판결 원문이 아닌 각색문에 "대법원 판결" 출처**를 붙임.
3. **혼인신고 수수료** — "확인했다"고 선언한 표 안에 판독이 갈리는 주장.

### 법적 불이익 — 전 파트 최대 구멍이었던 것

**금액을 정하는 화면에 청탁금지법 한도가 없었다.** `gift-money` 관행 표가 직장 축의금
10~30만원을 제시하면서 '청탁'을 0회 언급했다. 받는 쪽이 공직자등이면 **받은 사람에게
과태료**가 간다 — 축하하려던 사람이 상대에게 과태료를 안기는 구조였다.
표 바로 뒤에 경고 블록을 넣었다(각 파트가 단독 URL로 열리므로 다른 파트에 있는 것으로는 부족하다).

## 계약 테스트가 강제하는 것 (15단언)

**내용 계약**
- 모든 파트에 한계 고지(`caveat`) — 편차 또는 시효·확인 신호
- **예시 대사(`dialogue`) 최소 1개** — 이 제품의 값은 추상적 조언이 아니라 할 수 있는 말이다
- 수치 표: 출처를 대거나 `unsourced` 표시 + `asOf`에 연도 + `limits` 비어 있지 않음
- 출처: `https://`, 블로그·카페 도메인 거부, 확인일 형식·미래 금지, `supports` 필수
- 판정 금지 — **품질 판정만** 막는다. "일 최고 체감온도 33℃"(기상청 기준), "최고음",
  "설문 1위", "포장 등급"은 사실이라 통과해야 한다

**본문 위생** (전부 실제로 났던 사고)
- **편집 지시문 유출 0** — 지시문의 *문법*을 막는다(대상 지시어 + 명령형 + 직렬화 흔적).
  특정 문구만 막았다가 두 번 뚫렸다
- **필드 종류 일치** — 섹션 제목 80자·블록 제목 90자·대사 220자·열 제목 60자 미만.
  `title` 자리에 249자 문단, `say` 자리에 직렬화 원본이 들어온 사고를 길이로 잡는다
- **렌더 안 되는 마크다운 0** — 렌더러에 파서가 없어 `**강조**`가 별표로 보인다
- 문장 반복 0 — **완전 일치 + 앞 30자 겹침**. 어미만 다른 중복을 완전일치 검사가 놓쳤다
- 치환 파손 0 — `…않습니다입니다`, 이중 공백, 앞뒤 공백

**변이 테스트로 검증했다**(저장소 규칙: "가드는 반드시 변이 테스트로 검증할 것").
지시문 4형태 + 마크다운 + 필드종류 불일치 = 6종을 주입해 **전부 탐지**되는 것을 확인했다.

⚠️ **다음 사람에게**: 감사 결과를 일괄 적용할 때가 가장 위험하다. 모든 유출이 그 단계에서 나왔다.
적용 후에는 반드시 이 테스트를 돌리고, `git diff`로 눈으로 한 번 더 볼 것.

## data.ts 재생성 절차

`data.ts`는 **생성물이다.** 손으로 고치지 말고 원본을 고친 뒤 재생성한다.
손으로 고치면 다음 재생성에서 조용히 사라진다.

| 파일 | 역할 |
|---|---|
| `scripts/manners/parts.json` | **원본.** 10파트 전문 (내용 수정은 여기서) |
| `scripts/manners/generate.mjs` | 직렬화기 |

```bash
node scripts/manners/generate.mjs          # parts.json → data.ts 생성
node scripts/manners/generate.mjs --check  # 쓰지 않고 불일치만 확인 (CI용, 불일치 시 exit 1)
```

`--check`를 CI나 `verify-local`에 넣으면 "data.ts를 손으로 고쳤다"를 잡을 수 있다.
아직 넣지 않았다 — 넣는 것을 권한다.

⚠️ **생성기에 내용 수정 로직을 넣지 마라.** 2026-08-11에 그것 때문에 사고가 났다 —
부분 일치 치환이 문단을 잘라먹었고, 전체 필드 치환이 문단 앞부분을 통째로 날렸다.
`generate.mjs`는 직렬화만 한다. 내용은 `parts.json`에서 고치고 `git diff`로 확인한다.

## 남는 위험 — 없앨 수 없는 것

1. **법령·제도는 개정된다.** 결혼세액공제는 2026년 혼인신고분까지가 현행 일몰이다.
   청탁금지법 가액, 소비자분쟁해결기준(2025-12-18 개정본), 공정위 고시 계도기간이
   콘텐츠 수명보다 빨리 움직인다. → **분기 1회 강제 리뷰 목록**을 만들 것.
2. **출처 URL은 사라진다.** 67건이 `checkedAt: 2026-08-08`로 고정돼 있다.
   → **링크 헬스체크를 CI에** 넣고, 죽은 링크는 문장까지 함께 내리는 규칙이 필요하다.
3. **표는 캡처되어 경고 없이 돌아다닌다.** `asOf`·`limits`를 표 안에 넣었지만
   표 **뒤**의 경고 블록은 캡처에 안 따라간다. 숫자를 셀에 넣을 때는 그 셀 안에서 완결시킬 것.
4. **각 파트가 단독 URL로 열린다.** 이번에 발견된 안전 구멍 대부분이 여기서 나왔다
   (스미싱 경고가 발송 파트에만, 청탁금지법이 청첩장 파트에만). "파트 A에 있으니 됐다"는 틀린다.
5. **검토자도 틀린다.** 이번에 검토 에이전트가 "법제처 페이지에 답이 있다"고 해서 열어보니
   다른 페이지였고, 제안 문구에 `3.36%`가 있었는데 원문은 `3.17%`였다.
   **에이전트 제안의 수치·URL은 반드시 사람이 다시 확인할 것.**
