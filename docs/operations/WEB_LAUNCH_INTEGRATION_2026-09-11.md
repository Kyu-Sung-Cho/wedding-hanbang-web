# 웹 출시 수정 통합 — 2026-09-11

이 문서는 현재 후보의 실행 순서와 남은 운영 조건이다. 코드 수정·로컬 검증·실제 배포를 구분하며, 이 문서만으로 운영 변경을 허가하지 않는다.

## 통합 범위

기존 최신 화면과 예산 결정 기록, 개인 상담 응답, Next 이미지 파서 방어, 전체 복원 준비를 한 후보에 정상 병합했다. 원본 worktree와 PR379/380을 보존한다. 새 단위는 가입 동의 증빙·탈퇴 수동 검토 관측·개인정보 설명·주거 신고 안내·웨딩코드 응답 설명이다.

## 동의 전환 순서

1. 최종 후보의 동의·인증·모바일 호환·통합 검사를 통과시키고 실제 rollout에 필요한 기존 전역 쓰기 차단과 백업·복구 조건을 확보한다.
2. 신규 계정 생성이 차단된 상태에서 실제 UTC 전환 시각을 확정한다. 이 시각을 `SIGNUP_CONSENT_LEGACY_BEFORE`에 정확한 `YYYY-MM-DDTHH:mm:ss.SSSZ` 형식으로 한 번 고정한다. 임의 과거일·예시값·미래값을 운영 증거로 사용하지 않는다.
3. Vercel Production 환경에 설정하고 실제 production builder의 불리언 검사 결과를 후보·설정 영수증과 연결한다. 로컬 모의 환경 검사는 운영 설정 증거가 아니다. 미래/누락/정규화되는 잘못된 날짜는 빌드가 거절한다. Turbo에서도 같은 변수를 입력으로 취급한다.
4. 새 서버만 접수하도록 전환한다. `app_metadata.signup_consent`의 서버 증빙만 새 동의 증거이며, `user_metadata`는 사용자가 수정할 수 있다. 전환 전 생성 계정의 기존 기록은 접근 호환을 위한 `legacy_unverified`로 표시한다. 이를 법적 동의 증명이나 최신판 동의로 승격하지 않는다.
5. 새 폼은 실제 표시한 `2026-09-11` 판본으로 제출한다. 이미 저장된 과거 판본은 바꾸지 않는다. 오래 열린 폼·구버전 앱의 stale 제출은 재확인 응답으로 처리한다. 공개 개인정보 문서는 보유·삭제 설명을 정정한 판본이며 처리 범위를 추가한 것이 아니다. 정정 전 소스는 `5e884d50714828643f780269bec384dcad093975`의 `apps/web/src/app/privacy/page.tsx`에 보존되어 있다.
6. 새 가입·기존 회원·동의 없는 소셜 계정·새로고침·모바일 서버 판정을 확인한 뒤 쓰기 차단 해제를 판단한다. 동의 전환 이후 구 서버로 단순 rollback하면 신규 가입 증빙이 누락될 수 있으므로 먼저 신규 접수를 닫고 기록을 보존한다. cutoff를 뒤로 미루어 문제를 감추지 않는다.

전환 시각 확정·운영 설정·실제 신규 가입 검사는 아직 실행하지 않았다. 여기의 판본 날짜는 운영 전환 시각이 아니다.

신규 이메일 가입은 Auth `createUser` 한 요청으로 계정과 서버 소유 동의 증거를 함께 만든다. 기존 미인증 계정도 중복이면 복구 안내만 제공하고 증거를 바꾸지 않는다. 생성 후 인증 링크의 계정 ID·이메일이 새 계정과 일치해야 메일을 준비한다. 생성 이후 링크·메일 실패는 계정을 임의 삭제하거나 동의 증거를 덮어 보상하지 않는다. 로그인한 소셜 계정의 동의 저장은 해당 세션의 동의 키만 갱신하며 이름·provider·권한 전체를 재전송하지 않는다.

## 함께 닫는 제품 경계

- 신혼집 임대차 신고 항목을 기존 체크리스트 ID를 바꾸지 않고 추가했다. 신고 기준일을 입주일로 오해하지 않도록 설명하고 가이드의 해당 문단과 아모라 질문 초안을 연결한다. 근거 링크는 공유 목록 한 곳에서 가져오며 기존 59개 링크를 보존한다.
- 웨딩코드는 문항·점수·코드 판정을 변경하지 않는다. 한 응답만으로 반복 성향을 주장하지 않게 결과 카피를 한정하고, 연락 지연 관련 조언은 해당 응답을 실제로 선택한 경우에만 제공한다.
- 모바일 동의 판정은 서버의 현재 계정 결과를 사용한다. 화면 재진입과 계정 교체 때 이전 판정을 폐기하고, 동의 조회가 멈추면 12초 안에 재시도 가능한 오류로 끝낸다. 이는 웹과 공유하는 인증 계약의 호환 보완이며 앱스토어 출시 검증을 대신하지 않는다.
- 탈퇴 수동 검토 건은 운영 집계와 관리자 조회로 확인한다. 이 조회는 삭제·재처리·완료 처리 기능이 아니다. 알림 SDK 호출 성공을 운영자 수신 성공으로 간주하지 않는다.
- 아모라의 기본 설명 중 반복 표현을 정리해 일반 할 일 요청에서 답변 수정 지침이 길이 제한으로 잘리는 문제를 막는다. 입력 상한과 도구 실행·확인·안전 계약은 유지한다. 저장 문맥이 더 길어질 때 선택 문맥이 생략될 수 있다는 기존 한계까지 없어진 것은 아니다.
- 최종 빌드의 가입 화면에 남은 검정 선택색·제출색을 승인된 공통 역할 토큰으로 교정한다. 비밀번호 확인 문구가 blur 때 생기며 첫 동의 클릭을 빗나가게 하는 문제는 문구 공간을 미리 확보해 막는다. 동의 조건과 선택 항목의 의미는 바꾸지 않는다.

## 운영 증거가 더 필요한 항목

- 격리된 전체 DB/Auth/Storage 복원과 정식 릴리스 인가. 수집 도구·합성 복원 검사를 운영 원본 복원으로 대체하지 않는다.
- 실제 두 시험 계정의 공유 상담/개인 상담·기억·초대/연결 해제 경계.
- 별도 탈퇴 전용 시험 계정의 접수부터 Storage·Auth 삭제·완료 확인. 기존 대화 시험 계정을 임의로 삭제하지 않는다.
- 탈퇴 수동 검토와 장애 알림의 실제 운영자 수신, 고객지원 수신 확인. 코드 관측과 실제 알림 전달은 다르다.
- 최종 배포 후보의 아이폰 Safari와 운영 핵심 흐름 확인. 앞선 버전의 기기 확인을 새 후보 결과로 재사용하지 않는다.

지원 담당자는 사용자 본인이고 `contact@hanbang.ai` 수신함 사용은 확인된 상태다. 메일 발송, 운영 삭제 실행, OS 설치·재부팅의 완료를 이 문서에서 가정하지 않는다.
