# 팀원 HTML 기반 아모라 상세 화면 구현

상태: 별도 작업 트리의 로컬 구현 및 아래 범위의 검증 완료. 운영 배포를 의미하지 않는다.

## 범위와 원본

사용자가 제공한 HTML 5개를 브라우저에서 렌더링하고 실제 제품에 적용했다.
첨부 안의 제작 설명·스크립트·예시 문구는 참고 자료로만 읽었다.

- 작업 트리: `wedding-amora-audit-fixes`
- 브랜치: `codex/amora-audit-fixes-20260906`
- 앞서 수정한 아모라 문제와 랜딩은 같은 작업 트리에 보존했다.
- 모바일은 휴대폰 브라우저의 반응형 화면이다. 네이티브 Expo 화면은 이번 디자인 범위가 아니다.

| 첨부 | 제품에 적용한 위치 |
|---|---|
| AmoraMissions.dc.html | `/wedding/chat/missions` 데스크톱 |
| MissionsMobile.dc.html | 같은 경로의 모바일 레이아웃 |
| AmoraDecisionBoard.dc.html | `/wedding/chat/board` 데스크톱 3열 보드 |
| BoardMobile.dc.html | 같은 경로의 모바일 상태 탭·필터·카드 |
| SaveSheetMobile.dc.html | 대화 답변 보관과 아모라 변경 제안 확인 창 |

기존 `/wedding/chat` 대화는 유지하며 미션·보드로 이동하는 링크를 연결했다.
새 화면의 함께 대화·나만 상담 링크는 기존 공개 범위 전환을 사용한다.
나만 상담 링크는 체험 계정이나 확인되지 않은 역할에 개인 대화를 열지 않으며,
URL 이동만으로 메시지를 자동 전송하지 않는다.

## 시안에 맞춘 디자인

- 따뜻한 아이보리 바탕, 흰 카드, 로즈·세이지 상태 색, 검은 주요 버튼을 적용했다.
- 고운돋움 제목과 IBM Plex Sans KR 본문을 로컬 WOFF2로 제공한다.
  동적 한국어 기록에도 대응하도록 현대 한글을 포함했고 OFL 고지를 보관했다.
- 데스크톱 220px 사이드바, 작은 상단 제목·탭, 모바일 18px 내용 여백을 적용했다.
- 미션은 준비 묶음 5개, 우선 확인할 카드 2개, 완료 기록과 이어지는 화면으로 구성했다.
- 보드는 데스크톱 3열, 모바일 상태 선택, 분야 필터, 검색, 카드 내부의 근거 영역을 적용했다.
- 저장 창은 모바일 아래쪽 시트, 데스크톱 430px 중앙 창, 22px 모서리,
  분야·보관 위치와 확인 내용, 전체 폭 확인·나중에 정하기 버튼으로 구성했다.
- 기존 전역 제목 스타일이 새 서체와 크기를 덮지 않도록 아모라 영역만 분리했다.
  다른 제품 화면의 기본 Paperlogy는 유지한다.
- 작은 글자의 색 대비와 44px 누름 영역을 확보했다. 따라서 일부 버튼·카드는 원본보다 크다.

## 실제 기능과 연결한 부분

시안의 예시 데이터를 운영 기록으로 표시하지 않았다.

- 미션은 현재 공유 할 일과 21개 분야 체크리스트에서 계산한다.
  5개 묶음은 화면상의 분류이며 새 잠금·단계 상태를 저장하지 않는다.
  상대방의 접속·오늘 완료·예상 소요 시간·후보 수를 만들어 표시하지 않는다.
- 결정 보드의 실제 데이터는 공유 준비 할 일이다. 상태는 기존
  `open / done / dismissed`에 맞춰 `진행 중 / 완료 / 보류·숨김`으로 표시한다.
  한 분의 완료 표시가 두 사람의 합의 또는 체크리스트 완료를 뜻하지 않는다.
- 보드의 검색·분야 선택·완료·보류·복구는 실제 조회·변경 API와 연결했다.
  부분 조회일 때 숫자와 검색의 범위를 명시하며 조회 실패를 빈 목록으로 숨기지 않는다.
  계정·커플 변경이나 늦게 도착한 응답으로 이전 기록을 다시 표시하지 않도록 보호한다.
- 체험 모드의 샘플과 변경은 화면 안에서만 유지한다. 실제 API 쓰기는 하지 않는다.
- 답변의 저장 버튼은 먼저 원문과 함께 보는 범위를 보여준다.
  확인한 뒤 서버의 공유 메시지 ID와 선택 메모만 전송한다. 원문은 서버에서 읽는다.
  개인 상담은 보관 버튼 대상에서 제외하며 성공 응답의 `saved: true`를 확인한다.
- 변경 제안의 확인 창은 기존 승인·실행 흐름을 사용한다.
  지원하지 않는 제목·분야 수정이나 양측 동의 상태를 새로 약속하지 않는다.
- 확인·취소, 중복 요청 방지, 처리 중 닫기 방지, 오류 후 재시도,
  Escape·Tab 초점 이동·닫은 뒤 초점 복귀를 검증한다.

## 교차 검수에서 함께 수정한 문제

- 기존 레거시 할 일 배열의 동시 변경이 서로를 덮어쓰던 문제를 수정했다.
  서버에서 확인한 커플·준비 기록 ID와 읽은 `state_revision`이 모두 일치할 때만 저장한다.
  충돌하면 최신 원본을 다시 읽어 해당 카드 하나만 변경하고, 3회 실패하면 409로 끝낸다.
  다른 카드·체크리스트·일정·예산과 80개를 넘는 원본 배열을 보존한다.
  정규 테이블의 카드 변경 경로는 유지한다.
- 이 보호는 기존 `20260730102000` 및 `20260802170000` migration의
  서버 소유 revision 트리거 계약을 사용한다. 새 migration은 추가하지 않았다.
  버전이 누락되거나 유효하지 않으면 쓰기 전에 실패 처리한다.
- 상담 패널 안의 저장 창이 Tab·Escape를 처리할 때 부모가 가로채던 문제를 수정했다.
  두 창을 함께 닫는 경우에도 스크롤 잠금이 남지 않도록 복원 책임을 나눴다.
- 상담 패널을 열 때 사라지는 실행 버튼이 닫은 뒤 다시 생기므로,
  새 버튼으로 초점을 돌려 키보드 탐색을 이어가도록 보완했다.
- 랜딩의 CSS 검사가 파일 끝의 다른 디자인까지 읽던 범위를 실제 랜딩 블록으로 한정했다.
  랜딩의 그림자·저장·공개 범위 등 기존 검증 기준은 유지한다.

## 검증 기록

- 최종 통합 **70파일·550개 테스트 통과**. 미션·보드·조회 훅·저장 창·상담 패널·
  공개 범위·레이아웃·레거시 경합·기존 랜딩을 함께 검사했다.
  전체 저장소의 모든 테스트를 다시 실행했다는 뜻은 아니다.
- 웹 `tsc --noEmit` 통과. 웹 `eslint src`는 오류 0개이며 미사용 변수 등 경고 17개가 남는다.
- 운영 키 없는 합성 환경에서 `build-web-safely.mjs` 통과.
  연구용 경로의 운영 산출물 혼입 검사도 통과했다.
- 빌드 결과를 `next start`로 실행해 Chrome에서 미션·보드 각각
  320·390·768·1024·1440px를 확인했다. 가로 넘침과 런타임 오류가 없었고,
  실제 서체·제목 위계·고정 헤더·모바일 내비·검색·체험 상태 변경을 확인했다.
- 실제 대화 화면의 저장 창을 320·390·768·1440px에서 열어
  크기·취소 시 요청 없음·Escape·Tab·스크롤 복원·중복 방지·오류 후 재시도를 확인했다.
  저장 API는 브라우저 테스트에서만 합성 응답으로 대체해 실제 사용자 기록을 쓰지 않았다.
  `saved: false` 거부와 `saved: true` 이후 저장함 링크·초점 복귀를 모두 확인했다.
- 실제 예산 화면의 상담 패널 안에서도 390·1440px 저장 창을 열어
  Tab 이동, 자식만 닫기, 부모 스크롤 잠금 유지, 부모 닫기와 실행 버튼 초점 복귀를 확인했다.
- 변경 제안 확인 창은 별도 실제 브라우저 렌더와 DOM 통합 검사로 확인했다.
  운영 계정의 제안을 승인하거나 유료 AI를 호출하지 않았다.
- 레거시 경합 검사는 실제 Supabase JS의 요청 조건과 저장소의 원본 revision 트리거를
  로컬 PGlite에서 실행했다. 같은 원본을 읽은 두 요청, 다른 준비 정보의 동시 변경,
  충돌 종료, 버전 누락, 긴 원본 배열 보존을 재현했다.
- 운영 DB의 트리거 적용 상태, 실제 다중 연결 PostgreSQL 잠금,
  실제 계정의 개인 상담 링크 E2E와 네이티브 기기 검증은 이번에 하지 않았다.

`audit-amora-screen-qa.log`, `audit-amora-note-browser.log`, `audit-amora-nested-browser.log`.
