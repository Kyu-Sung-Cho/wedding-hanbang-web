# 아모라 페르소나 결함 수정 범위 — 2026-09-11

이 문서는 코드 변경의 근거와 검증 경계를 기록한다. 운영 배포 완료 증명이나 소비자 만족도 측정 결과가 아니다.

## 실제 점검

운영 M4 `e9f74aa3823cd75ed4180623d6276845180bd8ab`에 독립 합성 시험 계정 12개로 40개 사용자 발화를 실행했다. 39개 일반 응답은 SSE와 서버 정본 본문을 대조했고 준비 상태의 승인 없는 변경은 없었다. 마지막 발화는 일반 모델 응답이 아닌 HTTP 200 `ephemeral_safety` 분기였다. 시험 도구의 저장 메시지 기대와 달라 중단한 원본은 보존했으며, 별도 브라우저에서 긴급 안내·새로고침 후 비보관을 확인했다. 외부 연락은 실행하지 않았다.

새 시험 계정들은 소유권·잔존 확인 후 정리했다. 기존 로그인 시험 계정의 파트너와 자료는 유지했다. 실제 회원 탈퇴 UI나 서로 다른 두 계정의 격리 검사를 대체하지 않는다.

## 예산 SQL 배포 경계

- 새 SQL은 `20260911080244_amora_budget_plan_explicit_allocations.sql` 하나이며 SHA256은 `2d26acb1d7b4ef26e4ec7e1c04de3e4e0e4180e57521e49128059ab3c1ec9372`다.
- 실제 ledger216을 기준으로 기존 private dispatcher 함수 하나만 변경한다. 새 explicit-budget 계약은 이전 SQL 원문·기존 M3 예산 결정 영수증·Realtime 계약을 보존한다.
- 운영 반영은 `--amora-explicit-budget-hotfix`의 격리 검증, 동시성 검사, 백업, 쓰기 차단, 정확 pending SQL, 커밋 일치 및 적용 후 검증을 필요로 한다. 정적 검사만으로 배포를 승인하지 않는다.
- 운영의 새 웹과 구 SQL이 섞여 explicit 카드를 잘못 적용하지 않도록 SQL·웹 배포 순서를 함께 관리한다. 배포 후 원래 재현 문장의 카드·승인·예산 재조회·결정 기록·원복을 별도 확인한다.

## 기억 금지의 정확한 한계

실제 P10 합성 계정은 기억 OFF였다. 추가 로컬 Memory ON 검사에서 원래 후속 문장은 W4라 후보가 없었고, ‘결혼식 장식 취향이야’를 포함한 W0 변형에서 후보 1개가 재현됐다. 이를 실제 고객 정보 유출이라고 표현하지 않는다.

대화 범위 금지는 동일 actor/visibility/segment의 이후 발화까지 이어지며 첫 모델 실패 전에도 남긴다. 정책 조회/저장 오류·시간초과는 허용으로 바꾸지 않는다. cron은 제공자 전·생성 전·commit 전에 다시 확인하며 관측한 새 금지의 결과를 폐기한다.

다만 마지막 TS 조회 직후 금지가 기록되고 기존 DB memory commit이 동시에 진행되는 경쟁을 원자적으로 차단하는 새 DB RPC는 이번 변경에 포함하지 않는다. 이미 저장된 node를 이 정책이 자동 삭제·숨김한다고 말할 수 없다. 배포 전에 cursor가 지나간 과거 금지 원문의 전면 backfill도 포함하지 않는다. 최악의 다중 segment batch 쿼리 비용은 실제 부하 검사 과제로 남는다.

## 출시 판단에서 남겨야 할 검사

합성 상담 통과는 실제 소비자 만족이나 오류 0을 보장하지 않는다. 수정 후 동일 문장의 실제 운영 재시험, 시험용 두 독립 계정의 공유/개인 범위·초대·삭제, 실제 휴대폰, 고객지원 수신·장애 알림 및 DB/Auth/Storage 전체 복원은 각각 실제 증거가 있어야 완료로 판단한다. 기존 UI 기초 확인이나 격리된 SQL 되돌리기를 이 검사들의 대체 증거로 사용하지 않는다.
