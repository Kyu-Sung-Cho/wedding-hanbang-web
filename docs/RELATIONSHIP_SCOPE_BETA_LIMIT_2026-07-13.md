# 현재 베타의 커플 역할 범위와 공개 출시 차단 조건

> 판정일: 2026-07-13
> 상태: 제한된 베타 범위 고지 완료, 관계 구성 확대는 **NO-GO**
> 이 문서는 관계의 적합성이나 혼인 자격을 판단하지 않는다. 현재 데이터 모델과 개인정보 격리가 실제로 지원하는 범위만 기록한다.

## 결론

현재 웨딩한방의 커플 연결과 비공개 대화는 **신부 1명·신랑 1명 역할 구조만** 안전하게 지원한다. 사용자가 두 역할 중 하나를 정확히 선택할 수 없는 관계 구성은 아직 가입·커플 연결 대상으로 약속하면 안 된다.

이 제한은 제품이 지향하는 이용자 범위에 대한 가치 판단이 아니라 기술 부채다. 선택지의 이름만 `파트너 A/B`, `기타` 또는 원하는 성별로 늘리면 기존 비공개 대화가 잘못 노출되거나 커플 연결이 실패할 수 있으므로 그렇게 하지 않는다.

## 코드와 DB에서 확인한 경계

- `apps/web/src/types/database.types.ts`의 `UserRole`은 `bride | groom` 두 값뿐이다.
- `profiles.role`의 DB 제약은 `bride`, `groom`만 허용한다.
- `couples` 멤버십은 `couples.bride_id`, `couples.groom_id` 두 슬롯으로 저장된다.
- `join_couple`과 최신 서버 가입 RPC는 역할별 빈 슬롯 하나에만 사용자를 연결한다.
- 커플 소유권 RLS는 `bride_id = auth.uid()` 또는 `groom_id = auth.uid()`를 기준으로 한다.
- 비공개 채팅·요약·의사결정·아모라 메모는 `bride_private`, `groom_private` 가시성과 프로필 역할을 함께 검사한다.
- 웹과 모바일 채팅의 발신자 표시, 개인 모드 선택과 파트너 구분도 두 역할에 결합돼 있다.

따라서 현재 구조에서 역할 선택지만 추가하는 것은 UI 확장이 아니라 인증·권한 모델 불일치다.

## 현재 허용하는 공개 표현

- “현재 베타는 신부 1명·신랑 1명 역할 구조만 지원한다.”
- “이는 관계에 대한 판단이 아니라 현재 데이터 보호 구조의 기술적 한계다.”
- “두 역할 중 하나를 정확히 선택할 수 없다면 아직 가입하지 말아 달라.”

“모든 커플”, “어떤 관계든 함께”, “성별과 관계없이 커플 연결”처럼 실제 권한 모델보다 넓은 표현은 사용하지 않는다.

## 관계 구성 확대 전 필수 조건

다음 항목이 모두 설계·마이그레이션·검증되기 전에는 광범위 공개 출시를 **NO-GO**로 둔다.

1. 내부 식별을 성별 역할이 아닌 변경 불가능한 `member_a/member_b` 또는 별도 멤버십 행으로 이전한다.
2. 화면에 표시할 역할·호칭·대명사를 권한 식별자와 분리하고 사용자가 선택·수정할 수 있게 한다.
3. 기존 `couples.bride_id`·`couples.groom_id`와 프로필 역할을 손실 없이 새 멤버십 구조로 옮기는 업그레이드 migration과 롤백 계획을 만든다.
4. `bride_private`·`groom_private`를 회원 ID 기반 비공개 가시성으로 이전하고, 과거 메시지·요약·의사결정·아모라 프로필의 소유자를 보존한다.
5. 가입, 초대, 재연결, 탈퇴, 마지막 멤버 삭제, 계정 복구와 초대 경쟁 상태를 새 구조로 다시 검증한다.
6. 모든 커플 관련 RLS·RPC·Realtime·Storage 정책을 신선한 DB와 기존 데이터 업그레이드 DB에서 재생한다.
7. 웹·모바일의 채팅 발신자, 개인 모드, 예산 분담, 축의금 구분, 설정과 CSV 내보내기의 성별 결합을 제거한다.
8. 기존 두 역할 커플과 새 관계 구성 각각에 대해 상대의 비공개 데이터가 노출되지 않는 음성 테스트를 통과한다.
9. 이용약관·개인정보 처리방침·가입 안내·마케팅 문구를 새 지원 범위와 동시에 갱신한다.
10. 실제 기기 2대와 서로 다른 계정으로 초대부터 삭제까지 E2E 증거를 남긴다.

## 이번 변경에서 하지 않은 것

- 기존 사용자 역할, 커플 연결, 인증 세션을 변경하지 않았다.
- DB schema, RLS, RPC와 저장된 메시지를 수정하지 않았다.
- 지원하지 않는 관계 구성을 임의로 기존 두 역할 중 하나에 매핑하지 않았다.
- 관계 구성 확대가 완료된 것처럼 마케팅하지 않았다.

현재 안전한 조치는 제한을 가입 전에 정확히 알리고, 위 조건을 충족하는 별도 개인정보 마이그레이션이 끝날 때까지 범위를 넓히지 않는 것이다.
