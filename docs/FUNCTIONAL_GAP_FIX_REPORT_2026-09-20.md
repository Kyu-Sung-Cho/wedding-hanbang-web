## 검증 방식

정상 기대를 가진 사용자 행동 테스트가 수정 전 실패하는 것을 확인한 뒤 최소 수정했다. 웹 및 일부 모바일 검증은 실제 store/hook/React 화면을 실행하고 인증·전송·네이티브 host 등의 외부 경계를 대역으로 교체했다. 모바일 초기화·기억 삭제는 실제 화면 모듈을 실행하지만 React hook도 수동 제어하는 harness이므로 실제 React 수명주기·실기기 증거와 구분한다. 과거 감사의 “나쁜 동작이 나온다” 테스트는 역사 증거로 보존하고 정상 회귀 성공으로 세지 않는다.

새 회귀 테스트는 보호 코드를 고의로 비활성화하는 mutation을 잡는지도 별도로 검증한다. 이 과정의 소스 복원 해시와 최종 검증 당시 소스 해시를 보관한다. 단순 소스 문자열 검사만으로 행동을 통과 처리하지 않는다.

## 남은 경계와 출시 전 확인

1. **운영 미반영:** hanbang.ai, Vercel, GitHub, 원격 Supabase를 변경하지 않았다. 운영에서 이번 문제가 해결됐다는 의미가 아니다.

3. **전체 새로고침 복구:** 수동 준비 변경과 공유 할 일의 미확인 요청은 메모리 안에서 유지된다. 일정 폼 닫기/재열기 및 같은 소유자의 공유 할 일 화면 이동은 보호하지만 브라우저 새로고침·다른 탭·프로세스 종료를 넘어서는 영속 복구는 아직 없다. 공유 할 일은 인증/커플 전환 시 개인정보 보호를 우선해 임시 내용을 삭제한다. 민감 입력을 localStorage에 저장하지 않았다.
4. **서버 지연 순서:** HTTP abort로 JavaScript 요청이 끝나도 서버 트랜잭션이 취소됐다고 증명할 수는 없다. TodayOne·답글 알림·프로필·초대 코드의 완전한 원격 순서 보장은 서버 operation/revision 영수증 계약과 hosted 검증이 더 필요하다. GET은 그 시점의 조회 결과다.
