## 아모라 구현 판정

### 현재 런타임 계약

1. 사용자 요청은 인증·membership·가시성·입력 상한을 통과해야 한다.
2. 일반 턴은 `gpt-5.6-luna`를 사용한다.
3. 계약 문서 확인, 분쟁·안전 신호, 최근 반복 교정처럼 명시된 조건만 `gpt-5.6-terra`로 승격한다.
4. 실제 provider 생성 전에 커플 무료 턴과 전역 provider 호출을 원자 예약한다.
5. OpenAI Responses API 호출은 `store:false`, `reasoning:none`, 표준 tier, 자동 재시도 0회다.
6. 도구 계획 후속은 최대 한 라운드이며 한 사용자 턴의 생성은 최대 두 번이다.
7. 비공개·첨부 턴은 읽기 전용이다. 일정·예산·준비 상태·예약의 모델 기반 쓰기는 비활성이다.
8. proactive 채팅과 care cron, 별도 AI 요약/분류/프로필/중재/댓글은 하드 비활성이다.
9. 모든 실제 provider 생성은 감사 래퍼와 provider lease를 거친다.

### 소비자에게 좋은 점

- 대부분의 일상 질문을 낮은 비용 모델에 유지해 응답 비용을 줄인다.
- 계약·분쟁이라는 단어 하나가 아니라 실제 검토 의도와 안전 신호로 승격 범위를 제한한다.
- AI가 직접 데이터를 바꾸지 않아 잘못된 일정·예산·예약이 조용히 확정될 위험을 줄인다.
- 본식 당일/식후 단계는 한국시간 날짜 단위로 계산해 UTC 자정 오판을 막는다.

### 아직 증명되지 않은 것

- 사용자 OpenAI 프로젝트가 Luna/Terra에 실제 접근 가능한지
- 두 모델의 실제 스트리밍 이벤트와 도구 출력이 현 파서와 일치하는지
- PDF/이미지·거절·중단·네트워크 끊김·429/5xx에서 비용 원장과 lease가 기대대로 정리되는지
- 한국어 웨딩 질문에서 Luna 품질이 소비자 기대를 만족하는지, Terra 승격률이 비용 목표 안에 드는지

따라서 키를 넣은 뒤 고정 평가셋과 작은 canary 한도로 별도 승인해야 한다.

## 이번 감사에서 수정한 핵심 문제

### P0/P1

- 구형 모바일이 새 migration 뒤 파트너 조회·채팅·투표·북마크·이미지 업로드를 잃을 수 있던 contract migration을 expand-only로 되돌렸다.
- one-slot 커플을 자동 격리/재발급하던 파괴적 repair를 제거하고 명시 감사 절차로 이동했다.
- 금액 장부가 DB 오류를 데모/성공/빈 데이터로 위장하던 경로를 fail-visible로 바꿨다.
- 보호 페이지 prerender가 환경변수 없이 Supabase client를 생성해 빌드를 깨던 문제를 지연 초기화로 수정했다.
- 웹/모바일 인증 프로필 장애가 로그아웃·온보딩으로 오인되는 문제와 stale 응답 레이스를 수정했다.
- 예약을 확정으로 오인시키는 문구, 연락처 전달 누락, 같은 날 만료, 상태 자동 완료 오판을 수정했다.
- 설문의 연락처 질문을 제거하고 베타 신청 consent와 180일 보관 기준, 익명 설문 1년 보관 기준, 만료 후 최대 약 24시간 이내 정기 삭제를 서버 계약으로 만들었다.
- proactive 아웃바운드를 UI/API/cron/DB 기본값과 기존 opt-in 데이터에서 모두 껐다.

### P2 품질

- 한국시간 본식일, 날짜-only 파싱, DB 월요일 기준 요일, 불가능한 날짜 rollover를 공용 유틸과 테스트로 고정했다.
- 커뮤니티 실명 노출을 가명 정체성으로 분리하고 견적 공유를 명시적 공개로 바꿨다.
- 모바일 대시보드·프로필의 죽은 컨트롤, 예산·일정·업체의 거짓 빈 상태를 수정했다.
- 공용 dialog에 이름, `aria-modal`, Escape, 초기 focus, 닫은 뒤 focus 복귀 계약을 추가했다.
- 공개 랜딩의 중복·미사용 구현을 `/demo` 하나로 정리하고 14개 죽은 컴포넌트를 제거했다.
- 전역 오류 화면에서 내부 메시지·stack을 제거하고 재시도·지원 경로와 digest만 제공한다.

## 출시 차단 게이트

### 반드시 해결

1. OpenAI 키와 프로젝트 예산/알림을 설정하고 Luna/Terra canary를 통과한다.
2. Supabase CLI를 올바른 프로젝트에 연결해 migration history를 대조한다.
3. fresh reset과 운영 크기 복원본 upgrade에서 migration 시간·락·RLS/RPC를 검증한다.
4. 마지막 배포 모바일의 실제 JWT로 파트너 조회, 채팅 INSERT, 투표 RPC, 북마크, `{userId}/...` 이미지 업로드를 검증한다.
5. 2인 커플의 가입, 연결, 동시 예산/일정 수정, private/shared 채팅, 재연결, 탈퇴를 장애 주입과 함께 검증한다.
6. 업체 상담 요청의 수락·거절·변경·취소와 연락처 보유/삭제 계약을 제품 또는 운영 절차로 닫는다.
7. iOS/Android 실기기, 작은 화면, 큰 글씨, VoiceOver/TalkBack, 웹 키보드 전수 QA를 수행한다.
8. OpenAI·Supabase·Vercel·Resend 등 처리자 DPA, 리전, 보존, 국외 처리 고지와 국내 AI·전자상거래 법무를 승인한다.
9. 백업, 롤백, 오류 모니터링, 최소 앱 버전과 구버전 트래픽 0 기준을 승인한다.
10. 사용자 연구 선정 기준·검토 책임자·선정/미선정 통지 기한·문의 및 삭제 SLA를 승인한다. 이 결정 전에는 확인 완료를 선정으로 바꾸거나 결과 메일을 자동 발송하지 않는다.

### 출시 후로 미룰 수 있으나 추적

- `progress.__events`와 `__amora_actions`를 전용 테이블로 분리해 배열 동시성 완전 해소
- 이미지 초안의 영속 URI/권한 모델을 만든 뒤 모바일 글쓰기 이미지 복원 지원
- 공급자 데이터 정정·최신성 SLA와 업체 확인 왕복
- 사용성 지표를 위한 제3자 telemetry 재승인은 DPA/리전/보존 고지 후 별도 변경으로 수행

## Git 운용 계약

- 원격 최신 상태를 `git fetch --prune`으로 다시 확인하고, 다른 컴퓨터의 커밋이 있으면 clean worktree에서 일반 merge한다.
- 강제 push, hard reset, 사용자 변경 폐기는 금지한다.
- `.github/workflows/ci.yml` 변경이 포함된 push는 GitHub 토큰에 `workflow` scope가 필요하다.
- migration은 이 코드 push와 별개다. 연결·백업·승인 없이 운영 DB에 적용하지 않는다.
