# 커뮤니티 킬러 컨셉: "못 무르는 돈" + 웨딩 등기부 (2026-06-10)

> 프로세스: 코드 정밀조사 4건 → 서로 다른 렌즈의 컨셉 3개 생성(데이터 네트워크 / 소셜 코호트 / AI 네이티브) → 3인 심사단(소비자심리·기술실사·플랫폼전략) 채점.
> **결과: 3인 전원이 같은 순위(C>A>B), 같은 접목안을 독립적으로 도출.**

---

## 0. 한 줄 결론

**커뮤니티 자체는 키가 될 수 없다. 키는 "계약서 사진 한 장 → 못 무르는 돈 30초"라는 단일 동작이고, 그 스캔이 동의 하에 자동으로 '실거래 장부'에 등기되며, 동기방은 그 장부가 사는 곳으로 재정의된다.**

한 동작 = ① 진단(즉시 가치) + ② 등기(데이터 축적) + ③ 동기 비교 해금(커뮤니티의 존재 이유).

---

## 1. 후크 (예비부부에게 하는 말 그대로)

> **"계약금 보내기 전에, 계약서 사진 한 장만 찍으세요. 지금 사인하면 '못 무르는 돈'이 얼마인지 30초 안에 보여드립니다."**

- 피해의 57.8%가 위약금·계약해제 — 불안 최고점은 "이체 버튼 앞".
- 기준선이 유저 데이터가 아니라 **공정위 표준약관(2025-04) + 소비자분쟁해결기준** → **유저 0명·데이터 0건에서 가치 100%** (콜드스타트가 설계로 소멸).
- "못 무르는 돈 얼마 나왔어?"가 단톡 관용구가 되면 카테고리를 소유한다. 공포는 자랑보다 전파력이 세다 (소비자심리 심사위원: A의 "상위 18%" 카드는 잘 샀을 때만 공유하지만, C의 "못 무르는 돈 350만원"은 무서울수록 공유한다).

## 2. 첫 3분 UX

- **0:00** `/` 진입 — 문장 하나 + 업로드 버튼 하나. 온보딩 모달·튜토리얼 제거. 계약서 없으면 "샘플로 30초 구경".
- **0:10** 사진/PDF 업로드 (비로그인, 기존 Claude Vision 파이프라인).
- **0:15~0:45** 분석 스트리밍 — "제8조 발견: '계약금은 어떠한 경우에도 환불 불가' — 표준약관 제5조와 충돌" (로딩 자체가 신뢰 장치).
- **0:45** 결과 1화면:
  - 최상단: **"지금 사인하면 못 무르는 돈 약 320~380만원"** (레인지로 — 단정 금지)
  - **위약금 곡선**: 오늘/D-150/D-90/D-30 취소 시 각각 얼마
  - **독소조항 카드**: 원문 인용 + 표준약관 해당 조문 + "표준 대비 약 X만원 불리"
  - 사인 전 질문 3개 + 협상 멘트 (quoteCheck 카피 시스템 재사용)
- **2:30** CTA 둘: "저장 + 위약금 변동 알림" (여기서 첫 로그인) / "카드 공유" (등급+못 무르는 돈이 박힌 동적 OG).
- **하단 블러 레이어**: "같은 분기·지역 동기 대비 당신 조건 상위 X%" — **내 스캔 익명 등기 동의 시 해금** (give-to-get).

## 3. 플라이휠 (A 컨셉 접목 — 3인 심사단 공통 권고)

- 스캔 한 장에서 금액·카테고리·지역·포함항목이 이미 추출됨 → 동의 한 번으로 **실거래 장부(price_points)에 자동 등기**.
- 등기하면 분포·항목비교 해금 (블라인드 연봉 모델). 웨딩은 8~10건 계약을 순차로 하므로 등록→해제 사이클이 자연히 반복.
- 위약금 곡선은 날짜마다 변함 → "D-91: 내일부터 드레스 위약금 80→160만원" 알림 = 계약서가 스스로 재방문 이벤트를 만든다.
- **동기방 재정의**: 기본 탭을 '대화'→'우리 분기 계약 데이터판'으로. 커뮤니티는 모임이 아니라 **장부가 사는 곳**.

## 4. 방어력

- 웨딩북(업체 광고 수익): "지금 무르면 200만원 아낀다"는 **출구 안내**를 자기 고객(업체)을 적으로 돌리지 않고는 못 띄움. 그들의 AI는 예약을 늘리는 방향으로만 설계됨.
- 네이버카페: 업로드→분석 UX 자체가 플랫폼에서 불가. 70만 회원의 자산은 비정형 텍스트라 소급 구조화 불가.
- 약점(플랫폼 심사위원): 출시일 해자는 '포지션'뿐 — 6개월 안에 "못 무르는 돈" 언어 선점 + 조항 코퍼스/장부 축적으로 굳혀야 함.

## 5. 법적 안전선 (출시 전 필수)

1. **변호사법**: "무효" 단정 금지 → "표준약관 제X조와 다릅니다 + 소비자원 1372 안내" 톤, 상시 면책 고지.
2. **숫자 단일 실패점** (기술 심사위원): 헤드라인 숫자가 틀리면 신뢰 영구 붕괴 → 레인지 + 원문 조항 인용 + "확인 필요" 플래그로 출시. **실계약서 30건 수동 채점 검증세트 없이 출시 금지.**
3. **개인정보**: 계약서엔 실명·계좌 있음 → 구조화 필드만 저장, 원본 이미지 비저장 또는 24h 자동삭제, 업로드 화면 명시 동의.
4. **k-익명성**: 공개 집계는 서버 강제 n≥5만. 업체 실명 레이어는 초기 금지(익명 집계선에서 멈춤).
5. **명예훼손**: 평가어 시스템 카피에서 배제 — "판단하지 않고 사실만" (quoteCheck 기존 원칙).

## 6. 코드 조사에서 나온 긴급 수리 (컨셉과 무관하게 즉시)

1. **동기방 API 익명성 구멍**: `api/community/cohort/[id]/contracts/route.ts:47-51`이 `select("*")`로 vendor_name·user_id·금액 원본 행 전체를 방 멤버 전원에게 반환 — "업체명은 공개 안 됨" 약속이 클라이언트 렌더링에서만 유지됨. 5건 게이트도 프론트 전용. → **서버측 집계-only 응답으로 전환.**
2. **랜딩 허위 수치**: `/landing`의 "후기 120만+ / 시세 25만+ / 제휴 1,200+곳" — 부당표시 소지 + 실제 서비스와 괴리로 신뢰 타격. → 실수치 또는 삭제.
3. **첫 방문 마찰**: 6슬라이드 가이드 모달 + 4스텝 튜토리얼 연쇄(콘텐츠 보기 전 최대 10단계) → 제거/지연.
4. **시세 페이지 로그인 벽**: 비로그인에게 가장 매력적인 미끼(`/market-prices`)가 보호 경로 — 해제.
5. **전국 평균 이원화**: 동기방 `NATIONAL_AVG`(하드코딩) ≠ `hiddenCosts.ts`(참가격 기반) — 단일 소스로 통일.
6. **채팅 견적 진단이 `amora_quote_checks`에 저장 안 됨** → INSERT 추가로 두 경로 통합 + 공유 링크 생성.
