# v4.2 웨딩코드 화면 완성도 개선

## 요청과 선택

파운더 요청: “좀더 고급스럽게 못하나 잘 만들어봐 상품성 있게”.
범위는 시작, 질문, 개인 결과, 두 사람 결과와 공유 화면의 표현이다. v4.2 문항 원문·채점·링크·저장 계약은 그대로 사용한다.

검토한 방향:

1. 장식과 그림자를 기존 좁은 카드에 추가한다. 정보 위계와 폭 문제가 남으므로 제외했다.
2. 별도의 어두운 럭셔리 테마나 다른 폰트를 도입한다. 승인된 앱 정체성과 어긋나므로 제외했다.
3. 승인된 브랜드 안에서 편집형 제품 화면으로 구성한다. 제목·실제 코드·응답 근거를 중심으로 폭과 읽는 순서를 개선하며 이 방향을 선택했다.

## 화면별 구현 기준

- 독립 화면에는 실제 Amora 나침반과 웨딩한방 브랜드 머리글을 둔다. 앱 안에는 중복 머리글을 넣지 않는다.
- 입구와 결과는 넓은 화면에서 충분한 폭을 쓰고 질문은 읽기 좋은 폭에서 멈춘다. 모바일은 한 열로 읽는다.
- 입구는 큰 제목과 실제 8개 글자의 구조를 보여 준다. 예시 글자를 개인 결과로 오해하게 만들지 않는다.
- 문항은 번호, 상황, 질문, 선택, 다음 행동의 순서를 명료하게 한다. 선택 상태는 색과 체크 표시를 함께 쓴다.
- 결과는 실제 코드와 각 글자의 뜻을 주인공으로 둔다. 두 사람은 같은 시각적 비중으로 표시한다.
- 비율은 실제 응답 방향의 분포이고 성격의 확률이 아니다. 제외 답, 잠정 글자, 반반 상태와 미검증 고지를 유지한다.
- 먼저 나눌 대화를 결과 요약 다음에 읽을 수 있게 한다. 추가 근거와 계산은 필요할 때 펼쳐서 읽는다.
- 공유 선택과 공개되는 답 안내는 보내기 행동과 함께 묶는다. 기본 동의 상태·공유 범위·링크 동작을 바꾸지 않는다.

## 디자인 근거

정본은 `DESIGN.md`, 공유 디자인 토큰과 `globals.css`다. Pretendard, 아이보리 지면, 샴페인 요약, 흰 상세면, 더스티 모브 행동색을 사용한다.

Lazyweb의 현재 best-practices 흐름으로 [Impeccable](https://raw.githubusercontent.com/pbakaus/impeccable/main/.agents/skills/impeccable/SKILL.md), [bolder](https://raw.githubusercontent.com/pbakaus/impeccable/main/.agents/skills/impeccable/reference/bolder.md), [craft-floor](https://raw.githubusercontent.com/pbakaus/impeccable/main/.agents/skills/impeccable/reference/craft-floor.md)를 직접 읽었다. 기존 브랜드의 표현을 강화하고, 실제 제품 내용으로 시각적 정체성을 만들며, 데스크톱·모바일 실물과 상태를 함께 검수하는 지침을 적용한다. 설치나 새 유료 리포트 생성은 하지 않았다.

## 주장 감사와 검수

시각적 완성도 개선은 측정 타당성이나 실제 고객 성과를 증명하지 않는다. 사람 검증 0건이라는 현재 상태는 그대로다. 궁합·결혼 성공 예측·심리 진단·검증된 유형·희귀도·정확도 주장을 추가하지 않는다. 동물 별칭은 놀이 이름이라는 설명을 유지한다.

구현 후 테스트와 실제 화면 검수 영수증을 이 문서에 덧붙인다. 커밋·공개 배포는 이 요청 범위에 포함하지 않는다.

- v4 소스 가드 41개 통과. v4.2 생성 은행 `--check`는 원문과 일치한다.
- 임시 프리뷰 삭제와 경로 타입 재생성 뒤 최종 웹 typecheck, 전체 v4 결과·질문 컴포넌트 및 변경 클라이언트·중앙 문구의 scoped ESLint가 모두 종료 코드 0으로 통과했다. `git diff --check`도 통과했다.

- 합성 응답으로 개인 코드, 뜻·세기, 근거, 잠정 결과, 공유 동의와 비활성 버튼을 확인했다. 실제 두 사람 링크에서는 프로필을 먼저 보여 주는 순서와 `다음 장면`을 눌렀을 때 `현재 장면 2 / 3`으로 바뀌는 동작을 확인했다.
- 독립 이미지 검수에서 모바일 첫 프로필의 잘림·겹침이나 코드·뜻·별칭 의미 혼동을 발견하지 못했다. 하단 공유와 비율 영역은 root가 실제 브라우저에서 별도로 확인했다.

## 후속: 글자를 바로 이해할 수 있게 (2026-10-06)

사용자가 영어 레터의 뜻을 쉽게 보여 달라고 요청했다. 기존 구성은 개인 코드에 짧은 한글 이름만 있고 영문 출처는 아래 표에, 정의 문장은 개인 주제별 설명에 흩어져 있었다. 커플 프로필에는 전체 정의가 없었다.

- 개인 코드 바로 아래, 두 사람의 각 프로필에 `S · Scene / 장면 먼저 / 전체 정의 / 이번 답의 기울기`를 표시한다. 중앙 `LetterInfo` 정의를 공유하고 영문에 언어 속성을 붙인다.
- 영어 단어 첫 글자라는 설명과 네 자리의 순서를 한 번 안내한다. 정의와 이번 답의 기울기는 별개로 읽게 한다.
- 여덟 글자표에도 같은 전체 정의를 넣는다. 좁은 화면의 풀이와 표는 세로로 읽는다. 개인 풀이 목록은 코드 그림의 접근성 이름 밖에 제공한다.
- 적대적 검수에서 개인 풀이 자체에 반반·임시 표시가 없는 위험을 발견해 항목별 표시를 보완했다. 초기 중앙 문구 검사에서 첫 글자 설명이 두 번 나오는 문제도 발견해 글자표 안내를 수정했다.
- 최종 관련 7개 파일 299개 테스트, 소스 가드 41개, v4.2 생성 일치, 타입 검사, 변경 파일 ESLint, diff 공백 검사를 통과했다. 커플 관점을 바꿔도 같은 사람의 글자·영문·정의가 유지되는 회귀를 포함한다.
- 실제 데스크톱 읽기 폭 1265px, 모바일 요청 폭 390px와 320px에서 확인했다. 스크롤바를 제외한 모바일 읽기 폭은 각각 375px·305px이며 문서 폭과 일치했다. 잠정 개인 결과의 반반·임시, 별칭 미노출, 여덟 정의가 있는 모바일 글자표도 확인했다.
- 검수용 dev 프리뷰 파일은 삭제했으며 경로 타입을 재생성했다. 합성 응답을 저장하지 않았다. 새 심리·궁합·정확도 주장은 없다.

## 후속: 선택 비율과 판정 근거 (2026-10-06)

사용자의 퍼센트·주제별 전문성 요청에 따라 각 글자 정의 바로 아래에 실제 방향별 응답 비율과 분모를 붙였다. 숫자는 최대 소수 둘째 자리로 계산하며 compact 화면은 방향과 숫자를 가로 행으로 대응한다. 개인 결과의 실제 판정·동점·응답 부족 이유를 연결하고, 두 사람은 주제별 비교로 바로 이동할 수 있다. 상세 근거를 전체 글자표보다 먼저 읽는다. 최종 관련 테스트 315개, 소스 가드 41개, 생성 일치·타입·ESLint·공백 검사와 데스크톱·모바일 화면을 확인했다. 자세한 산술·주장 감사 및 검증 기록은 [선택 비율 계약](./2026-10-06_v42_percentage_report_contract.md)에 있다.
