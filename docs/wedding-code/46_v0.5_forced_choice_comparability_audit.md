## 0. 사용자 질문에 대한 답

한 문항 안의 선택지가 서로 다른 성향 구인에 매핑되는 것은 의도다. 하지만 선택지가 서로 다른 "카테고리 목록"처럼 튀면 안 된다.

올바른 구조:

- 같은 결혼 준비 상황
- 같은 응답 층위
- 모두 현실적으로 가능한 첫 반응
- 사용자는 "내가 맞다/틀리다"가 아니라 "내가 먼저 할 것"을 고름
- 점수는 그 선택을 성향 구인으로 번역함

잘못된 구조:

- 한 선택지는 예산, 다른 선택지는 부모님, 다른 선택지는 감정처럼 서로 비교 불가능한 주제 목록
- 한 선택지만 사회적으로 정답처럼 보임
- 여러 행동을 한 선택지에 묶어 사실상 복수 응답이 됨
- "나는 어떤 사람인가"를 직접 고르게 함

v0.5는 후자가 아니라 전자를 목표로 설계했다.

## 1. 감사 기준

각 문항은 아래 5개 기준으로 보았다.

| 기준 | 설명 |
|---|---|
| S1 상황 단일성 | 한 문항이 하나의 장면만 묻는가 |
| S2 행동 층위 동일성 | 선택지가 모두 "먼저 할 반응/필요한 것"으로 비교 가능한가 |
| S3 선택 가능성 | 네 선택지가 모두 현실적으로 고를 만한가 |
| S4 정답감 방지 | 특정 선택지만 너무 합리적/도덕적으로 보이지 않는가 |
| S5 복수문항 방지 | 한 선택지가 두세 개 행동을 과하게 묶지 않는가 |

## 2. 전체 판단

결론: v0.5는 forced-choice 형식으로 유지 가능하다.

중요한 전제:

- 한 문항의 선택지는 일부러 서로 다른 구인에 매핑된다.
- 사용자가 "모두 해당된다"고 느낄 수 있으므로, UI 안내는 "가장 먼저 할 반응"으로 고정한다.
- 결과 해석은 절대 "당신은 이런 사람"이 아니라 "현재 답변으로는 이런 기준이 편한 편"으로 유지한다.

## 4. 오늘 반영한 수정

### UI 안내

`WC_NO_RIGHT_ANSWER`를 다음 의미로 확장했다.

- 정답 없음
- 여러 선택지가 다 맞을 수 있음
- 그중 가장 먼저 할 반응을 고름

이 안내는 forced-choice의 핵심 오해를 줄인다. "하나만 맞다"가 아니라 "우선순위를 고른다"는 프레임이다.

### D1 문항

기존:

- 먼저 왜 걱정되는지 잠깐 들어주면 좋겠다
- 한마디로 알아주고, 그다음 같이 정리하면 좋겠다
- 다음에 뭘 하면 될지 바로 잡아주면 마음이 놓인다
- 다음엔 어떤 반응이 편한지 먼저 말해두고 싶다

수정:

- 왜 걱정되는지 잠깐 들어주는 것
- 한마디로 알아주고, 그다음 같이 정리하는 것
- 다음에 뭘 하면 될지 바로 잡아주는 것
- 다음엔 어떤 반응이 편한지 말해둘 시간

효과:

- 선택지가 모두 "그 순간 나에게 필요한 것"으로 같은 층위가 됐다.
- 감정 지원/실행 지원/메타 커뮤니케이션 차이는 유지된다.
- 특정 선택지가 더 성숙하거나 정답처럼 보이는 정도를 줄였다.

## 5. 남은 검증

코드상으로는 통과 가능하지만, 제품 신뢰를 위해 사람 검증이 필요하다.

인지 인터뷰에서 꼭 물어볼 질문:

1. "이 문항에서 선택지 4개가 같은 종류의 선택처럼 느껴졌나요?"
2. "하나만 고르기 어렵다면, 그 이유가 '다 맞아서'인지 '질문이 섞여서'인지?"
3. "특정 선택지가 정답처럼 보였나요?"
4. "고른 선택이 내 성향이라기보다 그날 상황 때문이라고 느껴졌나요?"
5. "상대에게 보내도 기분 나쁘지 않은 표현인가요?"

통과 기준:

- n=5 중 4명 이상이 "가장 먼저 할 것" 프레임을 이해
- 정답처럼 보이는 선택지 지적이 문항당 2명 미만
- "질문이 두 개 섞였다" 지적이 문항당 1명 이하

## 6. 최종 판단

현재 v0.5는 "한 질문 안에 서로 비교 불가능한 카테고리를 섞은 테스트"가 아니다.

정확히는:

- 같은 상황 안에서
- 서로 다른 우선순위 행동을 제시하고
- 그 행동을 내부 구인으로 번역하는 forced-choice 구조다.

다만 forced-choice 특성상 사용자가 "다 해당된다"고 느낄 수 있으므로, 제품 카피는 계속 "가장 먼저"와 "현재 답변"을 유지해야 한다.
