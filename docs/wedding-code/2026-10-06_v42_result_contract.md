# v4.2 문항·결과 개선 계약

상태: 작성 검수·로컬 구현·관련 회귀 및 화면 확인 완료 / 공개 배포 전 / 사람 검증 전. 실행 범위는 [검증 기록](./2026-10-06_v42_implementation_verification.md)을 따른다.

## 요청과 범위

2026-10-06 사용자는 모든 질문과 선택지의 어색함을 꼼꼼히 고치고 결과지를 개선하도록 요청했다. 68문항을 모두 읽어 상황, 질문과 답의 연결, 한 보기의 의미 수, 실제 축과 방향, 선택 강도, 언어와 도덕적 우열을 확인한다. 문항 원문은 별도 `v4.2-depth`로 고정한다. 기존 v4.1과 v4.0 답·링크는 각 판의 원문으로 계속 열린다.

## 대안 검토와 선택

1. 모든 원문·계산을 처음부터 펼치기: 확인 가능하지만 핵심을 찾기 어렵다.
2. 동물 유형 중심의 일반 성격 해석: 흥미는 있어도 실제 답에서 확인되지 않은 해석을 만들기 쉽다.
3. 코드와 뜻 → 장면별 응답 → 원문 근거·계산 → 다음 대화: 확인 가능한 요약과 세부 내용을 함께 읽을 수 있다. 이 방식을 선택한다.

## 결과 구현 기준

- 첫 요약은 기존 champagne 지면·ink 글자·mauve 동작 토큰으로 묶는다. 글자 뜻·세기를 바로 읽을 수 있고 놀이 별칭은 보조 역할로 쓴다.
- 응답 분포는 실제 답의 방향 개수 / 유효 응답 수로 표시한다. 눈금형 막대는 개수와 정확히 대응하며 숫자와 라벨을 함께 제공한다. 글자 판정은 네 묶음을 같은 비중으로 더한 선택 강도로 하므로 빈도와 따로 설명한다.
- 16개 장면 묶음은 기본 화면에서 확인할 수 있게 하고, 숫자 계산은 접어서 확인한다. 한쪽으로 답한 장면뿐 아니라 반대 답·중립·부족한 답도 보인다.
- 후속 선택 비율 보완: 코드 풀이 아래에서 방향별 실제 개수와 분모, 최대 소수 둘째 자리 비율을 함께 보여 준다. 값 0은 ‘한쪽으로 기울지 않은 답’으로 읽으며 개인 결과에는 실제 판정 이유를 연결한다. 주제별 근거 뒤에 전체 여덟 글자표를 놓는다. 계산·카피·검증의 세부 기준은 [선택 비율 계약](./2026-10-06_v42_percentage_report_contract.md)을 따른다.
- 두 사람 결과의 네 글자에는 세기와 미정·임시 상태를 함께 표시한다. 주제별 실마리와 원문 답은 자신/상대의 관점 전환을 따른다.
- 대화 시작 카드는 다른 답이 없으면 실제로 비슷하게 고른 답에서 출발한다. 어떤 답도 뽑히지 않으면 빈 상태를 설명한다. 같은 질문을 반복 표시하는 보조 목록은 접어서 확인한다.
- 추천 대화는 질문이며 동의·확정 결정·할 일·서버 저장을 대신하지 않는다.

## 적대적 검수와 주장 감사

| 실패 가능성 | 대응 |
| --- | --- |
| 75%인데 반반으로 보이는 이유를 알 수 없음 | 방향 빈도와 선택 강도 계산을 구분하고 묶음별 답을 함께 표시 |
| 코드가 없거나 임시인데 별칭이 확정 유형처럼 보임 | 미정·임시 별칭 생략, 세기 상태 표시 유지 |
| 회복 방식이나 상대에게 주는 도움을 원하는 도움으로 단정 | 문항의 실제 관점·범위를 보존하고 상담·심리 진단 해석 금지 |
| 질문 수가 늘어서 타당도가 증명된 것처럼 보임 | 작성 검수와 사람의 이해·안정성 검증을 별도 기록 |
| 과거 링크가 바뀐 보기로 열림 | 새 version, codec 표식, 저장 키로 격리 |
| 막대 색만으로 의미를 전달 | 고정 방향 순서, 라벨·개수·비율, 텍스트 대안 |
| 긴 한국어와 두 사람 카드가 좁은 화면에서 잘림 | 모바일 실제 화면·접기·관점 전환 확인 |

확인 범위: 코드·문항 문서로 재현 가능한 응답 요약. 사람의 내면 정확도, 심리 진단, 궁합, 결혼 결과, 희귀도, 실측 유용성은 주장하지 않는다. 현재 사람 검증은 완료되지 않았다.

## 코드 반영 문서 gate

결과 카피와 점수 산식은 위 주장 감사 범위 내에서 반영한다. 문항 반영은 64개 채점 문항과 4개 자기 선택의 감사표 및 최종 원본 구조·방향·강도 검사 완료 후 진행한다. 정적 문구 검사 통과는 인지면접이나 타당도 검증 통과를 뜻하지 않는다.

## 최종 주장 감사 보완

v4.2의 H/A 예시도 ‘마음이 풀린다’는 확인하지 않은 결과 대신 실제 질문에서 묻는 첫 행동으로 맞췄다. 듣기·서운함 확인·동의받은 연락 맡기·지친 날 남은 메시지 순서가 그 범위다. 이는 가능한 준비 행동의 예시이며 응답자의 회복 결과나 능력을 단정하지 않는다. 구판 예시는 해당 판에서 유지한다.

## 글자 풀이 보완 (2026-10-06)

- 검토한 배치: 아래 글자표만 보완 / 코드 안에 긴 설명 삽입 / 코드 바로 아래에 네 글자 풀이, 글자표에 여덟 글자 풀이.
- 세 번째 배치를 선택한다. 큰 코드는 빠르게 훑고, 바로 다음 줄에서 영어의 첫 글자·한글 이름·결정 순서의 뜻을 읽게 한다. 개인 결과와 두 사람의 각 프로필에 같은 중앙 정의를 쓴다.
- 순서는 돈 → 준비 과정 → 함께 정할 사람 → 지친 날의 도움. V/S, W/D, U/F, H/A의 영어 이름과 정의는 기존 상수에서 읽으며 문항·점수·판을 바꾸지 않는다.
- 적대적 검수: 성격이나 가족애의 우열로 해석하지 않고 해당 주제에서 무엇을 먼저 두는지를 설명한다. 반반·임시 표시는 유지하고, 미결정 주제에는 어느 한쪽의 영어 이름이나 뜻을 붙이지 않는다.
- 주장 감사: 영어 이름의 첫 글자와 표시 글자가 일치하는 것은 중앙 정의로 확인했다. 새 정확도·궁합·심리 진단 주장은 추가하지 않는다. 화면의 풀이 목록은 코드 그림 밖의 접근 가능한 일반 텍스트로 제공한다.

구현 확인: 개인·커플·글자표·판별 문맥·주제 풀이·중앙 문구 7개 테스트 파일 299개 통과. 새 개인 풀이의 반반·임시·미정 처리와 커플 관점 전환 뒤 같은 사람의 영어·뜻 유지도 확인했다. 소스 가드 41개, v4.2 원문 생성 일치 검사, 웹 typecheck, 변경 파일 ESLint, diff 공백 검사가 통과했다. 합성 응답으로 실제 개인·커플 화면과 모바일 글자표를 확인했으며, 임시 dev 프리뷰 두 파일을 제거하고 Next 경로 타입을 재생성했다. 문항 타당성이나 측정 정확도의 검증 기록은 아니다.
