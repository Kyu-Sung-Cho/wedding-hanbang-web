## 0. 결론

16개 문항은 v0.5 후보 세트로 묶어도 된다. 다만 원점수 합산으로 바로 유형을 만들면 안 된다.

이유:

1. 문항별 총점이 8~12점으로 다르다.
2. 구인별 노출량이 다르다.
3. `CP`, `ED`, `CR`은 상대적으로 많이 드러나고, `AM`, `EM`, `ES`는 적게 드러난다.
4. `DPR`, `GN`은 공개 유형 산출이 아니라 안전 가이드/제품 라우팅에만 써야 한다.

따라서 구현 전제는 다음이다.

- 16문항 원점수는 저장할 수 있다.
- 공개 결과는 정규화된 축 점수로만 만든다.
- 공개 동물/형용사/희귀도는 아직 확정하지 않는다.
- 코드 반영 시에도 "궁합", "적합도", "갈등 위험" 표현은 쓰지 않는다.

## 3. 전체 가중치 분포

| 구인 | 총 노출 가중치 |

해석:

- `CP`가 가장 높다. 커플 공유 도구라는 제품 목적에는 맞지만, 원점수 합산 시 "함께 준비" 성향이 과대표현될 수 있다.
- `ED`, `RO`, `CA`, `FI`, `CR`도 충분히 노출된다.
- `AM`, `EM`, `ES`는 낮다. 이 구인들을 원점수로만 비교하면 과소표현될 수 있다.
- `GN`은 3점뿐이며 제품 라우팅 전용이다.
- `DPR`은 빠른 계약/숙려 안전 가이드 전용이다.

## 5. 카테고리별 분포

| 카테고리 | 강한 축 | 보조 축 | 판단 |
|---|---|---|---|
| A | CR, ED, AM, EM | CP, CA, FI, GN, DPR | 돈·조건·취향 균형 |
| B | CP, RO | ED, EM, ES, EX, DPR | 함께 준비/역할 분담 중심 |
| C | CA, FI | CR, ED | 커플 기준/가족 조율 중심 |
| D | EX, ES, CP, RO | DPR, CR, ED, EM | 스트레스 상황 대화/회복 중심 |

이 분포는 의도와 대체로 맞다.

주의:

- B축은 `CP`와 `RO`가 매우 강해서 공개 결과에서 "둘 중 누가 더 잘 준비하는가"로 읽히면 안 된다.
- C축은 `CA`와 `FI`가 균형 있게 노출되지만, 결과 카피에서 "부모님 편" 또는 "반가족"으로 읽히면 안 된다.
- D축은 `ES`와 `EX`가 핵심이며, 공개 라벨은 "공감형/실행형"으로 고정하지 않는다.

## 7. 공개 축 계산

원점수 비교 금지. 아래처럼 정규화 점수 평균으로 계산한다.

| 공개 축 | 왼쪽 | 오른쪽 | 표시 |
|---|---|---|---|
| 결정 기준 | avg(norm(CR), norm(ED)) | avg(norm(EM), norm(AM)) | 조건 확인 / 의미 상상 / 균형 |
| 준비 방식 | norm(CP) | norm(RO) | 같이 맞춤 / 맡아 정리 / 혼합 |
| 조율 범위 | norm(CA) | norm(FI) | 우리 기준 / 가족 조율 / 균형 |
| 지원 순서 | norm(ES) | norm(EX) | 마음 먼저 / 할 일 먼저 / 순서 조합 |

confidence:

- 0~12pp: 균형
- 13~24pp: 조금 가까움
- 25pp 이상: 가까움

주의:

- 16문항만으로 심리검사식 신뢰도를 주장하지 않는다.
- "당신은 OO형"이 아니라 "현재 답변으로는 OO에 가까워요"라고 쓴다.

## 8. 공개 금지 축

`DPR`:

- 공개 유형명 금지
- "빠른계약형", "충동형" 금지
- 계약 전 확인 카드, 하루 숙려 리마인더, 업체 질문 카드에만 사용

`GN`:

- 공개 유형명 금지
- "도움이 필요한 사람" 금지
- 견적체크, 아모라 톤, 체크리스트 추천에만 사용

## 9. 결과 화면 가드레일

허용:

- 형용사+동물은 기억 장치로만 사용한다.
- 축 설명은 "준비 방식", "결정 순서", "대화 시작점"으로 표현한다.
- 커플 비교는 "준비 방식 겹침도" 또는 "대화가 쉬운 지점/먼저 맞춰볼 지점"으로 표현한다.

금지:

- 궁합
- 커플 적합도
- 결혼 성공 가능성
- 이혼/갈등 예측
- 전체 인구 대비 희귀도
- 상위 n% 유형
- 더 성숙한/합리적인 유형

희귀도:

- n<30: 퍼센트 금지
- n>=30: "초기 응답 n명 기준, 같은 주 결과 X명"처럼 원수+비율 병기
- n>=100: 분포 표현 가능하지만 "전체 인구 대비" 금지

## 11. 최종 판단

v0.5 16문항 세트는 문서 기준으로는 코드 반영 직전 단계까지 왔다.

단, "최종 제품 출시용으로 완벽하다"는 뜻은 아니다. 현재 확실히 말할 수 있는 것은 다음이다.

- 문항의 사실 전제와 제품 목적은 정리됐다.
- 위험한 해석과 금지 카피가 문항별로 정리됐다.
- 결과 산출은 원점수 합산이 아니라 정규화가 필요하다는 점이 확인됐다.
- 신뢰도 주장은 아직 하면 안 된다.

WeddingCode의 신뢰는 "논문이 있으니 맞다"가 아니라, 문항의 과장 방지, 결과 카피의 정직함, 실제 커플 테스트 데이터로 만들어야 한다.
