## 목표와 확인 범위

사용자는 문항 수가 많고 비슷한 질문이 반복된다고 느꼈다. 현재 v3.1은 40개가 아니라
**동의 문장 25개 + 직접 취향 6개 + 피하고 싶은 것·우선순위·추가 배분 각 1개 = 34개**다.
숫자를 바로잡는 것으로 부담 문제가 해결되지는 않는다. 모든 문항을 다시 읽고,
앞선 답과 다른 정보를 추가하는지, 그 정보가 결과에서 실제로 어떻게 쓰이는지를 대조했다.

이번 감사에서 직접 확인한 근거(E)는 `constants/weddingCodeV31.ts`, `lib/weddingCode/v31.ts`,
`WeddingCodeV31Client.tsx`, `WeddingCodeV31Inputs.tsx`, `WeddingCodeV31Results.tsx`와
현재 문항·결과 계약이다. 모든 동의 문장이 개별 결과 문구와 커플 후속 질문에 연결되어
있지만, 결과 문구가 있다는 사실만으로 별도 질문의 가치가 입증되지는 않는다.

팀 피드백은 `2026-09-22_complete_feedback_audit.md`의 PDF 페이지별 대조 기록을 참고했다.
이번 감사에서 원본 PDF와 이미지를 다시 열어 읽었다고 주장하지 않는다. 특히 “보기들이
동시에 해당한다”, “무엇을 판단하는지 모르겠다”, “당연한 답처럼 보인다”, “결과가 뻔하다”는
기록을 반복·모호성·추가 효용의 검수 기준으로 삼았다.

`PRINCIPLES.md`, 이 디렉터리의 `README.md`, `2026-09-23_v31_clarity_contract.md`를 따른다.
`31_fable_mode_adaptation_protocol_v0.1.md`의 16문항 고정 규칙은 RETIRED이므로 재사용하지 않는다.

## 조사 근거와 적용 한계

같은 작업의 원문 조사에서 확인한 1차 자료(S):

- [Pew Research Center, Writing Survey Questions](https://www.pewresearch.org/writing-survey-questions/):
  질문 문구와 응답 선택이 답에 영향을 주며, 한 질문에 여러 개념을 섞지 않는 설계가 필요하다.
- [Pew Research Center, How we keep our online surveys from running too long](https://www.pewresearch.org/decoded/2022/12/08/how-we-keep-our-online-surveys-from-running-too-long/):
  설문의 길이와 부담을 관리할 때 실제 질문의 형태와 응답에 필요한 시간을 살펴야 한다.

이 자료는 웨딩코드의 최적 문항 수를 정해주지 않는다. **23개는 현재 문항의 추가 정보와
제품 목적을 따져 선택한 편집·제품 판단(I)**이며, 측정 타당도나 소비자 완주율이 검증됐다는
뜻이 아니다. “짧으면 항상 더 정확하다”, “23개면 모든 웨딩 성향을 안다”는 주장도 하지 않는다.

## 초안과 대안 검토

검토한 대안은 다음과 같다.

1. 34개를 모두 유지하고 표현만 수정: 문장을 다시 읽고 답해야 하는 부담이 남는다.
2. 비슷해 보이는 항목을 하나의 강제 선택으로 합치기: 예산을 지키고 싶으면서 증액 논의도
   원하는 사람, 가족 의견을 듣되 최종 선택은 둘이 원하는 사람의 답을 잘못 단순화한다.
3. 기본 결과에 필요한 23개를 먼저 받고, 선택 9개는 결과 뒤에 답하기:
   반복 이득이 특히 작은 B2·D2는 새 흐름에서 다시 묻지 않는다. 문장·보기·응답 해석은
   사전에 보존하고, 기존 34개 경로·기존 답도 유지한다. 이 안을 최종 제안으로 삼는다.

기본 구성은 **동의 15개 + 직접 취향 6개 + 피하고 싶은 것 + 추가 배분**이다.

동의 15개:
`G1, G3, R4, B1, B3, D1, T1, T2, T3, F1, F2, F4, H1, H2, H4`.

선택 동의 8개:
`V1, G2, R3, B4, D3, T4, F3, H3`.
이미 고른 내용 중 최대 세 가지를 다시 추리는 `priorities`도 결과 후 선택 작업으로 둔다.

따라서 **기본 23 + 선택 9 + 기존 경로에만 남는 B2·D2 2개 = 기존 사전 34개**다.
B2·D2를 선택 영역으로 옮겨 다시 답하게 하는 것은 이번 중복 축소의 목적에 맞지 않아
초안에서 한 번 더 제외했다. 기존 답이 담긴 공유 링크와 저장 진행에서 두 문항을 지우거나
새 의미로 재해석하는 삭제는 하지 않는다.

기본 22개로 줄이며 F4까지 옮기는 대안도 검토했다. F4는 가족에게 **누가 먼저 말할지**를
묻고, F1의 **언제 의견을 들을지**, F2의 **누가 최종 결정할지**와 다르다. 커플이 실제로
정할 수 있는 대화 창구라 기본에 남긴다. T4는 담당을 정하는 시점을 더 묻지만 T2·T3의
가이드에서도 담당 범위와 공유 방식을 정하도록 제안하므로 F4보다 추가 이득이 작다고 판단했다.

V1까지 유지해 24개로 구성하는 대안도 가능하다. 다만 꽃 장식 한 문항은 전체 분위기를
대표하지 못한다. 입력 부담을 줄여 달라는 요청에 따라 기본에서는 옮기고, 장식 선호를
더 보고 싶은 사람이 선택해 답하도록 한다. 꽃에 답하지 않은 기본 결과가 예식 분위기를
완전히 파악했다고 설명해서는 안 된다.

| T2와 T3에 모두 높게 답함 | 맡겼으니 공유는 필요 없다고 추정 | 세부 결정 위임과 진행 공유를 별도 정보로 유지. |
| F1과 F2에 모두 높게 답함 | 가족 중심/둘 중심 중 하나로 강제 선택 | 가족 의견 청취와 최종 결정권을 각각 보여줌. |
| V1을 보지 않고 기본 결과까지 완료 | 꽃 장식에 관심이 없다고 출력 | 묻지 않은 상세 응답은 undefined로 남김. |
| G1에 높게 답하고 G2는 보지 않음 | 소규모·자주 만나는 사람만 초대한다고 출력 | G1 원문의 범위만 설명하고 규모는 직접 취향 답을 사용. |
| spending을 구체적으로 고르고 B2는 보지 않음 | B2를 높은 동의로 자동 채움 | 지출 항목의 직접 답만 근거로 설명. 별도 B2 점수는 만들지 않음. |
| 선택 상세에 답하지 않음 | 건너뜀 응답으로 대량 변환하거나 미완성 경고 | 묻지 않음과 사용자가 건너뜀을 구별. 기본 완료를 막지 않음. |
| 한 사람만 선택 상세에 답함 | 둘 다 미응답인 항목을 공통점으로 계산 | 두 사람의 실제 공통 응답에서만 내용 비교. |
| 이전 34개 진행 저장을 복원 | 기존 index를 새 23개 순서의 다른 질문으로 해석 | 원 질문 식별자에 맞는 복원·진행 이행 검증. 기존 답의 뜻 유지. |
| 이전 공유 링크를 열거나 다시 비교함 | 같은 코드의 답을 바뀐 문장에 붙임 | 문항·보기 원문, 코덱과 기존 해석 보존. |
| 기존 저장·공유에 B2·D2 답이 있음 | 새 흐름에서 제외했다는 이유로 기존 답을 지우거나 수정 경로를 깨뜨림 | 기존 34개 경로와 해당 답의 읽기·수정·결과 의미를 보존. 새 질문 순서와 원문 사전을 구분. |
| 앞 답 수정으로 우선순위 근거가 사라짐 | 선택 단계이므로 낡은 우선순위를 그대로 둠 | 기존 정규화·재확인 경계를 유지하되 선택 상세 전체를 강제하지 않음. |

선택 질문은 두 번째 필수 설문으로 만들지 않는다. 결과를 받은 뒤 관심 있는 주제의 답을
더할 수 있어야 한다. 문장·보기 원문과 코덱·해석을 고정하고, 이번 변경은 처음 결과까지
가는 경로와 결과에서 선택 항목을 여는 방식에 한정한다.

## 문항 수 외의 개선 후보

정적 코드 대조에서 결과 반복도 확인했다. `buildInsights`는 의상 조합 뒤에
`budget-reallocate`, `budget-revisit`을 넣고 결과는 앞 세 설명을 우선 보여준다.
관련 답을 모두 높게 고르면 첫 세 설명 중 두 개가 예산이다. 구체 spending까지 답하면
별도의 `budget-explicit-spending`도 생길 수 있다. 문항을 덜 물어도 기존 상세 응답에서는
비슷한 예산 설명이 반복될 수 있으므로, 첫 결과의 주제 분산이나 같은 근거의 설명을
묶는 방안은 별도 개선 후보다. 새 기본 경로에서는 B2를 받지 않아 일부 반복이 줄지만,
기존 B2 응답이 담긴 결과는 계속 고려해야 한다. 이 문서는 해당 개선을 구현하거나 실제 화면에서 검증했다는
주장이 아니다.

팀의 결과 피드백도 문항 수와 별개로 남는다. 사용자가 직접 고른 취향, 돈을 쓰는 기준,
둘의 준비 방식이 결과에서 이해되도록 해야 하며, 단지 질문을 다른 말로 되풀이하는
결과가 충분하다고 보지 않는다. 동시에 질문하지 않은 성격·예산·가족 사정을 그럴듯한
설명으로 채워 넣어서는 안 된다.

## 주장 감사와 구현 후 확인 항목

| 주장 | 근거·판정 |
|---|---|
| 감사 시작 시 운영 기본 진입은 34개였다. | E: 변경 전 constants와 client의 순서·개수 확인. |
| 기본 23개와 선택 9개로 경로를 나누고 B2·D2는 기존 경로에만 보존할 수 있다. | I: 현재 직접 응답과 해석 구조에 기반한 구현 제안. 아직 완료 아님. |
| G1/G2, B2/spending, D1/D2에서 체감 반복 위험이 있다. | I: 원문·결과 사용처의 의미 감사. 실제 오독률 미측정. |
| B1/B3, T2/T3, F1/F2는 합치지 않는 편이 낫다. | I: 각기 다른 결정 정보를 보존하기 위한 판단. |
| 23개가 최적이며 소비자가 더 잘 완주한다. | 근거 없음. 주장 금지. |
| 기본 결과로 전체 예식 분위기와 모든 웨딩 성향을 안다. | 근거 없음. 특히 장식 문항이 선택이라는 한계도 있음. 주장 금지. |
| 실제 소비자 이해도·재미·유용성이 검증됐다. | 이번 작업은 코드·문서 내부 감사. 미검증. |
| 축소 경로의 저장·공유·커플 비교가 문제없이 작동한다. | 구현 후 테스트·실제 화면 증거 필요. 이 문서만으로 통과 주장 금지. |

구현 후에는 기본 23개 완료, 선택 9개로 인한 완료 차단 없음, 원 질문으로 정확한
수정·복원, 기존 공유 링크, 같은/다른 길이의 커플 응답 비교, 우선순위 근거 변경,
모름·비해당·건너뜀·묻지 않음 보존을 검증해야 한다. 실제 준비 전·준비 중 소비자의
문항 이해도, 중복 체감, 결과 유용성은 사람에게 읽혀 확인하기 전까지 미검증으로 남긴다.

## 최종안 독립 검수

문항 의미 기준으로 **기본 23 + 선택 9 + 기존 경로 전용 2**는 위 반례를 만족하는 설계안이다.
B2를 제외하면 현재 대상이 없는 가정적 재배분 의향은 더 묻지 않게 되지만, 기본에서
구체 spending과 B1·B3를 받으므로 실제 답에 근거한 돈 사용 기준을 설명할 수 있다.
D2를 제외하면 조건 충족 즉시 선택 여부를 별도로 얻지 못하지만, 원문 자체가 즉시 선택을
명확하게 한정하지 않았으므로 D1만으로 이를 추정하지 않는 편이 낫다.

이 판정은 내부 의미 검수 통과이며 구현·저장 호환·커플 비교·사용성 통과가 아니다.
기존 답의 보존과 새 결과에서 미수집 내용을 추정하지 않는 조건이 깨지면 이 설계 판정도
적용할 수 없다. 코드 반영과 검증·배포 영수증은 별도로 확인해야 한다.
