# 웨딩코드 v3.1 문항·결과 계약

2026-09-23 · 문항·해석 구현 완료, 배포 검증은 별도 영수증 기준 · 기존 판: v3.0-preferences

## 목표와 범위

사용자가 원하는 결혼식, 돈과 선택의 기준, 둘의 역할·가족 상의·받고 싶은 도움을 직접 정리하고 비교한다. 질문을 쉽게 이해하고 결과의 근거를 확인할 수 있어야 한다. 모든 웨딩 성향·숨은 성격·궁합을 판정하거나 수요를 보장하지 않는다.

직전 운영 감사 `.verification/2026-09-23_question-audit.md`에서 재현한 우선순위 중복, 특정 응답의 빈약한 결과, 지출 희망 없음의 잘못된 비교 분류를 수정한다. 팀 PDF 대조 기록과 기존 연구 근거 `2026-09-22_complete_feedback_audit.md`, `2026-09-22_complete_research.md`를 이어받는다. RETIRED 상태인 Candidate 4의 16문항 생성 규칙은 현재 판에 재사용하지 않는다.

## 대안과 선택

1. 40개를 유지하고 말만 수정: 취향을 두 번 묻는 문제와 복합 보기의 의미 충돌이 남아 제외했다.
2. 모두 5단계 문장으로 변환: 구체적인 장소·사진·식사·식순 선택을 긴 문장으로 늘리므로 제외했다.
3. 준비 방식은 5단계, 구체 취향은 직접 선택으로 한 번씩 질문: 사용자가 요청한 응답 경험을 유지하면서 실제 중복을 제거하므로 선택했다.

## 문항 gate

- 기존 V2,V3,V4,G4,R1,R2는 직접 취향 질문과 겹치므로 새 판의 동의 문장에서 제거한다.
- D4는 D1과 의미 구분이 약하므로 제거한다. D1은 최종 선택 전 후보 비교, D2는 조건에 맞을 때 선택, D3는 방문 확인을 각각 묻는다.
- 남는 25문장 ID: V1; G1,G2,G3; R3,R4; B1,B2,B3,B4; D1,D2,D3; T1,T2,T3,T4; F1,F2,F3,F4; H1,H2,H3,H4.
- 문장은 현재의 희망으로 읽는다. 낮은 동의를 반대 성향으로 추정하지 않는다. 동시에 동의할 수 있는 가족·분담·예산·지원 문장을 억지 반대축으로 바꾸지 않는다.
- 직접 취향 6개: 예식 장소(식사 장소와 혼합 금지), 촬영 방식, 의상, 식사, 하객 규모, 식순.
- 식순은 간결함, 둘의 이야기, 감사 인사, 하객 참여, 축하 공연, 전통 순서를 별도 보기로 둔다. 의상과 식순은 해당하는 보기를 모두 선택할 수 있다.
- 피하고 싶은 것 1개 질문: 많은 꽃·장식, 붐비는 공간, 긴 사진 촬영, 하객을 무대에 부르는 순서, 큰 음악 소리. 기존에 직접 묻는 이동 시간·의상 편의·짧은 식순을 다시 묻는 보기는 추가하지 않는다. 없음·모름·비해당·맞는 보기 없음·건너뜀을 허용한다.
- 우선순위 1개: 원하는 문장·직접 취향·직접 확인한 피하고 싶은 것 중 최대 3개. 각 후보는 실제 응답에만 근거한다.
- 지출 1개: 총액 증액과 구별한 추가 배분 희망. 장소·꾸미기, 사진·영상, 옷, 헤어·메이크업, 식사, 식순·연출 중 최대 2개. 없음도 명시적인 유효 응답이다.
- 합계: 25 + 6 + 1 + 1 + 1 = 34개. 문항 수와 주제별 개수는 측정 타당도나 최적 시간을 의미하지 않는다.

독립 적대적 문항 검수: **내부 의미 gate 통과**. 사진 복합 선호는 비중을 추정하지 않는 ‘둘 다 남기고 싶어요’로 적는다. 회피의 장식 보기는 ‘꽃과 장식이 빼곡한 공간’으로 구체화한다. 풍성한 꽃 선호와 빼곡한 장식 회피, 하객 참여와 무대 호출 회피는 양립할 수 있으므로 충돌로 표시하지 않는다. 소비자 사전검증 통과라는 뜻은 아니다.

## 해석·copy gate

- 우선순위마다 원응답과 연결된 구체적인 다음 행동을 보여준다. 정해진 긍정 조합에 들지 않는다는 이유로 사용자 기준을 설명하지 않는 결과를 만들지 않는다.
- 우선순위를 정하지 않아도 직접 선택한 취향과 답에서 확인 가능한 설명·다음 행동을 제공한다. 전부 모름·건너뜀은 성향을 만들어 채우지 않는다.
- 결과는 근거를 펼쳐 볼 수 있고 원응답으로 돌아가 수정할 수 있다. 앞 답을 바꾸면 근거가 사라진 우선순위는 재확인을 받는다.
- 원하는 것과 피하고 싶은 것이 함께 나와도 둘 다 보존하고, 원하는 정도·대상을 직접 확인하게 한다. 모순된 사람으로 분류하지 않는다.
- ‘비용 더 나누기’, ‘상태를 남겼어요’, ‘조건 충족’, ‘증액’ 같은 불필요한 문서체는 소비자의 말로 고친다.
- 커플 결과에서 지출의 구체 항목 ↔ 추가 배분 희망 없음은 비교 가능한 답이다. 상대 희망에 대한 반대라고 단정하지 않는다. (2026-09-27 개정: 지출·피하고 싶은 것·우선순위에서 한쪽만 ‘따로 없어요’로 답하면 취향의 ‘어느 쪽도 괜찮아요’와 같게 **열린 답**으로 묶는다. 차이 묶음에 두지 않는 배치로 반대가 아님을 지키며, 판정 고지 문장은 쓰지 않는다.)
- 취향의 어느 쪽도 괜찮음은 열린 선호다. 모름·비해당·무응답과 구분하며, 구체 취향과 비교할 때 확정 합의나 갈등으로 만들지 않는다.
- 공통 답도 실제 합의가 아니다. 예산 금액, 개인의 지불 능력, 가족의 생각은 추정하지 않는다.

## 버전과 구현 계약

- 새 버전: `v3.1-preferences`. 신규 경로의 기본값을 새 판으로 전환한다. v3.0·v2.0·이전 링크는 기존 문항과 응답 해석으로 열 수 있어야 한다.
- v3.1은 별도 constants/model/client 파일로 둔다. 기존 문항 값을 새 문항에 옮겨 읽지 않는다.
- v3.1 모델 이름은 v3.0 대응 이름의 V31/v31이며, draft에 `avoidances?: V31Choice`를 추가한다.
- constants: `WEDDING_CODE_V31_AVOIDANCES`, `WEDDING_CODE_V31_*`; 기존 question ID 일부를 유지하되 version이 의미 경계다. 6 taste 키는 동일하나 새 판의 보기 원문은 v31에 독립 고정한다.
- profile은 기존 필드 외 `avoidanceLabels: string[]`, `priorityGuides: V31Insight[]`를 제공한다. evidence ID는 문장 ID, `taste.<key>`, `avoidances`, `priorities`, `spending`; 우선순위 옵션의 회피 기준 ID는 `avoid.<value>`다.
- UI 순서: 동의 25 → 취향 6 → 피하고 싶은 것 → 우선순위 → 지출. 수정·포커스·공유 동의 재확인·미응답 방어는 v3.0의 경계를 유지한다. 이 순서는 이전 전체(34단계, `full`) 흐름의 것이며 그대로다.
- 기본(`core`) 흐름 화면 순서(2026-09-27): 동의 15 → 취향 6 → 피하고 싶은 것 → 지출 → 우선순위. 완료 판정은 우선순위를 뺀 23개(`V31_CORE_INDEXES`)다.
- 공유는 fragment 전용이며 명시적으로 선택한 제한된 값만 담는다. 메모·임의 문자열·숨은 응답·로그인 계정·서버 저장은 추가하지 않는다.
- 실제 동의 없이 커플 의사결정·예산·일정에 자동 반영하지 않는다. 이 기능은 외부 AI 호출을 추가하지 않는다.

## 검증 계획

1. 문항 ID·선택지·codec 길이·알 수 없는 값·중복·초과 선택·버전 혼합 거절.
2. 이전 운영 반례에서 우선순위 의미 중복 없음, 34개 완료, 직접 기준에 근거한 결과와 수정 동작 확인.
3. 명시적 없음·열린 선호·모름을 구분하는 커플 비교의 양방향 사례.
4. 모두 동의·모두 낮음·모두 중간·모두 건너뜀에서 근거 없는 성향 생성 없음.
5. 새 판 및 기존 v3.0 공유 링크·커플 재개·동의 초기화 검증.
6. 관련 테스트, 새 검사 변형 증명, 저장소 공식 전체 검증, 실제 화면 QA, 배포 후 운영 확인.

실제 소비자의 이해도·문항 피로·재미·공유 의향·수요; 실기기 iPhone/Android 사용성; 심리측정 타당도와 모든 웨딩 성향의 포괄성은 별도 미검증으로 남긴다.

## 내부 구현 검수 기록

독립 검수에서 명시적인 우선순위 없음의 미정 분류, 동적 조사 오류, 예산 문장에 없는 선후관계, 복수 보기의 부분 공통점 누락, 동일 안내의 반복을 찾아 수정했다. 사진의 ‘둘 다’에 포함된 공통 선택도 보여주되 전체 희망이 같다고 분류하지 않는다. 실내·야외를 함께 쓰는 장소는 별도의 장소 조건으로 유지한다.

모델 62개, 화면 상호작용 16개, 기본 진입·구판 호환·메타데이터·랜딩 49개 관련 검사가 통과했다. 새 모델 검사는 지출 없음 오분류·공유 회피 답 누락·낮은 동의를 희망으로 바꾸는 변형을 모두 검출했다. 새 화면 검사는 공유 동의 제거·수정 후 우선순위 재확인 제거를 모두 검출했다. 원복 해시는 prove-guard 영수증으로 확인한다.

이 기록은 저장소 전체 검사와 배포 성공을 대신하지 않는다. 전체 검사는 `.verification/verification-receipt.json`, 실제 화면 및 배포 확인은 `.verification/v31-production.md`에 별도 기록한다. 응답자 역할을 맡은 내부 테스트는 소비자 참여 실험으로 세지 않는다.
