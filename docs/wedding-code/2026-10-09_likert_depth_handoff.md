## 구현한 해석 보완

- **L 정의:** 원문의 ‘내 이야기’를 보존했다. 사실 전달도 포함하며 감정·고민·위로로만 좁히지 않는다.
- **독립 비율:** 각 방향의 4·5 동의 수 / 그 방향의 1~5 응답 수를 보여 준다. 정수 반올림과 실제 분자·분모를 함께 표시한다. 양쪽 100%가 가능하며 분모 0은 계산할 응답 없음이다. 정확도·확률·희귀도가 아니다.
- **레터 근거:** 대표 표와 비율을 구별한다. 각 장면의 두 원답, 대표 표 포함 여부, 실제 비교한 장면 수를 펼쳐 확인한다.
- **도움·휴식:** 낮은 동의·보통·모름·비해당·건너뜀·미응답을 구별한다. 4·5 응답이 없으면 실제 도움 요청문을 만들어내지 않는다. 함께·혼자 쉬기에 모두 동의한 경우 실행 순서는 본인이 정한다.
- **커플 대화:** 첫 문항 고정 선택을 없앴다. 현재 장면의 다른 응답·미확인 응답을 원문·각자 답·확인 질문에 연결한다. 같은 칸만 있는 장면도 이유·행동이 같은지 묻는다.

## 검증의 현재 경계

초기 의미 보완 검사 55개, 이후 의미·저장·개인정보 관련 검사 103개·127개가 통과했다. 추가 감사에서 중앙 analytics 예외, 실제 오류 경계 버퍼, 느린 이동의 경로 확정, 지연된 Sentry envelope를 발견하고 실제 실패 반례를 먼저 실행한 뒤 고쳤다.

- `/wedding-code-next` 직접 진입에서 PostHog·Sentry의 새 초기화와 오류 보관을 차단한다. idle/import 대기 중 진입도 다시 확인하고 취소한다.
- 분석 SDK의 기존 예외보다 앞에서 새 경로를 확인한다. 전체 capture의 중첩 URL·배열·순환 객체를 확인하며 기존 v4·랜딩 허용 목록을 보존한다.
- 실제 `clientErrorReport`에서 새 경로의 오류를 생성·보관·flush하지 않는다. 기존 버퍼도 비우며 가벼운 import 0개 경계를 유지한다.
- Sentry event·transaction·breadcrumb은 현재 경로뿐 아니라 늦게 처리된 새 경로 URL도 sanitizer 전에 버린다.
- 일반 페이지 이동 완료는 무인자 window callback으로 확인한다. 경로나 오류 원문을 callback 연결에 저장하지 않는다. PostHog 키 없이 Sentry만 있을 때도 복구하며 반복 타이머나 history 변경을 사용하지 않는다.
- 독립 소스 감사에서 앞선 세 추가 경계의 교정과 기존 v4·랜딩 동작 보존을 확인했다. 이후 Provider의 설명 주석 한 줄을 현재 동작에 맞게 고쳤다.
