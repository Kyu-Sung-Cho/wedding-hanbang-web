## 0. 목적

웨딩코드의 점수화는 사람을 분류하기 위한 것이 아니라, **커플이 결혼 준비를 어떻게 이야기하면 덜 피곤하고 더 행복해질지**를 보여주기 위한 것이다.

따라서 결과는 다음을 금지한다.

- 성격 진단
- 궁합/결혼 성공 예측
- 이혼 가능성
- 우열 타입
- "정답"이 있는 행동 지침

결과가 해야 하는 일은 세 가지다.

1. 나의 준비 성향을 이해하기 쉽게 보여준다.
2. 상대에게 공유했을 때 대화거리가 되게 한다.
3. 커플 비교에서 "누가 맞냐"가 아니라 "어디부터 맞춰보면 좋냐"를 알려준다.

## 1. 추가 근거: 돈은 비용 문제가 아니라 대화 문제다

v0.5부터 비용 문항은 한국 결혼서비스 시장 근거만이 아니라 커플 재무 대화 연구에도 연결한다.

참고 근거:

- Financial communication 연구: 재무 대화의 질과 재무 스트레스/관계 만족이 연결됨.  
  DOI: `10.1007/s10834-025-10063-7`
- Financial planning discrepancy 연구: 커플 간 재무 계획 인식 차이가 클수록 결혼 만족도가 낮게 나타남.  
  DOI: `10.1007/s10834-024-09967-7`
- Financial management behavior 연구: 재무 관리 행동은 관계의 질과 주관적 안녕에 영향을 준다고 보고.  
  DOI: `10.3390/ijerph17041190`

제품 적용:

- 비용 문항은 "돈을 아끼는 성향"을 재는 게 아니다.
- 비용 문항은 "불확실한 큰돈 앞에서 커플이 어떤 순서로 대화하고 확인하는지"를 본다.
- 결과 문구는 "돈에 민감함"이 아니라 "조건 확인을 먼저 하면 안정되는 편"처럼 쓴다.

## 3. Scoring Rules

### 3.1 Choice Weight

각 선택지는 0~3개의 구인에 점수를 준다.

- primary: `+2`
- secondary: `+1`
- tertiary: `+1`

선택지 하나에 너무 많은 의미를 넣지 않는다. 한 답변의 총점은 원칙적으로 3점 이하, 필요 시 최대 4점까지 허용한다.

### 3.2 Axis Score

공개 축은 단순 MBTI식 이분이 아니다. 양쪽이 동시에 높을 수 있다.

축 계산은 원점수 합산으로 하지 않는다. 문항 세트 안에서 구인별 노출 기회가 다르기 때문에, 원점수를 그대로 비교하면 `CP`, `ED`, `CR`처럼 많이 노출된 구인이 과대표현될 수 있다.

계산 초안:

1. 각 구인의 원점수를 구한다.
2. 각 구인의 `exposureMax`로 나누어 0~100 점수로 정규화한다.
3. 축의 왼쪽/오른쪽은 관련 구인의 정규화 점수 평균으로 계산한다.
4. 축별 차이는 정규화 점수의 percentage point 차이로만 해석한다.

| 축 | 계산 초안 | 표시 |
|---|---|---|
| 결정 기준 | `avg(norm(CR), norm(ED))` vs `avg(norm(EM), norm(AM))` | 조건 확인형 / 의미 상상형 / 균형형 |
| 준비 방식 | `norm(CP)` vs `norm(RO)` | 같이 맞춤형 / 맡아 정리형 / 혼합형 |
| 조율 범위 | `norm(CA)` vs `norm(FI)` | 우리 기준형 / 가족 조율형 / 균형형 |
| 지원 순서 | `norm(ES)` vs `norm(EX)` | 마음 먼저형 / 할 일 먼저형 / 순서 조합형 |

### 3.3 Confidence

축별 결과는 정규화 점수 차이와 문항 수로 confidence를 계산한다.

- 차이 0~12pp: `균형`
- 차이 13~24pp: `조금 가까움`
- 차이 25pp 이상: `가까움`

문항 응답 수가 부족하거나 optional 문항을 많이 건너뛴 경우 confidence를 낮춘다.
구인별 `exposureMax`와 전체 세트 감사는 `44_v0.5_item_set_integrity_audit.md`를 기준으로 한다.

### 3.4 Result Language

허용:

- "현재 답변으로는 OO에 가까워요."
- "이 축에서는 두 기준을 같이 보는 편이에요."
- "상대와 비교할 때 먼저 얘기해볼 지점은 OO예요."

금지:

- "당신은 OO형입니다."
- "궁합 87%"
- "상위 3% 희귀 유형"
- "이 유형은 갈등이 많습니다."

### 3.5 Couple Overlap

커플 비교는 compatibility가 아니다.

계산 초안:

- 각 축에서 두 사람의 normalized distance를 계산한다.
- `100 - distance`를 내부적으로 만들 수는 있으나, UI에는 **"준비 방식 겹침도"**로만 표시한다.
- 전체 단일 점수보다 "같이 쉬운 지점 2개 + 먼저 맞춰볼 지점 1개"를 우선한다.

표시 예:

- "두 분은 결정 전 확인해야 마음이 놓이는 지점이 비슷해요."
- "다만 가족 기준을 반영하는 순서는 먼저 맞춰보면 좋아요."

금지:

- "잘 맞는 커플"
- "안 맞는 커플"
- "궁합 낮음"

## 5. Red-Team Notes

현재 초안에서 가장 위험한 부분:

1. `ED`, `CR` 선택지가 너무 책임감 있는 정답처럼 보일 수 있다.
2. `ES` 선택지가 더 따뜻하고 좋은 사람처럼 보일 수 있다.
3. `EX` 선택지가 차갑거나 일 중심으로 오해될 수 있다.
4. `FI` 선택지가 부모님 편으로, `CA` 선택지가 반가족으로 읽힐 수 있다.
5. `DPR`은 절대 유형명으로 쓰면 안 된다. "빠른계약형" 같은 이름은 금지.

검증 방법:

- 인지 인터뷰에서 "정답처럼 보인 선택지"를 문항마다 직접 물어본다.
- 인터뷰 후 선택지 하나가 70% 이상 몰리면 문항 또는 선택지를 재작성한다.
- 특정 선택지를 고른 사람이 "내가 나쁜 답을 고른 느낌"이라고 말하면 즉시 수정한다.
