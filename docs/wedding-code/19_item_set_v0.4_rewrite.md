## 0. 배경과 근거

첫 내부 테스트(n=1, 창업자 본인)에서 "질문이 너무 구체적이고 현실적으로 느껴지지 않는다"
피드백 — AI 레드팀이 1순위로 예측한 stage-fit 리스크와 일치. 진단:

1. 필수 문항이 계약 단계 상황·업계 용어(원본·보정·헬퍼·얼리스타트)에 치우쳐
   초기 단계 사용자에게 "남의 인생 용어"로 읽힘. 유통 유입층(준비 극초기)과 어긋남.
2. 선택지가 긴 절차 문장이라 측정 안전성은 높지만 공감·플로우가 없음 —
   MBTI류가 이긴 무기(공감)를 버리고 있었음.

## 1. v0.4 원칙 (변경 범위 한정 — n=1 과수정 방지)

**바꾼 것 (표면만):**
- 질문 = 감정 훅 한 줄 + "이럴 때 나는 —" 형태
- 선택지 = 한다체 단문 (25자 내외)
- 업계 용어 제거 (원본/보정/헬퍼/얼리스타트 → "어디서 돈이 더 나올지 감이 안 와요")

**안 바꾼 것 (뼈대):**
- 질문 ID·구성개념 매핑·선택지의 성향 구조 (v0.3 각 옵션의 구인 방향 1:1 유지)
- 낙인 방지 가드레일 전부 (정답 없음·성역할 없음·부모 중립·"설득" 금지·과업우선≠차가움)
- 사실 접지 (추가금 존재·구두약속-계약서 불일치·지역 300만 격차 — 18번 크로스체크의 🅰 앵커 유지)
- 단계 게이팅(Option B)·필수/선택 구분·게이팅 플래그
- 문항은행 교체(단계 재배분)는 **보류** — 지인 5명 데이터로 확증 후 결정

기록: 응답 테이블 form_version으로 v0.3(0건)/v0.4 구분 저장됨.

## 2. v0.4 전체 문항 (카피 원본 — `weddingCodeForm.ts`와 동기 유지 의무)

### q01 · costRisk (필수)
**견적서를 받았는데, 어디서 돈이 더 나올지 감이 안 와요. 이럴 때 나는 —**
- A. 뭐가 포함이고 뭐가 추가금인지부터 따져본다 (costRisk)
- B. 일단 결과물 분위기가 우리랑 맞는지 본다 (aestheticMood)
- C. 둘이서 '꼭 필요한 것'부터 추린다 (coPreparation)
- D. 실제 해본 사람들 후기를 찾아본다 (evidenceDecision)

### q02 · experienceMeaning (필수)
**이건 두고두고 기억에 남을 것 같은데, 추가 비용이 있대요. 이럴 때 나는 —**
- A. 시간이 지나도 의미 있을지를 먼저 생각한다 (experienceMeaning)
- B. 예산 안에서 감당되는지부터 계산한다 (costRisk)
- C. 비슷한 느낌의 다른 선택지를 찾아본다 (대안 탐색)
- D. 어떤 장면을 남기고 싶은지 둘이 얘기한다 (co+meaning)

### q03 · coPreparation (필수)
**마음에 드는 곳을 찾았는데, 상대는 아직 제대로 못 봤어요. 이럴 때 나는 —**
- A. 같이 보면서 처음부터 다시 살펴본다 (coPreparation)
- B. 내가 핵심만 정리하고 마지막 결정만 같이 한다 (roleOwnership)
- C. 결정 전에 둘 다 볼 체크 목록부터 만든다 (evidenceDecision)
- D. 왜 끌렸는지 먼저 말하고 반응을 들어본다 (emotional 공유)

### q04 · roleOwnership (필수)
**한 명이 알아보고, 결정 전에 둘이 최종 확인하기로 했어요. 이럴 때 우리는 —**
- A. 알아본 사람이 요약하고, 같이 승인한다 (roleOwnership)
- B. 중요한 건 처음부터 끝까지 둘이 같이 본다 (coPreparation)
- C. 되돌리기 어려운 것(계약·환불)만 집중해서 본다 (evidence/cost)
- D. 한 명은 조건을, 다른 한 명은 분위기를 나눠 본다 (분업 — 성별 매핑 없음 유지)

### q05 · evidenceDecision (필수)
**"그건 그냥 해드릴게요"라고 했는데, 계약서엔 그 말이 없어요. 이럴 때 나는 —**
- A. 문자로라도 남겨달라고 요청한다 (evidence — 서면화)
- B. 그 혜택이 진짜 필요한 건지 따져본다 (cost/필요성)
- C. 그 약속 없이도 괜찮은 곳인지 다시 본다 (기준 재확인)
- D. 확인될 때까지 결정을 잠깐 미룬다 (decisionPace)

### q06 · aestheticMood (필수)
**투어 중 들어간 곳이 딱 '우리 느낌'이었어요. 이럴 때 나는 —**
- A. 원하던 분위기가 맞는지 찬찬히 뜯어본다 (aestheticMood)
- B. 식대·인원·교통 같은 조건부터 확인한다 (family/cost)
- C. 사진과 영상에 어떻게 남을지 본다 (experienceMeaning)
- D. 상대와 가족이 볼 기준을 적어 맞춰본다 (정렬)

### q07 · familyIntegration (필수)
**우린 분위기에 끌리는데, 부모님은 음식과 교통을 보세요. 이럴 때 나는 —**
- A. 부모님 기준부터 구체적으로 들어본다 (familyIntegration — 경청)
- B. 양쪽 기준을 한 표에 놓고 비교한다 (구조화)
- C. 예산·인원까지 현실적인 차이를 확인한다 (cost)
- D. 우리 기준을 정리해 절충안을 준비한다 (coupleAutonomy+조율)

### q08 · coupleAutonomy (필수)
**우리 결혼식 기준을 부모님께 말씀드려야 해요. 이럴 때 나는 —**
- A. 그 전에 둘의 기준부터 확실히 맞춘다 (coupleAutonomy — 기준 설정)
- B. 예산과 이유를 숫자로 정리해 보여드린다 (evidence — "설명" 프레임)
- C. 걱정하실 지점을 먼저 예상해본다 (family — 경청 순서)
- D. 부드럽게 꺼낼 첫마디를 준비한다 (emotional — 표현 지원)

### q09 · emotionalSupport (필수 — 내부전용 구인)
**"걱정된다"고 했더니 상대가 바로 해결책부터 내놨어요. 이 순간 나는 —**
- A. 일단 내 마음부터 들어줬으면 싶다 (emotional-high)
- B. 짧게 공감받고, 같이 정리하면 좋겠다 (균형)
- C. 바로 정리해주는 것도 고맙다 (execution — "고맙다"로 차가움 프레임 차단)
- D. 나한테 맞는 반응을 얘기해두고 싶다 (메타 소통)

### q10 · executionSupport (필수·게이팅 q_execution_stage_flag)
**본식 직전, 연락할 곳과 챙길 게 한꺼번에 쏟아진다면 나는 먼저 —**
- A. 누가 뭘 맡을지부터 나눈다 (role)
- B. 마감 순서대로 할 일을 줄 세운다 (execution)
- C. 보낼 안내 문자부터 정리한다 (구체 행동)
- D. 서로 부담부터 얘기하고 일을 나눈다 (emotional→행동)

### q11 · decisionPaceRisk (필수 — 내부전용 구인)
**상담이 너무 좋아서 당장 계약하고 싶어요. 이럴 때 도움이 되는 건 —**
- A. 하루 자고 나서도 같은 마음인지 보는 것 (일시정지)
- B. 좋았던 점과 걸리는 점을 같이 적어보는 것 (공동 정리)
- C. 총액과 취소 조건을 확인하고 정하는 것 (evidence)
- D. 다른 후보와 한 번 더 비교해보는 것 (비교)
※ 흥분을 "충동"으로 낙인찍지 않음 — "도움이 되는 건" 프레임 유지

### q12 · guidanceNeed (필수·게이팅 q_guidance_stage_flag)
**견적서가 낯선 항목투성이라면, 나에게 필요한 건 —**
- A. 먼저 볼 3가지만 콕 집어주는 것 (압축 안내)
- B. 직접 비교하게 표로 정리해주는 것 (자기주도)
- C. 추가금 붙기 쉬운 곳만 표시해주는 것 (리스크 표시)
- D. 둘이 얘기할 질문 목록으로 바꿔주는 것 (커플 대화)

### q13 · costRisk (선택·게이팅 q_cost_boundary_flag)
**마음에 쏙 드는 식장이 예산보다 300만 원 비싸요. 이럴 때 나는 —**
- A. 총액과 추가금, 환불 조건부터 확인한다 (cost)
- B. 그만큼 오래 남을 곳인지 생각해본다 (meaning)
- C. 가족과 하객 동선까지 같이 따져본다 (family)
- D. 둘의 예산 기준을 다시 맞춰본다 (couple 기준)

### q14 · roleOwnership (선택)
**한 명은 스타일, 다른 한 명은 조건 보는 눈이 좋아요. 우리라면 —**
- A. 각자 잘 보는 걸 맡고 결과를 공유한다 (분업+투명)
- B. 중요한 후보는 둘 다 같이 본다 (공동)
- C. 한 명이 2~3개로 줄이고 마지막은 함께 정한다 (압축→합의)
- D. 각자 본 걸 한 표에 합쳐 같이 본다 (통합 — 점수 없음 유지)

### q15 · evidenceDecision (선택)
**느낌은 딱인데, 실제 후기가 별로 없어요. 이럴 때 나는 —**
- A. 실제 사례와 포함 조건을 더 찾아본다 (evidence)
- B. 우리 취향과 맞는지 한 번 더 본다 (mood)
- C. 비슷한 느낌에 후기 많은 곳을 더 찾아본다 (대안)
- D. 어느 정도 모험까지 괜찮은지 둘이 얘기한다 (허용치 합의)

### q16 · coupleAutonomy (선택·게이팅 q_autonomy_boundary_flag)
**몇 가지 전통 절차는 줄이고 싶은데, 가족 반응이 걱정돼요. 이럴 때 나는 —**
- A. 왜 줄이고 싶은지 둘의 이유부터 정리한다 (기준)
- B. 걱정하실 부분과 설명 방법을 준비한다 ("설명" — "설득" 아님)
- C. 지킬 것과 줄일 것을 구분해본다 (존중+간소화)
- D. 어떤 점이 좋아지는지 자료로 정리한다 (근거화)

## 3. 가드레일 자가점검 (레드팀 §9 기준)

- [x] 정답처럼 보이는 옵션 없음 — 비용 문항의 A(확인 우선)와 B/C/D(무드·필요성·대화)가 모두 유효한 스타일로 병립
- [x] 성역할 매핑 없음 — "한 명/다른 한 명" 패턴 유지, 예시 추가 없음
- [x] 부모 = 조율 대상, 갈등 원천 아님 (q07 A가 "경청"으로 시작)
- [x] "설득" 미사용 (q08·q16 — 설명/준비/공유만)
- [x] 과업 우선 ≠ 차가움 (q09 C "고맙다", q10 D 감정 경로 병립)
- [x] 흥분 ≠ 충동 낙인 없음 (q11 "도움이 되는 건" 프레임)
- [x] 안내 필요 ≠ 의존 (q12 B 자기주도 옵션 병립)
- [x] 구두약속 서면화 = 과정 선호, 불신 아님 (q05)
