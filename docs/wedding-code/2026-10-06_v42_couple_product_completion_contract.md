# 웨딩코드 종합 커플 리포트·초대 흐름 완성 계약

상태: 초안 → 적대적 검수 → 주장 감사 → 로컬 구현·관련 검증 완료 / 실제 사람 확인 0건·공개 배포 미수행.

## 요청과 완료 기준

사용자가 ‘종합 커플 리포트 완성 → 초대·비교 흐름 개선 → 실제 커플 검증과 문항 재수정’ 제안을 실행하도록 요청했다. 기존 관리 워크트리에서 실제 답 근거가 있는 네 주제의 준비 리포트, 로그인 없는 링크 여정의 분명한 다음 행동, 실제 관찰에 사용할 익명 검증 도구를 완성한다. 실제 사람의 이해·안정성·유용성을 조사하지 않고 완료로 표시하지 않는다.

## 대안과 선택

- 두 코드 조합만으로 정형 성격·궁합 해석 / 서버 익명 페어링 / 실제 답 기반 준비 제안 세 가지를 검토했다. 실제 답 기반 제안을 선택한다. 고정 글자를 능력·인격·관계 결과로 해석하지 않으며 확정 결정을 대신하지 않는다.
- 초대 설명만 보강 / 기존 폼 위에 짧은 과정 안내와 상태별 다음 행동 / 새 다단계 마법사를 비교했다. 기존 폼의 여정을 명료하게 하는 방식을 선택한다. 기존 링크·동의 범위·서버 미전송 계약을 사용한다.
- 연구 답 자동 수집 / 진행자가 사용할 익명 관찰 워크시트를 비교했다. 익명 워크시트를 선택한다. 참가자 모집·메시지·녹음·계정 저장·통계 수집은 이 작업에서 실행하지 않는다.

## 리포트 기준

- 돈, 준비 과정, 함께 정할 사람, 지쳤을 때 네 주제 각각에서 ‘함께 활용할 점 → 조율할 상황 → 역할을 나눠 보는 제안 → 먼저 맞출 기준 → 이번 답의 근거’를 읽는다.
- 도움되는 점은 이번 선택 기준을 준비에 활용할 수 있다는 가능성으로만 표현한다. ‘비용을 줄임’, ‘실수가 없음’, ‘갈등 해결’, 능력·성격·정확도·궁합·관계 예측은 주장하지 않는다.
- 두 사람이 모두 clear/lean일 때만 방향별 담당 후보를 제안할 수 있다. 같은 글자여도 합의했다고 말하지 않고, 서로 다른 장면을 살펴본다. even이면 방향을 고정하지 않고 함께 기준을 정하는 제안을 쓴다.
- 도움 주제 H/A는 받는 반응·다툰 뒤·주는 행동·자기 회복을 함께 요약하므로 사람별 돌봄 담당을 제안하지 않는다. 각자 원하는 말·도움을 적고 필요한 반응을 직접 확인하는 공동 제안만 쓴다.
- 미정·임시·관문 제외는 비교·담당자 배정을 보류한다. 유효 응답 수와 보류 이유, 먼저 다시 볼 기준을 보여 준다. 없는 답이나 사례는 만들지 않는다.
- 퍼센트는 기존 실제 응답 방향 개수/유효 답수이며 변경하지 않는다. 역할 제안은 선택·확정·저장이 아니다. 제품의 확정 커플 의사결정이나 서버 상태를 만들지 않는다.
- 기존 talk/similar 목록은 전체에서 각각 최대 세 장면이라 모든 주제를 대표하지 못한다. 부모가 이미 두 사람 결과에서 갖고 있는 bank·decoded 답을 선택적으로 넘겨 주제별 실제 장면을 고를 수 있다. 두 사람 모두 유효하게 답한 원문만 사용하고, 제외 주제는 장면 비교를 만들지 않는다. 원응답이 없으면 기존 목록의 해당 장면을 사용하고, 없으면 사례가 없음을 설명한다.
- 관점 전환 후 나/상대의 근거·제안 대상이 뒤바뀌지 않는다. 원문은 해당 판의 bank에서 읽는다. 공유 링크, 문항판, 저장 범위, 채점 엔진을 수정하지 않는다.

## 미팅 재검수: 각자의 글자 판정 이유 gate (2026-10-06)

- 발견: 개인 결과에는 글자별 계산 이유가 있지만 두 사람 요약은 각자의 비율만 보여 준다. `CoupleSideInfo`의 횟수만으로 선택 강도·동점·표시 하향 이유를 추정할 수 없다.
- 후보: 횟수로 새 이유 만들기 / 두 사람 원응답을 검증한 뒤 기존 개인 결과 계산과 이유 컴포넌트 재사용 / 안내만 추가하기. 두 번째를 선택한다. 채점·문항·비율은 변경하지 않는다.
- 원응답 gate: 기존 v4.2 판·68문항·응답 인코딩·`compareCouple` 재계산 일치 검사를 통과한 source만 사용한다. 같은 bank와 각자의 원응답으로 기존 `buildResult`를 호출한다. 원응답 부재·순서 오류·판 불일치·결과 변조에는 이유를 만들지 않고 확인하지 못했다는 안내를 보여 준다. bank는 기존 신뢰된 부모가 넘긴 정본이어야 한다.
- 적대적 검수: 나/상대 관점을 바꾸거나 두 사람 입력 순서를 바꿔도 이유는 해당 사람의 원응답에 붙는다. 임시·미정·응답 확인 보류의 개인 판정 설명은 비교 가능·담당 확정으로 바꾸지 않는다. H/A의 돌봄 담당 금지와 기존 제외 상태는 그대로 둔다.
- 주장 감사: 횟수 비율과 글자 판정은 구분한다. 새 설명은 실제 계산 경로를 읽기 쉽게 제시하는 것이며 정확도·확률·성격·궁합을 뜻하지 않는다. 실제 참가자 0명 / UNVALIDATED 유지.
- 검증 gate: 원응답에서 나온 각자의 정확한 이유, 관점·입력 순서 전환, 원응답 없음·불일치·다른 판, 임시·미정 상태를 기존 테스트에 추가해 RED → GREEN을 확인한 뒤 구현 완료를 기록한다. 이번 절은 기존 문항·채점 승인 범위를 넓히지 않는다.
- 구현·검증(E): 기존 `sourceIsVerified`를 재사용하는 `buildVerifiedCoupleIndividualResults`로 두 개인 결과를 읽고, 각자의 코드 풀이 아래에 기존 `AxisReadingReason`을 붙였다. 원응답이 없거나 검증을 통과하지 못하면 계산 이유를 표시하지 않았다는 안내 한 줄을 보여 준다. 신규 UI 검사 6개가 기존 화면의 실제 누락으로 실패한 뒤 구현 후 통과했다. 관련 4파일 88/88, 변경 코드·테스트 ESLint 통과. 사람별 이유 교환·원응답 검증 우회 변형을 각각 심어 4개·1개의 AssertionError를 확인하고 두 대상 해시로 원복을 확인했다. 기존 H/A 돌봄 담당 금지 변형도 다시 실패함을 확인했다. 영수증: `.verification/couple-individual-reasons-verification.json`. 이번 추가 화면의 실물 브라우저·운영 배포는 이 절의 검증에 포함하지 않는다.

## 초대·반환 기준

- 로그인 없는 링크 방식이다. 내 답을 담아 초대 → 상대가 자신의 답 완료 → 상대가 두 사람 결과 링크를 다시 보내기 과정을 본문 초반에 알린다.
- 질문만 보내기는 자동 비교가 되지 않는다고 표시한다. 내 답 포함 선택·동의 전 비활성·답 공개 범위·기존 링크 회수 불가를 유지한다.
- native 공유 API 완료는 공유 창에 전달한 상태, clipboard 완료는 복사한 상태, 주소 노출은 직접 복사가 필요한 상태, 취소는 전송하지 않은 상태로 분리한다. 실제 상대 수신·서버 연결을 확인했다고 말하지 않는다.
- 두 사람 결과 반환 행동을 결과 상단에서도 찾을 수 있게 하며, 실제 발송은 기존 동의 폼을 통과한 뒤에만 이루어진다. 주소 fragment를 변경하는 탐색 링크는 쓰지 않는다.

## 적대적 검수·주장 감사

독립 검수에서 현재 CoupleResult만으로 네 주제 모두 실제 장면을 제공할 수 없음을 확인했다. 선택적 원문 근거 입력과 명시적 빈 상태로 수정했다. 공유 창의 완료를 실제 메시지 수신으로 말하는 카피도 관찰 범위에 맞춰 수정한다. 네 글자가 같다는 이유로 함께 잘하거나 이미 합의했다고 말하지 않는다. 높은 비율·테스트 개수가 문항 타당성을 증명하지 않는다.

실제 커플 확인 0건 / UNVALIDATED를 유지한다. 문항 이해 재진술·정답감·예측가능성·일상 경험의 웨딩 전이·부담·결과 설명 이해·대화 유용성·역할 제안 오해를 기록하는 도구를 준비한다. 사용성 관찰과 심리 측정 타당성·G3·공개 배포 승인 상태를 구분한다. 관찰 자료 없이 원문·극·강도를 다시 바꾸지 않는다.

## 디자인과 검증

DESIGN.md의 Pretendard, ivory, champagne 요약, white 상세, mauve 행동 토큰을 사용한다. Lazyweb의 현행 best-practices 경로에서 Impeccable clarify/craft를 적용해 실제 근거와 다음 행동을 먼저 읽고 세부를 펼친다. 새 Growth Report는 요청되지 않아 생성하지 않는다.

실제 v4.2 bank 결과, 두 사람 순서 교환, 같은 글자/다른 장면, even·미정·임시·관문·원문 없음, 역할 대상과 관점 전환, 공유 성공/복사/취소·질문만·동의 상태를 검사한다. 변경 범위 타입·린트·소스 가드, desktop/mobile 실물과 독립 검증 워크시트 내보내기를 확인한다. 검수 영수증은 구현 후 덧붙인다.

## 구현과 독립 검수 영수증 (E)

- 새 순수 모델 `couplePreparationReport.ts`와 읽기 화면 `CouplePreparationSection.tsx`를 연결했다. 실제 글자와 주제별로 같은 앞 방향/같은 뒤 방향/다른 방향/반반 설명이 달라진다. 실제 답의 유효 개수와 원문 선택지는 접힌 근거에서 읽는다.
- 이미 완성된 두 사람 링크와 초대받은 사람이 자기 답을 마친 경로 모두 신뢰된 부모가 가진 bank·두 원응답을 넘긴다. source 검증은 v4.2 판 태그, 68개 배치, 두 답의 완전한 인코딩, 기존 compareCouple 재계산 일치를 확인한다. 동일 bank 객체 여부는 요구하지 않는다. 이 검증은 별도 심리 타당도나 임의 bank의 진실성을 인증하지 않으며, 전달하는 bank는 기존 부모의 정본이어야 한다.
- 기존 talk/similar의 해당 주제 장면을 먼저 읽고, 없으면 두 사람이 실제 유효하게 고른 해당 주제 원문에서 장면 하나를 고른다. 중립 값 0도 유효 답이다. 방향 차이와 산술 차이를 이용한 장면 선정이며 사람에게 가장 중요한 장면이라는 주장은 하지 않는다. 제외 축과 원응답 불일치에서는 장면과 역할을 보류한다.
- 독립 검수로 H/A의 받는 선호를 제공 능력으로 바꾸던 역할 연결과 보류 사유 누락을 발견해 수정했다. 같은 글자에 일반 문장만 반복되던 카피도 실제 준비 행동과 세부 조율 기준으로 바꿨다. 재검수에서 실제 답·역할 대상·관점 매핑과 주장 범위를 확인했다.
- 초대와 받는 화면에 짧은 정적 절차를 붙였다. 질문만 보내기에서는 비교 과정 안내가 숨겨진다. 상단 반환 버튼은 주소 fragment를 바꾸지 않고 기존 동의 폼으로 초점과 스크롤을 옮긴다. 두 동의 확인 전에는 반환 링크를 만들지 않는다.
- native 공유 완료는 공유 창 전달, clipboard 완료는 복사, 취소는 취소로 표시한다. 이용 통계와 민감 응답 범위는 확대하지 않았다. 실제 메시지 수신·자동 동기화·계정 연동 완료로 표시하지 않는다.

## 남아 있는 확인
