# WeddingCode C4 Item Review - 하객 수와 보증인원을 정할 때
작성일: 2026-07-07  
상태: v0.5 문항 후보 확정 전 심층 리뷰  
대상: C축 `조율 범위` 4번 문항, 기존 q계열 하객/보증인원 문항

---

## 0. 결론

C4는 유지한다. 하객 수, 보증인원, 식대는 실제 웨딩 준비에서 비용과 가족 조율이 동시에 걸리는 강한 장면이다. 다만 기존 문장은 그대로 쓰기에는 위험이 있었다.

기존 문장:

> 하객 수와 보증인원 이야기가 나오니 양가 생각이 조금 달라요.

이 문장은 현실적이지만 시작부터 양가 갈등을 전제할 수 있고, 선택지 일부는 "하객을 줄이고 싶은 사람", "부모님 말에 휘둘리는 사람", "양가를 설득하려는 사람"처럼 읽힐 수 있다. v0.5에서는 다음처럼 낮춘다.

> 하객 수와 보증인원을 정해야 해서, 양가가 생각하는 초대 범위도 같이 봐야 해요. 나는 먼저 -

- 예상 참석 인원과 보증인원 차이를 먼저 계산한다
- 양가가 꼭 초대하고 싶은 범위와 이유를 들어본다
- 우리가 무리 없이 감당할 예산과 인원선을 맞춘다
- 같은 기준으로 이야기할 초대 원칙을 정리한다

이 문항은 "하객을 많이 부르는 사람/줄이는 사람"을 가르는 문항이 아니다. 핵심은 하객 수 문제를 숫자 확인, 양가 초대 범위, 커플 예산선, 공통 초대 원칙 중 어디서부터 풀려는지다.

---

## 1. 이 문항이 필요한 이유

C4는 C축에서 가장 현실적인 비용-가족 결합 문항이다. 예식장은 보증인원과 식대에 따라 총액이 크게 달라지고, 하객 명단은 커플의 기준만으로 끝나지 않는 경우가 많다.

필요한 이유:

1. 보증인원과 식대는 실제 예식장 계약에서 확인해야 하는 핵심 조건이다.
2. 하객 명단은 가족·양가·혼주 관점과 커플의 예산선이 동시에 걸릴 수 있다.
3. "누구를 초대할지"는 체면이나 효도 평가가 아니라 초대 원칙과 비용 조건을 함께 맞추는 문제다.
4. 결과 화면에서 보증인원 시뮬레이터, 식대 체크, 양가 대화 카드, 초대 원칙 정리로 바로 이어진다.

## 2. 근거 레이어

### 2.1 S3: 참가격으로 확인 가능한 것

한국소비자원 참가격 결혼서비스 데이터는 식대, 대관료, 최소보증인원, 지역별 가격 구조를 다룬다. 따라서 C4에서 "하객 수와 보증인원은 실제 비용 조건과 연결된다"고 말할 수 있다.

허용:

- "식대와 최소보증인원은 실제 예식장 비용을 바꾸는 확인 항목이다."
- "예상 참석 인원과 보증인원 차이는 식대 손실 후보를 만들 수 있다."
- "보증인원은 업체별 계약 조건에 따라 최종 조정 가능 여부와 마감일을 확인해야 한다."

금지:

- "보증인원을 낮추면 항상 비용을 줄일 수 있다."
- "하객 수를 줄이는 쪽이 더 합리적이다."
- "참가격 데이터가 가족 초대 범위의 정답을 알려준다."

### 2.2 S4: 비용 부담과 정보 비대칭

정책 연구와 소비자보호 관점에서 결혼서비스는 비용 부담, 정보 비대칭, 계약 조건 확인이 중요한 영역이다. C4의 숫자 확인 선택지는 이 맥락과 맞는다.

허용:

- "식대, 보증인원, 최종 인원 통보 마감일은 계약 전 확인해야 할 수 있다."
- "비용 조건을 먼저 확인하는 것은 불안형이 아니라 정보 비대칭을 줄이는 방식일 수 있다."

금지:

- "숫자를 먼저 보는 사람이 결혼 준비를 더 잘한다."
- "가족 범위를 먼저 듣는 사람은 정보 확인을 덜 한다."

### 2.3 S9: 제품 자산 연결

현재 제품 코드에는 `simulateGuestGuarantee`와 계약 체크 항목이 있다. 특히 `apps/web/src/lib/amora/guestGuarantee.ts`는 예상 하객 수, 보증 인원, 1인 식대, 노쇼율, 최종 인원 통보 마감일을 받아 손실 후보와 업체 질문을 만든다. `apps/web/src/lib/amora/contractShield.ts`도 보증 인원, 1인 식대, 최종 인원 통보 마감일을 계약서 확인 항목으로 둔다.

허용:

- "C4 응답은 보증인원 시뮬레이터, 식대 체크, 양가 초대 범위 카드로 라우팅할 수 있다."
- "제품은 예상 하객 수, 보증 인원, 식대, 최종 인원 통보 마감일을 확인하도록 도울 수 있다."

금지:

- "이 기능을 쓰면 양가 갈등이 줄어든다."
- "보증인원 시뮬레이터가 최종 계약 판단을 대신한다."
- "초대 원칙 카드는 양가 설득에 성공하게 해준다."

## 3. 기존 문항 감사

기존 초안:

> 하객 수와 보증인원 이야기가 나오니 양가 생각이 조금 달라요. 나는 -

- 실제 올 사람을 기준으로 다시 계산한다
- 부모님이 생각하는 초대 범위를 들어본다
- 우리 예산에서 가능한 인원선을 정한다
- 양가에 같은 기준으로 설명할 말을 준비한다

좋은 점:

- 하객 수와 보증인원은 실제성이 높고 제품 기능과도 잘 붙는다.
- `familyIntegration`, `coupleAutonomy`, `costRisk`가 한 장면에서 드러난다.
- 커플 공유 시 "우리는 숫자부터 볼까, 범위부터 들을까"라는 대화가 열릴 수 있다.

위험:

| 위험 | 설명 | 수정 방향 |
|---|---|---|
| 갈등 전제 | "양가 생각이 조금 달라요"가 시작부터 대립처럼 보임 | "초대 범위도 같이 봐야 해요"로 완화 |
| 하객 축소 프레임 | "실제 올 사람"이 안 올 사람을 빼자는 말처럼 들릴 수 있음 | "예상 참석 인원과 보증인원 차이"로 변경 |
| 부모님 편향 | "부모님이 생각하는"이 좋은 자녀 답처럼 보일 수 있음 | "양가가 꼭 초대하고 싶은 범위와 이유"로 변경 |
| 비용만 보는 답 | "우리 예산에서 가능한 인원선"이 비용 절감처럼 보임 | "무리 없이 감당할 예산과 인원선"으로 완화 |
| 설득/통보 | "설명할 말"이 양가 설득 또는 방어처럼 보임 | "같은 기준으로 이야기할 초대 원칙"으로 변경 |
| 축 누수 | `GN`이 들어가면 도움 필요형처럼 보임 | 결과 점수에서 `GN` 제거 |

## 4. v0.5 권장 문항

질문:

> 하객 수와 보증인원을 정해야 해서, 양가가 생각하는 초대 범위도 같이 봐야 해요. 나는 먼저 -

선택지:

| 선택지 | 문장 | 측정 |
|---|---|---|
| A | 예상 참석 인원과 보증인원 차이를 먼저 계산한다 | 비용 조건과 확인 가능한 숫자 |
| B | 양가가 꼭 초대하고 싶은 범위와 이유를 들어본다 | 가족·양가 기준 확인 |
| C | 우리가 무리 없이 감당할 예산과 인원선을 맞춘다 | 커플 기준과 예산선 |
| D | 같은 기준으로 이야기할 초대 원칙을 정리한다 | 커플 기준과 가족 기준을 같은 언어로 정리 |

예비 대안:

> 하객 명단을 적다 보니, 초대 범위와 보증인원을 함께 정해야 해요. 나는 먼저 -

- 확정·가능·미정으로 나눠 예상 인원을 본다
- 양가가 꼭 챙기고 싶은 분들을 표시해본다
- 우리 예산에서 넘기 어려운 인원선을 정한다
- 같은 기준으로 볼 항목을 먼저 정리한다

예비 대안은 갈등 전제가 더 낮지만, C축의 가족·양가 조율 신호가 약해질 수 있다. 1차 후보가 너무 민감하게 읽힐 때만 테스트한다.

## 5. 채점 가중치

| 선택지 | 가중치 | 이유 |
|---|---|---|
| A | `CR+2`, `ED+1` | 보증인원과 예상 참석 인원 차이를 계산해 비용 리스크를 먼저 보는 신호 |
| B | `FI+2` | 양가가 중요하게 보는 초대 범위와 이유를 먼저 듣는 신호 |
| C | `CA+2`, `CR+1` | 커플이 무리 없이 감당할 예산선과 인원선을 먼저 맞추는 신호 |
| D | `CA+1`, `FI+1`, `ED+1` | 초대 기준을 공통 언어로 정리하는 균형+근거 신호 |

주의:

- `GN`은 제외한다. 초대 원칙을 정리하는 것은 도움 필요가 아니라 조율 방식이다.
- `ES`는 제외한다. 양가 범위를 듣는 답이 좋은 자녀 답으로 보이면 안 된다.
- `CP`는 제외한다. 이 문항은 커플 공동준비보다 가족 기준과 커플 기준의 조율 범위를 본다.
- `CR`은 A와 C에서만 쓴다. 하객 수 문항 전체를 비용 성향으로 해석하지 않는다.

## 7. 커플 공유 문구

A와 B가 갈린 경우:

> 한 사람은 보증인원과 예상 참석 인원 차이를 먼저 봐야 편하고, 한 사람은 양가가 꼭 초대하고 싶은 범위를 먼저 들어야 편해요. 오늘은 "예상 참석 인원"과 "양가가 꼭 챙기고 싶은 범위"를 따로 적어보세요.

C와 D가 갈린 경우:

> 한 사람은 우리 예산과 인원선이 먼저 맞아야 편하고, 한 사람은 같은 기준으로 이야기할 초대 원칙이 있어야 편해요. 먼저 "무리 없는 인원선"과 "초대 기준 3가지"를 나눠 적어보면 좋아요.

A/C가 강한 커플:

> 두 분은 숫자와 예산선이 보여야 하객 수 대화가 편할 수 있어요. 다만 양가가 꼭 챙기고 싶은 범위도 한 번만 따로 들어두면 기준이 덜 흔들려요.

B/D가 강한 커플:

> 두 분은 양가 초대 범위와 공통 기준이 먼저 정리돼야 마음이 편할 수 있어요. 다만 보증인원과 식대 조건도 숫자로 한 번 확인해두면 대화가 더 구체적이에요.

금지:

- "누가 더 현실적이다."
- "누가 더 가족 중심이다."
- "누가 하객을 줄이려 한다."
- "이 조합은 양가 갈등 위험이 있다."

## 8. 인터뷰 확인 질문

C4 직후 아래를 확인한다.

1. "하객 수와 보증인원"이라는 말이 바로 이해됐나요?
2. "양가가 생각하는 초대 범위"가 양가 갈등처럼 느껴졌나요?
3. "예상 참석 인원과 보증인원 차이"가 하객을 줄이자는 말처럼 들렸나요?
4. "양가가 꼭 초대하고 싶은 범위와 이유"가 좋은 자녀 답처럼 보였나요?
5. "무리 없이 감당할 예산과 인원선"이 비용만 보는 답처럼 느껴졌나요?
6. "같은 기준으로 이야기할 초대 원칙"이 대화 준비인가요, 설득/통보처럼 느껴졌나요?
7. 축의금, 체면, 부모님 지인 초대 같은 민감한 생각이 떠올랐나요?
8. 선택지 중 부모님 편/우리 편으로 갈라 보이는 답이 있었나요?
9. 이 답을 커플끼리 공유하면 대화가 열릴 것 같나요, 방어가 생길 것 같나요?

1번, 3번, 6번, 7번은 필수다. 보증인원 이해 실패, 하객 축소 프레임, 통보 프레임, 축의금/체면 민감도가 강하게 나오면 문항을 다시 쓴다.

- A 선택률 55% 이상이면 비용 확인이 모범답안처럼 보이는지 확인
- B 선택률 55% 이상이면 가족 범위 듣기가 좋은 자녀 답처럼 보이는지 확인
- C 선택률 55% 이상이면 예산선이 하객 축소처럼 보이는지 확인
- D 선택률 55% 이상이면 초대 원칙이 지나치게 성숙한 답처럼 보이는지 확인
- "하객 줄이기/체면/효도/가족 눈치" 응답 5% 초과 시 문항 실패
- "대화가 열릴 것 같다" 응답 70% 미만이면 커플 공유 문항으로 실패

## 10. 제품 라우팅

| 선택 | 자연스러운 다음 행동 |
|---|---|
| A | 보증인원 시뮬레이터, 식대 손실 후보 계산, 최종 인원 통보 마감일 확인 |
| B | 양가 초대 범위 질문 카드, 가족별 꼭 초대할 범위 정리 |
| C | 예산별 인원선 카드, 식대 총액 계산, 무리 없는 범위 표시 |
| D | 초대 원칙 카드, 양가와 이야기할 기준 정리 |

효과 검증 전까지는 "이 카드가 양가 갈등을 줄인다"고 말하지 않는다. "이렇게 정리해볼 수 있다"까지만 말한다.
