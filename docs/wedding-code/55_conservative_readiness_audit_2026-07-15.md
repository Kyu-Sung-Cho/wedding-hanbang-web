# WeddingCode 보수적 출시 준비도 재감사 — 2026-07-15

상태: **출시 차단 / Production 수집 차단 유지**

이 문서는 기존 `44_v0.5_item_set_integrity_audit.md`의 “16개 문항 통과” 결론을 독립적으로 다시
검토한 결과다. 현재 문항은 결혼 준비 대화를 위한 후보 세트이지, 사람의 웨딩 성향을 정확하게
파악한다고 주장할 수 있는 검증된 검사가 아니다.

## 1. 현재 운영 상태

- `/wedding-code`는 입력 없이 검증 준비 안내만 표시한다.
- `/wedding-code/result`는 안내 페이지로 redirect한다.
- response, pair, couple-report API는 `410 Gone`으로 닫혀 있다.
- 운영 DB의 기존 13개 행은 보존하되, write fence가 적용돼 있다.
- 인지면접 n=5, 미니테스트 n=20, 실제 커플 3쌍 검증 결과 문서는 존재하지 않는다.
- `48`, `49` 실행 문서는 RETIRED 상태이므로 Production 링크·SQL·수집 절차를 다시 사용하지 않는다.

결론: 현재 containment는 정상이며, 아래 게이트를 통과하기 전에는 수집이나 결과 화면을 다시 열지
않는다.

## 2. 근거가 말해주는 것과 말해주지 않는 것

### 현재 말할 수 있는 범위

- 한국소비자원 가격 자료와 피해예방 자료는 결혼서비스의 가격 편차, 선택품목, 추가금·계약 조건
  확인 장면이 실제 소비자 문제임을 뒷받침한다.
- 커플 재무 대화, 공동 의사결정, 사회적 지원 연구는 돈·역할·지원 순서를 대화 주제로 다루는 것이
  의미 있을 수 있음을 뒷받침한다.
- 따라서 A/C 일부 장면과 B/D 대화 장면은 제품 대화 소재로 사용할 근거가 있다.

### 현재 말할 수 없는 범위

- 위 시장 자료는 특정 선택지가 `costRisk`, `coPreparation`, `familyIntegration` 같은 구인을
  정확히 측정한다는 근거가 아니다.
- 일반 커플 연구는 이 16문항의 문항 타당도, 축 구조, 임계값, 커플 비교 공식을 검증하지 않는다.
- n=5/n=20 결과, 검사-재검사, 문항 변별도, 요인구조, 준거타당도 자료가 없다.
- 그러므로 “완벽하게 파악”, “정확한 유형”, “과학적 성향”, “궁합/성공 예측”은 모두 금지한다.

## 3. 16문항 독립 재감사

판정 기준:

- `BLOCK`: 현재 형태로 점수 문항에 사용하면 안 됨
- `REWRITE`: 같은 장면을 유지하되 질문/선택지/가중치 재설계 필요
- `INTERVIEW`: 문서상 후보로 유지 가능하지만 사람 검증 전 확정 금지

| 문항 | 판정 | 보수적 판단 |
|---|---|---|
| A1 견적서 추가금 | BLOCK | 포함 항목·추가금 확인은 소비자 안전 행동이라 취향 보기보다 객관적 정답처럼 보인다. 안전 가이드를 성향 점수로 만들지 않는다. |
| A2 오래 남을 옵션 | REWRITE | 의미·예산은 판단 기준이지만 “다른 방법 찾기”는 해결 행동, “둘 다 원하는지”는 합의 절차라 응답 층위가 다르다. |
| A3 예산보다 300만 원 초과 | REWRITE | 300만 원 고정 앵커는 지역·총예산에 따라 의미가 달라진다. 상대 비율 또는 사용자 예산 기준 장면이 더 안전하다. |
| A4 후기가 적은 업체 | BLOCK | 최근 실제 결과물 확인은 안전상 우월한 행동이고, “후기가 적어도 괜찮을지 동의”는 현실성이 낮다. |
| B1 상대가 아직 못 본 곳 | INTERVIEW | 네 선택지가 공유 방식이라는 같은 층위에 가장 가깝다. B/C 중복과 선택 난이도만 사람 검증한다. |
| B2 준비가 한쪽에 쏠림 | REWRITE | B는 같이 결정/각자 역할 두 행동을 묶고 모범답안처럼 보인다. D만 감정 지원이라 축이 섞인다. |
| B3 비교 기준이 다름 | REWRITE | A와 C가 거의 같은 분업/압축이고, D 비교표가 가장 합리적인 답처럼 보인다. |
| B4 후보 과부하 | BLOCK | D의 “오늘 더 보지 않기”는 페이스 조절이고 나머지는 후보 축소 방식이다. A가 `coPreparation` 2점을 받는 근거도 문장에 드러나지 않는다. |
| C1 부모님 음식·교통 우려 | REWRITE | C는 세 가지 지표를 묶고 D는 확인이 아니라 해결책이다. 질문의 “확인”과 선택지 행동이 맞지 않는다. |
| C2 부모님께 처음 설명 | INTERVIEW | 대화 전 준비라는 층위는 대체로 맞지만 D가 일반적 커뮤니케이션 기술로 몰릴 수 있다. |
| C3 전통 절차 간소화 | REWRITE | D의 “무엇이 달라지는지”가 모호하고, A/B는 이유 탐색, C는 분류라 선택 기준이 흔들린다. |
| C4 하객 수·보증인원 | BLOCK | 실제 참석 예상과 보증인원 차이 확인은 운영상 필수에 가까워 성향 선택지로 비교하기 어렵다. 안전/예산 계산 카드로 분리한다. |
| D1 해결책부터 말함 | BLOCK | B의 공감 후 정리가 사회적으로 이상적인 답처럼 보이고, D는 그 순간 필요한 지원이 아니라 다음 대화 규칙이다. |
| D2 준비 대화 피로 | INTERVIEW | 같은 회복 장면 안에 있으나 멈춤/감정/주제/분업 중 정답감과 상황 의존성이 큰지 확인해야 한다. |
| D3 준비 속도 차이 | REWRITE | 정서 선택지는 A 하나, 실행 선택지는 B/C/D 세 개라 지원 축이 구조적으로 불균형하다. C/D도 의미가 겹친다. |
| D4 당일 계약 혜택 | BLOCK | 총액·추가금·취소 조건 확인은 안전 행동이고, “오늘 결정해도 후회 없다는 확신”은 열등하거나 위험한 답처럼 보인다. 비점수 안전 문항으로 전환한다. |

요약:

- `BLOCK`: 6개
- `REWRITE`: 7개
- `INTERVIEW`: 3개

이는 기존 문항이 쓸모없다는 뜻이 아니다. 실제 장면 자산은 상당 부분 재사용할 수 있지만, “안전하게
해야 하는 행동”과 “사람마다 다른 우선순위”를 한 forced-choice 점수에 섞은 것이 핵심 문제다.

## 4. 채점식 구조 감사

현재 구현은 선택지 가중치를 12개 구인에 누적하고 구인별 theoretical exposure max로 나눈 뒤,
4개 공개 축의 양쪽 평균을 비교한다. 이 계산은 코드와 테스트상 일관되지만 타당도가 검증된 것은
아니다.

2026-07-15에 16개 문항을 A/B/C/D 균등 확률로 선택한 결정론적 합성 응답 50,000개를 생성해
구조 편향을 확인했다. 이 결과는 실제 사용자 분포가 아니라 **가중치/임계값의 중립성 진단**이다.

| 공개 축 | 왼쪽 | 균형 | 오른쪽 | 평균 절대 차이 |
|---|---:|---:|---:|---:|
| 결정 기준 | 42.1% | 32.6% | 25.3% | 22.3pp |
| 준비 방식 | 30.5% | 37.9% | 31.6% | 19.6pp |
| 조율 범위 | 31.9% | 37.5% | 30.6% | 23.6pp |
| 지원 순서 | 28.6% | 12.3% | 59.1% | 33.6pp |

발견:

1. 지원 순서 축은 균등 선택에서도 실행 쪽으로 크게 기운다.
2. 결정 기준도 조건 확인 쪽 비율이 의미 상상보다 높다.
3. `0~12pp`, `13~24pp`, `25pp+` 임계값은 표본으로 보정된 기준이 아니다.
4. 코드의 `confidenceBand`는 통계적 신뢰도가 아니라 단순 점수 차이다. 공개 카피에서 “신뢰도”나
   “확실함”으로 번역하면 안 된다.
5. 0~100 정규화 수치와 커플 overlap %는 백분위나 정확도가 아닌데도 사용자에게 정밀한 검사처럼
   보일 위험이 크다.

## 5. 이번 감사에서 적용한 안전 수정

- 서로 다른 candidate 버전은 동등성 자료 없이 커플 비교하지 않도록 exact-version만 허용한다.
- 비활성 결과 UI에서 개인 축 퍼센트, 커플 overlap 퍼센트, solution 카드 퍼센트를 숨긴다.
- 공개 containment와 DB write fence는 유지한다.
- 문항/가중치는 사람 검증 전에 새 후보로 확정하거나 Production에 다시 연결하지 않는다.

## 6. 재개 게이트

다음 순서를 모두 통과해야 한다.

1. `candidate.5` 문서 초안에서 소비자 안전 문항과 성향 문항을 분리한다.
2. 각 축을 3~4개 단일구인 문항으로 재구성하고 선택지 총 가중치/방향을 균형화한다.
3. Production과 분리된 연구용 화면, 동의 문구, 보유 기간, 삭제 방법을 먼저 승인한다.
4. n=5 인지면접을 수행하고 item-level 원문 메모가 아닌 익명 판정표를 남긴다.
5. 반복된 정답감/낙인/무응답 문제를 수정한다.
6. n=20을 10명씩 두 wave로 진행하고 첫 10명에서 중단 조건을 검사한다.
7. 선택지 분포, 완주율, 공유 의향뿐 아니라 축 방향 편향과 문항 변별을 본다.
8. 실제 커플 3쌍 이상에서 결과가 비난 도구가 아닌 대화 시작점으로 작동하는지 확인한다.
9. 소비자/관계 연구 또는 측정 전문가에게 문항·점수·결과 카피 검토를 받는다.
10. exact-version Preview, 모바일 320/390px, 접근성, API/DB privacy fence, rollback을 검증한 뒤에만
    Production 재개를 별도 승인한다.
