# 웨딩코드 소비자 흐름 재검토 — 2026-09-24

기준 소스: `e3ab333c229d91fb5797a36f3dfcac750c542b72`. 기본 23개와 선택 9개, 개인 결과·커플 비교·초대·재방문을 검토한다. 합성 응답과 코드·화면 검증이며 실제 소비자 조사로 해석하지 않는다.

## 확인한 문제와 수정 판단

- **하객 수의 기준**: 본인 쪽 인원과 두 사람 합계로 다르게 읽힐 수 있다. 질문을 교체하거나 기존 답의 의미를 바꾸는 대신, 새로 답하는 화면에 두 사람의 가족·지인을 합한 하객 수라는 안내를 둔다. 기존 결과는 희망 규모로만 설명하며 실제 참석·보증 인원이나 기존 답의 계산 기준을 단정하지 않는다.
- **답과 어긋나는 안내**: 하객 없이 둘만 하는 예식을 골라도 초대 명단을 권하는 공통 안내, H2의 ‘일부를 맡아주기’를 ‘나눠주기’로 줄인 조합 문구를 수정한다. 하객 관련 다른 답은 지우거나 반대 뜻으로 추론하지 않는다.
- **상태의 오해**: 맞는 보기 없음은 취향 미정과 다르다. 원래 상태를 유지하고 개인·커플 결과의 설명이 이 차이를 포함하도록 보완한다. 위임을 허용하는 답도 ‘둘 다 원한다’고 단정하지 않는 제목을 쓴다.
- **결과의 반복**: 우선순위 단일 설명과 같은 답의 조합 설명이 두 곳에 나온다. 조합을 버리는 안은 정보를 잃고, 모두 두는 안은 반복을 유지한다. 관련 조합을 우선순위 안내에서 한 번 설명하고 나머지 안내에서 중복을 제거하는 안을 우선 검토한다. 사용자가 직접 고른 우선순위 목록과 원답 근거는 보존한다.
- **느린 공유 요청과 재방문**: 요청 완료 전에 답 수정으로 이동하면 늦은 성공이 화면을 강제로 바꿀 수 있다. 화면 이탈 후 자동 이동을 막되 이미 만들어진 공유의 복구 경로는 남긴다. 생성 응답이 유실된 뒤 새로고침해도 같은 탭의 복구 주소를 볼 수 있게 하고, 성공 여부를 아직 확인하지 않았다는 점을 문구에 반영한다.
- **답 수정 화면의 중복 버튼**: 같은 결과로 돌아가는 ‘결과 보기’와 ‘수정한 결과 보기’가 함께 나왔다. 수정 화면에서는 ‘수정한 결과 보기’ 하나만 주 동작으로 제공한다. 자동 저장을 꺼도 요청 확인 주소는 현재 탭에 임시로 남는다는 설명을 추가한다.

## 유지하는 계약

문항 ID·원문·보기 값·응답 버전·23+9 구성·코드 계산·백분율 변환은 변경하지 않는다. 동시 동의가 가능하다는 이유만으로 독립 문항을 중복으로 보지 않는다. 저장된 답은 새 의미로 재해석하지 않으며 공유 동의·보유 기간·권한 범위를 늘리지 않는다.

## 적대적 검수와 주장 감사

문항, 결과 계산, 초대 흐름을 독립적으로 읽은 뒤 해당 소스 줄을 다시 확인했다. 같은 코드도 같은 취향을 뜻하지 않으며, 낮은 점수를 반대 취향으로 바꾸지 않는 계약을 유지한다. 4글자와 척도는 응답 요약이고 성격 진단·궁합·전체 웨딩 성향의 완전 측정이라는 주장을 하지 않는다. 실제 소비자의 이해도, 완주율, 만족도, 추천 의향은 미검증이다.

화면 구성은 현행 디자인 토큰과 구조를 유지한다. 질문 페이지 참고 자료는 [GOV.UK 질문 페이지](https://design-system.service.gov.uk/patterns/question-pages/)이며, 이를 현행 페이지 수가 최적이라는 증거로 사용하지 않는다. Lazyweb 현재 워크플로 조회는 요청 제한으로 자료를 받지 못했다. 별도 보고서를 생성하거나 확인하지 않은 디자인 근거를 추가하지 않는다.
