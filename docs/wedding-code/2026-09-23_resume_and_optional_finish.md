# 웨딩코드: 부담을 줄인 마지막 선택과 본인 브라우저 이어하기

2026-09-23 · 상태: **현재 변경의 설계 계약 / 구현 반영·릴리스 검증 진행 중 / 운영 배포 완료 증거 아님**

## 요청과 바뀌는 범위

사용자는 마지막 부분이 모두 적어야 하는 것처럼 느껴지고 어렵다고 피드백했으며, 로그인하지 않아도 같은 브라우저에서 답을 자동저장하고 이어서 하기를 요청했다. 어려웠던 지점이 우선순위·지출 선택·결과 메모 중 어디인지는 특정하지 않았다. 세 영역 모두 입력 부담을 낮출 수 있어 현재 문항의 의미를 바꾸지 않는 개선을 적용했다.

현재 v3.1의 33번은 앞서 고른 문장·취향·회피 조건을 최대 36개 후보로 다시 보여준다. 34번은 지출 항목 여섯 가지를 고른다. 결과 자유메모는 필수가 아니지만 기존에는 입력창이 항상 노출됐다. 후보 수와 상태는 `constants/weddingCodeV31.ts`, `getV31PriorityOptions`, `WeddingCodeV31Client`, `WeddingCodeV31Inputs`, `WeddingCodeV31Results`에서 확인했다. 이 구조가 실제 소비자에게 얼마나 부담스러운지는 측정하지 않았다.

## 검토한 대안과 선택

| 대안 | 얻는 것 | 부담·제약 | 결정 |
|---|---|---|---|
| 마지막 추가 선택을 접고 넘어가기를 먼저 제공 | 결과를 보기 위해 긴 후보 목록을 다시 읽지 않아도 된다. | 더 세밀한 우선순위는 원하는 사람이 직접 선택해야 한다. | 채택. 기존 입력값과 결과 의미를 보존하는 최소 변경이다. |
| 후보를 주제별로 나눠 단계적으로 선택 | 한 화면의 후보 수를 줄인다. | 여러 주제를 열고 다시 비교하는 단계가 생긴다. | 이번 기본 흐름에는 추가하지 않는다. |
| 앞 질문마다 ‘꼭 지킬 것’ 표시 | 마지막 재선택을 줄인다. | 답할 때마다 추가 판단이 생기고 진행 중 우선순위 교체가 필요하다. | 이번 범위에서 제외한다. |

높은 동의 점수에서 상위 세 개를 자동으로 골라 주는 방식은 사용하지 않는다. 문장에 동의하는 정도와 실제로 먼저 지킬 우선순위는 같은 정보가 아니다.

## 마지막 부분의 응답 계약

총 34단계와 질문·보기·공유 값의 뜻은 유지한다. 편해진 조작을 완료된 성격검사나 더 정확한 측정이라고 설명하지 않는다.

- **33번 우선순위:** 후보는 기본적으로 접는다. 원하는 사람이 직접 선택 영역을 열며, 명시적으로 넘어가는 동작을 제공한다. 넘어가기를 누르면 `skipped`로 기록한다. ‘특히 지킬 것이 없음’이나 ‘아직 모름’으로 대신 저장하지 않는다. 이미 고른 답이 있으면 현재 선택을 보이고, 접거나 재방문하는 것만으로 답을 지우지 않는다.
- **34번 지출 희망:** ‘더 쓰고 싶은 곳은 지금 없어요’와 ‘아직 모르겠어요’를 긴 설명이나 전체 보기 아래에서 찾지 않아도 되게 한다. 전자는 명시적 지출 희망 없음, 후자는 미정이다. 다른 곳의 비용을 줄여 더 쓰고 싶은 항목이라는 질문의 뜻과 최대 두 개 선택은 유지한다.
- **결과 자유메모:** 선택 사항임을 밝힌 접힌 영역에서만 입력창을 연다. 적지 않아도 개인 결과·커플 비교·공유를 이용할 수 있다. 메모는 이번 자동저장이나 공유 값에 넣지 않는다.
- 우선순위를 건너뛴 결과에는 본인이 확인하지 않은 우선순위를 만들지 않는다. 기존 답에서 설명할 수 있는 취향·준비 방식·커플 비교는 계속 보여준다.

## 저장 계약의 명시적 변경

이전 기본 v3.1은 서버·계정·브라우저 저장소에 답을 남기지 않는 계약이었다. **이번에는 사용자의 비로그인 자동저장 요청에 따라, 기본 v3.1의 본인 브라우저 보관만 명시적으로 허용한다.** `2026-09-23_v31_clarity_contract.md`와 이전 통합 문서의 일괄 브라우저 비저장 설명은 당시 계약의 기록이며, 아래 좁은 범위에서는 이 문서가 후속 기준이다.

이 변경은 기존 구판의 응답 뜻·저장 계약, 별도 취향 도구, 로그인된 웨딩라운지의 선택 저장, 연구 답 보태기, Candidate 6.3 연구 차단을 바꾸지 않는다. 공개 응답의 서버·계정 저장을 새로 열거나 상대 답의 소유자를 추정하는 근거도 아니다.

| 구분 | 현재 변경의 계약 |
|---|---|
| 목적 | 같은 브라우저에서 본인이 작성하던 답과 진행 위치를 이어서 사용한다. 로그인이나 계정 연동을 요구하지 않는다. |
| 저장하는 내용 | 이 화면에서 직접 작성하거나 명시적으로 불러온 본인 응답, 현재 단계, 수정 상태 등 이어하기에 필요한 상태. |
| 저장하지 않는 내용 | 서버·계정의 응답 복제, 상대의 답, 받은 두 사람 결과, 공유 동의, 자유 메모. 다른 서비스·연구·AI로 자동 전달하지 않는다. |
| 위치 | 같은 브라우저의 로컬 저장소. 다른 브라우저·다른 기기·계정 간 동기화를 약속하지 않는다. |
| 기한 | 마지막으로 응답·진행 변경을 실제 저장한 시각부터 30일. 단순히 읽거나 다시 방문했다는 이유로 기한을 새로 시작하지 않는다. 만료된 답은 이어하기에 사용하지 않는다. |
| 이용자 안내·제어 | 시작 전에 자동저장과 공용 기기 유의사항을 안내한다. 켜기·끄기·저장 답 지우기·재방문 시 명시적인 이어하기를 제공한다. |
| 공유 | 저장된 답이 있어도 공유 동의는 매 방문 다시 확인한다. 답 보관과 공유 허가는 별개의 동작이다. |
| 실패·충돌 | 저장 불가·읽기 오류·다른 탭의 변경을 숨기고 저장 완료라고 말하지 않는다. 오래된 탭의 저장으로 지운 답을 되살리거나 새 답을 조용히 덮지 않는다. |

브라우저 보관은 로그인으로 본인 여부를 인증하는 기능이 아니다. 같은 브라우저를 함께 쓰는 사람에게 답이 보일 수 있으므로 시작 전에 알리고 끄기·삭제 동작을 제공한다. 브라우저 데이터 삭제나 저장 제한이 있는 환경에서 복원을 보장하지 않는다.

**자동저장 끄기**는 저장된 답을 즉시 지우고 이후 자동저장을 중단한다. 브라우저에는 꺼짐 설정만 남기며, 현재 화면의 답은 메모리에 유지해 계속 진행할 수 있다. **저장된 답 지우기**는 저장 기록과 현재 진행을 함께 초기화한다. 두 동작의 차이는 화면에서도 알리며, 지연된 저장이나 오래된 탭이 삭제를 되돌리지 않아야 한다.

## 공유 판과 결과 의미

`v3.1-preferences`의 문항·보기·응답 코드·비교 의미는 바꾸지 않는다. 후보를 접는 화면 배치와 선택을 건너뛰는 명시적 동작은 기존 `skipped` 상태를 이용한다. ‘지출 희망 없음’, ‘어느 쪽도 괜찮음’, ‘아직 모름’, ‘해당 없음’, ‘건너뜀’은 계속 구분한다.

로컬 이어하기의 보관 형식과 응답 공유 판은 별개다. 저장 형식을 검증할 정보는 두되, 임의의 과거 저장값을 현재 문항의 새 답으로 바꾸어 해석하지 않는다. 받은 링크의 응답은 기존 판으로 해석하고, 브라우저에 남긴 본인 답 때문에 받은 링크의 의미가 바뀌지 않아야 한다.

## 고지·문서·검사 정합성

- 현재 기본 진입의 ‘새로고침하면 진행 중인 답은 사라진다’는 안내와 이를 요구하는 `app/wedding-code/page.test.tsx`는 새 계약에 맞춰 함께 바꾼다. 서버·계정 비저장 안내는 유지한다.
- `/privacy`의 공개 웨딩코드 설명에는 서버 비저장과 별개로 같은 브라우저의 본인 응답 보관·기한·끄기·삭제·공용 기기 범위를 구분해 설명한다. 연구 답 보태기와 기존 계정 저장 설명을 같은 기능으로 합치지 않는다.
- v3.0·v2.0·장면형 구판과 별도 취향 도구의 비저장 안내는 해당 구현의 계약이므로 일괄 치환하지 않는다. 자유메모 비저장 안내도 유지한다.
- 이 문서는 설계 선택과 기대 동작을 고정한다. 테스트 개수·통과·배포 식별자·운영 반영 여부는 실제 실행 후의 해당 영수증과 PR·운영 관측으로 별도 확인한다.

## 검증할 시나리오와 남는 한계

검증 대상은 새로고침 후 중간 답·수정 상태 복원, 완료 후 본인 결과 복원, 명시적 우선순위 건너뛰기, 이미 선택한 우선순위 보존, 지출 없음·모름 구분, 메모 미작성 완료, 만료와 단순 읽기 시 기한 비연장, 자동저장 제어와 삭제, 저장 실패·교차 탭 충돌, 초대 링크의 명시적 본인 답 불러오기, 받은 두 사람 결과의 개인 저장 격리, 공유 동의 초기화, 구판 링크 호환이다. 이 목록을 작성한 것이 각 시나리오의 통과 증거는 아니다.

실제 소비자의 마지막 선택 부담·이해도·재미·유용성·수요, 실기기 사용성, 심리측정 타당도와 모든 웨딩 성향의 포괄성은 검증했다고 주장하지 않는다. 자동저장은 입력 복구 기능이며 결과 해석의 정확도를 높였다는 근거가 아니다.

## 구현 검수에서 보완한 경계

- 다른 탭에서 삭제한 뒤 불러올 답이 없을 때 자동저장을 다시 켜지 않는다. 새로 불러온 답도 이후 다른 탭 변경으로부터 보호한다.
- 복원 버튼을 누르는 시점에 저장 기한·꺼짐 설정·삭제 여부를 다시 읽는다. 소개 화면을 오래 열어 둔 경우에도 처음 읽은 캐시만으로 복원하지 않는다.
- 저장소 접근이나 삭제가 실패해도 현재 화면은 새로 시작할 수 있게 하고, 저장된 기록을 지웠다는 주장은 하지 않는다. 초대 링크를 벗어나 새 화면으로 바뀌어도 삭제 실패 안내를 유지한다.
- 우선순위를 고르지 않았을 때는 비활성 다음 버튼을 중복으로 보여주지 않는다. 결과에서도 건너뜀을 선택한 우선순위처럼 목록에 넣지 않는다.

이 경계의 회귀 검사와 변형 검증, 전체 검사 및 실제 브라우저 관측은 해당 PR과 `.verification/` 실행 기록에서 확인한다. 기존 배포의 검사 영수증을 이번 변경의 통과 증거로 사용하지 않는다.
