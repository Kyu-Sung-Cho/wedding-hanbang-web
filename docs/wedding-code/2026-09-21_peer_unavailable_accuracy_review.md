# 상대 이용 불가 상태의 개인 결과 보존

2026-09-21. 사용자의 정확성 재점검 요청에 따른 추가 검수다. 문항·보기·집계·역할 해석은 변경하지 않는다.

## 확인한 문제

상대의 탈퇴 작업이 접수됐지만 기존 프로필·커플 연결이 아직 남아 있으면, 준비 스타일 RPC는 본인 답을 유지하면서 `partnerUserId`를 null로 돌려준다. 일반 계정 조회는 아직 기존 상대를 반환할 수 있다. 클라이언트가 두 응답의 상대 ID 차이를 모두 오류로 처리해, 남은 사람의 개인 결과도 볼 수 없었다.

운영 고객에게 이 상태가 발생했는지는 조회하지 않았다. SQL과 계정 조회 경로를 대조해 발견했으며, 해당 상태를 재현하는 클라이언트 검사를 추가한다.

## 대안과 선택

1. 일반 계정 조회에서 탈퇴 중 상대를 필터링: 서비스 전체 인증 상태에 영향이 있으며 이미 열린 화면의 오래된 상태는 여전히 남을 수 있다.
2. 같은 본인·같은 커플 응답에서 서버가 상대를 없다고 확인한 경우 개인 결과만 수용: 준비 스타일의 실제 권한을 재확인한 응답을 사용한다. 이 방법을 선택한다.
3. 상대 ID 검사를 모두 제거: 다른 상대의 응답을 오래된 이름 아래 보여줄 수 있어 사용하지 않는다.

현재 계정·커플 검사는 그대로 유지한다. 기존 상대와 다른 유효 ID는 계속 거부한다. 상대가 없는 응답에는 공유 허가와 상대 답이 없다는 기존 파서 조건도 유지한다. 일반 계정·연결 변경 시 화면을 새로 만들고 지연 응답을 버리는 경계는 유지한다.

## 안내 문구 검수

상대 이용 불가 원인은 응답에 없으므로 “상대가 탈퇴했어요”라고 추정하지 않는다. 기존 빈 상태 위치에서 “지금은 둘이 함께 볼 수 없어요”, “내 결과는 계속 볼 수 있어요. 연결 설정에서 현재 상태를 확인해 주세요.”로 안내한다. 공유 버튼과 열려 있던 공유 확인은 닫고 개인 결과·다시 답하기·개인 저장·삭제는 유지한다.

이 문구는 현재 비교 가능 여부만 말한다. 탈퇴 이유·복구 시점·두 사람의 관계를 설명하지 않는다. UI 디자인·문항 판·DB 권한·API 형식은 바꾸지 않는다.

## 검증 기준

- 기존 계정 상태에 상대가 있어도 RPC가 상대 없음으로 반환하면 개인 결과를 보여준다.
- 이미 보던 커플 결과와 공유 확인은 새 조회에서 상대가 없어지면 남기지 않는다.
- 그 상태에서도 본인 답을 새로 저장할 수 있다.
- 다른 계정·커플·새로운 상대의 응답은 계속 거부한다.
- 회귀 검사의 실패/성공과 실제 변형 검출, 저장소 필수 검사 및 빌드를 확인한다.

## 증거와 한계

수정 전 재점검: DB·API·화면 경계 검사 4파일 51건 통과, native PostgreSQL의 합성 커플 저장·상호 공유·철회·삭제 검사 통과. 이 기존 검사들이 발견한 연결부 오류를 다루지는 않았으므로 새 회귀 검사가 필요하다.

실제 소비자의 문항 이해도·몰입도, 실제 커플 계정의 공동 사용, 실제 iOS·Android 기기는 미검증이다. 브라우저의 운영 준비 스타일 접근은 로그인 화면으로 이동했다. 테스트 계정 두 개의 가용성을 사용자에게 물었으며 비밀번호는 요청하지 않았다. 합성 DB나 모킹된 화면을 실제 계정 종단 검증으로 표현하지 않는다.

수정 전 새 검사에서는 개인 결과 보존 3개 경로가 예상대로 실패했다. 수정 후 해당 화면 검사 21개가 통과했다. 같은 상대·같은 revision이 돌아와도 이전 공유/철회 확인은 되살아나지 않는 경우를 포함한다. 원래의 상대 ID 비교 복원, 오래된 계정 상대 사용, 확인창 폐기 누락, 새 상대 검사 제거의 의미 변형 4개도 모두 검사에서 실패했고 파일 복원을 확인했다.

별도 수기 기준표로 문항 계산을 대조했다. 유효 단일 선택 57개, 문항별 유효 순서쌍 177개(건너뜀 포함 311개), 각자 한 문항씩 답하는 3,249쌍, 축별 답·건너뜀 전체 조합 4,972개에서 계산 불일치를 찾지 못했다. 모든 20문항 커플 응답 벡터를 전수검사한 것은 아니며 사람의 이해도·타당도 검증도 아니다.

전체 저장소 실행 결과와 운영 반영은 릴리스 PR의 정확한 커밋·검사·배포·운영 관측으로 기록한다. 이 문서 자체는 전체 검사·배포 완료 증거가 아니다. 전체 검사가 끝난 동일 소스를 push할 때 중복 pre-push 실행을 생략한다면 AGENTS.md의 허용 경로를 사용하고 PR에 남긴다.
