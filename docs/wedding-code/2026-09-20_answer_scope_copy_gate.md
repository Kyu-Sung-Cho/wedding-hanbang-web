# 응답 범위와 취향 선택 안내 보완

2026-09-20. 코드 반영 전 원고·집계 검토. 직전 재검수에서 찾은 A4 결과 표현 불일치와 옷 취향 선택 기준을 고친다. 현재 구현·배포 여부는 아래 실행 기록으로 별도 확인한다.

## 문제와 선택한 대안

| 대상 | 직접 확인한 문제 | 검토한 대안 | 채택 |
|---|---|---|---|
| v1.2 A축 | A4는 ‘가장 자세히 볼 것’을 묻는다. 가격을 먼저 훑고 사진을 더 자세히 볼 수 있으므로 결과에서 ‘먼저’를 단정할 수 없다. | A4 질문을 ‘먼저’로 바꾸고 새 판을 발행 / 결과 전체를 실제 관심 대상으로 한정 | 후자. 기존 질문·응답 의미를 보존한다. |
| 취향 v2 옷 | 깔끔하고 하늘하늘한 한복은 세 보기에 해당하지만 최대 두 개다. 추리는 기준 안내가 없다. | 속성별 질문 분리 / 모두 선택 허용 / 기존 제한 안에서 특히 원하는 것을 고르도록 안내 | 세 번째. 질문 수·보기·공유 값·최대 개수를 바꾸지 않는다. |

## 반영할 원고

- v1.2 A축 이름: ‘정할 때 살펴볼 것’.
- v1.2 V/M의 짧은 이름: ‘비용·조건’ / ‘분위기·경험’.
- V 설명: ‘비용이나 서비스 내용을 확인하는 답을 더 많이 골랐어요’.
- M 설명: ‘사진과 공간의 모습, 그날의 경험과 남길 기억에 관한 답을 더 많이 골랐어요’.
- 결과 제목·개수·배지·비교·후속 대화는 같은 이름을 사용한다. 선택한 답의 시간 순서를 임의로 설명하지 않는다.
- 반복 연결문은 ‘총액이나 예산, 돌려받을 돈을 확인하는 답’, ‘사진이나 영상, 공간의 모습을 살펴보는 답’, ‘그날의 경험이나 나중에 간직할 기억에 관한 답’으로 좁힌다.
- 부분 부재 문장은 ‘…부터 보는 답’ 대신 ‘…에 관한 답’으로 쓴다. 답을 고르지 않은 것을 실제 준비에서 확인하지 않았다는 뜻으로 바꾸지 않는다.
- 취향 v2 옷 안내: ‘여러 개가 맞으면, 특히 원하는 것 두 개까지 골라 주세요.’

후속 대화에서 앞으로 무엇부터 할지 제안하는 문장은 유지할 수 있다. 제거 대상은 사용자가 무엇을 먼저 보았다고 단정하는 표현이다. 옷 안내에서 고른 순서를 중요도 순위로 해석하지 않는다.

### 후속 대화의 효과 단정 추가 검수

활성 카드의 ‘얘기가 쉬워져요’, ‘다시 따질 일이 줄어요’, ‘헤매지 않아요’, ‘헷갈리지 않아요’는 실제 효과를 확인하지 않고 결과를 보장한다. 표현을 ‘도움이 될 수 있어요’로 약화하는 안과, 실제로 할 대화만 남기는 안을 비교해 후자를 채택한다. v1.2 전용 후속 카드에서 다음 원고를 사용한다.

- 분위기·경험: ‘결혼식 영상일 수도 있고 드레스일 수도 있어요. 각자 하나씩 적어 와서 왜 그게 좋은지 얘기해 보세요.’
- A 한 표 차이: ‘남은 일 하나를 놓고 비용·조건에서 확인할 것과 분위기·경험에서 원하는 것을 하나씩 적어 보세요. 둘의 생각이 다르면 그 항목부터 얘기해 보세요.’
- 마음 도움: ‘얘기를 들어 주기, 같이 산책하기처럼 구체적으로 말해 보세요. 실제로 힘든 날에는 그날도 같은 도움이 필요한지 다시 물어보세요.’
- 도움 한 표 차이: ‘부모님 얘기는 들어 주기, 업체 연락은 같이 정리하기처럼 적어 보세요. 적은 걸 서로 보여 주고, 그날 필요한 도움이 무엇인지 물어보세요.’

공통 구판 상수는 바꾸지 않는다. 좋은 관계나 대화 성공을 단정하는 새 해석을 붙이지 않는다.

## 적대적 검수와 집계 gate

- A4의 보기끼리 구분은 유지된다. 배점·네 글자·소문자 기준·질문과 답의 원문·공유 형식·연구 수집 허용 판은 바꾸지 않는다.
- 문항 판을 올리지 않는다. 이미 답한 문장의 뜻을 바꾸는 변경이 아니라, 결과에서 근거 없는 시간 순서 해석을 제거하는 보정이다.
- 구판 v1.1 이전은 기존 문구로 재현한다. 취향 v1의 질문·보기도 보존한다. 판 정보 없는 코드 소개는 개별 응답 추론을 하지 않는 기존 경계를 유지한다.
- 반반·부분 응답·단일 응답·전부 미응답에도 같은 범위 제한을 적용한다. 단일 응답으로 반복 성향을 만들지 않는다.
- 모든 웨딩 성향·잠재 성격·본인도 모르는 내면을 알아낸다고 주장하지 않는다. 지금 답한 선택에서 관심 대상, 준비 역할, 부모님 참여, 원하는 도움과 건넬 말을 정리하는 도구다.
- 내부 검수는 실제 사람의 이해도·몰입도·유용성 입증이 아니다. 문항을 늘리거나 결과를 더 단정적으로 써서 이 한계를 숨기지 않는다.

원문 재검수와 위 반례에 근거해 수정 방향은 내부 gate 통과다. 코드 반영 이후 결과 전파 경로와 구판 보존을 별도로 검증한다.

## 실행 기록

코드 반영 후 관련 11개 검사 파일·350개 검사가 통과했다. 웹 타입 검사와 canonical 웹 빌드도 종료 코드 0이었다. 빌드는 저장소의 `verify-local.mjs`에 정의된 정적 검증용 환경과 `build` 명령을 그대로 사용했다. 운영 인증·DB 저장을 검증한 빌드가 아니다.

결과 순서 표현·짧은 이름·부분 부재·후속 대화·커플 제목을 되돌리는 고장 6개를 주입해 모두 탐지했고, 원본 복원을 확인했다. 기존 검사 확장으로 실제 A4 응답, 반반·미응답·단일·소문자, 구판 결과를 확인했다. 새 안내 한 문장을 그대로 비교하기 위한 별도 검사는 만들지 않고, 기존 옷 선택 제한 검사와 브라우저를 사용했다.

새 빌드에서 A4-A와 A4-D만 답한 합성 두 사람 링크를 열어 새 축 이름·두 글자 이름·각자 1응답 집계·원문 인용을 확인했다. 같은 답 기호의 v1.1 링크는 옛 장면과 이름을 유지했다. 375px와 320px viewport에서 비교 화면의 문서 폭과 스크롤 폭이 같았다(각각 360px, 305px). 경고·오류 로그는 없었다.

취향 v2에서 옷을 골라 새 안내를 읽고 두 항목을 선택했다. 나머지가 비활성화되는 기존 제한이 유지됐고 375px viewport에서 가로 넘침이 없었다. 스크린샷은 작업의 브라우저 출력에 있다. 로컬 증거는 `.audit-output/consumer-reaudit-20260920/`와 `.verification/guard-proofs.json`에 남겼다.

문항·보기·weights·NEXT_STEPS는 배포 기준 `dcdc15f0`과 원문이 동일하다. 제품 소스·검사 9개를 해시로 고정했다. 전체 관문·PR CI·운영 배포는 후속 실행 결과로 확인하며 이 부분 검증을 그 완료로 쓰지 않는다.

미검증 범위: 실제 소비자의 문항 이해도·몰입도 및 커플 사용성, 운영 DB 전송·삭제, 실제 로그인 계정의 설정 저장, 실제 iOS·Android 기기 및 외부 브라우저의 새 탭 동작.

배포는 정상 PR·필수 코드 검사·기존 Vercel Git 연결 경로를 사용한다. DB·Storage·운영 플래그·보호 설정은 바꾸지 않는다. 운영 이상이 생기면 해당 변경을 되돌리는 PR로 이전 제품으로 복구한다.
