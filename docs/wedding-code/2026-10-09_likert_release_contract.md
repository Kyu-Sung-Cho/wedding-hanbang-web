측정 `likert-preferences-alpha.1`, 문항 `preferences-20261008-r2`, 현재 표현 `likert-letters-alpha.4`. 원래 25파일 manifest `cb040a9c51a07917ec6f54f2e7acea38fe5d99ae952d8442dd87765ade8ea266`는 2026-10-08 인수본의 증거다. 최종 통합본의 해시나 Git commit SHA가 아니다. 문항·계산을 유지한 표현 수정과 이후 통합 변경에는 새로운 파일 manifest가 필요하다.

## 반영 범위

후속 요청에 따라 alpha.4는 기존 8줄 활용 설명을 실제 장면별 원답 관찰과 짧은 자기 확인으로 보완했다. 도움·휴식의 네 원답을 함께 읽고, 같은 코드·비율의 다른 장면 차이를 보존한다. 캐릭터는 놀이 별명으로 소개하며 근거 질문/원답은 펼쳐 볼 수 있다. 문항·장면·은행 순서·척도·계산·캐릭터 대응은 유지하고 동일 은행 alpha.1/2/3의 원답과 날짜·진행 위치를 보존해 표현만 메모리에서 갱신한다. alpha.3에는 이번 표현 보완만 안내한다. [alpha.4 계약](./2026-10-09_likert_alpha4_result_copy_contract.md)에 반례와 검증 범위를 적으며 09227의 이전 성공을 새 수정본 성공으로 사용하지 않는다.

- 기본 `/wedding-code`는 30문항·12장면 개편본으로 열린다. 명시적 구판 쿼리나 fragment는 기존 parser·문항·계산으로 읽는다. `/wedding-code-next` 링크도 유지한다.
- 네 주제의 여덟 고정 글자 C/E, J/T, O/U, L/A와 16개 형용사+동물 조합은 정적 대응이다. 모호하거나 부족한 답으로 글자를 채우지 않는다.
- 방향별 비율은 해당 방향의 4·5 응답 수 / 해당 방향의 1~5 응답 수다. 분자·분모, 반올림과 결측 제외를 알린다. 양쪽 100%도 허용하고 분모 0을 0%로 표시하지 않는다. 대표 글자의 장면 표와 비율은 다른 계산이다.
- 12장면마다 관찰한 답 → 조건 안의 가능한 읽기 → 실제 문항·답 → 자기 확인 → 동의한 답에 한한 요청 초안을 제공한다. 결과와 파트너 조언은 캐릭터보다 원답을 우선한다.
- L은 **준비 직후 상대가 내 이야기를 들어주는 도움을 받고 싶은 마음**이다. 사실 전달도 포함한다. T는 기준 아래 초기 후보 분담 방식을 받아들일 수 있다는 답이며 욕구·능력·결정권으로 확대하지 않는다. O/U는 가족과 둘의 기준을 확인·정리하려는 답이며 대화 순서·최종 권한을 정하지 않는다.
- 필수 반례: 같은 CJOL·세심한 수달이어도 A의 세 장면 경청과 B의 업체 연락 뒤 정리·혼자 쉬기 요청을 개인/파트너 화면에서 다르게 설명한다. 혼자 쉬기를 관계 회피로 해석하지 않는다.
- 모름·비해당·건너뜀·미응답·중립과 양쪽 높은/낮은 답, 장면 차이를 보존한다. 현실 제약을 성격으로 단정하지 않는다.

## 저장·공유·개인정보

본인 답·진행 위치만 이 판의 독립 키에 30일 저장한다. 끄기는 저장값을 제거하되 현재 답을 유지한다. 지우기는 이 판의 저장과 현재 답만 초기화한다. 구판 키·받은 답·전달한 링크는 건드리지 않는다. 읽기나 재개로 갱신하지 않으며 잘못된/만료 자료도 사용자 삭제 전 원본을 보존한다. 공유 동의와 상대 답은 저장하지 않는다.

독립 검수에서 자동 저장 켜기가 원본 보호를 풀 수 있던 경로를 찾아 수정했다. 원본 보호와 저장소 오류는 별도 상태다. 설정 켜기는 원본 보호를 풀지 않으며, 끄기나 명시 삭제도 실제 제거가 확인되어야 보호를 해제한다. 읽기 오류·삭제 실패에도 원본과 현재 답을 보존하고, 정상 빈 저장소의 쓰기 오류는 재시도할 수 있다. 해당 변경 전 전체 검사 실행은 중단했으며 최종 수정본의 새 검증을 따로 남긴다.

링크는 두 동의를 확인한 뒤 로컬에서 만든다. 초대 코드·로그인은 필요 없고 자동 전달도 없다. 상대가 두 사람 링크를 직접 돌려주는 절차를 세 단계로 안내한다. 수정 후 재공유는 새 동의를 요구하고 원래 링크는 고정 상태로 남긴다.

공개 `/wedding-code`와 `/wedding-code-next` 및 하위 경로에서는 브라우저 PostHog/Sentry 초기화·전송을 막는다. 기존 SDK가 다른 화면에서 초기화된 경우에도 Sentry 최종 transport에서 세션/client_report 포함 전체 envelope를 차단하고 지연된 보호 주소도 거절한다. 서버·edge의 기존 정제 경계와 구별해 고지한다. 이 소스/단위 검사는 운영 번들의 실제 outbound 검증을 대신하지 않는다. PR #486의 미해결 전송 검증 보류도 #473 병합만으로 해결됐다고 판단하지 않는다.
