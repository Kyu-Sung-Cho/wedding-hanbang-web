# 묶음 질문·양방향 결과 흐름 계약

상태: 구현·검증 중. 완료·배포·소비자 검증의 증거가 아니다.

## 사용자 문제와 선택

2026-09-23 사용자는 매 질문마다 다음 버튼을 누르는 부담, 상대를 초대한 두 사람이 각자 결과와 함께 준비할 기준을 모두 보는 흐름을 개선하도록 요청했다.

한 문항은 집중하기 쉽지만 이동이 반복되고, 다섯 문항 이상은 좁은 화면에서 답과 문장을 혼동하기 쉽다. 짧은 동의 문장은 최대 세 개로 묶고, 선택지가 많거나 응답 방식이 달라지는 취향·마무리 질문은 독립 화면을 유지하는 후보를 적용한다. 세 개가 최적이라는 실사용 증거는 없으며 실제 소비자 완주·이해도는 별도 검증한다.

## 질문·계산 보존 관문

- v3.1 원문·선택지 의미·문항 ID·고정 응답 직렬화·코드 계산은 그대로다. 페이지는 표시 묶음일 뿐이다.
- 질문 순서를 유지한다. 기본·선택 동의 질문만 최대 세 개, 선택형 질문과 구판 전체 흐름·결과에서 한 답 수정은 한 개씩 보여준다.
- 하나를 골라도 자동으로 페이지를 넘기지 않는다. 페이지 안의 모든 응답을 명시적으로 고른 뒤 다음으로 간다. 모름·계획 없음·건너뜀도 독립된 선택이며 중간값으로 바꾸지 않는다.
- 모든 응답을 즉시 기존 본인 브라우저 저장에 반영한다. 기존 canonical index를 유지하여 구판 진행을 복원하며, 페이지 중간에 나가도 앞서 답한 항목을 보존한다.
- 이전 페이지·새로고침·결과 수정·선택 질문 조기 종료·누락 이동을 실제 상호작용으로 검사한다. 선택 표시만 색에 의존하지 않는다. 모바일에서 선택지 원문과 질문별 라벨·터치 영역을 유지한다.

## 두 사람 결과 목표와 현재 경계

변경 전 v3.1은 A의 답을 담은 초대 링크를 B가 열고, B가 완료하면 두 답을 비교한다. A에게 자동으로 전송되지 않으며 B가 동의 후 두 사람 결과 링크를 다시 보내야 한다. 이를 자동 연결이라고 표현하지 않는다.

자동 연결의 목표는 각자 독립 응답 → 각자 공유 동의 → 두 참여자만 같은 비교 결과 확인이다. 결과 저장·조회·삭제·만료·권한과 운영 릴리스 근거가 확보되기 전에는 자동 연결을 제공한다고 표시하지 않는다. 기존 v1.2 계정 저장 계약이나 다른 목적의 테이블에 v3.1 답을 끼워 넣지 않는다.

## 서버 비교 세션 설계 관문

로그인·기존 커플 연결을 강제하는 안, 수동 왕복 링크 안내만 보완하는 안, 별도 만료형 비교 세션을 비교했다. 무로그인 응답과 양쪽 자동 결과 확인을 함께 만족시키는 세 번째 안을 채택한다. 실명 확인 기능은 아니며 초대 링크를 먼저 사용하는 사람이 참여한다는 범위를 알린다.

- 결과에서 각자 명시적으로 서버 보관·상대 공유를 선택할 때만 본인 v3.1 응답 스냅샷을 보낸다. 평상시 답하기·자동저장은 기존 본인 브라우저에 한정한다.
- 비교 세션은 생성부터 7일간 조회할 수 있다. 이는 법정 기간이 아니라 이 기능의 제품 선택이다. 만료 즉시 읽기를 차단하고 별도 매일 정리 작업으로 만료 후 24시간 안에 저장 내용을 제거한다.
- 처음 답한 사람의 접근 토큰, 일회 초대 토큰, 참여자의 접근 토큰을 각각 256비트 난수로 분리한다. DB는 토큰 원문 대신 해시를 보관한다. 토큰·답은 URL query나 로그에 넣지 않는다. 초대 URL에는 답이 없고 fragment의 일회 참여 권한만 있다.
- 초대를 열기만 해서는 상대 답을 반환하지 않는다. 자신의 응답과 공유 동의를 제출해 참여가 성립한 뒤에만 두 답을 반환한다. 두 번째 슬롯은 원자적으로 한 번만 할당하며 동일 요청 재시도만 허용한다.
- 각 참여자는 별도 본인 접근 권한으로 조회·연결 종료할 수 있다. 종료 시 두 응답을 즉시 지우고 늦은 참여·재전송을 차단한다. 재시도로 종료된 세션을 되살리지 않는다.
- 공유한 스냅샷을 몰래 갱신하지 않는다. 답을 바꿔 다시 비교하려면 현재 연결을 종료하고 새 답으로 새로 동의한다. 기존 fragment 공유 링크는 변하지 않으며 별도 경로로 유지한다.
- 본인 결과 화면이 열려 있을 때 제한된 상태 조회로 상대 완료를 반영한다. 닫힌 브라우저에 알림이 도착한다고 약속하지 않는다. 초대 링크와 본인 확인 링크·권한을 혼동하지 않게 분리한다.
- 서버는 요청 크기·출처·빈도·동의 버전·정규 v3.1 codec·기본 응답 완료를 검증하고 캐시를 금지한다. 테이블은 직접 접근 기본 거부, 좁은 서버 전용 RPC만 허용한다. 읽기·claim 경합·만료·철회·재생·ACL을 native PostgreSQL에서 검사한다.
- 기존 237 릴리스 원문을 보존한 정확한 238 후속 릴리스에서 정적 관문·합성 실행·inspect·rollback rehearsal·apply·별도 readback 증거를 확인한 뒤에만 운영을 연다. 기존 포괄 readiness의 실패를 우회하거나 권한을 느슨하게 바꾸지 않는다.

설계 관문: 위 범위의 신규 구현을 진행한다. 이 문단은 테스트·DB 적용·배포 성공을 뜻하지 않는다.

결과는 본인·상대의 실제 응답, 공통으로 원하는 것, 차이, 아직 비교할 수 없는 것, 함께 이야기할 다음 단계로 연결한다. 신원이 확인되지 않은 수신 링크에서는 ‘먼저 답한 사람 / 나중에 답한 사람’을 유지하고 임의로 나와 상대를 배정하지 않는다. 원하지 않는 것을 고르지 않았다는 이유로 반대 취향으로 추정하지 않는다. 제안은 합의나 확정 결정으로 저장하지 않는다.

## 근거와 주장 감사

- GOV.UK Question pages: 한 질문에서 시작하되 관련 질문 묶음은 사용자 검증으로 판단한다. https://design-system.service.gov.uk/patterns/question-pages/
- W3C Multi-page Forms: 논리적인 단계·진행 표시·선택 단계 구분을 제공한다. https://www.w3.org/WAI/tutorials/forms/multi-page/
- Lazyweb로 조회한 Vercel Web Interface Guidelines: 질문별 라벨, 명확한 포커스, 입력 오류의 위치와 복구, 모바일 조작성을 확인한다. https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md
- E: 변경 전 초대는 수동 왕복이었다. 원문·코드 계산 보존은 diff·회귀 검사로 확인한다.
- I: 세 문항 묶음은 이동 횟수를 줄이는 후보다. 완주율·정확도 개선은 UNVERIFIED.
- 문서 관문: 위 질문 표시 변경 구현 허용. 서버 공유는 별도 권한·보유·릴리스 설계 검토 후 구현·출시를 구분한다.

## 구현 검수 기록

접근 주소의 키가 바뀌면 같은 방이어도 이전 결과와 진행 요청을 폐기한다. 연결 종료 중 늦게 도착한 읽기 응답은 결과를 되살리지 못한다. 초대에 응답하는 중 일시적 통신 실패는 입력 화면을 유지한다. 만료 시각은 화면의 타이머로도 확인한다. 생성 시각을 방 식별자에 고정하여 만료 정리 후 시각만 바꾼 재생도 차단한다. 자동저장 OFF는 영구 확인 주소만 함께 지우고, 서버 종료와 실패 요청 복구는 분리한다.

검수 당시 작은 화면에서 선택지 단어가 잘리는 부분을 확인해 카드 여백과 칸 간격을 조정했다. 실제 스마트폰 조작, 소비자 완주율·문항 이해도·결과 만족도·추천 의향은 아직 확인하지 않았다. 운영 cron이 7일 뒤 실제 이용자 기록을 정리한 장기간 관측도 이번 배포 전 검사로 대신할 수 없다.

새 개인정보 안내의 문서 날짜와 신규 가입 동의판은 2026-09-23으로 맞춘다. 배포된 모바일의 가입을 중단시키지 않도록 직전 정식 가입판 2026-09-11도 명시적으로 지원하며, 제출한 판을 최신판으로 바꾸지 않고 기록한다. 미지원·미래판과 필수 동의·연령 확인 누락은 계속 거절한다. 기존 서버 소유 동의 기록을 무효화하지 않으며, 이 가입 호환은 함께 보기의 별도 보관·공유 동의를 대체하지 않는다.
