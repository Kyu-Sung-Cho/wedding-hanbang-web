# 직접 취향 Q6 — 단일 선택 명료화와 버전 gate

상태: 원고·해석 검토 후 코드 반영 및 아래의 부분 검사·브라우저 확인을 수행했다. 최종 전체 관문은 [소비자 역할 테스트 기록](./2026-09-20_consumer_walkthrough.md)을 따른다. 실제 소비자 조사나 이해도 검증 결과가 아니다.

## 발견한 문제

현재 `wedding-taste-v1`의 ‘가능하면 지키고 싶어요’와 ‘다른 안도 함께 볼 수 있어요’는 동시에 참일 수 있다. 예를 들어 야외를 가능하면 유지하고 싶으면서 실내도 비교할 수 있는 사람은 두 답 모두에 해당한다. 단일 선택에서 유지 선호와 대안 검토 의사를 나란히 물은 편집 문제다. 기능·보안 장애는 아니지만, 고른 문장이 공유·비교·아모라 전달문으로 이어지므로 소비자의 뜻을 불필요하게 좁힐 수 있다.

## 후보와 결정

| 후보 | 판단 |
|---|---|
| ‘내가 고른 취향을 우선해서 찾고 싶어요’ / ‘다른 취향도 함께 비교해 보고 싶어요’ | 기존 문장을 자연스럽게 만들지만, 내 취향 우선과 다른 취향 비교가 동시에 가능하다는 반례가 남는다. |
| 기존 두 보기를 복수 선택으로 변경 | 마음의 공존을 표현할 수 있지만 응답 형식·공유 계약을 늘리고, 첫 탐색 방향을 한 가지 고르는 목적에서 벗어난다. |
| **처음 살펴볼 후보의 범위를 묻는 v2** | 같은 시점의 후보 범위를 비교한다. 현재 취향 안부터 찾을지, 처음부터 다른 취향의 후보도 같이 비교할지를 구분한다. 채택. |

새 질문: **의견이 다르면, 먼저 어떤 후보부터 볼까요?**

- `prefer_keep`: 지금 고른 취향 안에서 찾아보고 싶어요
- `open_to_options`: 다른 취향의 후보도 함께 비교하고 싶어요
- `undecided`: 아직 정하지 못했어요

도움말: ‘앞에서 고른 주제마다, 처음 살펴볼 후보를 골라 주세요. 다른 후보를 비교해도 그걸로 바꾸겠다는 뜻은 아니에요.’

두 선택을 영구적인 성격이나 양보 의사로 해석하지 않는다. A를 고른 사람이 나중에 다른 후보를 보는 것은 모순이 아니다. 이번 답은 처음 살펴볼 후보의 범위만 설명한다. 보기 수·추가 질문·기본 선택·수집 항목은 늘리지 않는다.

### 하객 규모의 0명 중복

별도 브라우저 검토에서 ‘둘만, 하객 없이’와 ‘50명 미만’은 0명에서 겹친다는 반례를 확인했다. v2의 `guests.under50` 표시는 **‘1~49명’**으로 바꾼다. ‘50명 미만, 하객 있을 때’라는 대안보다 범위를 바로 읽을 수 있다. `no_guests`는 기존대로 유지한다. 공유 패키지의 전역 상수와 v1 표시는 바꾸지 않으며, v2 폼·요약·아모라 전달문 모두 같은 라벨을 사용한다.

## 버전·집계·결과 gate

- 새 진입은 `wedding-taste-v2`다. 기존 `wedding-taste-v1` 질문·보기·요약·아모라 문구는 그대로 보존한다. v1의 유지 선호를 v2의 후보 범위로 바꾸어 읽지 않는다.
- 고정 enum 기호와 JSON 모양은 유지하되 의미는 각 버전에 묶는다. `WeddingTasteDraftV1`과 `WeddingTasteDraftV2`를 구분하고 공통 소비자는 `WeddingTasteDraft` 합집합을 사용한다.
- v1 링크를 받아 답하는 사람에게는 v1 질문을 보여준다. 다시 고르기와 로그인 인계에서도 답의 버전을 보존한다. 링크 없이 새로 시작하면 v2를 사용한다.
- 다른 버전끼리 두 사람 링크를 생성·수신하거나 직접 비교하려 하면 거절한다. 겉의 버전과 내부 응답 버전이 다르거나 알 수 없는 버전이면 실패 상태로 닫는다.
- v2 요약과 아모라 전달문은 ‘의견이 다르면 먼저 볼 후보’라는 맥락과 실제 고른 문구를 사용한다. v1 전달문은 글자 그대로 유지한다.
- 동의 기본값, 공유 범위 고지, 미응답·미정 구분, 직접 고른 상세 주제에만 Q6를 묻는 조건, 로그인·15분 인계·전송 전 확인 경계는 변경하지 않는다.

## 주장 감사와 검증 계획

| 주장 | 근거·한계 | 판정 |
|---|---|---|
| 기존 두 보기는 함께 해당할 수 있다. | 원문을 읽고 ‘야외 유지 희망 + 실내 비교 가능’이라는 반례를 구성했다(E/I). | 수정 근거 |
| 새 질문은 첫 후보 검토 범위를 묻는다. | 질문·선택지 원문에 범위와 시점을 명시했다(E). 모든 사람이 같은 뜻으로 읽는지는 미측정이다. | 내부 gate 통과·사람 검증 필요 |
| 옛 링크도 새 문구로 바꾸어도 된다. | v1과 v2의 해석 범위가 달라 옛 의사를 재해석하게 된다(I). | 기각 |
| 수정안이 소비자 혼란을 없앴다. | 실제 사람 테스트가 없다. | UNVERIFIED·주장 금지 |

구현 후 v1 원문 요약·아모라 전달문, 양 판의 인코딩 왕복, 알 수 없는 버전·겉/속 버전 불일치·혼합 pair 거부, v2 기본 진입, v1 수신 시 같은 판의 응답, 다시 고르기, 미정·건너뛰기·동의 경계를 검사한다. 새 회귀 검사는 버전 혼합 거부를 제거하는 고장을 주입해 탐지와 원상복원을 확인한다. 전체 관문과 최종 브라우저 확인은 별도 실행 증거로 닫는다.

## 구현 후 관련 검사 기록

2026-09-20 새 진입 v2, v1 수신·재응답·요약·아모라 문구 보존, 다른 판 pair 거절, v2 하객 수 `1~49명` 표시를 구현했다. 관련 8개 검사 파일의 134개 테스트가 통과했다(`.verification/logs/taste-v2-related.log`). 최초 타입 검사에서는 기존 테스트의 추가 필드 타입 단언이 합집합 타입과 충돌해 실패했고, 타입 단언 없이 추가 필드 객체를 검사하는 방식으로 고친 뒤 타입 검사가 통과했다(`taste-v2-typecheck.log`). 해당 변경 범위의 린트도 통과했다(`taste-v2-lint.log`).

새 `versions.test.tsx`에 대해 혼합 판 공유 수신 허용, 혼합 판 직접 비교 허용, v1 Q6 원문을 v2로 덮기, v1 하객 범위를 v2로 덮기의 네 고장을 각각 주입했다. 네 고장 모두 검사가 실패했고 대상 파일은 원본 해시로 복원됐다. 영수증은 `.verification/taste-v2-guard-proofs.json`, 실행 로그는 `.verification/logs/taste-v2-prove-guard.log`다. 개별 실행 로그도 `taste-v2-clean.log`, `taste-v2-mutated-0.log`부터 `taste-v2-mutated-3.log`에 별도 보존했다.

이 시점에 소스·검사 파일을 확정했으며 전체 저장소 관문·빌드·최종 브라우저 검증은 상위 작업에서 이어간다. 이 기록만으로 그 후속 검증이나 배포를 완료했다고 주장하지 않는다.

## 최종 교차 검수에서 발견한 전달문 과장

v2 아모라 전달문에 `처음 살펴볼 후보를 고른 것이고`가 조건 없이 붙어 있었다. 분위기만 답해 Q6가 나오지 않은 경우, Q6를 건너뛴 경우, `아직 정하지 못했어요`를 고른 경우에도 후보 범위를 선택했다고 말하는 누락이었다. 실제 선택 행과 별개인 공통 안내가 미응답까지 설명하지 않도록, 전체 안내를 `먼저 이야기할 주제를 골라도 돈을 더 쓰겠다는 뜻은 아니에요. 다른 후보도 비교하고 싶다고 답했더라도, 그걸로 바꾸겠다는 약속은 아니에요.`라는 조건형으로 바꾼다. v1 전달문은 변경하지 않는다.

기존 `summary.test.ts`에 Q6 미노출·건너뜀·미정의 회귀 사례를 추가해, 답하지 않은 후보 범위를 골랐다고 서술하지 않고 미정은 실제 미정으로 전달하는지 확인한다. 앞의 부분 검사·변형 검증 기록은 이 수정 전 실행이며, 새 검사와 영수증 갱신은 이후 실행 결과로 확인해야 한다.

조건형 안내 반영 후 `summary.test.ts`와 `versions.test.tsx`의 23개 검사가 통과했다(`.verification/logs/taste-v2-unanswered-summary.log`). v1 원문 일치 검사도 포함한다. `versions.test.tsx`의 v2 안내문 기대값만 새 조건형과 맞췄으며, 변형 재검증과 전체 관문은 상위 작업에서 다시 실행한다.

조건형 안내까지 반영한 파일에서 기존 네 변형을 다시 실행해 모두 탐지·복원했다
(`.verification/logs/taste-v2-final-prove-guard.log`). 무응답을 선택으로 서술하는 문장을 되살린 추가 변형도
`summary.test.ts`가 탐지했다(`taste-v2-unanswered-prove-guard.log`). 최신 정본 영수증은
`.verification/guard-proofs.json`이며, 앞서 분리해 만든 taste 전용 영수증을 최종 해시의 증거로 사용하지 않는다.
새 빌드의 브라우저에서도 주제 건너뛰기·분위기만 선택하기 경로를 직접 눌러, 후보 질문이 나오지 않고
전달문에 실제 분위기만 담기는 것을 확인했다. 로그인이나 실제 AI 전송은 수행하지 않았다.
