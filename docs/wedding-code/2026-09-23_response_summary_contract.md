# 네 글자 응답 요약과 동의 척도

## 요청과 근거

- 사용자는 MBTI처럼 기억할 코드·이름과 퍼센트 척도를 요청했다. 현재 v3.1의 문장별 설명만으로는 결과를 짧게 소개하기 어렵다.
- E: PRINCIPLES P5는 네 글자를 응답 요약으로 허용하고, 글자별 근거의 분명함과 재응답 시 변경 가능성을 요구한다. 현재 core 23에는 아래 여덟 문장이 모두 있다.
- S: [Myers & Briggs Foundation 결과 설명](https://myersbriggs.org/my-mbti-personality-type/my-mbti-results/home.htm)은 응답 일관성과 선호 강도를 구분한다. 이를 웨딩코드의 타당성 근거로 사용하지 않는다.
- S: [Pew 문항 작성 지침](https://www.pewresearch.org/writing-survey-questions/)은 한 문항에 여러 개념을 묻지 않도록 권한다. 현재 문항의 뜻을 유지하고, 서로 다른 문장을 몰래 반대 척도로 합치지 않는다.
- Lazyweb의 data-visualization 지침을 읽었다. 동일한 0–100 범위의 독립 막대, 직접 표기한 수치·응답명, 세부 근거 펼치기를 사용한다. 색만으로 뜻을 전달하지 않는다.

## 대안과 결정

1. 기존 두 문장을 빼서 네 양극 척도/16유형 만들기: 기각. 예산 유지와 증액 논의, 공동 탐색과 세부 선택 위임은 공존할 수 있다.
2. 높은 점수 네 개를 순위로 골라 코드 만들기: 기각. 동의 정도를 중요도 순위로 바꾸며 동점 처리도 임의적이다.
3. 고정된 네 주제의 응답 조합을 코드로 요약하고 문장마다 동의 정도 표시: 채택. 같은 주제의 두 바람을 함께 보존한다. 소비자 심리검사나 검증된 성향 유형으로 소개하지 않는다.

## 계산 계약

| 자리 | 주제 | 첫 문장·글자 | 둘째 문장·글자 |
|---|---|---|---|
| 1 | 예산 | B1 / K / Keep: 처음 전체 예산 지키기 | B3 / R / Revisit: 늘릴지 다시 의논하기 |
| 2 | 일 나누기 | T1 / T / Together: 시간을 맞춰 함께 찾기 | T2 / D / Delegate: 계약·추가 결제 없는 세부 선택 맡기기 |
| 3 | 가족과 상의 | F1 / F / Family: 가족의 바람 초반에 듣기 | F2 / C / Couple: 마지막 선택은 둘이 하기 |
| 4 | 받고 싶은 도움 | H1 / L / Listen: 해결책 전에 이야기 듣기 | H2 / A / Assist: 몰린 일 일부 맡아주기 |

- 매 자리에서 두 응답이 모두 숫자 1–5일 때만 글자를 정한다.
- 둘 다 4–5면 B / Both. 둘 중 하나만 4–5면 그 문장의 글자. 높은 두 점수의 차이로 한쪽을 고르지 않는다.
- 둘 다 1–2면 N / Neither: 두 문장 모두 낮게 답함. 반대 취향·독립적 성격 등을 추론하지 않는다.
- 4–5가 없고 3이 포함되면 M / Middle: 중간 답 포함. '모름'과 구분한다.
- 숫자가 아닌 응답이나 미응답이 하나라도 있으면 ? / 요약 보류. 계획 없음·답하지 않음을 아직 결정하지 못한 상태로 바꾸지 않는다. 답한 다른 문장의 수치와 원래 응답명은 그대로 보여준다.
- ~~제목은 확인된 긍정 응답 조합에서만 만든다. 둘 다 높으면 두 바람을 함께 설명한다. 한 항목의 낮은 동의를 반대 선호나 우선순위로 번역하지 않는다. 일부 미정은 '지금 답한 부분의 요약'임을 보인다. 이름은 코드 전체를 대체하는 진단명이 아니다.~~ 2026-09-27 폐지: 제목·이름을 만들지 않는다(아래 개정의 ‘이름 없음’). 한 항목의 낮은 동의를 반대 선호나 우선순위로 번역하지 않는다는 원칙은 글자 뜻 줄에 그대로 적용한다.
- 글자별 `요약 근거`에 사용한 문장 수(2개 중 몇 개), 중간 답·낮은 답·둘 다 동의 여부를 보여준다. 확률/통계적 확신도/검사 신뢰도 수치는 만들지 않는다.

## 퍼센트 계약

- 이름은 **문장 동의 정도**. 1→0%, 2→25%, 3→50%, 4→75%, 5→100%. `(응답 - 1) / 4 × 100`으로 5개 보기를 눈금으로 표시한다. 실증적으로 검증된 등간척도라고 주장하지 않는다.
- 문장별 독립값이다. 같은 주제의 두 값 합계가 100일 필요가 없다. 총점, 평균 성향 점수, 사람 비율, 정확도, 궁합, 인구 순위로 사용하지 않는다.
- 숫자 이외에는 막대·퍼센트 대신 원래 응답명을 표시한다. 미노출 문항은 상세 척도에서 제외한다. 별도 설명으로 0%는 반대 취향의 증거가 아님을 알린다.
- 코드를 만든 여덟 문장 외에도 답한 나머지 동의 문장은 상세 척도로 열어볼 수 있다. 직접 취향 선택·우선순위·회피항목·지출항목은 수치로 바꾸지 않는다.
- 선택 질문을 추가해도 기본 여덟 문장을 수정하지 않으면 코드는 유지된다. 해당 문항의 척도와 기존 상세 결과만 늘어난다.

## 화면과 호환 계약

- 개인 결과: 네 글자→네 자리의 뜻과 요약 근거→문장별 척도·수정 경로(2026-09-27부터 ‘짧은 준비 스타일 제목’은 없다. 아래 개정의 ‘이름 없음’). 코드만 보고도 모든 웨딩 취향을 파악했다는 문구 금지.
- 커플 결과: 먼저/나중에 답한 사람의 코드를 각각 표시. 척도는 각자 펼쳐 볼 수 있다. 기존 공통 바람·차이·구체 대화 제안을 유지한다. 같은 코드가 궁합이나 모든 답의 일치를 뜻하지 않는다.
- 공개와 라운지의 공용 v3.1 결과에 적용한다. 구판 클라이언트에는 붙이지 않는다.
- Draft, 질문 순서·뜻·버전, 공유 hash, 로컬 저장 schema, API/DB는 변경하지 않는다. 원래 응답에서 순수 계산하며 결과를 계정에 쓰거나 자동 공유하지 않는다.
- 실패 시 이 파생 요약 컴포넌트를 제거하면 기존 결과로 복구 가능하다.

## 적대적 검수와 주장 감사

- 문항 독립 검수에서 네 쌍 모두 양극성이 없음을 확인했다. BOTH 상태와 독립 막대로 보완했다.
- 별도 적대적 검수에서 `? / 미정`이 계획 없음·건너뜀까지 미정으로 바꾸는 문제를 지적했다. `? / 요약 보류`와 원래 상태명으로 수정했다.
- 중간 응답=미정이라는 오해: M과 ?를 분리하고 원래 보기명을 함께 표시한다.
- 낮은 응답=반대 취향이라는 오해: N 또는 확인된 긍정 문장만 요약하고 상세 설명에서 반대 선호를 만들지 않는다.
- 누락=0/50이라는 오해: null로 유지한다. 1개 문장만 답한 주제는 ?를 유지한다.
- 코드가 전 영역·중요도·성격을 뜻한다는 오해: 네 주제 응답 요약임을 앞에 밝히며 실제 취향·상세 설명을 보존한다.
- 추가 응답·기존 공유 링크·커플 순서에서 같은 응답이 같은 요약을 만드는지 검증한다.
- 실제 소비자 이해도, 선호도, 심리측정 신뢰도·타당도, 수요 증가는 **UNVALIDATED**. 합성 테스트로 이를 주장하지 않는다.

문서 scoring/copy gate: 위 계산·표현 범위로 구현 가능. 구현 후 경계값·누락·공존·중간·구판 직렬화·수정 반영·커플 소유권·화면 검증을 통과하기 전 배포 완료로 보고하지 않는다.

## 2026-09-27 개정

2026-09-26 v3.1 감사 반영. 글자 계산 규칙(위 ‘계산 계약’)은 그대로이고, 보여주는 방식만 바뀐다. 아래가 위의 퍼센트 계약과 ‘? / 요약 보류’ 표기, 위의 제목·이름 설명을 대체한다. 위의 ‘적대적 검수와 주장 감사’는 당시 기록이라 그대로 둔다.

- **퍼센트 → 다섯 칸 점.** 문장마다 고른 칸까지 칠한 점(●○, 1~5칸)과 보기 이름을 함께 보여준다. 선호 확률이나 비율이 아니라 고른 보기의 자리다. 퍼센트·막대 너비 계산·`meter` 역할은 쓰지 않는다. 아직 모름·이번 계획에 없음·지금 답하지 않음·안 본 문장은 칸 없이 그 보기 이름만 적는다.
- **요약 보류 → 두 가지 ‘?’.**
  - 아직 모름·지금 답하지 않음·안 본 문장이 있는 주제: 카드 위 한 줄이 ‘?’로 남긴 이유와 함께 그 문장의 동의 정도를 고르면 글자가 생긴다고 한 번 알린다.
  - 이번 계획에 없다고 답한 문장이 있는 주제: 두 문장 모두 그런 주제와 한 문장만 그런 주제를 나눠 적는다. 계획 없음은 끝난 답이라 다시 답하라고 하지 않는다.
  - ‘?’·M·N 자리는 뜻 한 줄과 답 줄만 둔다. 근거 줄에서 같은 사정을 되풀이하지 않는다.
- **근거 줄의 문장 수(n/2) 표기는 없앤다.** 글자가 정해진 자리만 ‘두 문장 모두 ‘그런 편’ 이상’ 또는 ‘한 문장에만 ‘그런 편’ 이상’ 한 줄을 둔다. 한 문장에서 나온 글자는 뜻 줄을 따로 쓰지 않고 그 문장의 답 줄에 영문 낱말을 붙인다.
- **아슬한 글자(2026-09-27 파운더 결정 "스타일 이름은 빼고 아슬한 글자 기준도 바꿔줘"로 기준 변경).** 한 문장만 ‘그런 편’ 이상인 한쪽 글자(K·R·T·D·F·C·L·A)이고, 두 문장의 답이 정확히 한 칸 차이일 때만 아슬한 글자다. 글자 규칙상 한 글자 25칸 중 (4,3)(3,4) 두 칸뿐이다. 두 방향 중 한쪽으로 한 칸 차이로만 기운 글자라는 뜻이다. B·M·N·‘?’는 아슬하다고 하지 않는다.
  - 대체한 기준: 두 답 중 하나를 1~5 안에서 ±1 옮겼을 때 글자가 바뀌면 아슬. 25칸 중 19칸이 아슬이다. 답이 고르게 흩어진다고 치면 네 주제 중 하나라도 걸릴 확률이 약 99.7%라 경고가 뜻을 잃는다(계산값, 실제 사용자 비율은 재지 않았다). 새 두 칸은 예전 19칸의 일부다.
  - 아슬한 글자가 있으면 코드보다 먼저 주제 이름과 사실을 한 줄로 알린다(예: ‘가족과 상의’ 글자는 두 문장의 답이 ‘그런 편이에요’와 ‘어느 쪽도 아니에요’로 한 칸 차이예요. 넷 모두면 ‘네 글자 모두’). 없으면 이 줄은 없다.
    - 「한 칸 차이」만 적지 않는다. 두 답이 한 칸 차이인 칸은 25칸 중 8칸(B 4,5·5,4 / M 2,3·3,2 / N 1,2·2,1 / 아슬 4,3·3,4)이라, 그 말만으로는 표시 없는 줄이 한 칸 차이가 아니라고 읽힌다. 실제로 고른 두 보기 이름까지 적으면 아슬한 두 칸에서만 참이다. 보기 이름은 질문 화면의 보기(`WEDDING_CODE_V31_OPTIONS`)에서 가져오고 반드시 ‘’ 안에 둔다(밖에 두면 「아니에요」가 판정 고지처럼 읽힌다).
  - 정해진 글자가 하나라도 있는 코드에는 공통으로 「다시 답하면 글자가 달라질 수 있어요.」를 코드보다 먼저 한 번 둔다. 아슬한 글자가 0개여도 참인 문장이다(PRINCIPLES.md 5절). 예전 0개일 때의 「지금 글자는 답 하나를 한 칸 옮겨도 그대로예요」는 새 기준에서 거짓(4 대 4 의 B 도 한 칸 내리면 바뀐다)이라 없앴다. 두 사람 카드를 나란히 두는 함께 보기에서는 두 카드 위에서 한 번만 말한다.
  - 밑줄처럼 눈으로만 보이는 표시를 가리키지 않는다. 주제 줄에는 글로 된 「‘그런 편’과 ‘어느 쪽도’로 갈렸어요」 표시를 단다(같은 까닭으로 「한 칸 차이」만 적지 않는다).
- **이름 없음(2026-09-27 파운더 결정).** ‘~스타일’ 이름, 이름 출처 줄, 이름에 딸린 헤드라인(편집 순서의 첫 주제 하나에서 나온 문장)을 두지 않는다. 코드 옆에는 코드와 주제별 줄(글자, 글자 뜻 한 줄, 두 문장의 실제 답)만 있다(CLAUDE.md WeddingCode 조항 「코드 옆 설명은 본인이 고른 문장 인용과 글자 뜻 한 줄뿐」). 한 문장에서 나온 글자(K·R·T·D·F·C·L·A)는 뜻 줄을 따로 두지 않고 그 문장의 답 줄에 영문 낱말을 붙이며, 글자가 정해진 자리(이 여덟 글자와 B)에는 ‘한 문장에만/두 문장 모두 ‘그런 편’ 이상’ 근거 한 줄이 붙는다. 카드 첫머리는 제목(누구의 웨딩코드인지) → (아슬한 글자가 있으면) 아슬한 글자 안내 → (정해진 글자가 하나라도 있으면) 공통 한 줄 「다시 답하면 글자가 달라질 수 있어요.」(함께 보기에서는 두 카드 위에 한 번) → 코드 → 주제 순서 설명 → (‘?’가 있으면) ‘?’ 안내 → 주제별 줄이다. 주제별 줄 앞에는 「결혼식 취향은 아래에 따로 모았어요.」(넓은 카드만)와 칠한 칸의 뜻을 말하는 한 줄이 있다.

## 2026-09-28 개정 (결과 되풀이 걷기)

파운더 요청 "결과 화면 되풀이 걷는 것도 해줘". 글자 계산 규칙(위 ‘계산 계약’)은 그대로이고 보여주는 방식만 바뀐다. 아래가 위 ‘계산 계약’의 「글자별 `요약 근거`에 사용한 문장 수…를 보여준다」, ‘화면과 호환 계약’의 「네 자리의 뜻과 요약 근거」와 커플 결과 문장, 2026-09-27 개정의 근거 줄·두 카드 문장보다 앞선다.

- **근거 줄 → 카드에 규칙 한 줄.** 주제 줄마다 붙던 ‘한 문장에만/두 문장 모두 ‘그런 편’ 이상으로 답했어요.’는 두지 않는다. 같은 문장이 줄마다 되풀이됐고 바로 위 두 문장의 칸과 보기 이름이 같은 사실을 보여줬다. 글자별 요약 근거는 이제 그 주제 줄의 두 문장 칸·보기 이름(한 문장에서 나온 글자는 그 답 줄의 영문 낱말, B·M·N은 뜻 한 줄)과 카드에 한 번 있는 규칙 문장이다. 한 문장이나 두 문장에서 나온 글자(K·R·T·D·F·C·L·A·B)가 하나라도 있으면 칠한 칸 설명 뒤에 「두 문장 모두 동의 정도를 고른 주제는 ‘그런 편’ 이상으로 답한 문장이 하나면 그 문장의 글자를, 둘이면 ‘B’를 붙였어요.」를 한 번 둔다. 칠한 칸 설명 「주제마다 두 문장에 따로 답했어요. 칠한 칸이 많을수록 그 문장에 더 동의했다는 거예요.」는 그대로다.
- **‘다른 문장에 고른 답도 보기’는 없앤다.** 코드에 쓰지 않은 문장의 다섯 칸 점과 보기 이름은 ‘문장별로 내가 고른 답 모두 보기’(상대 결과 탭과 받은 링크의 사람별 탭은 ‘{이름}의 문장별 답 모두 보기’, 내 결과 탭은 혼자 결과와 같은 이름)에서 연다. 그 접기 첫 줄이 「네 글자는 주제마다 두 문장의 답으로만 만들었어요.」라고 알린다. 위 ‘나머지 동의 문장은 상세 척도로 열어볼 수 있다’는 이 접기로 지킨다.
- **함께 보기는 두 카드 대신 두 사람 코드 표 하나다.** 순서: 제목 → 공통 한 줄(다시 답하면 …, 코드만 보지 말고 …) → (있으면) 사람마다 아슬한 글자 안내·‘?’ 안내 → 두 사람의 코드(먼저 답한 사람이 먼저, 합치지 않음) → 칠한 칸 설명과 규칙 한 줄 → 주제마다 두 사람의 글자(누구의 글자인지 글자 옆에 보이게, 아슬하면 글로 된 표시, M·N이면 뜻 한 줄)와 두 문장의 칸·보기 이름(문장 이름 옆에 영문 낱말) → 나머지는 사람별 탭에서 본다는 한 줄. 두 글자가 모두 정해졌고 다를 때만 「글자가 달라요」를 단다. ‘?’는 다르다고 하지 않고, 같다·일치·점수는 쓰지 않는다. ‘커플 결과: 코드를 각각 표시. 척도는 각자 펼쳐 볼 수 있다’는 이 표와 사람별 탭의 넓은 카드로 지킨다. 2026-09-27 개정의 카드 첫머리 순서는 넓은 카드(혼자 결과·사람별 탭)에만 적용하고, ‘두 카드 위에서 한 번’은 표 위에서 한 번으로 읽는다.
