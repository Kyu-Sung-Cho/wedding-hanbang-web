# 네 글자 응답 요약과 동의 척도

## 요청과 근거

- 사용자는 MBTI처럼 기억할 코드·이름과 퍼센트 척도를 요청했다. 현재 v3.1의 문장별 설명만으로는 결과를 짧게 소개하기 어렵다.
- E: PRINCIPLES P5는 네 글자를 응답 요약으로 허용하고, 글자별 근거의 분명함과 재응답 시 변경 가능성을 요구한다. 현재 core 23에는 아래 여덟 문장이 모두 있다.
- S: [Myers & Briggs Foundation 결과 설명](https://myersbriggs.org/my-mbti-personality-type/my-mbti-results/home.htm)은 응답 일관성과 선호 강도를 구분한다. 이를 웨딩코드의 타당성 근거로 사용하지 않는다.
- S: [Pew 문항 작성 지침](https://www.pewresearch.org/writing-survey-questions/)은 한 문항에 여러 개념을 묻지 않도록 권한다. 현재 문항의 뜻을 유지하고, 서로 다른 문장을 몰래 반대 척도로 합치지 않는다.
- Lazyweb의 data-visualization 지침을 읽었다. 동일한 0–100 범위의 독립 막대, 직접 표기한 수치·응답명, 세부 근거 펼치기를 사용한다. 색만으로 뜻을 전달하지 않는다.

## 대안과 결정

1. 기존 두 문장을 빼서 네 양극 척도/16유형 만들기: 기각. 예산 유지와 증액 논의, 공동 탐색과 세부 선택 위임은 공존할 수 있다.
2. 높은 점수 네 개를 순위로 골라 코드 만들기: 기각. 동의 정도를 중요도 순위로 바꾸며 동점 처리도 임의적이다.
3. 고정된 네 주제의 응답 조합을 코드로 요약하고 문장마다 동의 정도 표시: 채택. 같은 주제의 두 바람을 함께 보존한다. 소비자 심리검사나 검증된 성향 유형으로 소개하지 않는다.

## 계산 계약

| 자리 | 주제 | 첫 문장·글자 | 둘째 문장·글자 |
|---|---|---|---|
| 1 | 예산 | B1 / K / Keep: 처음 전체 예산 지키기 | B3 / R / Revisit: 늘릴지 다시 의논하기 |
| 2 | 일 나누기 | T1 / T / Together: 시간을 맞춰 함께 찾기 | T2 / D / Delegate: 계약·추가 결제 없는 세부 선택 맡기기 |
| 3 | 가족과 상의 | F1 / F / Family: 가족의 바람 초반에 듣기 | F2 / C / Couple: 마지막 선택은 둘이 하기 |
| 4 | 받고 싶은 도움 | H1 / L / Listen: 해결책 전에 이야기 듣기 | H2 / A / Assist: 몰린 일 일부 맡아주기 |

- 매 자리에서 두 응답이 모두 숫자 1–5일 때만 글자를 정한다.
- 둘 다 4–5면 B / Both. 둘 중 하나만 4–5면 그 문장의 글자. 높은 두 점수의 차이로 한쪽을 고르지 않는다.
- 둘 다 1–2면 N / Neither: 두 문장 모두 낮게 답함. 반대 취향·독립적 성격 등을 추론하지 않는다.
- 4–5가 없고 3이 포함되면 M / Middle: 중간 답 포함. '모름'과 구분한다.
- 숫자가 아닌 응답이나 미응답이 하나라도 있으면 ? / 요약 보류. 계획 없음·답하지 않음을 아직 결정하지 못한 상태로 바꾸지 않는다. 답한 다른 문장의 수치와 원래 응답명은 그대로 보여준다.
- 제목은 확인된 긍정 응답 조합에서만 만든다. 둘 다 높으면 두 바람을 함께 설명한다. 한 항목의 낮은 동의를 반대 선호나 우선순위로 번역하지 않는다. 일부 미정은 '지금 답한 부분의 요약'임을 보인다. 이름은 코드 전체를 대체하는 진단명이 아니다.
- 글자별 `요약 근거`에 사용한 문장 수(2개 중 몇 개), 중간 답·낮은 답·둘 다 동의 여부를 보여준다. 확률/통계적 확신도/검사 신뢰도 수치는 만들지 않는다.

## 퍼센트 계약

- 이름은 **문장 동의 정도**. 1→0%, 2→25%, 3→50%, 4→75%, 5→100%. `(응답 - 1) / 4 × 100`으로 5개 보기를 눈금으로 표시한다. 실증적으로 검증된 등간척도라고 주장하지 않는다.
- 문장별 독립값이다. 같은 주제의 두 값 합계가 100일 필요가 없다. 총점, 평균 성향 점수, 사람 비율, 정확도, 궁합, 인구 순위로 사용하지 않는다.
- 숫자 이외에는 막대·퍼센트 대신 원래 응답명을 표시한다. 미노출 문항은 상세 척도에서 제외한다. 별도 설명으로 0%는 반대 취향의 증거가 아님을 알린다.
- 코드를 만든 여덟 문장 외에도 답한 나머지 동의 문장은 상세 척도로 열어볼 수 있다. 직접 취향 선택·우선순위·회피항목·지출항목은 수치로 바꾸지 않는다.
- 선택 질문을 추가해도 기본 여덟 문장을 수정하지 않으면 코드는 유지된다. 해당 문항의 척도와 기존 상세 결과만 늘어난다.

## 화면과 호환 계약

- 개인 결과: 네 글자+짧은 준비 스타일 제목→네 자리의 뜻과 요약 근거→문장별 척도·수정 경로. 코드만 보고도 모든 웨딩 취향을 파악했다는 문구 금지.
- 커플 결과: 먼저/나중에 답한 사람의 코드를 각각 표시. 척도는 각자 펼쳐 볼 수 있다. 기존 공통 바람·차이·구체 대화 제안을 유지한다. 같은 코드가 궁합이나 모든 답의 일치를 뜻하지 않는다.
- 공개와 라운지의 공용 v3.1 결과에 적용한다. 구판 클라이언트에는 붙이지 않는다.
- Draft, 질문 순서·뜻·버전, 공유 hash, 로컬 저장 schema, API/DB는 변경하지 않는다. 원래 응답에서 순수 계산하며 결과를 계정에 쓰거나 자동 공유하지 않는다.
- 실패 시 이 파생 요약 컴포넌트를 제거하면 기존 결과로 복구 가능하다.

## 적대적 검수와 주장 감사

- 문항 독립 검수에서 네 쌍 모두 양극성이 없음을 확인했다. BOTH 상태와 독립 막대로 보완했다.
- 별도 적대적 검수에서 `? / 미정`이 계획 없음·건너뜀까지 미정으로 바꾸는 문제를 지적했다. `? / 요약 보류`와 원래 상태명으로 수정했다.
- 중간 응답=미정이라는 오해: M과 ?를 분리하고 원래 보기명을 함께 표시한다.
- 낮은 응답=반대 취향이라는 오해: N 또는 확인된 긍정 문장만 요약하고 상세 설명에서 반대 선호를 만들지 않는다.
- 누락=0/50이라는 오해: null로 유지한다. 1개 문장만 답한 주제는 ?를 유지한다.
- 코드가 전 영역·중요도·성격을 뜻한다는 오해: 네 주제 응답 요약임을 앞에 밝히며 실제 취향·상세 설명을 보존한다.
- 추가 응답·기존 공유 링크·커플 순서에서 같은 응답이 같은 요약을 만드는지 검증한다.
- 실제 소비자 이해도, 선호도, 심리측정 신뢰도·타당도, 수요 증가는 **UNVALIDATED**. 합성 테스트로 이를 주장하지 않는다.

문서 scoring/copy gate: 위 계산·표현 범위로 구현 가능. 구현 후 경계값·누락·공존·중간·구판 직렬화·수정 반영·커플 소유권·화면 검증을 통과하기 전 배포 완료로 보고하지 않는다.

## 구현 검증 기록

- 공용 v3.1 결과에 네 글자·짧은 이름·정확한 조건 설명·문장별 막대를 추가했다. 공개와 라운지는 같은 컴포넌트를 사용한다.
- 관련 4개 테스트 파일 69개 통과. 모든 숫자 응답 조합 25개를 네 주제에 적용하고, 누락·공존·중간·선택 질문 추가·공유값 왕복·수정 권한을 검사했다.
- 표시 눈금 오류, 동시 동의를 한쪽으로 강제하는 오류, 미응답의 코드 배정, 받은 공유 답 수정 허용의 네 변형 모두 실제 테스트 실패로 검출했고 원본 복원을 확인했다.
- 로컬 브라우저: 결과 척도에서 답 수정→코드/퍼센트 갱신→새로고침 복원. 모름 응답은 `?`와 원래 상태로 남고 해당 막대는 없다. 라운지의 합성 커플 결과는 각자 코드를 표시하고 편집 버튼이 없다.
- 데스크톱·320px·390px에서 코드·이름·막대 확인, 가로 넘침 없음. 해당 QA 탭의 브라우저 오류 로그 없음. 실기기 검증을 뜻하지 않는다.
- 전체 관문·최종 후보 SHA·운영 배포 확인은 PR과 `.verification` 영수증에 별도로 기록한다. 이 기록만으로 배포 성공이나 소비자 타당성을 주장하지 않는다.
