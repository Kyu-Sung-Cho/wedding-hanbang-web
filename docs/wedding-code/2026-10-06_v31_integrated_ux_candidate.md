## 새판 선택형의 완성 원문·보기

아래 전체는 제안이며 저장/전송 구현이나 기본 판 전환이 아니다. 질문당 `특별히 선호하는 …은 없어요`(no_preference), `아직 모르겠어요`(undecided), `맞는 보기가 없어요`(no_match), `이번 계획에는 없어요`(not_applicable), `지금 답하지 않을게요`(skipped)를 구분한다. 구체 보기의 `없음`과 no_preference는 서로 다르다.

- **next.venue.space**: 어떤 공간에서 식을 올리고 싶나요? 하나 선택: 실내 / 야외 / 실내와 야외를 함께 쓰는 곳. 호텔·웨딩홀·공공시설은 공간의 다른 차원이므로 이 답으로 정하지 않는다.
- **next.photo.moments**: 예식 사진에 어떤 장면을 남기고 싶나요? 하나 선택: 자연스럽게 흘러가는 순간 / 미리 준비한 포즈와 장면 / 두 가지 모두. 스튜디오·본식 영상까지 자동 확장하지 않는다.
- **next.attire.form**: 예식에 내가 입고 싶은 옷의 종류는 무엇인가요? 해당하는 것 모두: 드레스 / 정장 / 한복이나 전통 혼례복 / 그 밖의 옷. 성별로 보기를 제한하지 않는다. 예식 중 갈아입는 옷도 함께 고를 수 있다. ‘그 밖의 옷’은 구체 형태를 추론하지 않는다.
- **next.attire.decoration**: 예식 옷에는 어느 정도의 장식이 있으면 좋겠어요? 하나 선택: 장식이 거의 없는 옷 / 일부에 장식이 있는 옷 / 장식이 많이 들어간 옷. 재질·움직임·복식 종류와 분리한다. 기존 ‘하늘하늘한 옷’의 소재 취향은 구판 프로필에서만 보존한다.
- **next.meal.plan**: 예식과 함께 하객이나 두 사람이 먹을 것을 준비할 계획인가요? 하나 선택: 식사를 준비하고 싶어요 / 간단한 다과나 음료를 준비하고 싶어요 / 먹을 것을 따로 준비하지 않고 싶어요. 없음도 명시적 계획이다. 예식 자체가 없는 경우는 not_applicable로 구분한다.
- **next.meal.service**: 식사를 준비한다면 어떤 방식이 좋아요? 하나 선택: 각자 음식을 골라 담는 뷔페 / 한 접시씩 차례로 나오는 코스 / 한 사람씩 받는 정식이나 도시락 / 한 상에 놓인 음식을 함께 나눠 먹는 방식 / 그 밖의 식사 방식. meal.plan이 식사일 때만 질문하며 다과·없음은 이 질문을 물어 억지 답을 만들지 않는다. 기존 구판 service 답만으로 새 plan을 자동 확정하지 않는다. 식이 제한·알레르기는 이 답으로 추정하지 않는다.
- **next.guests.count**: 두 사람의 가족·지인을 합해 하객은 몇 명쯤 초대하고 싶나요? 하나 선택: 하객 없이 둘만 / 1~49명 / 50~99명 / 100~199명 / 200~299명 / 300명 이상. 예식 당사자 두 사람을 제외한 희망 초대 규모이며 실제 참석·보증 인원과 다르다.
- **next.ceremony.length**: 예식의 주요 순서가 이어지는 시간은 어느 정도면 좋겠어요? 하나 선택: 20분 미만 / 20~39분 / 40~59분 / 60분 이상. 식사·대기·사진 촬영 시간을 제외한다. 특정 시간이 좋다는 규범을 만들지 않는다. 실제 진행 시간은 이후 확인한다.
- **next.ceremony.contents**: 예식에 넣고 싶은 내용은 무엇인가요? 해당하는 것 모두: 둘의 이야기를 전하는 순서 / 가족이나 하객에게 감사 인사 / 하객이 함께 참여하는 순서 / 축가 같은 축하 공연 / 전통 혼례 순서 / 그 밖의 순서. 별도 구체 선택: 이런 순서를 추가하지 않고 싶어요. ‘추가 없음’은 다른 내용과 동시 선택할 수 없다. 하객 없는 예식에서도 공연·감사 인사가 가능한 맥락을 먼저 확인하며 답을 자동 삭제하지 않는다.
- **next.avoidances**: 이번 예식에서 피하고 싶은 것은 무엇인가요? 해당하는 것 모두: 꽃과 장식이 빼곡한 공간 / 사람이 붐비는 공간 / 오래 이어지는 사진 촬영 / 하객을 무대로 부르는 순서 / 큰 음악 소리 / 오래 이어지는 예식 순서 / 뜻하지 않은 추가 비용 / 그 밖의 불편한 것. 없음과 보기 없음은 구분. ‘그 밖’에서 구체 불편을 생성하지 않는다. 추가 비용과 모든 비용 거부를 동일시하지 않는다.
- **next.spending**: 전체 예산을 늘리지 않고, 다른 항목의 비용을 줄여서라도 더 쓰고 싶은 곳은 어디인가요? 최대 두 개: 예식 장소 이용 / 공간 장식 / 사진 / 영상 / 예식에 입을 옷 / 헤어·메이크업 / 식사·다과 / 예식 순서·연출 / 그 밖의 예식 준비 항목. ‘더 쓰고 싶은 곳은 지금 없어요’는 구체 비용 이동 희망이 없는 상태. 범위는 예식 준비이며 신혼집·여행 전체 예산이라고 설명하지 않는다. 묶음 항목의 구판 선택을 세부 항목으로 자동 분배하지 않는다.
- **next.priorities**: 지금 답한 내용 중 특히 지키고 싶은 기준을 최대 세 개 골라 주세요. 후보는 원문 문장+본인이 고른 응답, 선택형의 실제 선택, 피할 것, 더 쓸 곳이다. 동의 1~3도 선택 가능하게 하되 원문 응답을 그대로 붙여 ‘낮게 답했다=반대 성향’으로 번역하지 않는다. 여러 선택을 한 취향의 우선순위는 그 선택 집합 전체를 가리킨다. 고르지 않음은 순위 미정·별도 기준 없음·건너뜀으로 구분한다. 보기에서 더 중요한 기준을 찾을 수 없었다면 no_match로 남긴다.

### 빠진 보기와 결과 근거 연결

옷의 성별/복식 누락은 종류 질문으로, 식사 없음·다과·개별 식사는 계획/서비스로, 식순의 길이·내용 혼합은 두 질문으로 해결한다. ‘그 밖’이나 ‘맞는 보기 없음’은 추가 정보를 받았다는 뜻이 아니다. 자유 입력 수집은 이번 제안에 넣지 않는다. 추가 자료 없이 결과의 구체 옷·식사·공연을 만들어내지 않는다. 우선순위가 높다는 것과 실제 비용을 더 쓰겠다는 동의도 구분한다.

### 저장 답 호환과 전환 완료 기준

1. 새판 version discriminator와 새 ID/보기 키를 확정하고, 기존 v3.1 파서·코덱·원답 결과를 별도로 보존한다.
2. 기존 답을 자동 변환하지 않는다. 새 질문에 다시 답해야 새판 결과를 만든다. 과거 결과에는 당시 판과 문장을 표시한다.
3. 혼합 판 두 사람 비교는 의미가 같은 공통 항목만 버전 출처와 함께 비교하거나, 같은 판으로 다시 답하도록 안내한다. 구판 네 글자를 새판에 그대로 계산하지 않는다.
4. UI 카피 변경은 숫자/상태 의미를 보존하는 표시 변경이지만, 중립 문구의 인지 차이는 사용자 검토에서 확인한다.
5. 새판 등록 수/분기 수/기본 질문 부담을 다시 계산한다. 옷·식사·식순 분리로 현재24개를 그대로 유지한다고 주장하지 않는다. 실행 흐름·코덱·API·저장 계약이 필요하므로 구현 전에 범위를 별도로 승인받는다.
6. 34개 항목별 인지면접: 자기 말로 질문 설명 → 떠올린 상황 → 보기 누락/중복 → 실제 선택 이유 → 결과 설명과 일치 여부. B와 N에 대한 캐릭터 이해도, 첫 화면에서 자신의/상대의 결과 식별, 초대 후 노출 범위를 따로 확인한다. 합성 화면 검증을 실제 사용자 검증으로 보고하지 않는다.
