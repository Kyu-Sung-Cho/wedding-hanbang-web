# 웨딩코드: 한 번에 이해하는 내 결혼식과 준비 방식

## 구현 상태 추가 기록

아래 원고 감사 후 사용자가 구현을 요청해 `v3.0-preferences`로 반영했다. 본문의 ‘구현 전’과 ‘이번 턴’은 원고 작성 당시의 기록이다. 현재 기본 진입은 32개 동의 문항 + 6개 직접 취향 + 우선순위·지출 희망 2개, 총 40개 질문이며 구판 링크는 해당 판으로 유지한다. 반영 파일은 `constants/weddingCodeV30.ts`, `lib/weddingCode/v30.ts`, `app/wedding-code/WeddingCodeV30*.tsx`와 진입·랜딩이다. 최종 검사·배포 여부는 릴리스 PR과 검증 영수증을 따른다.

구현 중 독립 검수에서는 다음을 추가로 수정했다. 선택을 해제한 채 결과로 넘어가지 않게 하고, 앞의 답이 바뀌어 우선순위가 달라지면 다시 확인한다. 동일 취향을 다른 순서로 고른 것은 차이로 만들지 않는다. 낮음·비해당·미정인 답에는 원한다고 전제한 후속 질문을 붙이지 않는다. 공통으로 비교할 응답이 없을 때는 ‘차이가 없다’고 말하지 않는다. 지출의 장소 범위는 대관과 꾸미기를 포함하며, 우선순위·지출에도 ‘맞는 보기가 없어요’를 허용한다. 추가 비용과 취소·변경 조건을 확인하는 안내는 모든 응답자에게 제공한다.

수요·소비자 이해도·문항 피로·재미·커플 대화 유용성은 여전히 실제 사람에게 검증하지 않았다. 자동 검사와 소비자 역할 시뮬레이션은 이 경계를 바꾸지 않는다.

## 1. 이번에 만들려는 경험

사용자 요구: 쉽게 답하고, 끝나면 내가 원하는 결혼식과 준비 방식을 이해하고, 상대와 함께 보면 실제 준비에서 맞춰볼 부분을 알 수 있어야 한다. 응답은 익숙한 5단계를 유지한다. 팀 피드백의 핵심은 쉬운 문장뿐 아니라 결과의 설명력이다.

**추천 방향은 한 번의 응답 흐름과 하나의 결과다.** 취향을 알기 위해 다른 도구를 다시 찾아가게 하지 않는다. 상대가 참여하지 않아도 개인 결과에서 가치가 끝까지 나와야 한다. 상대 참여는 나중에 비교를 더하는 동작이다.

이 문서의 ‘완성형’은 제품 경험의 완결성을 뜻한다. 모든 잠재 성격을 측정한다는 뜻이 아니다. 문항 수와 분야 수는 설계 선택이며 최적값이나 타당도가 입증된 숫자가 아니다. 아래 32문장은 검토할 원고 풀이다. 모두 실제 소비자에게 이해된다고 확인하거나 운영 코드에 반영한 상태가 아니다.

## 4. 질문과 응답 계약

소개 원고: **“내가 바라는 결혼식과 준비 방식을 알아봐요. 지금 내 생각에 가까운 정도로 답해 주세요. 아직 정하지 못한 것은 모른다고 답해도 괜찮아요.”**

다섯 답은 `전혀 그렇지 않아요 / 그렇지 않은 편이에요 / 어느 쪽도 아니에요 / 그런 편이에요 / 매우 그래요`다. 중간값은 중립 응답이며 미정이나 비해당으로 대체하지 않는다.

별도 상태: `아직 모르겠어요`, `이번 계획에는 없어요`, `지금 답하지 않을게요`. 이것들은 점수가 아니다. 질문을 아예 보지 않은 상태도 별도로 둔다. 결과에서 중립·미정·비해당·건너뜀·미노출을 서로 변환하지 않는다.

예식·촬영·가족 협의 등 해당하지 않는 주제는 한 번에 ‘이번 계획에는 없어요’로 둘 수 있다. 이 선택은 전체 주제를 미노출로 조용히 지우지 않고 사용자가 직접 비해당으로 표시한 것으로 남긴다. 주제 재개 시 이전 답 복원 여부를 분명히 보여주며 조용히 이전값을 끼워 넣지 않는다.

아래 모든 문장은 실제 행동 이력이 아니라 **현재의 바람**이다. 과거 경험이 없어도 상상해서 답할 수 있지만 모르겠다는 답을 허용한다. 한 문장에 낮게 답했다고 반대 취향을 만들어내지 않는다.

## 5. 검토용 32문장과 문항별 용도

각 행은 주로 확인하는 한 가지를 갖는다. 대안은 표현 비교용이며 화면에는 채택 후보 하나만 나온다. 이 표의 문구는 내부 검수 초안이며 실사용자 통과 문구가 아니다.

| V1 | 꽃 장식이 풍성한 공간에서 식을 올리고 싶다. | ‘화려한 결혼식이 좋다’는 조명·옷·규모까지 섞이므로 장식 하나로 좁힘 | 풍성한 꽃 장식 선호. 고급·과시·큰 예산으로 해석 금지 |

| B1 | 마음에 드는 것이 생겨도 처음 정한 전체 예산 안에서 준비하고 싶다. | ‘낭비하지 않는다’는 도덕 판단이라 제외 | 총액 유지 의향. 실제 능력·금액·절약 성격 추정 금지 |

| B3 | 새로 하고 싶은 것이 생기면 전체 예산을 늘릴지도 다시 의논하고 싶다. | ‘예산을 넘겨도 괜찮다’는 합의·지불 가능성을 단정하여 제외 | 증액 여부를 논의할 의향. 증액 동의·가능 금액 아님 |

| T1 | 업체를 알아볼 때는 시간을 맞춰 둘이 같이 찾아보고 싶다. | ‘함께 정보를 본다’는 각자 조사한 자료 공유와 섞여 같은 시간의 공동 탐색으로 좁힘 | 함께 탐색할 시간 희망. 상대 시간 여유·모든 조사 공동 수행 추정 금지 |

V4의 ‘꼭 필요한 순서’, T2의 ‘세부 선택’, F4의 ‘자기 쪽 가족’은 인지면접에서 대안 해석을 특히 확인할 잔여 문구다. 가족을 이처럼 나누지 않거나 함께 상의할 가족이 없는 경우에는 비해당으로 둘 수 있어야 한다. 문서가 있다고 통과로 처리하지 않는다. 추가 비용·취소 조건 확인은 모든 응답자에게 필요한 실행 안내로 옮기며, 관련 문항에서 낮게 답했다는 이유로 안내를 생략하지 않는다.

## 6. 우선순위와 구체 취향을 혼동하지 않는 마무리

동의 정도에서 중요도 순위를 만들지 않는다. 마지막에 사용자가 직접 확인한다.

1. **“이번 결혼식에서 특히 지키고 싶은 것은 무엇인가요?”** 방금 긍정한 문장의 쉬운 요약 중 최대 세 개. ‘아직 우선순위를 정하지 못했어요’ 허용. 이 선택은 심리 점수나 예산 배분이 아니다. 긍정 응답이 없으면 순위를 강제하지 않는다.
2. **“다른 곳의 비용을 줄여서라도 더 쓰고 싶은 곳이 있나요?”** 장소 꾸미기 / 사진·영상 / 입을 옷 / 식사 / 예식 순서·연출. 최대 두 개, ‘아직 모르겠어요’, ‘지금은 없어요’, ‘이번 계획에는 없어요’, ‘답하지 않을게요’를 구분한다. 총액 증가 약속은 아니다. 이 질문에 직접 고른 경우에만 특정 항목의 재배분 의향을 말한다.

**같은 완료 흐름 안에서 구체 취향도 직접 확인한다.** 기존 취향 도구의 장소·사진·옷·식사·하객 규모·식순 여섯 항목을 모두 한 번씩 보여주며, 관심 주제 두 개만 상세 질문하던 제한은 두지 않는다. 독립 5단계 응답은 준비 방식과 바람에 쓰고, 실내/야외·뷔페/코스처럼 이름으로 고르는 취향은 기존의 직접 선택을 사용한다. 해당하지 않는 것과 아직 모르는 것에는 위의 별도 상태를 제공한다. 이는 별도 검사를 다시 시작하라는 뜻이 아니라 같은 결과로 이어지는 마지막 확인이다.

구체적인 색상·옷의 세부 형태·실제 금액은 여기서도 자동 추정하지 않는다. 각 항목은 기존 선택지만으로 충분히 표현되는지 검토하고, 현재 선택에 없는 취향은 '맞는 보기가 없어요'로 남길 수 있게 한다. 마지막 직접 선택과 앞 문장의 답이 함께 있을 때는 둘 다 보존한다. 예를 들어 야외 문장에는 낮게 답했지만 장소로 야외를 직접 고르면 어느 쪽을 정답으로 삼지 않고, 사용자가 답을 바꾸거나 그대로 둘 수 있게 확인한다. 공개할 전체 문항 수와 소요 시간은 이 흐름이 확정되고 실제로 확인한 뒤 적는다. 현재 32는 동의 문장 후보 수이며 전체 질문 수나 최적 길이가 아니다.

## 7. 결과의 중심: 답 두 개 이상을 연결해 설명하기

개인 결과는 다음 순서의 원고를 갖는다. 이는 시각 디자인 확정안이 아니라 정보와 해석 계약이다.

1. **내가 직접 고른 우선순위**: 사용자가 마지막에 고른 내용을 중심에 둔다. 고르지 않았으면 우선순위를 지어내지 않는다.
2. **내 답을 함께 보면**: 아래 조건을 충족하는 설명을 주제 순서대로 최대 세 개 보여준다. 최대 세 개는 읽기 부담을 위한 편집 선택이며 성향 상위 세 개가 아니다. 나머지 설명과 모든 원문은 펼쳐 볼 수 있다.
3. **실제 준비에 써보기**: 설명 하나에 바로 할 수 있는 행동이나 결정 질문 하나.
4. **아직 정하지 않은 것**: 미정·비해당·답하지 않은 내용의 상태를 보존한다. 안 정했다고 준비 부족을 판정하지 않는다.
5. **상대와 함께 보면**: 독립 응답 후 같은 문장과 우선순위를 나란히 보여준다. 개인 결과를 보기 위해 초대를 강제하지 않는다.

높은 응답은 4~5를 뜻한다. 이 묶음은 문장 편집 조건일 뿐 통계적으로 검증된 심리 경계가 아니다. 결과마다 사용한 실제 답을 표시하며 한 답만 근거인 설명은 두 답 조합인 것처럼 표시하지 않는다. 어떤 조건도 충족하지 않으면 서술형 특성을 만들어 채우지 않는다.

| 조건 | 설명 후보 | 연결할 준비 행동 | 금지하는 확대 해석 |
|---|---|---|---|
| B1·B2 높음 | “전체 예산은 지키면서, 꼭 하고 싶은 곳에 비용을 더 나누고 싶어 해요.” | 더 쓰고 싶은 한 항목과 줄여도 되는 한 항목을 직접 정하기 | 절약형·현명한 소비·실제 감당 능력 |
| B1 높음 + 재배분 질문에서 사진·영상 직접 선택 | “총액은 지키되, 사진·영상에 더 배분하고 싶어 해요.” | 두 견적을 같은 총액으로 맞추고 다른 항목에서 줄일 수 있는지 비교 | 취향 점수만으로 지출 의사 생성 |
| R1·R2 높음 | “자연스러운 순간도, 미리 준비한 사진도 남기고 싶어 해요.” | 촬영 전에 꼭 남길 장면과 자유롭게 담을 시간을 각각 요청 | 두 답이 모순·우유부단·욕심 |
| T2·T3 높음 | “세부 결정은 맡겨도 괜찮지만, 진행 상황은 함께 알고 싶어 해요.” | 중간 공유 시점과 함께 결정할 범위를 직접 정하기 | 상대 불신·간섭형·통제형 |
| F1·F2 높음 | “가족의 바람은 먼저 듣고, 마지막 선택은 둘이 하고 싶어 해요.” | 상의할 내용과 둘이 최종 선택할 내용을 나누기 | 가족과 갈등·독립형·관계 우열 |
| V3·V4 높음 | “둘의 이야기는 넣고 싶고, 전체 순서는 간결했으면 해요.” | 꼭 넣고 싶은 이야기 한 가지를 고르기 | 짧은 식이면 감동 부족이라는 주장 |

| H1·H2 높음 | “힘들 때는 이야기를 먼저 들어주고, 몰린 일도 나눠주길 바라요.” | 이야기만 들어줄 때와 일을 나눌 때를 구분해 요청하기 | 본인이 상대에게도 잘해준다는 평가 |
| D1·D2 높음 | “다른 후보도 보고 싶고, 정한 조건에 맞으면 선택하고 싶다고 답했어요.” | 선택을 끝낼 조건과 비교 범위를 직접 정하기 | 상충 답을 평균내어 균형형이라고 부르기 |
| B1·B3 높음 | “정한 총액을 지키고 싶지만, 새로 원하는 것이 생기면 증액 여부도 의논하고 싶다고 답했어요.” | 어떤 경우에만 총액을 다시 의논할지 확인하기 | 일관성이 없다·돈 관리에 약하다 |

전부 높음·낮음·중간이라고 별명이나 특별 유형을 만들지 않는다. 직접 우선순위가 없으면 “먼저 지킬 기준은 아직 고르지 않았어요”로 둔다. 모든 답이 낮으면 “이번 문장들과는 거리가 있다고 답했어요”라고 하고 원문과 답을 보여준다. 여기에 맞지 않는 개인 기준은 결과의 로컬 편집 메모로 적을 수 있지만 공유 링크나 서버에 넣지 않는다.

## 8. 커플 결과: 공통 선호와 가까운 응답은 다르다

- 같은 긍정: 둘 다 4~5에 답한 문장만 “둘 다 원한다고 답한 것” 후보에 넣는다.
- 같은 낮은 응답: 둘 다 1~2라고 해서 반대 취향이 같다는 뜻은 아니다. 원문과 낮은 응답만 보여준다.
- 중간 포함: 2/3 또는 3/4가 가까워도 공통 긍정이나 공동 우선순위로 올리지 않는다.
- 응답 차이: 원점수의 차이를 보여주되 갈등·위험·중요도 순위로 변환하지 않는다. 첫 대화 주제는 둘 중 한 사람이 직접 우선순위로 고른 항목을 먼저 제안하고, 그 이유를 명시한다.
- 비해당/미정/건너뜀: 불일치와 별개다. 한 사람이 가족 주제를 비해당으로 둔다고 “가족관이 다르다”고 표시하지 않는다.
- 도움: 둘 다 경청을 원한다는 것과 서로 그 도움을 줄 의사·여유가 있다는 것은 다르다. “상대에게 해줄 수 있는 방식도 이야기해 보세요”로 연결한다.
- 취향이 다른 두 사람에게 중간값을 정답으로 주지 않는다. 사진은 서로 원하는 장면을 포함할 수 있지만, 장소·총예산 등 하나를 골라야 하는 항목은 후보와 조건을 함께 정하도록 안내한다.

예시 원고: “두 분 모두 사진·영상에 더 배분하고 싶다고 골랐어요. 촬영에 얼마를 쓸지는 아직 정하지 않았어요. 원하는 장면부터 각각 골라보고, 전체 예산 안에서 어떤 항목을 줄일 수 있는지 함께 확인해 보세요.”

부적절한 원고: “두 분은 감성형 찰떡 커플입니다. 사진 예산을 늘리면 만족도가 높아져요.” 후자는 측정하지 않은 유형·궁합·미래 만족도를 지어낸다.

## 9. 재미와 정확성을 함께 만드는 기준

- 재미의 단위는 멋진 유형 이름보다 “따로 생각했던 두 답이 이렇게 연결되는구나” 하는 이해다. 이것이 실제로 재미있는지는 관찰해야 한다.
- 문항을 다시 길게 읊는 것 대신 짧은 연결 설명 + 실제 답 근거 + 준비 행동을 쓴다.
- 모든 설명에 “내 생각과 달라요”를 제공한다. 누르면 근거 답을 수정하거나 해당 설명을 접는다. 수정 전후 응답을 임의로 합치지 않는다.
- 긍정적인 형용사를 누구에게나 붙이는 방식, 동물 캐릭터, 가짜 희귀도, 가짜 정밀한 %는 쓰지 않는다.
- 원응답 없는 공유 카드에는 사용자가 확인한 한 줄과 응답값이 없는 일반 시작 링크를 둔다. 이 링크만으로는 두 사람 결과를 자동 비교할 수 없다. 비교 초대에는 첫 사람의 답이 필요하므로 포함할 답과 공개 범위를 보여주고 별도로 확인한다. 가족·돈 원응답을 포함하는 URL fragment를 '원응답 없는 초대 링크'라고 설명하지 않는다. 링크는 암호화·신원 확인 수단이 아니다.

## 10. 구현 전에 닫을 검토와 완료 기준

이 문서는 제품 질문에 대한 구체적 설계 산출물이다. 운영 v2.0 교체나 새 해석의 배포 완료 보고가 아니다. 이번 턴에는 문항·결과 원고와 실제 사람 검증안을 먼저 완성한다.

1. 문항별 한 의미, 중복 용도, 낮은 응답의 과잉 해석, 가족·예식 비해당, 비용과 중요도 혼동을 적대적으로 재검토한다.
2. 문항·응답·근거·결과 규칙을 같은 버전으로 고정하고 1/2/3/4/5·비해당·미정·건너뜀·미노출 상태를 보존한다. 구판 링크는 구판 원문과 해석으로 연다.
3. 사람에게 문장을 자기 말로 설명하게 하고, 왜 답했는지와 결과 중 틀리게 느껴지는 문장을 확인한다. 진행자의 설명 없이 같은 뜻으로 이해되는지 항목별 기록한다.
4. 혼자 끝내도 유용한지, 상대와 비교했을 때 비난보다 구체적 대화가 생기는지 관찰한다. 완료 시간·지루한 구간·공유 의향은 묻고 실제 행동과 구분한다.
5. 구현 시 관련 상태·조합·공유·버전 회귀 검사를 하고 실제 화면을 확인한다. 자동 검사 성공은 사람 검증을 대체하지 않는다.

### 실제 사람 확인용 진행 문안

- 시작: “검사를 평가하는 자리입니다. 답을 잘 고르는지를 보는 자리가 아니에요. 이해가 안 되면 그대로 말씀해 주세요.”
- 문항: “이 문장은 어떤 뜻으로 읽혔나요?”, “고르기 어려웠다면 어떤 부분 때문인가요?”, “내 상황에는 없는 일인가요?”
- 결과: “이 설명이 나온 이유를 어디에서 찾을 수 있나요?”, “맞지 않는 말은 무엇인가요?”, “결혼 준비에서 실제로 해볼 일 하나가 떠오르나요?”
- 커플: 각자 따로 답하고 각자 공유할 범위를 확인한다. 비교 뒤 “서로에 대해 새로 알게 된 게 있나요?”, “이 표현이 상대를 탓하는 말로 느껴지나요?”
- 기록: exact 문항/버전, 참여자 임의 번호, 자발적 설명, 오해, 진행자 도움 여부, 수정 후보, 재확인 여부. 이름·가족 사정·실제 금액·녹음을 기본 수집하지 않는다.
- 판정: `이해 확인 / 다르게 이해 / 미평가`, `유용 / 유용하지 않음 / 모름`을 구분한다. 적은 인원에게 통과했다고 모든 소비자에 대한 정확도 숫자를 만들지 않는다.

### 반드시 확인할 실패 사례

전부 5, 전부 1, 전부 3, 전부 미정, 모든 가족 비해당, 예식 계획 없음, 한 주제만 응답, 우선순위 없이 완료, 선호는 높지만 추가 배분 의사 없음, 총액 유지와 증액 논의 동시 긍정, 세부 위임과 중간 공유 동시 긍정, 한쪽만 건너뜀, 중간 응답끼리의 비교, 앞 동의 답과 마지막 직접 선택의 차이, 초대 링크를 제3자가 열었을 때, 이전 문항 수정 뒤 요약·추가 질문·공유값의 동기화. 전부 높더라도 어느 항목을 더 중요하게 보는지는 알 수 없으며, 편집 순서로 먼저 노출한 세 설명을 대표 성향이나 상위 성향이라고 부르지 않는다.

### 독립 적대 검수 후 수정 기록

- 비용 총액 확인 B4는 보편적인 계약 확인 행동이어서 항목별 사전 배분 의향으로 교체했다. 계약 확인은 응답과 무관한 실행 안내로 분리한다.
- D3의 확인 대상, D4의 예약 전 시점, T1의 공동 탐색 시간, T2의 위임 범위, F4의 대화 주체를 구체화했다.
- 낮은 동의에서 실내·식사 대안 등을 추론하는 대신 여섯 취향 항목을 같은 흐름에서 직접 확인하도록 명시했다. 문항 수·시간을 확정된 성능처럼 약속하지 않는다.
- 응답 없는 일반 링크와 답이 담기는 비교 초대를 구분했다. 전체 답이 높거나 낮거나 중간인 경우의 유형화, 동의 정도를 중요도로 바꾸기, 같은 도움 희망을 실제 제공 의사로 바꾸기는 계속 금지한다.
- 남은 검증: 32문장에 직접 취향·우선순위 확인까지 더했을 때의 피로, V4/T2/F4의 문구 이해, 실제 결과의 구별성과 대화 유용성. 이번 수정은 독립 원고 감사이며 실제 소비자 검증이나 운영 반영이 아니다.
