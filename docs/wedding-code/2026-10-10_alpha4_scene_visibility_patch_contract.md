# alpha.4 장면 표시·첫 대화 보완 계약

## 근거와 범위

기준 커밋은 `6099dc392313cb2e2e48b9908be301183e031b15`다. 30문항·12장면의 원문과 ID, 5점 응답 라벨, 측정판 `likert-preferences-alpha.1`, 은행 `preferences-20261008-r2`, 저장·공유 형식, 비율·대표 표·16캐릭터 계산을 유지한다. 표현판 `likert-letters-alpha.4` 안에서 이미 남아 있는 원답의 표시 누락과 초기 장면 선택을 보완하며, 새 Git SHA·manifest·검증 기록으로 정확한 변경을 구분한다. 기존 원답을 새로운 문항 의미로 읽거나 재채점하지 않는다.

별도 연구·읽기 검수 채팅이 전달한 두 반례를 실제 소스에서 확인했다. 논문 검토와 AI 검수는 사람·전문가 타당성 검증을 대신하지 않는다. 현재 사람·전문가 검증 참여자는 0명이다.

## 1. 상단에서 마지막 장면의 차이를 보존

- 반례: 도움 장면의 L/A가 투어 5/1, 비교 4/1, 연락 5/4인 답과 연락만 4/5인 답. 휴식은 모두1, 나머지 문항은 같은 CJOL 구성이다. 대표 L과 L/A 동의 비율은 같지만 연락 직후의 실제 원답이 다르다. 기존 `first + first different` 선택은 투어·비교만 보여 상단 두 설명을 같게 만든다. 하단 원답은 이미 보존되어 있다.
- 후보 A: 차이가 있으면 완전한 장면 최대3개를 원문 순서대로 모두 짧게 나란히 표시한다.
- 후보 B: 동의/휴식 변화가 더 크다고 정한 장면을 우선한다. 표시 순위가 숨은 중요도 판단으로 읽힐 수 있다.
- 후보 C: 현재 두 장면을 유지한다. 확인한 표시 누락을 남긴다.
- 선택: A. 원답을 줄이지 않고, 새 심리적 중요도·갈등 점수 없이 마지막 장면도 자기 확인에 사용한다. 4와5를 같은 원답으로 압축하지 않는다. 같은 조합·부분 응답·비수치 응답과 8개 준비 포인트 행의 기존 계약을 유지한다.

필수 회귀는 두 답의 코드·비율이 같고, 상단에서 연락 장면과 해당 L/A 수치를 각각 확인할 수 있으며 설명이 달라지는 것이다. 같은 답이 반복된 장면의 제목도 원답으로 보존한다. 입력 객체를 변경하지 않는다.

## 2. 초기 대화에 두 사람의 답이 있는 장면을 선택

- 반례: 예식장 C/E에 두 사람이 모두 비해당, 사진에는 첫 사람5/1·두 번째1/5. 기존 money/첫 장면 고정은 비해당 예식장부터 대화를 연다.
- 후보 A: 같은 문항에 두 사람의 수치 응답이 있는 첫 장면을 기존 순서대로 선택한다. 해당 주제가 없으면 수치 쌍이 있는 첫 주제를 먼저 연다. 수치 쌍이 없을 때에는 양쪽 모두 비해당인 장면을 다른 후보가 있으면 초기 선택에서 뒤로 둔다.
- 후보 B: 가장 큰 점수 차이가 나는 장면부터 연다. 차이를 긴급도나 문제 크기로 해석할 위험이 있다.
- 후보 C: 기존 고정 시작을 유지한다. 확인한 불필요한 첫 대화를 남긴다.
- 선택: A. 중립3도 수치 응답이며 모름/비해당/미응답으로 바꾸지 않는다. 임의의 궁합·갈등·긴급도 점수를 만들지 않는다. 사용자가 직접 고르면 비해당 장면도 볼 수 있고 전체 원답에는 그대로 남는다. 모든 장면에 확인할 수치 쌍이 없다면 해당 상태를 정직하게 표시하며 실제 차이를 만들어내지 않는다.

필수 회귀는 실제 결과 UI의 초기 선택값, 활성 주제, 사용자가 다시 비해당 장면을 볼 수 있음, 중립3, 비수치 상태·원답 불변이다. 같은 탭에서 새 두 사람 링크를 열어 비교할 답이 바뀌면 새 원답에 맞춰 초기 주제·장면을 다시 선택한다. 두 답변 시각이 같아도 원답이 다른 링크는 구분하고, 동일한 원답의 화면 갱신은 사용자의 선택을 유지한다. 이 선택 초기화는 받은 두 snapshot에만 적용하며 이 탭의 개인 답이나 기존 링크를 교체하지 않는다.

## 3. 공동 경청 요청의 구체적인 질문

같은 도움 장면에서 두 사람이 L에4 또는5로 동의했으면, 그 관찰을 바탕으로 누가 먼저 이야기하고 지금 서로 들어줄 수 있는 범위가 어디까지인지 묻는다. 실제 제공 능력이나 관계 만족을 단정하지 않는다. 비수치·중립·낮은 동의에는 경청을 원했다고 말하지 않는다. 점수·개인 부탁·원답은 유지하고 기존 대화 문장 안에서 다듬는다.

## 4. 첫 완료와 수정에 함께 쓰는 결과 버튼

`9ee6975f82311780262afc8f841ccdf06e4459a3`의 실제 Preview에서 30문항을 처음 완료해도 보조 버튼이 ‘고친 답으로 결과 돌아가기’라고 표시되는 것을 확인했다. 첫 결과와 수정 이후 모두 적용되는 ‘현재 답으로 결과 보기’로 바꾼다. 버튼의 노출 조건과 동작, 응답·점수·저장·공유 계약은 유지한다. 실제 첫 완료와 수정 진입에서 새 문구와 결과 열기를 확인하고, 변경된 Client 바이트에 영향받는 기존 저장·공유 guard를 다시 증명한다.
