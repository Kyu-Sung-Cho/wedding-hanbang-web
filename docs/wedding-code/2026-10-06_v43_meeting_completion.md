# 팀 미팅 재검수와 v4.3 반영 계약

## 요구사항 대조

- 문항 번호: 현재 각 문항에 보이는 고정 번호가 있으며 두 질문이 한 화면에 있어도 각각 표시한다. 유지한다.
- 레터: V/S, W/D, U/F, H/A는 각기 한 뜻을 가지며 나와 상대에 동일한 정의를 쓴다. 유지한다.
- 결과: 실제 선택 개수와 분모, 글자 정의, 원응답을 유지한다. 커플에도 각자의 계산 이유를 같은 계산기로 보완한다.
- 공유: 비교 초대와 질문만 보내는 선택의 목적과 실행 이름을 구분하고 절차 번호를 보인다.
- 문항: 68개 전수 검수 후 뜻 겹침, 한쪽만 다정하거나 책임감 있게 보이는 표현, 다른 측면을 묻는 상황 등 명확한 결함을 수정한다.

## 문항판 대안과 선택

1. v4.2 원문을 직접 교체: 구현량은 작지만 이미 생성된 미리보기 답 링크에 새 뜻을 붙일 수 있어 제외했다.
2. 수정 문항을 v4.3-depth로 분리: 기존 판의 문항·답·저장·링크를 유지하고 새 판은 별도 표식과 키를 사용한다. 이 안을 선택했다.
3. 질문을 무조건 더 추가: 현재 반복 문제를 남긴 채 피로를 늘릴 수 있어 제외했다. 먼저 현재 문항의 의미와 상황을 고친다.

## 적대적 검수

- 공유 코드는 은행 해시를 싣지 않으므로 원문 수정에는 정확한 판 분리가 필요하다.
- v4.3의 답과 짐작을 v4.2 링크에 섞거나 반대로 넣으면 전체 링크를 거절해야 한다.
- 이전 판의 자동 저장 끄기 선호는 따르되 진행 답과 기록을 자동 이전하거나 지우지 않는다.
- 커플 계산 이유는 검증된 원응답에 기존 buildResult를 적용한 값만 표시한다. 원응답이 없거나 요약값과 어긋나면 근거를 만들지 않는다.
- 보기 의미가 흐려질 정도로 결과 방향을 숨기지 않는다. 양쪽에 실제 선택할 이유를 갖게 하고 지난 한 번의 행동을 묻는 문항을 유지한다.

## 주장 감사

E: 이번 작업은 작성 검수와 코드·합성 응답 검사다. 실제 참가자 자료는 0건이다.

I: 고정된 네 준비 기준과 하위 장면의 응답을 더 이해하기 쉽게 묻고 설명하는 개선이다. 내면 전체, 궁합, 결혼 성공, 검사 정확도나 예측 불가능성을 확인한 것은 아니다.

최종 코드 반영 gate는 문항 감사 문서의 원문·보기·재인용 동기화, 구조·극·강도 불변 대조, 공통 문항 검사, 판 격리 부정 사례와 실제 화면 검수로 확인한다. 운영 배포의 기존 오류수집 본문 개인정보 gate는 별도로 유지한다.

## 디자인 근거 경로

E: 기존 커플 결과를 합성 응답으로 직접 열고 화면을 캡처해 Lazyweb 개선 리포트를 요청했다. 생성 작업은 서버 합성 시간 초과로 종료되어 리포트·시안 근거는 받지 못했다. 현재 승인된 DESIGN과 실제 화면·코드 검토를 기준으로 범위를 제한했다. 생성 실패를 디자인 검증 통과로 다루지 않는다.

## 최종 문항·원응답 대조

68문항 중 명확한 결함 33개를 수정하고 35개를 보존했다. 문안 전후와 남은 다양성 한계는 문항 감사에 기록한다. 커플은 실제 v4.3 bank와 화면 판을 연결하고, 비교값이 같아도 교차 판 원응답은 거절한다. 관련 4파일 94검사, 해당 6파일 ESLint 및 정상 입력 통과·사람 교환/검증 우회/판 혼합 오류 검출·원본 복원을 확인했다. 전체 저장소 gate와 새 Preview 화면 확인은 별도 최종 검증 대상이다.
