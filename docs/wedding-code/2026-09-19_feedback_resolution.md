## 20문항 전체 검토와 공통 안내

PDF에 등장한 문항만이 아니라 A1–A5, B1–B5, C1–C5, D1–D5 전체의 상황·질문·선택지를
읽었다. 각 답의 주체·시점·행동을 구분할 수 있었고, 이번 대조에서 원문을 다시 바꿔야 할
확정 결함은 발견하지 못했다. 여러 행동이 순서대로 일어날 수 있는 문항은 남아 있으므로,
이를 “완전히 배타적인 선택지” 또는 “검증된 질문”으로 표현하지 않는다.

이번 공통 안내의 수용 문구:

> 아직 겪지 않았다면 지금 나라면 어떻게 할지 생각해 보세요. 여러 답이 비슷하면 내 선택에 가장 가까운 하나를 골라 주세요.

이 안내는 소개와 질문을 푸는 화면에서 찾을 수 있어야 한다. 모든 문항에 “가장 먼저”를
강제하면 B4의 “결국 표는 어떻게 샀어요?”, C4의 “결국 어떻게 했어요?”와 충돌하므로
기존 질문이 정한 시점을 바꾸지 않는다. 상황에 맞지 않으면 건너뛰는 동작도 유지한다.

결과 설명에서는 D2의 산책을 적극적인 감정 공감으로, D4의 즉시 결정을 좋은 실행 능력으로
단정하지 않는다. 본인이 고른 행동의 인용·응답 수와 다음 대화 제안을 구분한다.

## 원문·계산·버전을 유지하는 이유

- 기존 질문·선택지·가중치·답 기호의 의미를 변경하지 않는다. 현재 코드는 성격 점수가
  아니라 축별로 어느 쪽 답을 더 많이 골랐는지의 요약이다.
- 질문이나 선택지의 뜻을 같은 판에서 바꾸면 과거 공유 링크가 사용자가 고르지 않은
  문장을 인용하고, 같은 연구 기여 판에 서로 다른 질문의 답이 섞일 수 있다.
- 이번 공통 도움말과 화면 배치는 응답의 의미를 바꾸지 않으므로 `v1.0-code`를 유지한다.
  v0.6·v0.8·v0.9·v1.0 과거 링크의 exact-version 해석도 유지한다.
- 앞으로 질문 순간·선택지 행동·주체 등 의미를 바꾸면 새 exact-version과 문서·회귀 검증이
  필요하다. 연구 기여에서 새 판까지 받는 일은 DB·API 허용 판과 별도의 릴리스 조건도
  갖춰야 하므로 화면 수정에 묵시적으로 포함하지 않는다.

전송 결과를 모르는 상태에서 재시도가 429/503으로 거절되면 삭제 코드가 사라지던 문제도
고쳤다. 재시도 중에도 삭제 코드를 복사할 수 있고, 실패 후 삭제·재시도 경로가 유지된다.
저장 여부를 확인하지 못한 요청을 성공이나 미저장으로 단정하지 않는다.

디자인 참고 도구는 한 축씩 넘기는 캐러셀과 대화 문장을 제안했다. PDF의 한눈에 비교하려는
요구를 우선해 네 축을 모두 펼친 상태를 유지했고, 기존 대화 제안에 바로 가는 동선을 보완했다.
도구의 가설 점수는 사용자 이해도나 제품 효과를 입증하는 근거로 사용하지 않았다.

## 추가 재검수에서 발견하고 고친 것

사용자가 다시 전체를 확인해 달라고 한 뒤, 초기 자동 검사 통과와 별도로 예외 응답·
삭제 중 조작·작은 화면의 실제 전환을 다시 확인했다. 아래 수정은 15:07 검증 이후의
앱 소스 변경이므로, 그때의 통과 기록을 이 수정들의 최종 검증으로 사용하지 않는다.

- 삭제 요청을 기다리는 동안 다른 삭제 코드를 입력하거나 중복 요청을 보내면, 첫 요청의
  완료 표시가 다른 코드의 결과처럼 보일 수 있었다. 요청 시점의 코드를 고정하고 입력과
  중복 제출을 잠갔다. 답 전송·즉시 삭제에도 요청 중 중복 실행을 막는 잠금을 적용했다.
- 최초 전송에서 서버가 5xx를 반환해도 저장이 이미 이뤄졌을 가능성을 배제할 수 없다.
  이를 미저장으로 단정하던 경로를 불확실 상태로 바꾸고 삭제 코드·재시도 경로를 보존했다.
- HTTP 2xx만 받고 본문이 잘렸거나 `ok: true`가 없는 경우에는 저장·삭제 완료로 표시하지
  않도록 고쳤다. 확인되지 않은 전송은 불확실로, 확인되지 않은 삭제는 실패로 안내한다.
- 320×568 화면에서 문항 아래로 스크롤한 위치가 다음 문항과 결과에도 남아 질문·코드
  상단이 보이지 않는 문제를 재현했다. 장면·결과·재시작·링크 문맥이 바뀔 때 화면 위로
  이동하고 `main`에 포커스를 옮긴다. 답 선택이나 결과 내부 입력만으로는 이동하지 않는다.
- 커플 결과에서 글자별 뜻이 접힌 설명 안에 남아 있었다. 개인 결과와 마찬가지로
  네 축 설명을 처음부터 공개하고, 사용자가 원하면 직접 접을 수 있게 했다.
- 개인 결과에서 취향 선택으로 이동했다가 브라우저 뒤로가기를 누르면 소개로 돌아가고,
  방금 고른 답이 사라지는 문제를 실제 화면에서 재현했다. 결과 화면의 취향 링크만
  `target="_blank"`와 `rel="noopener noreferrer"`로 열고, `aria-describedby`로 연결한
  “결과를 남겨 두고 새 탭에서 열어요.” 안내를 추가했다. 소개에서는 같은 탭으로 이동한다.
  기존 답을 브라우저 저장소나 공유 주소에 새로 저장하지 않고 원래 결과 탭을 유지하는
  범위로 수정했다. 최종 빌드에서 링크를 누른 뒤 원래 결과 탭의 답이 유지됨을 확인했다.
  인앱 브라우저 도구에는 외부 새 탭이 노출되지 않아 외부 브라우저의 실제 탭 열림은 미검증이다.
