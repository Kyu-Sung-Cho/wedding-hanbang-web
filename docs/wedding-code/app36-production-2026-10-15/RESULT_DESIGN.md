# 36문항 결과 화면 구성

사용자가 참고 화면을 그대로 따를 필요 없이 가장 적합한 방향을 선택하도록 요청했다. 기존 운영 main `67f630b780d9a228c13f70b5a8b9f158c1419550`에서 결과 화면만 변경한다.

## 검토한 방향과 선택

1. 큰 동물과 꽃 장식 중심: 이름은 기억하기 쉽지만 답변 근거와 커플 대화 내용이 뒤로 밀린다.
2. 평균 그래프 중심: 기준 간 비교는 빠르지만 같은 평균을 만든 서로 다른 답을 감추고 능력 점수처럼 보일 수 있다.
3. 작은 동물과 이름 → 답변 근거 → 함께 해볼 일 → 장면별 원답: 기억할 요소와 실제 준비에 쓸 내용을 함께 보여준다. 이 구성을 선택했다.

이 선택은 제품 구성에 대한 판단이다. 이용자 이해도·선호도나 측정 타당도가 실증됐다는 의미는 아니다.

## 구현

- 형용사와 동물 이름을 첫 제목으로 유지한다. 비버·펭귄·고양이·공작·안내용 수달은 각각 별도 그림을 사용한다. 투명 PNG를 Next Image로 표시해 화면 크기에 맞춰 최적화한다.
- 기존 검수된 이름·개인 해석·강점·주의점·대화 문구는 그대로 사용한다. 실제로 채택된 기준만 짧은 태그로 보여준다.
- 수달 안내 이름이 같아도 중간 응답, 모두 동의, 모두 비동의, 미응답, 장면별 상반 응답, 동점·차이 부족을 구분한다. 없는 성향을 새로 만들어 붙이지 않는다.
- 9가지 기준은 각 세 문항의 원답을 먼저 보여준다. 펼치면 질문의 조건, 질문, 원답과 기존 평균을 확인할 수 있다. 평균은 중요도나 능력 점수가 아니며, 빈 답은 3점으로 바꾸지 않는다.
- 완전한 이름은 기존 검수된 유형 카드의 행동 제안을 보여준다. 안내 상태는 답한 장면을 대화로 확인하는 제안만 보여준다. 제안을 합의나 할 일로 자동 저장하지 않는다.
- 커플 화면은 실제 공유된 답 중 두 칸 이상 다른 문항을 먼저 보여준다. 그런 문항이 없으면 정확히 같은 유효 응답을 고른 문항을 보여준다. 궁합·관계 점수로 해석하지 않는다.
- 커플의 이름과 동물 그림은 서버가 두 사람의 이름 공유 동의를 확인한 경우에만 함께 보여준다. 공유 철회 시 새 요약과 그림도 기존 보고서와 함께 사라진다.

## 변경 경계

36문항 원문, 문항 버전·지문, 점수 엔진, 유형 카드 원본, 초대·응답 API, 보관·삭제, DB·권한·동의 규칙을 바꾸지 않는다. 새 DB migration을 적용하지 않는다. 기존 범위의 자동 검사를 그대로 유지하며 운영 배포는 필수 CI와 정확한 source 확인 후 진행한다.

## 사전 검수

- 기존 개인·커플 1,000개씩의 기준 구현 대조를 포함한 관련 4개 파일·78개 테스트 통과.
- 새 표시 전용 회귀검사 34개 통과: 전부 같은 1~5점, 20개 이름과 동물 자산, 1·3·5 원답, 건너뜀, 이름 철회 시 커플 그림 제거와 개인 그림 유지.
- 독립 검수의 관련 3개 파일·63개 검사 통과. 이는 앞선 검사와 겹치므로 더해 세지 않는다.
- 첫 로컬 빌드는 분리 작업 트리에 Supabase 공개 설정이 없어 데이터 수집 단계에서 실패했다. 실제 공개 설정 두 개만 해당 빌드 프로세스에 전달한 재실행에서 TypeScript·1,229개 페이지 생성·운영 빌드가 성공했다. 비공개 운영 키는 복사하지 않았다.
- `wedding-code36-release.mjs --check-only` 통과: 기존 보호 파일 388개 불변, 원격 쓰기 없음.
- 첫 PR CI는 새 환경에서 생성 전인 `next-env.d.ts`에 의존한 PNG 모듈 타입 선언을 발견했다. 결과 자산에 Next의 실제 이미지 타입 참조를 추가하고, 생성된 파일을 일시적으로 제외한 `tsc --noEmit --incremental false`가 통과하는지 확인했다. 검사 기준을 낮추지 않았다.
- 실제 렌더·CI·운영 상태는 후속 실행 증거로 확인한다. 이 사전 기록만으로 운영 반영 완료를 주장하지 않는다.

외부 디자인 근거 도구는 이번 추가 조회에서 호출 제한으로 사용할 수 없었다. 기존 확보 자료, 사용자 참고 화면, 현재 코드와 실제 렌더를 기준으로 판단했다.
