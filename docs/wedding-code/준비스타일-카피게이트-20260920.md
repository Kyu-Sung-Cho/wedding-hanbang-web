# 라운지 준비 스타일 — 카피·상태 게이트

2026-09-20. 기존 문항과 선택을 라운지에서 다시 살펴보는 내부 설계 검토다. 사람 대상 이해도·유용성 검증이나 운영 배포 완료를 뜻하지 않는다. 문항·보기·점수는 변경하지 않는다.

## 적용 기준

`PRINCIPLES.md` P1·P3·P5와 WeddingCode `README.md`의 현재 공개 대화 도구 계약을 따른다. `31_fable_mode_adaptation_protocol_v0.1.md`를 읽었으며, 문서 머리의 RETIRED 지시에 따라 옛 16문항·유형 생성 규칙은 재사용하지 않는다. 아래 후보 → 적대 검토 → 주장 감사는 현행 원칙에 맞춘 작업 기록이다.

## 적대 검토·상태 구분

| 반례/상태 | 허용 동작·카피 |
|---|---|
| 내 답만 있음 | 내 답의 수·원문·주제별 요약만 제공한다. 상대 생각이나 둘의 합의를 만들지 않는다. |
| 둘 다 공유한 같은 판 | 같은 문항에서 실제로 고른 보기 기호와 원문을 비교한다. 같은 집계 방향이어도 다른 보기를 골랐으면 ‘다른 답’이다. |
| 한쪽 또는 양쪽 미응답 | ‘한 사람이라도 답하지 않은 장면은 비교하지 않았어요.’ 같은 답·다른 답의 분모에서 제외하고 행동 안내도 붙이지 않는다. |
| 서로 다른 판 | 개인 요약은 각 판으로 보여주되 ‘서로 다른 문항으로 답해서 나란히 비교하지 않았어요.’ 비교 수·장면별 차이는 만들지 않는다. |
| 없는 판·그 판에 없는 보기/문항 | 다른 판이나 첫 보기로 대체하지 않고 읽기 실패 상태를 반환한다. |
| 저장했지만 공유 안 함/철회함 | 저장과 공유를 구분한다. 모델에 상대 답을 넘길 수 있는지는 API 권한 검증과 UI 공유 상태가 결정한다. 저장 성공만으로 ‘둘이 함께 보기’를 만들지 않는다. |
| 모든 답을 건너뜀 | 답한 장면 0으로 표시하고 글자·성격·같은 점을 만들지 않는다. 저장 허용 여부는 API 계약이 별도로 정한다. |
| 예시 300만원을 고름 | 장면 원문으로만 인용한다. 실제 예산·일정·분담액을 갱신하지 않는다. |

## 주장 감사

| 주장 | 근거 | 판정 |
|---|---|---|
| 현재 문항은 네 주제를 다룬다. | E: 기존 config의 네 축과 문항을 읽었다. | 허용. 모든 결혼 준비 영역이라고 부르지 않는다. |
| 개인 요약은 응답에서 나온다. | E/I: 기존 `buildWeddingCodeResultProfile`이 `buildWeddingCodeSelfProfile`의 셈·인용을 사용한다. | 그 경로를 재사용하며 새 성격 해석을 만들지 않는다. |
| 같은 답은 같은 이유·궁합을 뜻한다. | 근거 없음. | 금지. |
| 가이드가 갈등·실수를 줄이고 완벽한 준비를 만든다. | 실제 사용자 결과 없음. | 금지. ‘함께 해 볼 대화’로만 표현한다. |
| 답의 저장·공유가 완료됐다. | 서버 응답과 권한 검증 필요. | 순수 모델에서 주장하지 않는다. |

카피·범위 게이트는 위 조건으로 구현 가능하다. 기술 검증과 실제 화면 확인은 구현 후 기록하며, 이 문서만으로 통과했다고 표시하지 않는다.

## 검증·변이 계획

단위 검사는 같은 판의 원문·다른 보기·같은 보기, 서로 다른 판, 없는 판, 없는 보기, 한쪽/양쪽 건너뜀, 전체 미응답, 그룹별 실제 합계를 확인한다. 구판의 문구와 다음 대화도 그 판에서 가져오는지 검증한다.

의미 변이는 (1) 판 불일치 거절 제거, (2) 양쪽 미응답을 같은 답으로 계산, (3) 같은 축 방향이면 같은 보기로 계산, (4) 같은 판의 없는 보기 수용을 대상으로 한다. 구문 오류가 아닌 잘못된 결과를 단위 검사가 검출하는지 확인하고 원복 증거를 남긴다. 다른 작업자의 proof와 공통 로그를 동시에 쓰지 않는다.

## 모델 계약·실행 결과

`preparationStyleGuide.ts`의 `buildPreparationStyleGuide(mine, partner?)`는 `{version, answers}`를 받는다. API의 `{sceneVersion, answerCode}`는 UI가 해당 판의 문항으로 디코딩한 뒤 전달한다. 반환 상태는 `solo`, `couple`, `version_mismatch`, `invalid`다. 개인 결과에는 기존 결과의 `reading` 전체와 장면별 선택·다음 대화를 보존하고, 비교 결과에는 실제 같은/다른 답 수와 미응답 수를 따로 둔다. 순수 계산 함수이며 저장·공유·예산 변경을 실행하지 않는다.
