# WeddingCode — 파운더 비전 & 전체 자산 브리프 (v2, 2026-07-06)

> 용도: **이 문서 하나만 복사해서** 외부 AI/자문에게 주면 웨딩코드의 전부를 알 수 있는
> 자기완결 브리프. 외부 파일 참조 없이 구성개념·문항·규칙·데이터 전문을 내장한다.
> §1은 파운더 발언의 충실한 기록(추론과 엄격 분리). 마지막 §13이 던질 질문이다.

---

## §1. 파운더가 웨딩코드에 대해 직접 말한 것 (전량, 시간순)

1. **정체성**: "내가 지금 만들던 **MBTI인 웨딩코드**" — MBTI형 테스트로 구상, 직접 만들던 프로젝트.
2. **작업 방식 요구**: "싹 다 봐줘" / "1번부터 순서대로 다 해줘" — 전수 검토 + 순서 실행.
3. **접근 자체를 의심하라**: "잠시만, 그 전에 **더 좋은 방법은 없지?**" — 정해진 계획(노코드 폼)도 더 나은 대안이 있으면 뒤집기를 원함 → 인앱 프로토타입 전환을 "좋네 이거지" 승인.
4. **검증·출처 요구 (3회 반복 — 가장 강한 신호)**:
   - "이게 최선인 거지? **모든 문항 검증**이 되고 **신뢰도가 높은 출처**를 토대로 한 건지 검토해줘"
   - "지금 모든 것들은 **신뢰성이 입증**되어야 하는 거 아니야? **MBTI처럼?** 그럴 필요는 없나?"
   - "지금 **모든 지표는 근거가 있는 거지**, 웨딩코드에 대해서?"
5. **첫 사용 체험 피드백 (n=1, 본인)**: "질문이 **너무 구체적**이고 실제 결혼하면서 **현실적으로 느껴지는 상황들이 아니었어**" — v0.3 기각. 감정 훅 예시에 "**맞아 이 톤이야**" → 전체 리라이트 지시.
6. **문항 품질 기준**: "**최대한 심플하면서 쉽게, 근데 신뢰성이 있게**" — 단순함과 근거 동시 요구.
7. **최종 비전 (핵심 발언)**: "정말 **사람들이 선볼 때도 '웨딩코드가 뭐예요?' 할 수 있을 만큼 재미있어야 하고 정확해야** 하거든" — 목표는 기능이 아니라 **문화 현상**(맞선 자리의 자기소개 토큰). 두 축 = **재미 × 정확**.
8. **현재 상태 고백**: "솔직히 지금 **어떻게 어디서부터 해야 할지 모르겠어**".

관련 발언(제품 전반, 맥락 연결): ⑨ "앱을 사용하면 알림도 주고 … **청모는 어땠는지 먼저 물어봐주고, 카톡 주듯이**" — 먼저 챙기는 친언니 케어 비전(웨딩코드 내부 신호가 이 개인화의 입력 후보). ⑩ 카톡·문자가 자연스러운 채널이라는 감각.

**파운더가 아직 답하지 않은 것(열린 상태)**: 결과 화면의 주인공(4글자 코드+캐릭터 vs 커플 차이 리포트) / 아모라 프롬프트 연결 시점 / "웨딩한방을 '커플을 아는 앱'으로 만드는 데이터층"이라는 해석(Claude 추론, 미승인).

## §2. 구성개념 12종 전문 (내부 채점 기반 — 0~100 연속 신호, 이분 유형 아님)

공통 원칙: 공개 4글자는 표현층 후보일 뿐 채점 원천이 아님. 아래 "높음/낮음"은 지원
필요·결정 패턴 서술이지 사람 가치 평가가 아님.

### 공개축 후보 4쌍 (쌍 = 반대극이 아니라 "서로 다른 우선 기준" — 동시에 높을 수 있음)

**B — costRisk (비용·리스크 민감도)**
결정 전에 총비용·숨은 추가금·환불/취소 조건·보증인원·계약 리스크가 명확해지기를 원하는 정도.
높음=조건이 명확해야 안심 / 낮음=경험·분위기·가족을 먼저 볼 수 있음.
제품 연결: 견적체크(1순위)·아모라 질문 스크립트·체크리스트. 금지: 쩨쩨함·돈 집착으로 서술 금지.

**D — experienceMeaning (경험·의미 중시도)**
사진·영상·의상·공간 분위기·예식 경험이 오래 남을 정서적 의미로서 중요한 정도.
높음=오래 남을 의미 만족 중시 / 낮음=비용 안정·실행을 먼저 볼 수 있음.
제품 연결: 아모라 예산 인터뷰(의미 항목 보존)·라운지. 금지: 낭비·허영 프레임 금지.

**C — coPreparation (함께준비 기대도)**
준비가 커플의 공동 과정으로 느껴지기를 원하는 정도 — 위임받아도 참여 없으면 외로움.
높음=공동 참여 기대 / 낮음=분업·위임에 편안.
제품 연결: 커플 리포트·온보딩(파트너 초대)·체크리스트 공동 항목. 금지: 의존·집착 프레임 금지.

**O — roleOwnership (역할주도 선호도)**
일을 담당자별로 나누고 맡은 사람이 주도하는 방식 선호("후보 압축은 한 명, 최종은 함께").
높음=효율적 분업 선호 / 낮음=공동 탐색 선호.
제품 연결: 체크리스트 담당자·마감 구조. 금지: 분업=무관심·차가움 프레임 금지.

**P — evidenceDecision (근거기반 결정성향)**
후기·실지불가·계약서·견적 비교·환불 조건이 갖춰져야 결정할 준비가 되는 정도.
높음=근거 확보 후 결정 / 낮음=분위기·신뢰·전문가 안내로 결정 가능.
제품 연결: 견적체크·커뮤니티 실후기·서면 확인 스크립트. 금지: 높음=우월, 낮음=경솔 프레임 금지.

**M — aestheticMood (무드·취향 결정성향)**
비주얼 무드·색감·포트폴리오·첫인상·미적 적합성이 결정을 이끄는 정도.
높음=분위기를 빠르게 읽고 기준으로 삼음 / 낮음=조건·근거 먼저.
제품 연결: 라운지 무드 탐색·아모라(무드+조건 병행 유도). 금지: 피상적·비합리 프레임 금지.

**F — familyIntegration (가족·양가 조율도)**
부모·혼주·하객·식사·동선·예절·양가 화합을 결정에 적극 반영하는 정도.
높음=가족·하객 고려 통합 / 낮음=커플 기준·간소화 선호.
제품 연결: 예절 가이드·커플 리포트·양가 설명 스크립트. 금지: 높음=맹종, 낮음=이기적 프레임 금지.

**U — coupleAutonomy (커플자율 지향도)**
커플 자신의 기준·라이프스타일·실용·취향·예산이 결정을 이끌기를 원하는 정도("우리다운 결혼").
높음=커플 기준 우선(격식 간소화 포함) / 낮음=가족 기대·전통 통합에 유연.
제품 연결: 예절 가이드(생략 가능 절차)·커플 리포트. 금지: 미성숙·불효 프레임 금지.
※ F/U 쌍은 데이터 확인 전 단순 이분 금지(둘 다 높은 사람 다수 예상).

### 내부전용 4종 (공개 정체성 라벨 금지 — 아모라 튜닝·리스크 예방 신호)

**emotionalSupport (공감먼저 필요도)** — 스트레스 상황에서 해결책보다 감정 인정이 먼저 필요한 정도. 아모라 응답 순서(공감→과제) 튜닝용. 금지: 예민함·유난 프레임.

**executionSupport (실행먼저 필요도)** — 감정 정리보다 행동·담당·마감이 먼저 있어야 안정되는 정도. 아모라 행동 요약 선행·액션 카드 튜닝용. 금지: 차가움 프레임.

**decisionPaceRisk (빠른계약 위험도)** — "오늘만 할인"·박람회·상담 흥분 아래 조건 확인 전 계약할 위험. 견적체크 개입·일시정지 룰 제안용. 금지: 충동적·어리석음 프레임.

**guidanceNeed (정보압축 필요도)** — 정보 과부하에서 선택지 압축과 "지금 할 일" 정리를 원하는 정도. 아모라 안내량·온보딩 튜닝용. 금지: 의존적·무능 프레임.

## §3. 현행 폼 전문 (v0.4 — 라이브 배포됨, hanbang.ai/wedding-code)

### 인트로/동의 (원문)

제목: "웨딩코드 3분 테스트 — 프로토타입"
고지: 심리 진단·관계 상담·법률 자문·결혼 성공/이혼 예측 아님. 이번 테스트에서는 최종
유형·점수·캐릭터·4글자 코드가 부여되지 않음. "정답은 없습니다" 고지. 동의 체크 필수.

### 참여자 컨텍스트 5문항

1. 준비 단계(9지선다): 연애 중 / 결혼 얘기 중 / 날짜 미정 준비 / 예식장 탐색 / 스드메 탐색 / 계약 직전 / 계약 완료 / 본식 주간 / 결혼식 이후
2. 답변 방식: 혼자 / 상대와 함께 / 상황따라 / 해당없음
3. 견적 경험: 없음 / 상담만 / 견적 받음 / 계약함
4. 가족 관여도: 낮음 / 보통 / 높음 / 모름
5. 최대 고민(복수): 예산·견적 / 예식장 / 스드메 / 가족 조율 / 역할 분담 / 일정 / 정보 과다 / 모름 / 기타

### 16문항 전문 (형식: 감정 훅 → "이럴 때 나는 —" → 단문 선택지. 괄호=측정 성향)

**q01 · costRisk (필수)** 견적서를 받았는데, 어디서 돈이 더 나올지 감이 안 와요. 이럴 때 나는 —
A 뭐가 포함이고 뭐가 추가금인지부터 따져본다(costRisk) / B 일단 결과물 분위기가 우리랑 맞는지 본다(mood) / C 둘이서 '꼭 필요한 것'부터 추린다(co) / D 실제 해본 사람들 후기를 찾아본다(evidence)

**q02 · experienceMeaning (필수)** 이건 두고두고 기억에 남을 것 같은데, 추가 비용이 있대요. 이럴 때 나는 —
A 시간이 지나도 의미 있을지를 먼저 생각한다(meaning) / B 예산 안에서 감당되는지부터 계산한다(cost) / C 비슷한 느낌의 다른 선택지를 찾아본다(대안) / D 어떤 장면을 남기고 싶은지 둘이 얘기한다(co+meaning)

**q03 · coPreparation (필수)** 마음에 드는 곳을 찾았는데, 상대는 아직 제대로 못 봤어요. 이럴 때 나는 —
A 같이 보면서 처음부터 다시 살펴본다(co) / B 내가 핵심만 정리하고 마지막 결정만 같이 한다(role) / C 결정 전에 둘 다 볼 체크 목록부터 만든다(evidence) / D 왜 끌렸는지 먼저 말하고 반응을 들어본다(emotional 공유)

**q04 · roleOwnership (필수)** 한 명이 알아보고, 결정 전에 둘이 최종 확인하기로 했어요. 이럴 때 우리는 —
A 알아본 사람이 요약하고, 같이 승인한다(role) / B 중요한 건 처음부터 끝까지 둘이 같이 본다(co) / C 되돌리기 어려운 것(계약·환불)만 집중해서 본다(evidence/cost) / D 한 명은 조건을, 다른 한 명은 분위기를 나눠 본다(분업 — 성별 매핑 없음)

**q05 · evidenceDecision (필수)** "그건 그냥 해드릴게요"라고 했는데, 계약서엔 그 말이 없어요. 이럴 때 나는 —
A 문자로라도 남겨달라고 요청한다(evidence) / B 그 혜택이 진짜 필요한 건지 따져본다(cost) / C 그 약속 없이도 괜찮은 곳인지 다시 본다(기준) / D 확인될 때까지 결정을 잠깐 미룬다(pace)

**q06 · aestheticMood (필수)** 투어 중 들어간 곳이 딱 '우리 느낌'이었어요. 이럴 때 나는 —
A 원하던 분위기가 맞는지 찬찬히 뜯어본다(mood) / B 식대·인원·교통 같은 조건부터 확인한다(family/cost) / C 사진과 영상에 어떻게 남을지 본다(meaning) / D 상대와 가족이 볼 기준을 적어 맞춰본다(정렬)

**q07 · familyIntegration (필수)** 우린 분위기에 끌리는데, 부모님은 음식과 교통을 보세요. 이럴 때 나는 —
A 부모님 기준부터 구체적으로 들어본다(family-경청) / B 양쪽 기준을 한 표에 놓고 비교한다(구조화) / C 예산·인원까지 현실적인 차이를 확인한다(cost) / D 우리 기준을 정리해 절충안을 준비한다(autonomy+조율)

**q08 · coupleAutonomy (필수)** 우리 결혼식 기준을 부모님께 말씀드려야 해요. 이럴 때 나는 —
A 그 전에 둘의 기준부터 확실히 맞춘다(autonomy) / B 예산과 이유를 숫자로 정리해 보여드린다(evidence—"설명" 프레임) / C 걱정하실 지점을 먼저 예상해본다(family) / D 부드럽게 꺼낼 첫마디를 준비한다(emotional)

**q09 · emotionalSupport (필수·내부전용 구인)** "걱정된다"고 했더니 상대가 바로 해결책부터 내놨어요. 이 순간 나는 —
A 일단 내 마음부터 들어줬으면 싶다(emotional-高) / B 짧게 공감받고, 같이 정리하면 좋겠다(균형) / C 바로 정리해주는 것도 고맙다(execution — "고맙다"로 차가움 프레임 차단) / D 나한테 맞는 반응을 얘기해두고 싶다(메타 소통)

**q10 · executionSupport (필수·게이팅)** 본식 직전, 연락할 곳과 챙길 게 한꺼번에 쏟아진다면 나는 먼저 —
A 누가 뭘 맡을지부터 나눈다(role) / B 마감 순서대로 할 일을 줄 세운다(execution) / C 보낼 안내 문자부터 정리한다(구체 행동) / D 서로 부담부터 얘기하고 일을 나눈다(emotional→행동)

**q11 · decisionPaceRisk (필수·내부전용 구인)** 상담이 너무 좋아서 당장 계약하고 싶어요. 이럴 때 도움이 되는 건 —
A 하루 자고 나서도 같은 마음인지 보는 것(일시정지) / B 좋았던 점과 걸리는 점을 같이 적어보는 것(공동 정리) / C 총액과 취소 조건을 확인하고 정하는 것(evidence) / D 다른 후보와 한 번 더 비교해보는 것(비교)

**q12 · guidanceNeed (필수·게이팅)** 견적서가 낯선 항목투성이라면, 나에게 필요한 건 —
A 먼저 볼 3가지만 콕 집어주는 것(압축) / B 직접 비교하게 표로 정리해주는 것(자기주도) / C 추가금 붙기 쉬운 곳만 표시해주는 것(리스크 표시) / D 둘이 얘기할 질문 목록으로 바꿔주는 것(커플 대화)

**q13 · costRisk (선택·게이팅)** 마음에 쏙 드는 식장이 예산보다 300만 원 비싸요. 이럴 때 나는 —
A 총액과 추가금, 환불 조건부터 확인한다(cost) / B 그만큼 오래 남을 곳인지 생각해본다(meaning) / C 가족과 하객 동선까지 같이 따져본다(family) / D 둘의 예산 기준을 다시 맞춰본다(couple 기준)

**q14 · roleOwnership (선택)** 한 명은 스타일, 다른 한 명은 조건 보는 눈이 좋아요. 우리라면 —
A 각자 잘 보는 걸 맡고 결과를 공유한다(분업+투명) / B 중요한 후보는 둘 다 같이 본다(공동) / C 한 명이 2~3개로 줄이고 마지막은 함께 정한다(압축→합의) / D 각자 본 걸 한 표에 합쳐 같이 본다(통합·점수 없음)

**q15 · evidenceDecision (선택)** 느낌은 딱인데, 실제 후기가 별로 없어요. 이럴 때 나는 —
A 실제 사례와 포함 조건을 더 찾아본다(evidence) / B 우리 취향과 맞는지 한 번 더 본다(mood) / C 비슷한 느낌에 후기 많은 곳을 더 찾아본다(대안) / D 어느 정도 모험까지 괜찮은지 둘이 얘기한다(허용치 합의)

**q16 · coupleAutonomy (선택·게이팅)** 몇 가지 전통 절차는 줄이고 싶은데, 가족 반응이 걱정돼요. 이럴 때 나는 —
A 왜 줄이고 싶은지 둘의 이유부터 정리한다(기준) / B 걱정하실 부분과 설명 방법을 준비한다("설명"—"설득" 아님) / C 지킬 것과 줄일 것을 구분해본다(존중+간소화) / D 어떤 점이 좋아지는지 자료로 정리한다(근거화)

### 단계 게이팅 규칙 (해당 단계면 바로 노출, 아니면 "아직 겪지 않았을 수 있는 상황" 섹션 + 건너뛰기 허용)

- q10: 계약완료/본식주간/결혼후 → 직접, 그 외 → 가정 섹션
- q12: 견적 경험(상담/받음/계약) 있으면 → 직접, 없으면 → 가정
- q16: 가족 관여 보통/높음 or 결혼얘기중/날짜미정/계약완료 → 직접
- q13: 예식장탐색/계약직전/계약완료 → 직접
- 노출 상태는 stage_flags(direct/hypothetical/skipped)로 응답마다 기록

### 사후 측정 (전부 선택)

피드백 1~5 척도: 내 얘기처럼 느껴졌다(feels_like_me) / 실제 상황 같았다(scenario_realism) / 이해 쉬웠다(clarity) / 불편·평가받는 느낌(stigma) / 헷갈림(confusing)
CTA 관심 1~5: 상대에게 보내 비교 / 커플 리포트 / 아모라 상담 / 견적 확인 / 예절·체크리스트
자유 텍스트 4개: 가장 공감된 질문 / 가장 어색한 질문 / 받고 싶은 리포트 / 자유 의견

## §9. 합의된 로드맵 (사다리 5칸 — 재미와 정확이 각각 어느 칸에서 생기는지)

3. **결과 화면 v1 "미러 프로필"** — 채점 없이 본인 응답을 따뜻한 언어로 되비춤(+맞춤 다음 행동). 재미의 본체 시작. 판정 아님이라 심리측정 없이 정직하게 가능
4. 커플 비교 리포트 — 두 사람 응답의 같음/다름을 "대화거리"로 (판정·궁합 아님)

## §10. MBTI 신뢰성 논점 정리 (합의된 입장)

MBTI는 학술 신뢰성이 낮음에도 이겼다 — 채택을 결정하는 건 검증이 아니라 공감("어 나잖아")과 공유성. 따라서 ①입구 단계: 검증 불필요, 단 "검증된 검사" **주장 금지**(현재 준수 — 표시광고+브랜드 리스크) ②4글자를 정체성으로 파는 단계: **재검사 안정성**이 필수(유형이 홱홱 바뀌면 신뢰 브랜드에 치명상). 마케팅 상한선: "실태조사·참가격 데이터를 바탕으로 만든 결혼 준비 상황 테스트"까지.

## §11. 열린 결정

1. 결과 화면 v1 형태 — 미러 프로필이 최선인가? 더 재미있는 정직한 대안?
2. 16문항 길이 적정성 (바이럴 테스트 통상 8~12 대비)
3. 필수 문항의 계약 단계 편중 — 문항은행 재배분 시점 (현재: 5명 데이터 후 결정)
4. 커플 비교 UX — "차이"를 갈등 아닌 대화로 보이게 하는 설계
5. 4글자 축 확정(B/D·C/O·P/M·F/U는 후보)·네이밍·캐릭터 IP 전략
6. "선 자리 회자"까지의 공유 유발 메커니즘
