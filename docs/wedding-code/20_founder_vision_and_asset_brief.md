# WeddingCode — 파운더 비전 & 자산 브리프 (2026-07-06)

> 용도: 이 문서 하나로 외부 AI/사람에게 "업그레이드나 새로운 접근이 필요한가?"를
> 물을 수 있게 만든 자기완결 브리프. §1은 파운더 발언의 충실한 기록(추론과 엄격 분리),
> §2는 보유 자산 전량, §3은 열린 결정, §4는 외부에 던질 질문 제안.

---

## §1. 파운더가 웨딩코드에 대해 직접 말한 것 (전량, 시간순)

1. **정체성**: "내가 지금 만들던 **MBTI인 웨딩코드**" — MBTI형 테스트로 구상, 직접 만들던 프로젝트.
2. **작업 방식 요구**: "싹 다 봐줘" / "1번부터 순서대로 다 해줘" — 전체를 깊게 검토하고 순서대로 실행하는 방식 선호.
3. **접근 자체를 의심하라**: "잠시만, 그 전에 **더 좋은 방법은 없지?**" — 정해진 계획(노코드 폼)도 더 나은 대안이 있으면 뒤집기를 원함. → 인앱 프로토타입 전환을 "좋네 이거지" 승인.
4. **검증·출처 요구 (3회 반복된 주제 — 가장 강한 신호)**:
   - "이게 최선인 거지? **모든 문항 검증**이 되고 **신뢰도가 높은 출처**를 토대로 한 건지 검토해줘"
   - "지금 모든 것들은 **신뢰성이 입증**되어야 하는 거 아니야? **MBTI처럼?** 그럴 필요는 없나?"
   - "지금 **모든 지표는 근거가 있는 거지**, 웨딩코드에 대해서?"
5. **첫 사용 체험 피드백 (n=1, 본인)**: "질문이 **너무 구체적**이고 실제 결혼하면서 **현실적으로 느껴지는 상황들이 아니었어**" — v0.3 문항 기각. 감정 훅 예시를 보고 "**맞아 이 톤이야**" → 전체 리라이트 지시.
6. **문항 품질 기준**: "**최대한 심플하면서 쉽게, 근데 신뢰성이 있게**" — 단순함과 근거가 동시에 있어야 함(둘 중 하나 포기 불가).
7. **최종 비전 (핵심 발언)**: "정말 **사람들이 선볼 때도 '웨딩코드가 뭐예요?' 할 수 있을 만큼 재미있어야 하고 정확해야** 하거든" — 목표는 기능이 아니라 **문화 현상**(맞선·소개팅 자리의 자기소개 토큰). 두 축 = 재미 × 정확.
8. **현재 상태 고백**: "솔직히 지금 **어떻게 어디서부터 해야 할지 모르겠어**" — 비전과 현 단계 사이 경로가 안 보이는 막막함.

### 관련 발언 (웨딩코드 외 제품 전반 — 맥락상 연결됨)

9. **친언니 케어 비전**: "앱을 사용하면 알림도 주고, 어떻게 지내고 준비 잘하는지, **청모는 어땠는지 먼저 물어봐주고, 카톡 주듯이**" — 먼저 챙기는 친언니. (웨딩코드의 내부 신호 4종이 이 케어의 개인화 입력이 될 수 있다는 구조적 연결)
10. **채널 취향**: "문자로나 카톡으로도 가능하다는 거지?" — 카톡이 자연스러운 채널이라는 감각.

### 파운더가 아직 답하지 않은 질문 (발언 아님 — 열린 상태)

- 결과 화면의 주인공: 4글자 코드+캐릭터(공유 정체성)인가, 커플 차이 리포트(대화 지원)인가?
- 웨딩코드 답변을 아모라 프롬프트에 연결하는 시점.
- (Claude 추론이며 미확정) "웨딩한방을 '업체 찾는 앱'이 아니라 '우리 커플을 아는 앱'으로 만드는 데이터층" — 이 해석에 명시적 승인/거부 없음.

### 라이브 프로덕트 (hanbang.ai — 전부 배포됨)

- **`/wedding-code`** (v0.4): noindex·robots 차단·미링크. 동의→컨텍스트 5문항→16문항(한 화면 한 질문, Option B 단계 게이팅+가정 섹션)→피드백 척도→CTA 관심→자유의견→감사 화면(견적체크/베타 CTA).
- **수집 API**: IP rate limit 10/h·32KB 캡·엄격 스키마 검증(테스트 9종). **채점 코드 0줄.**
- **DB** `wedding_code_responses`: 원시 선택지 JSONB만(점수 컬럼 없음, 의도적), PII 0, service_role 전용(권한 원격검증), form_version으로 v0.3/v0.4 분리.
- **계측**: first-touch UTM 자동 캡처, PostHog 이벤트(started/completed/to_quote_check).

### 활용 가능한 모체(웨딩한방) 자산

- 견적 체크 엔진(판정 금지+회귀테스트 잠금), 참가격 시세 파이프라인, 숨은비용 44항목(실태조사 접지), 아모라(모멘트 루프 12종·케어 아웃바운드 인프라 — 현재 일시정지), 커플 연동 구조, 커뮤니티/동기방, 베타 계정 50개, 유통 테스트 킷(지식iN·카페 완성글).

### 데이터 현황 (정직하게)

- **외부 응답 0. 내부 n=1**(파운더 — v0.3 현실감 기각 → v0.4 반영). v0.4에 대한 응답 아직 0.
- 검증 상태: 사실 접지 ✅ / 커플역학 문헌 미정독(hypothesis) / 심리측정 0(설계상 Phase 5 이전 금지).

### 합의된 로드맵 (사다리 5칸)

1. 문항 공감 확인(지인 5명) → 2. 20명 미니 → 3. **결과 화면 v1 "미러 프로필"**(채점 없이 응답을 되비춤 — 재미의 본체 시작) → 4. 커플 비교 리포트 → 5. 4글자+캐릭터(재검사 안정성 확보 후에만 = 문화 현상 단계).

## §3. 열린 결정 (외부 의견이 실제로 유용한 지점)

1. 결과 화면 v1의 형태 — 미러 프로필이 최선인가? 더 재미있는 정직한 대안?
2. 16문항이 적정 길이인가 — 바이럴 테스트 통상 8~12문항 대비?
3. 필수 문항의 단계 편중(계약 직전 중심) — 문항은행 재배분 시점?
4. 커플 비교의 UX — "차이"를 갈등 아닌 대화로 보이게 하는 설계?
5. 4글자 축의 최종 후보(B/D·C/O·P/M·F/U)와 네이밍·캐릭터 전략.
6. "선 자리 회자"까지의 유통 메커니즘 — 무엇이 공유를 유발하는가?

## §4. 외부 AI/자문에게 이 브리프와 함께 던질 질문 (복붙용)

1. "위 브리프 기준으로, '선볼 때 웨딩코드가 뭐예요?'가 되기까지의 병목이 뭐라고 보는가? 사다리 5칸에서 빠진 칸이 있는가?"
2. "채점 없이 정직하게 만들 수 있는 결과 화면 중 '미러 프로필'보다 재미있는 형식이 있는가? (판정·유형·궁합 금지 제약 하에서)"
3. "16Personalities·티키타카류 바이럴 테스트가 공유를 유발한 구체 장치 중, 우리 가드레일(채점 금지 현 단계)과 양립 가능한 것은?"
4. "구인당 1.3문항인 현 세트에서 Phase 5(신뢰도)로 가는 최소 비용 경로는? 문항은행 144개를 어떻게 활용하겠는가?"
5. "커플 두 명의 응답 비교를 '판정 없이' 보여주는 최고의 UX 사례는?"
6. "이 접근에서 우리가 스스로 못 보고 있는 가장 큰 리스크 하나는?"
