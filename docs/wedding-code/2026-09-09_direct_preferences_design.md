# 웨딩코드: 응답 요약 정정과 직접 취향 확인

2026-09-09 사용자의 구현 요청에 따른 최종 구현 설계.

**상태: 작업 트리 구현 완료 / 관련 회귀 검사 진행 / 통합 최종 검사·운영 배포 진행 중.**
이 문서는 코드에서 확인한 구현 계약이며 최종 품질 검사나 운영 배포 영수증이 아니다.
실제 배포 판정은 최종 commit/tree, 검사 결과, Vercel deployment와 운영 도메인 관측을 함께 확인한다.

## 목표와 선택

관심을 끌 첫 결과와 결혼 준비에 쓸 실제 선택을 연결한다. 사람의 성격·관계·궁합·성공을 추정하지 않는다.

세 가지를 검토했다. 기존 20개 장면의 집계에서 취향을 추론하면 질문이 묻지 않은 것을 답하게 된다. 모든 결혼 분야의 긴 설문은 사용 부담과 미정인 답의 강제를 늘린다. 따라서 기존 장면 도구는 잘못된 해석을 고치고, 별도 선택형 화면에서 **먼저 이야기할 두 주제의 직접 취향**을 확인한다. 선택하지 않은 분야는 중요하지 않다는 뜻이 아니다.

## 순서와 완료 기준

1. **응답 해석 정정**: 공통 장면의 원문으로 비교, 부분 응답·동률 구분, 소수 답의 근거 보존, 수신/제공 도움과 실패 경험을 현재 선호로 단정하지 않기. 현재 공개 진입은 20장면 `v0.8-code`이며 `v0.6-scene` 과거 링크 호환을 유지한다. 기존 선택지·가중치·공유 코드 의미는 바꾸지 않고 결과 설명만 `wedding-code-response-summary-v2`로 구분한다. 답의 분포를 사람의 확신이나 응답 안정성으로 표시하지 않는다.
2. **아모라 도움 설정**: 결과에서 기본 선택 없이 직접 고른 enum만 저장한다. 고르지 않은 기존 설정은 보존한다. 비로그인은 명시적인 계속 버튼에서만 enum을 현재 탭에 15분 보관하고 URL에는 일회용 표식만 싣는다. 로그인 후 계정과 변경 전후를 다시 확인한다. 서버 저장 성공 전에는 완료라고 말하지 않는다.
3. **내가 원하는 결혼식**: 별도 `/wedding-code/taste`에서 우선 주제 최대2, 분위기, 그 주제 상세 최대2, 피할 것, 협의 범위를 최대6개 본문 질문으로 확인한다. 선택·미정·상관없음·계획없음·건너뜀을 구분한다. 질문 수를 채우려고 임의로 주제를 선택하지 않는다.
4. **선택 공유와 상담**: 직접 선택한 고정 enum만 별도 버전 fragment로 공유한다. 두 응답 중 한쪽이라도 확인한 항목은 나란히 볼 수 있지만, 양쪽 모두 값을 고른 경우에만 같은/다른 선택으로 분류한다. 미정·상관없음·계획없음·미응답이 포함되면 직접 확인할 부분이며 합산 점수는 없다. 받은 링크는 본인 인증이 아니므로 받은 응답을 내 계정에 귀속하거나 자동으로 아모라에 넘기지 않는다. 내 선택만 현재 계정의 나만 상담에 초안으로 열고 사용자가 보내기를 눌러야 일반 개인 대화 경로로 전송한다.

## 확정한 질문·응답 계약

`WeddingTasteDraftV1.version`은 `wedding-taste-v1`이다. 자유문 대신 아래의 고정 값만 받는다.

| 필드 | 질문과 범위 | 해석 제한 |
|---|---|---|
| `priorityDomains` | 공간·장소 / 사진 / 입을 옷 / 식사 / 함께할 사람 수 / 식순·연출 중 최대 2개 | 먼저 이야기할 주제이며 예산 비율·순위·추가 지출 약속이 아니다. 선택하지 않은 분야를 낮은 중요도로 보지 않는다. |
| `mood` | 공유 `WEDDING_STYLE_OPTIONS`의 4개 분위기 중 최대 2개 | 장면 응답에서 추론하지 않는다. 기존 공동 준비 정보에 자동 반영하지 않는다. |
| `details` | 고른 주제별 질문만 0~2개. 공간·사진·식사·규모는 1개 값, 옷·식순은 최대 2개 값 | 규모는 본인의 희망이다. 실제 초대 인원·계약 인원·양가 합의가 아니다. |
| `avoids` | 고정된 8개 항목 중 최대 3개 | 개인적으로 피하고 싶은 것과 공동 계약 조건을 구분한다. |
| `negotiability` | 세부 값을 직접 답한 주제에만 `prefer_keep` / `open_to_options` / `undecided` | 다른 안을 함께 검토할 의사이며 양보·동의 완료가 아니다. |

선택 상태는 `{ status: "answered", values: [...] }` 또는
`{ status: "undecided" | "no_preference" | "not_applicable" | "skipped" }`다.
상태형 답에 `values`를 섞지 않고, `answered`의 빈 값·중복·허용되지 않은 enum·개수 초과를 거절한다.
`details`는 고른 주제에만 존재하며 `negotiability`는 세부 값을 실제로 고른 주제에만 존재한다.
기본값은 모두 건너뜀이다. 명시한 미정·상관없음·계획없음은 응답이지만 전부 건너뛰기는 공유·상담할 선택으로 세지 않는다.

주제를 해제하면 그 주제의 세부 답과 협의 의사를 함께 지운다. 세부 답을 바꾸거나 미정 등으로
바꾸면 이전 답에 대한 협의 의사도 지운다. 이전 질문으로 돌아가는 것만으로 답을 지우지 않는다.
질문 순서는 우선 주제 → 분위기 → 선택 주제의 상세 → 피할 것 → 답한 상세의 협의 범위다.
상세 답이 없으면 협의 질문을 만들지 않는다.

## 공유와 두 응답의 귀속

새 공유는 `/wedding-code/taste#v=wedding-taste-v1&a=...`에 첫 응답을 싣고 필요할 때만 `b`를 추가한다.
기존 `/wedding-code`의 장면 응답 codec과 섞지 않는다. 알 수 없는 버전·필드, 중복 parameter,
두 번째 답만 있는 링크, 잘못된 enum, 손상·길이 초과 토큰은 다른 버전으로 보정하지 않고 거절한다.
고정 enum의 인코딩은 암호화가 아니며 링크를 받은 누구나 읽을 수 있다. 공유 직전 이 범위와 회수 불가를 알리고 동의받는다.

한 사람의 링크를 받은 경우 내 답을 직접 고른 뒤 비교한다. 두 응답이 들어 있는 링크만 읽은 경우에는
어느 쪽도 현재 로그인 사용자의 답으로 취급하지 않는다. 화면의 "먼저 답한 사람 / 나중에 답한 사람"은
공유 payload의 순서이며 작성자 신원·커플 인증을 뜻하지 않는다. 내 응답이 있을 때만 본인 선택 공유와
아모라 인계를 제공하고, 받은 첫 응답까지 함께 공유하는 선택은 별도이며 기본 해제 상태다.

## 데이터 경계

- 기존 20개 답은 서버·브라우저 저장소에 저장하지 않는다. 공유를 위해 기존 fragment 형식을 유지한다.
- 새 취향도 기본은 화면 메모리다. 이름·날짜·금액·가족 사정·자유문·사진을 수집하지 않는다.
- 로그인·기존 온보딩·개인 상담을 명시적으로 이어갈 때만 새 취향의 허용된 선택값을 현재 탭 `sessionStorage`에 최대 15분 보관한다. 정적 라벨로 전체 전달문을 재구성하며 URL query에는 일회용 표식만 넣는다. 읽고 사용한 임시 항목은 제거한다. 이 보관은 응답 DB 수집이나 장기 기억 저장이 아니다.
- 개인 상담 인계는 현재 사용자·커플에 묶고, 변경·만료·손상은 거절한다. 본문·첨부가 있는 기존 초안을 덮지 않는다. 초안만 연 상태에서는 메시지 저장·AI 호출·예산·일정·할 일 변경이 없다.
- 한 사람의 선택을 공동 `progress.__preferences`, 확정 결정, 예산 배분으로 저장하지 않는다. 상대가 보낸 응답을 AI에 자동 전달하지 않는다.
- Candidate 6.3 연구와 휴면 response/pair/couple-report API의 차단은 유지한다. 이 설계는 측정 연구 수집 재개가 아니다.
- 전용 취향 DB 테이블·마이그레이션은 추가하지 않는다. 도움 설정은 기존 `amora_personalization_preferences` 경로,
  본인이 전송한 취향 상담은 기존 개인 대화·AI 로그 경로를 사용한다. 도움 설정 저장과 취향 상담 전송은 다른 동작이다.

아모라 전달문은 내 선택이며 공동 합의가 아님, 중요도는 추가 지출 약속이 아님, 다른 안 검토는 양보 약속이 아님을
밝힌다. 답하지 않은 취향을 추정하지 않고 다음 확인 질문을 돕도록 요청하며 예산·일정을 지금 변경하지 않도록 적는다.
전달문은 고정 라벨에서 다시 만들고 최대 1,200자를 넘으면 거절한다. 초과 내용을 조용히 잘라 전달하지 않는다.
상담 초안이 열리는 것과 사용자가 보내기를 눌러 기존 개인 대화 저장·AI 호출이 시작되는 것을 구분한다.

## UI

기존 WeddingCode의 정본 색상·Paperlogy·6px 반경과 공통 Button을 사용한다. 한 화면에 한 질문, 복수 선택 수 제한과 해제 동작, 이전으로 돌아가기, 미정/건너뛰기를 제공한다. 결과는 직접 고른 내용 → 상대와 나란히 보기 → 아모라로 이야기하기 순서다. 아모라 전달문과 저장 범위를 행동 직전에 보여준다. 320px부터 넓은 화면까지 넘침·한글 줄바꿈·포커스·선택 상태를 검증한다.

## 출시 판단에서 구분할 것

자동 테스트는 집계·공유·계정 경계·동작을 검증한다. 실제 사용자가 문구를 같은 뜻으로 이해하는지, 취향 파악에 충분한지, 공유하고 싶어 하는지는 사람 사용성 검증 전까지 미검증이다. '완벽한 파악', '검증된 유형', '관계 예측', '흥행 보장'을 제공하지 않는다. 운영 배포 성공은 후보 검사나 로컬 실행과 따로 확인한다.

문서 갱신 시점에 관련 모델·codec·폼·인계·개인 설정 회귀 검사를 진행했으며 통합 최종 검사는 진행 중이다.
실제 로그인·계정 전환, 개인 상담 초안과 전송, 보호된 후보와 운영 도메인의 새 화면 반영은 각각의 실행 증거로 닫는다.
이번 구현을 Candidate 6.3 사람 검증·연구 수집 재개나 전체 서비스의 무결점 보장으로 표시하지 않는다.
