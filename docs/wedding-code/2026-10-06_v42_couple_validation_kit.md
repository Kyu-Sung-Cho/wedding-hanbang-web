# 웨딩코드 v4.2 커플 관찰 준비물

상태: **로컬 관찰 도구 준비 / 실제 커플 확인 0건 / UNVALIDATED**  
대상: `v4.2-depth`의 문항과 결과·초대 화면. 이 파일을 만들거나 도구 검사를 통과한 것은 사람 검증이 아니다.

## 1. 목표와 범위

실제 커플이 문항의 상황·보기를 어떻게 읽고, 응답 요약과 두 사람 리포트를 이해하며, 자신의 기준으로 대화를 시작할 수 있는지 관찰할 준비물이다. 문항 수나 화면 완성도를 심리 측정 타당성의 근거로 삼지 않는다.

| 확인할 것 | 관찰할 행동 | 이 도구로 확인하지 않는 것 |
|---|---|---|
| 문항 이해 | 상황과 모든 보기의 뜻을 자기 말로 설명하는가 | 숨은 속마음·성격의 정확도 |
| 문항 품질 | 정답처럼 보임, 유형을 맞추려 함, 반복·부담, 경험 없음 | 모집단 대표성·요인 구조·재검사 안정성 |
| 결과 이해 | 글자·응답 비율·근거·미정/반반/임시를 구분하는가 | 궁합·관계 성패·신뢰도 확률 |
| 대화 유용성 | 먼저 맞출 기준을 서로 말하고 제안을 수정할 수 있는가 | 실제 합의·역할 분담 확정·갈등 해결 효과 |
| 초대·반환 | 누구의 답이 포함되는지와 상대가 링크를 돌려보내야 함을 아는가 | 실제 상대 수신·서버 연결 완료 |

사용성 관찰 기록의 완료, 문항 이해 성공, 기존 연구 G3, 심리 측정 타당성, 공개 배포 승인은 별개다. 이 도구에는 G3 또는 출시 승인 버튼이 없다. 기존 문서의 표본 수·정량 통과 기준·모집 권한을 이 도구로 바꾸지 않는다.

## 2. 파일과 실행

- [독립 워크시트](validation-kit/v42-couple-validation.html)를 브라우저에서 연다. 서버나 계정이 필요 없다. 외부 글꼴·이미지·분석 도구·네트워크 요청이 없다.
- 입력은 현재 탭 메모리에만 있다. 새로고침·닫기·‘현재 기록 비우기’로 사라진다. 자동 저장, 저장소, 파일 불러오기, 참가자 모집, 메시지 발송, 녹음 기능은 없다.
- 도구 준비 상태에서는 실제 커플 0건을 유지한다. 리허설은 ‘도구 리허설’로 표시하고 사람 관찰 자료와 합치지 않는다.
- 관찰할 제품 화면은 진행자가 별도로 준비한다. 해당 판의 로컬 화면을 사용하고 판이 맞는지 직접 확인한다. 이 HTML은 제품을 실행하거나 제품 답을 읽지 않는다.
- 워크시트는 진행자 화면에 둔다. 참가자에게는 제품 화면을 보여준다. 판정 기준·글자/채점 설명을 질문을 처음 읽기 전에 보여주거나 가르치지 않는다. 처음에는 “어떤 뜻으로 읽혔나요?”처럼 열려 있는 질문으로 듣고, 설명을 제공한 뒤의 이해는 `설명 후`로 기록한다.
- 화면의 보기 순서는 제품에서 바뀔 수 있다. 워크시트 원문 목록의 순서를 화면 순서나 응답 번호로 해석하지 말고 **문장 자체를 대조**한다. 내장 목록에는 채점 극·점수·응답값이 없다.

## 3. 설명과 동의

진행자는 두 사람 각각에게 설명하고 각각의 의사를 확인한다. 상대의 동의로 대신하지 않는다.

> 오늘은 여러분의 성격이나 관계를 평가하는 자리가 아니라, 웨딩코드의 문장과 화면을 이해하기 쉬운지 살펴보는 자리입니다. 정답은 없습니다. 어떤 답을 고르셨는지와 개인 사연은 기록하지 않습니다. 이름·연락처·실제 답·결과 코드·공유 주소도 받지 않습니다. 이해가 어려웠던 위치와 화면 사용 과정만 익명으로 메모합니다. 질문을 건너뛰거나 언제든 멈출 수 있고, 그 이유를 설명하지 않아도 됩니다. 파일로 남기기와 인쇄는 따로 동의를 여쭙습니다.

1. 재사용할 수 있는 임의 세션 ID와 A/B ID를 만든다. 실제 이름·전화번호·날짜·이메일·계정·공유 코드에서 ID를 만들지 않는다.
2. 실제 관찰인지 도구 리허설인지 선택한다. 리허설의 동의 상태는 상태 전이 검사일 뿐 실제 동의가 아니다.
3. A/B의 **참여 및 익명 관찰 메모 동의**를 각각 확인한다. 둘 다 동의하기 전에는 관찰 입력이 잠긴다.
4. A/B의 **JSON 다운로드·인쇄 보관 동의**도 별도로 확인한다. 관찰 동의만으로 파일을 남기지 않는다.
5. 거절·철회가 나오면 설득하지 않는다. 관찰 동의가 취소되면 현재 탭의 관찰 내용·실패·수정 메모가 비워지고 출력이 막힌다. 익명 ID와 최소 동의 상태만 남는다.

이미 내려받은 파일·인쇄물은 탭이 지울 수 없다. 진행자는 별도로 회수·삭제해야 한다. 보관 동의를 거절한 경우 파일을 만들지 말고 탭 안에서만 살펴본다. 자유 메모에는 신원이나 실제 응답이 들어갈 수 있으므로 출력 전 진행자가 내용을 직접 검토한다. 이 검토는 입력 내용의 개인정보를 자동으로 탐지한다는 뜻이 아니다.

## 4. 진행 순서

### 준비

관찰할 문항 ID를 **시작 전에** 고른다. 모든 문항을 한 자리에서 자세히 말하게 하지 않는다. 대화가 필요한 문항을 나누어 관찰하고, 각 문항에서 누가 무엇을 실제로 봤는지 남긴다. 고정 표본 수·시간을 통과 기준으로 새로 만들지 않는다.

전수 관찰이 아니면 관찰하지 않은 문항은 `관찰 안 함`으로 남긴다. 일부 문항 관찰의 성공을 68문항 전체 성공으로 확대하지 않는다. 보기 재진술을 추가하면 실제 테스트 소요 시간에 영향을 줄 수 있으므로 ‘관찰 대화 포함 부담’과 제품만 사용한 부담을 구분한다.

### 문항 — 각자 먼저 설명

설명을 유도하기 전 A/B 각각에게 묻는다. 어느 답을 골랐는지 묻거나 상대 답을 평가하지 않는다.

1. “이 질문은 어떤 상황인가요? 누구의 어떤 행동을 묻나요?”
2. “보기마다 어떤 뜻인지 말해 주세요. 비슷하거나 구별하기 어려운 보기가 있나요?”
3. “좋은 사람·좋은 커플이라면 골라야 할 답처럼 보이나요?” **유형 예측 질문은 최초 읽기 후에만** 묻는다. 사전에 글자 뜻을 가르쳐 답을 맞추게 하지 않는다.
4. “이 보기만 보고 어떤 결과가 나올지 맞추려 하게 되나요?” 예측의 정확도를 확인하는 검사가 아니다. 답을 결과에 맞추려는 행동 여부를 기록한다.
5. 일상/과거 문항: “이 경험을 결혼 준비로 옮겨 읽었나요, 그때 경험 자체로 읽었나요? 결혼 준비와 연결하기 어렵나요?” 개인 사건 내용은 기록하지 않는다.
6. “경험이 없거나 해당하지 않을 때 어떤 선택을 할 수 있다고 이해했나요?” 실제 선택값은 남기지 않는다.

메모는 상황·보기의 **뜻** 재진술이나 혼동 지점만 짧게 적는다. 선택한 보기, 여섯 칸 배분, 강도 단계, 직접 선택, 실제 응답 이유·가족 사연을 적지 않는다. 이해 전/도움 후 상태를 구분하고 ‘설명해 주었으니 이해함’을 최초 이해로 합치지 않는다.

### 결과 — 원문과 설명 연결

제품 화면을 보며 두 사람이 각각 설명하게 한다. 이 도구에 실제 코드·퍼센트·답을 옮기지 않는다.

- 글자는 각 주제의 어떤 준비 기준인가? 영어 원뜻·한국어 이름·전체 정의가 같은 뜻으로 읽히는가?
- 비율의 분모는 유효하게 답한 문항 수인가? 사람의 속마음 확률·정확도·신뢰도라고 오해하는가?
- 문항별 선택 강도와 장면 묶음 비중이 글자 계산에 쓰이는 설명을 이해하는가? 응답 개수의 큰 쪽과 글자가 다를 수 있다는 설명을 이해하는가?
- `한쪽으로 기울지 않은 답`을 모든 보기의 완벽한 중간 또는 ‘모르겠음’으로 오해하는가?
- 한 답만 있는 장면 묶음이 묶음 평균에서 빠져도 일부 동점 정리에는 쓰일 수 있다는 설명을 이해하는가?
- 실제로 보인 문항 원문이 결과 근거와 연결되는가? 보기 문장의 원뜻과 상대/나의 관점이 바뀌지 않았는가?
- `반반`은 이번 채점의 고른 범위이지 응답 개수가 반드시 50:50이라는 뜻이 아님을 아는가? `임시`를 확정 성향으로 읽지 않는가? `미정`을 반대 유형이나 낮은 궁합으로 읽지 않는가?
- 같은 글자라도 합의가 확인된 것은 아니고, 다른 글자도 부적합 판정이 아니라는 뜻을 이해하는가?
- 역할 제안은 아직 선택·합의·저장된 역할이 아님을 아는가? 이미 담당자가 정해졌다고 읽히면 실패를 기록한다.
- 둘이 먼저 맞출 기준을 각자 말할 수 있는가? 실제로 도움이 된 경우와 ‘좋아 보인다’는 반응만 나온 경우를 구분한다. 개인 기준의 내용은 기록하지 않는다.

보지 않은 상태는 `화면에 안 나옴`으로 남긴다. 필요하면 판과 출처가 표시된 예시 화면을 따로 준비하되 실제 결과처럼 소개하지 않는다. 예시·설명으로 확인한 이해는 실제 결과에서 스스로 읽은 이해와 구분한다.

### 초대·반환

실제 발송을 요구하지 않고, 먼저 화면에서 다음 행동을 찾게 한다. 실제 두 사람이 원해서 공유할 경우 기존 제품 동의 절차를 사용한다. 진행자가 메시지나 주소를 수집하지 않는다.

1. 질문만 보내기와 내 답 포함 초대의 차이를 설명할 수 있는가?
2. 답 포함 동의 전 비활성, 공개 범위, 기존 링크 회수 불가를 발견하는가?
3. 상대가 자기 답을 마친 뒤 두 사람 결과를 어디에서 보는지 아는가?
4. 처음 보낸 사람이 결과를 보려면 상대가 두 사람 결과 링크를 다시 보내야 함을 아는가?
5. 공유 창 전달·복사·취소와 실제 메시지 수신을 구분하는가?
6. 새로고침·탭 이동·저장 끄기와 이미 보낸 링크의 범위를 이해하는가?

실제 공유 동작을 하지 않았으면 ‘화면에서 찾음’과 ‘실제 실행함’을 합치지 않는다. 수신은 수신자가 직접 확인한 경우에만 관찰로 표시한다. 이 키트는 수신 증거를 자동으로 확인하지 않는다.

## 5. 종료·실패·수정 판단

- 중도 종료·부담: A/B 각각 완료/잠시 멈춤/중도 종료, 부담 정도, 제품만/관찰 대화 포함 여부를 남긴다. 이유를 말하기 싫으면 ‘기록 안 함’으로 둔다. 중도 종료는 실패한 사람이라는 뜻이 아니다.
- 오해·막힘·압박이 있으면 위치/문항 ID, 관찰한 현상, 도움 제공 여부, 수정 과제를 기록한다. 개인 성향이나 관계 원인을 추정하지 않는다.
- 이해 실패·도움 필요·판단 어려움·큰 부담을 기록했으면 실패/수정 과제를 적어야 기록 완료로 표시된다. 상황과 보기의 재진술이 비어 있거나 확인하지 않은 항목이 남으면 완료 체크만으로 완료가 되지 않는다.
- 동의/답 공개 범위 오해, 궁합·진단 오해, 역할 확정 오해, 사람의 실제 답을 옮겨 적은 경우는 **신뢰·범위 문제**로 표시한다. 도구의 세션 종료를 출시 승인으로 해석하지 않는다.
- 해당 판의 문구를 바꾸면 관찰 근거가 적용되는 원문판을 새 판과 구분한다. 이전 문구에서 관찰한 이해를 수정 문구가 확인된 것으로 옮기지 않는다.

| 종료 표시 | 뜻 |
|---|---|
| 준비 중 / 동의 대기 | 실제 관찰 내용 입력 전 |
| 관찰 중 | 양쪽 동의가 있고 기록이 진행 중 |
| 기록 미완료 / 중도 종료 | 계획한 문항·결과·흐름 확인의 일부가 남았음 |
| 관찰 기록 완료 / 수정 필요 | 계획한 부분을 관찰했으나 오해·문제·열린 수정 과제가 있음 |
| 관찰 기록 완료 / 이번 범위에서 문제 미발견 | 계획한 범위의 기록과 검토를 마쳤고 문제 기록이 없음. 측정 타당성·전체 문항·출시 통과가 아님 |
| 동의 거절·철회 / 내용 제거 | 현재 탭 관찰 메모가 제거되고 출력이 막힘 |

워크시트는 세션 종류, 동의 확인, 예정 문항의 A/B 관찰 상태, 결과/흐름 관찰 여부, 종료 상태, 검토 체크를 바탕으로 기록 상태를 표시한다. 이해 실패를 ‘기록 미완료’로 숨기지 않는다. 확인하지 않은 항목은 성공으로 세지 않는다.

## 6. 명시적 출력과 보관

JSON 다운로드/인쇄는 버튼을 눌렀을 때만 실행한다. 양쪽의 관찰 및 출력 동의, 익명 ID, 실제 답·신원·주소가 없다는 진행자 검토가 필요하다. 부분 관찰도 내보낼 수 있지만 `미완료/중도 종료`를 유지한다. 파일은 관찰 사실과 수정 과제이며 점수·답 코드·검증 승인 파일이 아니다.

내보내기에는 고정 `validationStatus: UNVALIDATED`, `scientificValidity: not_assessed`, `researchGateG3: not_assessed`, `releaseApproval: not_assessed`를 담는다. 현장 관찰이 이루어졌다면 별도 승인된 검토자가 익명 기록의 범위와 질을 검토해야 한다. 이 도구가 기존 gate를 자동으로 통과시키지 않는다.

## 7. 도구 자기 검증

`validation-kit/verify-kit.mjs`는 합성 리허설로 동의 잠금·철회 삭제·출력 경계·부분/완료 상태·고정 UNVALIDATED·공개 문항 원문만 포함됨을 검사한다. 실제 사람은 참여하지 않는다. 실행 영수증은 완료 후 아래에 남긴다.

도구 자기 검증: **2026-10-06 합성 DOM 검사 16/16 통과**. 확인한 범위는 공개 원문 68개 일치, 동의/출력 경계, 철회 메모 제거, 리허설·실제 세션 분리, 중도 종료·완료/수정 필요 판단, 명시적 JSON/인쇄, 메모리 초기화다. 외부 자산·네트워크·저장소 호출 없음도 소스와 합성 실행으로 확인했다. 실제 브라우저 시각 검수는 이 영수증에 포함하지 않는다.

실행: 저장소 루트에서 `node docs/wedding-code/validation-kit/verify-kit.mjs`. 기존 웹 개발 의존성의 jsdom을 사용한다. 제품의 채점·문항·공유·저장을 실행하거나 바꾸지 않는다.

실제 커플 확인: **0건 / UNVALIDATED**. 모집·발송·녹음·사람 자료 수집·배포를 이 작업에서 실행하지 않았다.
