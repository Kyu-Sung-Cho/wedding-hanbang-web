## 중요한 설계 선택

1. 반대 범위 삭제 때 콜백을 계속 허용하는 범위별 세대 변경과, 현재 전역 무효화 경계를 유지하며 단일 전송 소유권에 원본 스냅샷을 두는 안을 비교했다. 후자를 선택했다. 이미 검증된 오래된 콜백 차단을 보존하며 필요한 원문만 올바른 범위에 돌려준다. 첨부 소유권 이전도 표시해 옛 요청이 복구된 미리보기를 해제하지 않게 했다.
2. 작은 화면에서 안내를 숨기거나 글자·입력을 축소하는 대신 안내·검색·추천을 스크롤 영역에 넣었다. 가장 짧은 체험 화면에서는 바깥 열도 스크롤될 수 있다. 입력 접근성 확인이지, 모든 기기에서 충분한 대화 높이를 확보했다는 주장은 아니다.
3. 안전 오탐은 평범한 합의·명시적 의미 정정 구간만 좁게 정규화했다. 문장 전체에 안전 예외를 주지 않으며, 같은 문장 뒤의 실제 위협·폭력 신호는 그대로 검사한다.
4. 기억 문구는 “대화를 저장/기억한다”는 보장 대신 “이 탭의 장기 기억 사용이 켜져 있어요”로 좁혔다. 사용자 설정만 true여도 runtime이 꺼져 있으면 켜짐으로 표시하지 않는다. 웹과 모바일의 해당 상태 설명을 맞췄다.

## 반복 중 실제로 찾고 닫은 문제

- 패널 재마운트 초안 소실, 비공개 안전 보류 충돌, 만료된 전송 잠금: 행동 재현 실패 후 구현하고 정상·반례를 대조했다.
- 반대 범위 삭제가 전역 세대를 바꾸며 전송 원문을 잃는 경로: 실제 mounted DOM에서 빈 문자열을 재현했다. 첫 스냅샷 구현이 별도 안전 보류를 잃는 문제도 추가로 찾아 수정했다.
- 독립 보류 메시지 재확인이 무관한 FileReader에 막히는 경로를 분리했다. 일반 입력 전송은 파일 읽기가 끝날 때까지 계속 막는다.
- 작은 화면 배치 변경 후 검색 자동 이동 및 새 실패 안내 노출 문제를 독립 리뷰로 찾아 DOM 테스트 4개로 보강했다.
- 패널의 기존 정리 확인창이 계정 전환 뒤 새 계정을 대상으로 실행되는 문제를 실제 DOM에서 재현했다. 같은 순간의 범위·세대 변경, 이중 클릭, 늦은 완료가 새 확인창을 닫는 경우까지 대조했다.
- 초기 변형 증명에서 첨부 소유권 보호를 꺼도 검사가 통과했다. 원인은 PDF 미리보기가 실제 `blob:` 해제 분기를 지나지 않은 것이었다. PNG→FileReader→blob 미리보기 경로를 추가해 옛 요청에서는 해제 0회, 새 재시도 성공 후 정확히 1회를 검사했다. 최초 실패 영수증을 보존했다.

TDD 스킬의 행동 재현→실패 확인→최소 수정→대조 테스트 순서를 적용했다. QA 스킬의 자동 커밋·되돌리기 절차는 기존 미커밋 변경 보존과 충돌해 적용하지 않았다. 기존 디자인을 유지하는 배치·동작 보수이며 별도 디자인 보고서 업로드나 유료 작업은 하지 않았다.

2. iOS/Android 실기기 키보드, 배경/복귀, 스크린 리더, 가변 높이 목록의 `maintainVisibleContentPosition`은 미검증이다. 이전 기록을 많이 불러오면 메모리 사용도 늘어난다.
3. signed-in 긴 이력 안내의 실제 브라우저 조합, 다양한 확대 비율·입력기, 모든 접근성 조합을 확인한 것은 아니다.
4. C04의 모든 오탐이 해결된 것은 아니다. 예를 들어 “남편한테 맞았다는 뜻이 아니라 취향이 맞았다는 말이야”, “폭행 당했다는 말이 아니라 서로 취향이 맞았다는 말이에요”는 현재 좁은 수정 밖에 남는다.
5. **C11은 미해결이다.** 현재 모델 이력은 W0/W1/W4만 허용하며 정서 W3·안전 W2/W5를 의도적으로 제외한다(`amoraTrustedHistory.ts`). 제한된 후속 문맥도 동일 사용자·범위·segment의 직전 W0/W1 쌍만 허용한다(`amoraBoundedContinuity.ts`). 장기 기억은 W0/W1만 허용한다(`amoraMemorySourceScope.ts`). 일부 “그 얘기 때문이야” 문장은 선행 대상을 잃을 수 있다. 실제 모델이 유해하거나 냉담하게 답했다는 실측은 이번에 하지 않았다.
6. C11을 닫으려면 일반 정서 상담과 비저장 위기 발화를 분리해야 한다. 다음 결정 후보는 “일반 정서 상담의 바로 직전 서버 연결 한 쌍을 현재 본인 private segment에서만, 도구·장기 기억 없이 이어 쓰되 안전 상담 연속성은 별도로 남길 것인가”다. 허용 범위·유효 시간·종료·삭제 계약 승인 없이 필터를 넓히지 않는다. 복구용 `safetyRecovery`를 후속 상담 기억으로 전용하지 않는다.

이 문서의 완료 단위는 위에 정의한 코드 수정과 증명된 로컬 경계다. 사용자에게 불편이 전혀 없는 제품, 모든 상황의 안전성, 운영 배포 완료를 뜻하지 않는다.

## 다음 검증자가 실제 환경에서 확인할 순서

실행 전 환경·테스트 계정·비용 한도를 승인받는다. 운영 이용자의 상담 원문을 복사하거나 테스트용으로 전송하지 않는다. 아래는 **실행 계획이지 완료 기록이 아니다.**

1. 두 개의 합성 계정을 연결하고 각각 로그인한다. 공유/개인 대화·설정·삭제·모바일 동기화가 기대한 상대에게만 보이는지 확인한다. 특히 연결 해제와 A→B→A 전환 뒤 복구 초안이 나타나지 않아야 한다.
2. 본인 초안이 있는 상태에서 전체 화면↔작은 패널↔결정 보드를 왕복한다. 느린 파일 읽기, 첨부만 있는 질문, 준비 안내에서 이어 온 질문을 각각 확인한다. 전체 새로고침/프로세스 종료는 현재 메모리 수명 밖임을 혼동하지 않는다.
3. 승인된 테스트 환경에서 저장 요청의 헤더/본문을 각각 지연·단절시킨다. 결과 불명 안내와 같은 요청 키 재확인이 하나의 메시지만 남기는지 서버 원장까지 대조한다. “실패”와 “저장 여부를 모름”을 구분한다.
4. 전송 중 반대 범위만 삭제한 경우와 같은 범위 삭제를 대조한다. 전자는 원본·첨부·키가 남고, 후자는 되살아나지 않아야 한다. 옛 성공/실패 응답이 새 초안·새 확인창·첨부를 바꾸면 실패다.
5. 320×568 및 통상 휴대전화에서 긴 이력 안내·검색·오류·보류 복구·첨부를 조합한다. 실제 키보드, 브라우저 확대, 화면 회전, 화면 읽기로 입력·취소·재확인이 접근 가능해야 한다. 검색 중 토큰 도착 및 과거 대화 읽기 중 오류도 확인한다.
6. 모바일에 합성 이력 250개 이상을 넣고 공유/개인 범위를 번갈아 이전 페이지를 읽는다. 같은 시각의 다른 ID, 삭제/권한 전환 중 늦은 페이지, 네트워크 복구를 확인한다. 다른 범위 행·중복·빠진 커서가 없어야 한다.
7. 모바일 과거 답변을 읽는 중 새 답변·긴 스트리밍·이미지 크기 변경·범위 전환·배경 복귀를 확인한다. 실기기의 읽던 메시지가 튀지 않는지, 최신 이동 후 추적이 정상인지 확인한다.
8. 비용 한도를 정한 실제 모델 평가에서 평범한 합의, 명시적 정정, 같은 문장에 섞인 위험 신호, W3 후속 지시어, 승인 전후 행동·원장·출처 설명을 대조한다. 단순 분류 함수 통과를 자연스러운 상담 답변 성공으로 대신하지 않는다.
