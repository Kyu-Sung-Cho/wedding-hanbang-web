2. 전체 회귀·타입·lint·웹 빌드·모바일 export를 수정된 동일 소스 기준으로 재실행한다.
3. 미적용 SQL `20260920120000_amora_approved_decision_records.sql`, `20260920160000_privacy_confirmation_targets.sql`의 승인·출시 순서를 검토한다. 이전 release fence는 `NEW_MIGRATION_NOT_REVIEWED`로 차단된 상태였으며 이번에 해제하지 않았다.
4. 기존 Supabase 프로젝트에서 웹 API·SQL·지원 모바일 버전·구버전 오류 안내의 호환성을 검증한다. DB 새 프로젝트 생성·복원·유료 플랜 변경이 이번 보완의 전제는 아니다.
5. 별도 허용된 검증 환경/계정으로 실제 두 계정 저장→새로고침→파트너 조회, 개인정보 경계, 실제 iOS/Android 권한·알림·로그인을 확인한다. 현재 로컬 대역 검사로 대신할 수 없다.
6. 전체 브라우저 새로고침/앱 종료를 넘는 미확인 작업 복구와 서버 operation/revision 순서 보장은 별도 미완료 계약이다. 민감 초안을 무조건 localStorage에 넣는 방식으로 우회하지 않는다.
7. 실제 AI 응답의 대화 품질·오탐·개인화는 합성 안전성 회귀와 구분해서 검증한다. 이번에는 유료 모델 호출을 하지 않았다.

검토 범위는 위험도가 높은 변경 및 인접 연결 경로다. 171개 파일 전체를 한 줄씩 재검토하거나 모든 기기·네트워크 조합을 실행했다는 뜻은 아니다. 보조 검토 에이전트는 사용량 제한으로 실행하지 못했으며, 독립 에이전트 교차 승인으로 집계하지 않았다. 이번 재현과 판정은 주 에이전트의 로컬 검토다.

권장 순서는 **계정/동의 대상(R5·R2) → 폼 세대/미확인 쓰기(R1·R4) → 조회 복구(R3) → 통합 검증 → 호환성·hosted 검증 → 승인된 운영 배포**다. 새 기능 확장보다 이 연결 경계를 먼저 닫는 것이 맞다.
