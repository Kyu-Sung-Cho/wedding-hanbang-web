# Consumer-Needs Aligned Product Design 2026

> 현재 제품 결정 기준: 2026-07-13
> 시장 자료는 조사 시점의 문제를 이해하기 위한 근거다. 개인 견적의 적정성, 예상 추가금, 계약 안전성 또는 추천 순위를 산출하는 근거로 사용하지 않는다.

## 1. 해결할 문제

예비부부에게 필요한 것은 더 많은 기능이 아니라 다음 세 가지다.

1. 지금 무엇을 확인해야 하는지 알기
2. 업체의 공식 연락처와 서면 절차에서 같은 기준으로 다시 물어보기
3. 직접 확인한 날짜와 계획액·계약 금액·지급액·다음 지급액을 잃어버리지 않고 커플과 정리하기

웨딩한방의 현재 역할은 판단을 대신하는 것이 아니라 확인과 기록을 돕는 것이다.

> 커뮤니티와 시장 자료는 참고하고, 중요한 조건은 직접 확인하고, 확정한 기록만 저장한다.

## 2. 조사 스냅샷

아래 사실은 연결된 원문의 조사 시점과 범위 안에서만 인용한다. 외부 문구에 재사용할 때는 원문 접근, 발표일, 조사 범위와 최신성을 다시 확인한다.

### 혼인 수요

- 2025년 혼인건수 24만 건, 전년 대비 8.1% 증가
- 출처: [대한민국 정책브리핑, 2025년 혼인·이혼통계](https://www.korea.kr/news/policyNewsView.do?newsId=156749798)

### 결혼서비스 정보 비대칭

- 한국소비자원 소비자시장평가지표에서 결혼서비스가 별도 심층 인포그래픽 대상이 됐다.
- 출처: [한국소비자원, 2024 소비자시장평가지표](https://www.kca.go.kr/home/sub.do?menukey=6081&mode=view&no=1003903636&page=0)

### 가격 공개

- 한국소비자원 조사 515개 업체 중 가격 공개 비율 36.1%라는 조사 결과가 공개됐다.
- 출처: [한국소비자원, 결혼서비스 가격 동향 조사](https://www.kca.go.kr/kca/sub.do?menukey=5084&mode=view&no=1003902297)

이 비율은 조사 대상·시점의 공개 현황이지 모든 업체의 현재 상태를 뜻하지 않는다.

### 스드메 추가 지불 조사

- 정부 2024년 자료에는 2023~2024년 결혼한 신혼부부 995명을 대상으로 한 조사 결과로, 스드메 묶음상품 이용자의 기본금 평균 346만원과 추가 지불 평균 174만원이 제시됐다.
- 출처: [정부 「결혼서비스 발전 지원방안」](https://www.korea.kr/briefing/pressReleaseView.do?newsId=156660308)

두 값은 해당 조사 범위의 시장 문제를 설명한다. 특정 견적에 174만원이 추가될 것이라는 예측이 아니며 항목별 예상 추가금으로 배분하지 않는다.

### 공식 가격 정보

- 한국소비자원 참가격은 예식장·스튜디오·드레스·메이크업·스드메의 가격 정보와 통계를 제공한다.
- 출처: [참가격 결혼서비스 가격 정보 안내](https://www.price.go.kr/tprice/portal/pricenewsandtpriceintro/tpriceintro/getWeddingPriceIntro.do)

예식장과 스드메처럼 조사 단위가 다른 값은 합산하지 않는다. 평균·중위값은 개인의 권장 예산이 아니다.

### 계약 조건 문제

- 공정거래위원회는 결혼준비대행업체의 불공정 약관 시정 내용을 발표했다.
- 출처: [대한민국 정책브리핑, 불공정 약관 시정](https://www.korea.kr/briefing/policyBriefingView.do?newsId=156659944)

이 자료는 계약 전 원문 확인의 중요성을 보여주지만 웨딩한방이 법률 판단이나 계약 검토를 제공할 근거는 아니다.

## 3. 외부 자료로 확인한 문제와 제품 가설 분리

### 조사로 확인된 문제

- 결혼서비스 가격과 조건은 업체·지역·시점·포함 항목에 따라 다르다.
- 공개 정보만으로 개인 계약의 최종 금액을 알기 어렵다.
- 계약 전 포함·불포함·변경·취소 조건 확인이 중요하다.

### 아직 검증되지 않은 가설

- 사용자는 업체 원문에서 정리한 확인 질문을 웨딩한방 밖의 공식 문의와 서비스 안의 예산·일정 기록으로 이어갈 것이다.
- 아모라 답변 뒤 예산·일정을 직접 기록하면 재방문이 늘어날 것이다.
- 커뮤니티 글을 가격 정답이 아니라 질문 출발점으로 설명하면 신뢰와 신고 품질이 좋아질 것이다.
- 커플이 같은 예산·일정을 보면 중복 확인과 전달 누락이 줄어들 것이다.

가설은 인터뷰 문장만으로 확정하지 않는다. 행동 지표와 사용자 오인 여부를 함께 측정한다.

## 4. 현재 제품 약속

### 소비자에게 약속할 수 있는 것

- 아모라에게 준비 질문을 남길 수 있다.
- 사용자가 직접 제공한 견적서·계약서 문구를 바탕으로 업체에 다시 물어볼 질문 문장을 정리할 수 있다. 이는 법률 검토나 계약 승인 의견이 아니다.
- 직접 확인한 계획액·계약 금액·지급액·다음 지급액을 구분해 기록할 수 있다.
- 직접 확인한 일정과 할 일을 기록할 수 있다.
- 이용자 작성 커뮤니티 글과 출처가 표시된 공식 시장 자료를 참고할 수 있다.

### 약속하면 안 되는 것

- 여러 항목을 다시 입력받아 견적의 누락·적정성·안전성을 판정하는 독립 기능
- 견적의 적정성 또는 안전성 자동 판정
- 출처 없는 숨은 비용 평균
- 개인 예상 추가금 또는 절약액
- 고정 비율 카테고리 예산 배분
- 업체 목록·평점·포트폴리오·검증·추천·매칭·문의 전송·예약
- 계약서 법률 검토, 계약 승인, 전자서명 또는 업체 전송 대행
- 동기방·동기 가격·계약 기록·타임라인
- WeddingCode 설문·점수·결과·공유·커플 비교
- 별점·짧은 평가 중심의 빠른 후기
- 댓글 단위 신고·차단 없이 새 댓글·답글을 늘리는 기능
- 모든 웹 기능의 모바일 제공
- 계정 삭제 처리 경로가 꺼진 상태에서 삭제 접수·완료 약속

## 5. 핵심 흐름

### Flow A: 질문 정리

입력:

- 준비 카테고리
- 사용자가 직접 아는 조건
- 아직 모르는 항목
- 업체 답변 또는 문서에서 확인할 내용

출력:

- 사용자가 원문에서 확인했다고 제공한 내용
- 아직 확인하지 않은 질문
- 업체에 보낼 수 있는 짧은 질문 문장
- 중요한 결정 전 원문 확인 안내

출력하지 않는 것:

- 등급
- 발생률
- 예상 추가금
- 계약 권고

### Flow B: 직접 예산 기록

- 총예산이 없으면 미정으로 둔다.
- 사용자가 직접 확인한 계획액·계약 금액·지급액·다음 지급액을 서로 다른 상태로 저장한다.
- 계약 금액 기록은 웨딩한방에서 계약했음을 뜻하지 않고, 지급액 기록도 웨딩한방이 결제를 처리했다는 뜻이 아니다.
- 공식 평균이나 AI 계산을 사용자 예산으로 자동 저장하지 않는다.
- 저장 실패를 0원 또는 성공처럼 표시하지 않는다.

### Flow C: 직접 일정 기록

- 사용자에게 의미 있는 제목과 날짜를 입력받는다.
- 안정적인 이벤트 ID로 수정·삭제한다.
- 서버 조회나 소유권 확인이 실패하면 변경하지 않는다.
- 템플릿 권장 시기를 개인 마감으로 표현하지 않는다.

### Flow D: 커뮤니티 참고

- 작성 시점, 일반·협찬·광고 표시와 신고 경로를 보여준다.
- 이용자 작성 정보가 검증된 사실이 아님을 안내한다.
- 글을 아모라 질문으로 이어갈 수 있다.
- 비공개 예산·일정으로 자동 저장하지 않는다.

### Flow E: 공식 시세 참고

- 출처, 조사월, 지역, 항목과 포함 범위를 표시한다.
- 조사 범위가 다른 수치를 합산하지 않는다.
- 개인 견적 판정이 아님을 같은 화면에서 반복해 알린다.

## 6. 웹과 모바일

플랫폼 간 기능 차이를 숨기지 않는다.

현재 모바일에서 공개하지 않는 항목:

- 커뮤니티 글 작성(직접 작성 화면·FAB·초안 퇴역)
- 빠른 후기(작성 화면·초안 퇴역)
- 동기방
- 예절 WebView
- 푸시 알림
- 업체와 예약 기능
- WeddingCode

모바일 소개, 프로필과 튜토리얼은 이 기능을 현재형으로 말하지 않는다.

## 7. 신뢰 설계 규칙

공개 화면에서 가격·업체·계약·법률 사실을 설명하는 문장은 가능한 범위에서 다음 메타데이터를 함께 보여야 한다. 사용자 개인 기록에는 이 규칙을 사실 검증 표시처럼 덧씌우지 않는다.

- 출처
- 조사 또는 작성 시점
- 적용 범위
- 개인 판단에 사용할 수 없는 한계
- 사용자가 다음에 직접 확인할 행동

근거가 없으면 수치를 만들지 않는다. 자료가 오래됐으면 오래됐다고 표시한다. 확신할 수 없으면 `확인 필요`로 남긴다.

## 8. 베타 지표

### 유용성

- 아모라 질문 완료율
- 질문 문장 복사율
- 직접 예산·일정 기록 전환율
- 7일 재방문율

### 신뢰

- 가격·계약 답변의 원문 확인 안내 포함률
- 저장 실패의 정확한 노출률
- 게시글 신고 처리 상태의 설명 가능성
- 비공개 데이터의 공개 전환 사고 0건
- “AI가 가격을 판정했다”는 사용자 오인 비율

유용성이 높아도 신뢰 사고가 생기면 성공으로 보지 않는다.

## 9. 중단 기준

아래 현상이 반복되면 기능을 확장하지 말고 숨기거나 수정한다.

- 평균을 정답 가격으로 받아들임
- AI 답변을 계약 승인으로 받아들임
- 자동 생성 값이 사용자 확정 값처럼 저장됨
- 웹에서 되는 기능을 모바일에서도 된다고 오해함
- 계정 삭제 접수 없이 로그아웃되어 삭제됐다고 오해함
- 업체 연결이 되지 않는데 문의가 전달됐다고 오해함

## 10. 퇴역 기능을 다시 제안할 조건

업체 카탈로그·연결·예약, 동기방, 익명 견적 카드, WeddingCode, 빠른 후기, 모바일 커뮤니티 작성, 새 댓글·답글, 계약 관련 도구와 아모라 업체·예약 도구는 현재 로드맵 약속이 아니다. 해당 소비자용 화면·FAB·초안·계산 엔진과 아모라의 실행 스키마·선택·업체 데이터 접근 경로를 제거했다. 퇴역 기능의 소비자용 API와 새 댓글·답글 POST는 `410` 경계이며, 웹 기본 글쓰기와 기존 댓글 읽기·웹 작성자의 수정·삭제는 유지한다. 과거 도구 이름 목록은 구형 호출 거절에만 사용한다.

과거 테이블·SQL은 계정 삭제, 명시적 공개 해제와 보존 정리에만 남는다. 소비자용 과거 기록 조회는 제공하지 않으며, 남은 DB 구조는 현재 기능이나 재개 계획을 뜻하지 않는다.

재개하려면 최소한 다음 증거가 필요하다.

1. 소비자 문제와 성공 지표 합의
2. 데이터 소유권과 최소 수집 범위
3. 수정·삭제·신고·철회 전 과정
4. 실패·중복·지연·응답 유실 E2E
5. 법무·개인정보 고지
6. 웹·모바일 동등성 또는 명시적 플랫폼 차이
7. capability를 기본 false로 두는 출시 계획

검증되지 않은 기능은 “준비 중” 마케팅에도 사용하지 않는다.

## 11. 최종 제품 방향

현재 가장 신뢰할 수 있는 방향은 “AI가 좋은 거래를 판정한다”가 아니다.

> 커뮤니티 경험은 미확인 참고로 읽고, 아모라가 확인 질문을 정리하며, 사용자가 원문으로 확인한 일정과 계획·계약·지급 상태를 커플 기록에 직접 남긴다.

이 흐름을 완성한 뒤에만 더 복잡한 거래 기능을 검토한다.
