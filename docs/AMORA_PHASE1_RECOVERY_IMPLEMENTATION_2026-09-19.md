## 선택한 설계

대안 1은 대화 엔진·메모리·화면을 통째로 재작성하는 것, 대안 2는 기존 세 레인과 canonical 메시지/요청 키를 재사용하는 것이다. D1과 P1/P3에 따라 대안 2를 택했다. 새로운 저장 성공 판정이나 오프라인 자동 재전송 경로를 만들지 않는다.

초안은 기존 개인정보 목표 문서 §12.1의 **memory-only** 기본값을 따른다. 같은 인증 세션의 SPA 화면 왕복은 보존하되, 새로고침/브라우저·앱 강제 종료 후 **미저장 원문 복원은 보장하지 않는다**. 이미 서버에 저장된 요청의 cold recovery와는 별개다. 원문·첨부·새 request ID를 localStorage/sessionStorage에 추가로 영속 저장하지 않는다.

```text
레인별 초안 → 고정 요청 ID + 전송 스냅샷 → 서버 저장 확인
                                      ├─ 저장 확인: 정본/기존 답변 복구 경로
                                      ├─ 확정 거절: 원래 초안 복구
                                      └─ 결과 불명: 같은 ID로 확인, 새 요청으로 단정하지 않음

화면 왕복 → 같은 메모리 세션 유지
계정/커플/역할 전환 → 이전 generation 폐기 → 늦은 콜백 차단
원문 삭제 확정 → 해당 범위의 복구 초안 폐기 (단순 화면 정리와 구분)
```

### 안전 전환과 기존 초안 충돌

- 빈 private 작성창이면 텍스트+동일 요청 키를 함께 복원한다.
- 기존 private 글/첨부/읽기/참고 맥락이 있으면 이를 유지하고, 실패한 전송은 별도 private 메모리 항목에 고정한다.
- “보류 메시지 다시 확인”은 그 항목의 원문과 키만 사용한다. 현재 작성창의 다른 글에 그 키를 붙이지 않는다.
- 로컬 안전 홀드로 전송하지 않은 글은 자동 재전송하지 않는다. 기존 작성창을 비운 후 명시적으로 불러올 수 있다.
- 보류 초안 삭제는 기기 메모리만 지운다. 서버 전송 취소가 아니라는 안내를 유지한다.

## 후속 패널 수정의 필수 검증 경계

읽기 전용으로 진입점과 수명을 재확인했다. 패널 닫기는 DOM을 숨기는 반면 확대 후 `/chat` 이동은 실제 언마운트가 될 수 있으므로, 닫기·재열기만 성공해도 C01/C02 전체 해결은 아니다.

1. 앱 전역 패널과 커뮤니티 패널 각각에서 닫기·재열기, 확대·뒤로가기, 경로 이탈·복귀를 검증한다.
2. 세 레인의 원문·첨부·요청 ID·선택 범위를 함께 보존하며, 숨겨진 패널이 전체 화면의 선택을 덮지 않게 한다.
3. 실제 authStore로 로그아웃, A→B→A, 역할·커플·데모 변경과 상대 연결 해제를 검사한다. 같은 세션의 늦은 복구와 다른 세션의 폐기를 구분한다.
4. 안전 전환의 확정 실패·결과 불명·예외·로컬 홀드와 기존 개인 초안 충돌을 각각 검사한다. 민감 원문을 공유 칸에 복원하지 않는다.
5. 메모리 저장소와 전송 claim을 함께 사용해 전체 화면·패널 동시 전송에서도 초안 소모와 요청이 한 번만 일어나도록 한다.
6. FileReader 완료와 늦은 전송 결과가 계정·연결 전환 이후의 새 초안을 건드리지 않는지 확인한다.
7. 패널의 작은 draft 형식으로 공용 초안을 통째로 덮지 않는다. 준비 맥락·안전 보류·읽기 카운터·취향 전달 정보도 보존한다.
8. 화면 정리는 초안을 유지하고, 확인된 원문 삭제는 해당 복구 초안만 폐기한다. 미저장 원문의 영속 저장은 추가하지 않는다.

## 실제 기기·계정 검증에서 남은 확인

- 저장 응답이 끊긴 상황에서 대기 제한 뒤 다음 행동이 가능하고, 재시도가 같은 요청으로 확인되는지 시험한다.
- 공유 화면의 안전 전환과 기존 개인 초안 충돌에서 공유 화면으로 원문이 새어나가지 않는지 두 계정으로 확인한다.
- 모바일 답변 스트림이 중간에 끊겼을 때 미완료 표시·실행 차단·정본 복구를 화면에서 확인한다.
- 개인화 저장 결과가 불명확할 때 재조회 전 성공으로 표시하지 않는지, 계정을 바꾼 뒤 이전 결과가 적용되지 않는지 확인한다.
- iOS/Android 키보드, 백그라운드 복귀, 작은 뷰포트, 스크린리더를 별도 확인한다. C03과 C10은 미해결 목록에 남긴다.

## 이어갈 순서

1. 이번 코드 묶음의 가드·전체 로컬 관문·웹 빌드·모바일 번들 검증은 완료했다. 운영 반영이나 모든 화면의 완료로 확대 해석하지 않는다.
2. 별도 패널과 실제 모바일/두 계정/네트워크 장애 동작을 같은 복구 계약으로 맞춘다.
3. 대화 이해·개인화 정확도(C04/C05/C11), 긴 대화/작은 화면(C03/C09/C10)을 각자의 실패 재현으로 닫는다.
4. 사용자 승인된 배포 범위와 운영 게이트가 준비됐을 때 기존 프로젝트로 배포하고 hanbang.ai에서 실제 버전을 확인한다.
