## 0. 한 장 요약

**키 = "견적 등기소".** 이미 라이브인 견적 진단(계약 아님 — 가격·숨은비용·포함항목 사실 비교)을 정문으로 꺼내고, 진단한 견적을 익명 등기하면 같은 분기 동기들의 실제 금액 분포가 열리는 give-to-get을 단다. 진단 1건이 ① 유저의 즉시 가치 ② 라운지 자산(예산/체크리스트 자동 반영) ③ 동기 장부 ④ vendor_leads(업체 수요 증거)에 동시 적재된다 — **유저 1명의 행동 하나가 업체를 끌어올 증거를 자동 생산하는 기계.**

```
유저: 견적 진단(30초, 비로그인) → 등기 → 동기 분포 열람 → 라운지 습관
                ↓ (vendor_name 자동 적재)
업체: "귀사 견적 N건 확인됨" 아웃리치 → 무료 검증 프로필(가격 공개 자격) → 공식가 병기
                ↓
유저: 추정치가 공식 기준으로 격상 → 진단 신뢰↑ → 진단 증가 → (반복)
수익: 검증은 영원히 무료. 유료는 옵트인 리드 라우팅만 (순위 판매 영구 금지)
```

## 1. 법적 비교 판정 (먼저 — 파운더의 우려)

**판정: 견적 장부 리스크 등급 "중" — 가드레일 적용 시 "하"로 관리 가능. 진행해도 된다.**

| 리스크 축 | 계약 서비스 (폐기) | 견적 장부 |
|---|---|---|
| 변호사법 §109 | **상** — 계약서 효력·위약금 판단은 '감정'에 근접, 구조적 | **하** — 가격 통계 집계는 법률사무 아님 |
| 명예훼손·업무방해 | 중하 | **실명 시 상 / 익명 집계 시 하** — 한국은 사실적시도 처벌 |
| 개인정보 | 중 (계약서 실명·계좌) | 중 (견적서는 적음, k-익명성 관리) |
| 정확성 책임(민사) | **상** — 위약금 오계산→해지 강행→직접 손해 | 중 — 표본수·출처 병기로 완화 |

구조적 차이: 계약 서비스 리스크는 **서비스 본질에 내재**(제거 불가)했지만, 견적 장부 리스크는 표현·익명화 **정책으로 통제 가능한 운영 리스크**.

**업체명 3단계 정책 (영구 원칙)**:
1. 현행: 외부엔 익명 집계만. vendor_name은 내부 vendor_leads 점수용으로만.
2. k≥5 셀만 최소–중위–최대 레인지 공개, 업체명 여전히 비노출. k 게이트는 **API/DB 레벨 강제** (프론트 금지 — cohort 구멍 교훈).
3. 실명-가격 연결은 **업체 본인이 검증 프로필로 가격 공개에 opt-in한 경우만**. 동의 없는 실명+가격+평가 결합은 **영구 불가**.

**기존 기능 처리 (제거 불필요, 표현 정비만)**:
- `contractQuestions` → 라벨 "계약 전 확인 질문" → "업체에 확인할 질문" (실체는 포함 여부 확인 질문)
- `negotiationScript` → "확인 요청 문자" (실체는 문서화 요청)
- `analyze_contract_readiness` → "예약 전 확인 도우미"로 개명, 위약금 '액수' 산식 추가 영구 금지

**1인 운영 일상 수칙 10**: ①배포 전 업체 실명 노출 화면 확인 ②k<5 셀 API 누출 확인(select("*") 금지) ③평가어("바가지" 등) 전면 금지 — 사실+숫자만 ④모든 통계에 n·기간·출처 병기 ⑤신고 메일 24h 확인, 권리침해 신고 즉시 블라인드 ⑥견적서 이미지 내 개인정보 저장 전 마스킹 ⑦아모라 출력 주간 샘플 점검(업체 비방/법률 판단 여부) ⑧"전국 평균"은 참가격 인용 시에만, 자체 표본은 "등기 N건 기준" ⑨랜딩 수치는 근거 있는 것만 ⑩분쟁 시 데이터 보존+블라인드, 임의 삭제 금지.

## 2. 문(Door): /check — 첫 3분

**후크 (추천)**: **"결혼 준비, 견적서대로 끝난 적이 없습니다. 원본비·헬퍼비·얼리스타트비 — 결제 전에 30초 진단."**
(근거: 고유명사가 당사자에겐 공감, 비당사자에겐 호기심. hiddenCosts 50항목으로 실증 가능 — 무근거 수치 불필요. "안심"이 아니라 손실 회피 프레임, 계약 언급 0.)

- **0:00** `/check` (비로그인): 폼이 히어로. 입력 3개 — 카테고리 칩 / 지역 / 견적 총액. "30초. 회원가입 없음."
- **0:40** 결과 (비로그인, 전부 무료): 투명도 등급 A~F + 참가격 중위가 대비 ±%("통계 기준" 라벨) + 숨은 추가금 목록(위장명·사용률·추정 min~max) + 협상 스크립트 1개 전문. 공유 → `/quote/[id]`.
- **1:30** 게이트 (유일한 로그인 지점): "2026년 4분기 결혼 ○○지역 커플들이 **실제로 낸 금액** 분포에서 내 위치 보기" → 카카오 로그인 1회.
- **2:00** 등기 제안: 직전 진단 데이터 재사용 + 결혼 분기 1개만 추가 입력, 토글 1번 → 분포/동기방 진입.

**원칙: 진단 가치는 게이트 앞에서 전부 주고, 분포(남들의 데이터)만 give-to-get 뒤에.**

**표본 0건 정직 처리 (2단 분리 표기 고정)**: 상단 "전국 통계 기준(참가격)" / 하단 "실등기: 0건 — 당신이 이 조합의 1호 등기입니다" + '1호 등기' 배지. k<5는 "현재 N건 (5건부터 공개)". 두 층 절대 혼합 금지.

**견적서 사진 업로드: 추가 (가드 4종)**: ①추출 결과 수정 가능한 확인 화면 → 사용자 확정 후 진단 ②이미지 비저장(구조화 필드만 추출 후 폐기) ③추출 업체명은 화면 미노출, vendor_leads 전용 ④사진 6/h 리밋.

**구조 변경**: `/` 분기(비로그인→/check 랜딩, 로그인→라운지) / 6슬라이드 모달+4스텝 튜토리얼 제거 / "후기 120만+" 허수 → 실측 카운터("이번 주 진단 N건") / `/market-prices` 공개 전환(하드코딩 상수라 보호 이유 없음, 지역별 정적 페이지로 SEO 면 확보 — 잠그는 건 실등기 분포뿐).

## 3. 업체 엔진 (원래 의도 "유저→업체"의 기계화)

**업체가 움직이는 트리거** (광고 영업엔 면역): ①자기 업체명 박힌 수요 증거("지난 30일 귀사 견적 N건 진단됨" — 사실 통보라 무시 어려움) ②평판 정정권(추정치만 보이는 상태에서 "정정 기회"는 거절 비용이 큼) ③동네 FOMO(사실일 때만 사용).

**아웃리치 래더** (vendor_leads 점수제 위):
- **T1** (7점+ AND 진단 1건+, 카톡채널/DM): "광고 영업이 아니라 정보 확인차 연락드립니다. 지난 한 달간 예비부부 N분이 저희 견적 진단에서 귀사 견적서를 확인했습니다. 공식 가격 기준을 직접 등록하시면 무료로 검증 프로필로 정확하게 표시됩니다. 등록비·광고비 없고, 순위 판매도 하지 않습니다."
- **T2** (11점+ OR 진단 3건+, T1 무응답 7일 후, 메일+지역 리포트 PDF 1장): "예비부부들이 가장 많이 묻는 게 원본비·헬퍼비 포함 여부입니다. 귀사 기준을 등록해 주시면 공식 답으로 표시됩니다."
- **T3** (응답 시): 요구 딱 3개 — 가격 범위 / 포함·미포함 / 취소·환불 기준. 15분 콜 종료.
- 고위험 진단 반복 업체는 "사실 확인 요청" 톤만 (명예훼손 차단).

**무료 검증 프로필** (P4 자격 필터): 사업자 증빙 + 기본가 범위 + 대표 추가금 3종(hiddenCosts 매핑) + 취소·환불 기준 공개. 받는 것: 검증 뱃지, 공식 가격표(진단 결과·정보판에 "공식 기준" 병기), 익명 추정치 정정권, 분기 수요 리포트, 영구 무료. 핵심: 파는 건 "노출"이 아니라 **자기 가격 정보의 통제권**.

**유료 (P1: 순위 판매 영구 금지, 검증 영원히 무료)**: 옵트인 리드 라우팅만 — 유저가 진단 후 "검증 업체에 공식 견적 받아보기" 손들면 익명 요청(예산대·희망일)이 업체에 전달. 건당 3만원(응답 시 과금) 또는 월 12만원(8건 캡). **판매 조건**: 해당 지역×카테고리 셀 월 진단 30건+ AND 옵트인 전환율 측정 완료 전엔 안 판다(그 전엔 "3개월 무료 베타"). 시점: 8주차 이후 서울 스드메부터.

**1인 운영**: 주 6시간 루틴(월 1h 리드 정리 / 화 2h T1·T2 발송 20건 / 목 1h 후속·콜 / 금 2h 검증+인사이트 글). 첫 10곳: 웜리드(진단에 업체명 이미 입력된 곳)부터 + 박람회 1회 명함 30장 → 40곳 접촉 → 응답 25% → 검증 5~6, 부족분은 유저 추천 보상("상담 업체명 알려주면 우선 진단권"). **8주 목표: 리드 300 / 접촉 120 / 온보딩 25 / 검증 12 / 유료 0(베타 무료 3곳).** 선행 빌드 1개: 진단 결과에 옵트인 버튼(미검증 셀은 "검증 업체 모집 중" 대기열) — 유료 전환율 증거를 지금부터 축적.

## 4. 리텐션 (모먼트 도구 → 12~18개월 습관)

1. **등기 직후 연결**: 진단 결과 CTA "이 견적을 내 예산에 반영" → apply_budget_plan 재사용으로 progress에 기록 + 체크리스트 "견적 받음" 자동 체크 + 동기판 익명 공유 제안. **진단 1건 = 예산·체크리스트·동기 장부 3곳 동시 적재.** (선행 수리: 채팅 진단이 amora_quote_checks에 저장 안 되는 갭 — source 컬럼 추가로 단일화.)
2. **월요 좌표 리포트** (B안 "기수 점호" 흡수): ①내 좌표 변동("+8%→+5%, 동기 등기 3건 추가") ②동기 신규 등기 ③다음 카테고리 예고. 채널: Resend 이메일(무료 3,000통/월, 기존 cron 패턴) + 라운지 웹 배지. 카카오 알림톡은 오픈율 25% 검증 후 보류.
3. **아모라 선제 개입 3종** (전부 규칙 기반, ML 불필요): ①카테고리 선행 가이드("다음은 스튜디오네요, 견적 받기 전 체크 5가지" — hiddenCosts에서 추출, 제작비 0) ②실수방지 레이더 v0(등기 시 기존 등기·예산 대조 1회성 경고) ③방문 시 브리핑(라운지 접속 시점 서버 즉석 생성 한 줄).
4. **amora_action → 라운지 단일 피드**: 채팅에만 사는 ActionCard를 라운지 카드 스택으로. 원칙: **라운지에 오면 항상 새 카드 1장+.**
5. **빈 라운지 해체**: "0%·미정" 나열 대신 단일 카드 — "받아둔 견적서 있어요? 30초 만에 우리 지역 시세 대비 좌표를 보여드려요." (폴백: 분기 입력→동기방 배정.) 첫 세션 목표 = 등기 1건 또는 기수 배정 1건.

**측정**: 등기→예산 반영률 ≥40% / 다이제스트 오픈율 ≥25%, 재방문 CTR ≥10% / WAU/가입자 ≥30% / 첫 세션 등기 or 배정 ≥50%. **북극성: 가입 12주차에도 주 1회+ 라운지 복귀하는 유저 비율.**

## 5. 빌드 순서 (수정된 90일 앞부분)

**W1**: D1–2 `/` 분기 + `/check` 랜딩 / D3–4 등기 스키마(is_ledger·quarter·region)·게이트 API·분포 화면(0건 2단 표기) / D5 **cohort contracts API select("*") 익명성 구멍 수리 (집계만 반환)**.
**W2**: D6–8 사진 업로드(확인 화면, 이미지 미저장) / D9–10 시세 공개 + NATIONAL_AVG 단일 소스 통합 / D11–12 온보딩 해체·허수 교체·동적 OG / D13–14 퍼널 계측(광고→진단완료→로그인→등기 4단계).
